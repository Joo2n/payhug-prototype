## 1. 화면 결정

### M-1 정산채권 양수
| 구분 | 내용 |
|---|---|
| TO-BE | `계약서보기` — 전자계약서로 넘어가기 전 계약서 내용을 볼 수 있다. 계약서 원본이 전자서명으로 교체되지만 **액션 자체는 둘 다 동일** |
| AS-IS | 전자서명 계약서 보기는 동일. 전자 서명이고 `서명하기`는 파트너와 동일. 추후 전자계약서로 서명 |

### M-2 계약기록
- `선택 문서 다운로드` 결과물 = **전자서명 결과**
- 기존: 서명도 이미지, 페이허그가 만든 계약서도 이미지
- 전자서명: 계약서도 텍스트, 서명값도 텍스트 → **PDF 이미지로 받을 필요가 없다**
- 확인필요 ①: 이미지 서명과 전자서명 텍스트는 다른 것 — 기술 확인 필요
- 확인필요 ②: 이미지는 조작 가능하므로 전자서명 텍스트가 본질. **이 결과물을 어떤 파일로 받아야 하는가** 확인 필요
- 이번 노출 기준: **하나인증서를 사용한 전자서명이라 페이허그가 조작할 수 없다**는 것을 보이고, 그것을 내려받게 한다

### M-3 가맹점
- 정렬 필터 삭제 · 표 보기 갯수 삭제 · `표시 1-8` 삭제
- 표 왼쪽에 `No` 열 — 1, 2 …

### M-4 쿠콘 관리 현금

- 확인필요 ③: 현재 동작 안 함

## 2. 용어 설명 — 대표가 뜻을 설명한 것

**이 절은 시스템 변경 요청이 아니다.** 반영처는 용어 해설 문서 본문 한 곳이며, 이것 때문에 산식·데이터 구조·화면 라벨을 바꾸지 않는다. 화면이나 원고가 아래 정의와 **정면으로 어긋나면 그때만 오류로 보고 고친다**.

`ID`는 뜻 설명일 뿐 할 일이 없다. 새 카드를 만들지 않는다.


| 용어 | 대표 확정 정의 |
|---|---|
| 투자자 할인율 | **(채권매입)수수료율**. 내부 용어이며 **외부에는 `할인율`로 표기** |
| ID | 가맹점 식별값. 가맹점 번호·투자자 번호 등의 구분값 |
| 정산금채권 | 돈 주는 곳은 모두 **플랫폼**. 특정 플랫폼이 특정 가맹점에게 서로의 약속으로 **정산예정일에 주기로 한 돈**, 그 권리. `채권매입`은 정산금채권 매입이며 **정식 용어는 정산금채권** |
| 정산금채권 단위 | 특정 일자 · 특정 가맹점(ID)에 대해 특정 플랫폼이 지급할 돈 |
| 대상정산금채권 | 정산금채권 중 **투자자(나)에게 속하는 것**. 투자자 어드민(로그인 계정)이 다루는 모든 채권. 정산금채권 ID는 **매출 일자 단위**. 모집단은 **가맹점 단위**로 매입 → **가맹점당 투자자 1명**, **투자자 1명 : 가맹점 다수** |
| 순현금 | **쿠콘 가상계좌의 현 잔액**. 현재는 페이허그 가상계좌 1개. 법적으로는 페이허그용으로 개설된 **쿠콘 명의의 케이뱅크 계좌** |

순현금 부속 결정:
- 페이허그용 계좌와 같은 방식으로 **투자자별 케이뱅크 계좌 1개씩 제공 예정**
- 투자자도 **입출금계좌를 등록**해야 하며, 그 계좌로 **할인율(수수료율) 몫이 입금**
- 당분간 투자자가 없으므로 **오프라인 계약 → 계좌번호 수령 → 관리자 시스템 입력 → 수동 지급**
- 투자자 규모 **10명 내외**
