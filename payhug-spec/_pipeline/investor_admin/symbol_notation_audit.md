### 2-1 HTML — 가능. 15:33 에 실제로 적용된 것을 검증했다

기준선 15:12 시점 `<sub>` **0건**, 유니코드 아래첨자(`ᵢ` `₁` `₋`) **0건**.

문제였던 것 — `build_glossary.py:68` 이 `H.escape(t, quote=False)` 로 본문 전체를 이스케이프한다. 살아남는 원시 HTML은 `RAWA` 로 빼돌리는 `<a id="…"></a>` 하나뿐이었고, 코드펜스도 통째로 이스케이프한다. **원고에 `<sub>` 를 그냥 넣으면 화면에 `&lt;sub&gt;` 글자가 찍힌다.**

15:33 현재 생성기에 변환 규칙이 들어갔다.

```python
build_glossary.py:66
SUBRE = re.compile(r'(?<![A-Za-z0-9_])(SMR|SB|SA|SM|SD|SL|A|B|M|D)_(?:\{(D-1,i|D-1|p,i)\}|(i))(?![A-Za-z0-9_])')

def subs(t):
    def one(m):
        body = (m.group(2) or m.group(3)).replace('-', '−').replace(',', ',&thinsp;')
        return f'{m.group(1)}<sub>{body}</sub>'
    return SUBRE.sub(one, t)

def flat(t):   # alt·검색키처럼 태그를 못 넣는 자리
    return SUBRE.sub(lambda m: m.group(1) + (m.group(2) or m.group(3)).replace(',', ''), t)
```

원고 규약 `A_i` · `A_{D-1,i}` · `SA_{D-1}` · `A_{p,i}`. 하이픈을 빼기표 U+2212 로, 쉼표 뒤에 가는 공백을 넣는다. 인용 자리는 원고가 평문이라 정규식에 안 걸린다.

**시험 2 — 문장 한가운데 섞기.** `CellRichText(['w금융일수 = Σ ', TextBlock(plain,'A'), TextBlock(sub,'i'), ' × ', …])` 정상. 평문 부분은 `str` 로 그냥 넣어도 된다.

**시험 3 — 셀 서식과의 공존.** 리치텍스트 셀에 `Font(bold=True, name='맑은 고딕')` · `Alignment` · `PatternFill` · `Border` 를 걸고 재판독한 결과 `font.b=True` · `name='맑은 고딕'` · `fill='FFEFF6FF'` · `align='center'` 전부 보존. **충돌하지 않는다.**

**시험 4 — 기존 검증기 영향.** `load_workbook(path)` 기본값(`rich_text=False`)으로 읽으면 값이 **평문 문자열로 납작해진다.**

### 4-1 인용과 서술이 화면에서 구분되지 않는다 — 남아 있는 결함

`glossary-legacy.html` 에는 `<pre class="calc quote">` 인용 전용 클래스가 있었다. 현행 배포본에는 **`calc quote` 0건 · `calc` 123건.**

```python
build_glossary.py:108(기준선)
o.append('<pre class="calc">' + H.escape('\n'.join(L[i+1:j])) + '</pre>')
```

원고 코드펜스 246개가 전부 같은 상자로 나온다. **어느 블록이 대표 원문 인용이고 어느 것이 우리가 쓴 식인지 화면에서도 DOM 에서도 갈리지 않는다.** 표기를 고치는 조가 인용 자리를 자동으로 피할 방법이 없다.

지금은 `_` 유무로 우회하고 있지만, 그건 원고를 손으로 정확히 쓴다는 전제에 기댄다. 인용 블록에 실수로 `_` 를 넣으면 원문 표기가 조용히 바뀐다. **막는 장치가 없다.**
