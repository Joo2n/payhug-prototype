## 본문

주신 용어 정의서를 투자자 어드민 화면과 엑셀에 적용하는 중에, 정의서만으로는 값이 하나로 정해지지 않는 곳이 4군데 남았습니다. 여기에 8/28 미팅에서 확인 필요로 남겨 두신 전자서명 결과물의 파일 형식 1건을 더해 5건입니다. 아래 순서대로 회신 주시면 화면 숫자를 확정하고 계약기록 다운로드를 열겠습니다.

앞서 여쭈려던 3건 — 정의서가 가리키는 번호 마커, 채권매입수수료의 기준금액·요율, `미지급금`·`과지급금`의 정의 — 은 사내에서 자료와 운영 어드민 화면을 대조해 닫았습니다. 번호 마커는 스토리보드 캡처 2장의 마커와 1:1로 맞췄고, 채권매입수수료는 계약별로 정해지는 요율이라 어드민 요율 설정에서 읽어 옵니다. `미지급금`·`과지급금`은 어드민에 이미 있는 개념(선정산 지급 대상인데 못 준 금액 / 더 나간 금액)과 같은 것으로 확인했습니다. 회신 대상이 아닙니다.

숫자는 화면 기준일 2026-08-27, 조회 기간 2026-08-21 ~ 08-27(일주일) 기준입니다.

### 회신이 필요한 5건

**Q-1. 투자자산 대비 Ty수익율은 어느 값이 맞습니까**

- 현재 상태 : 화면은 정의서 ⑤(유량 기준)로 맞춰 `2.24%`를 씁니다. 같은 실적을 분모만 바꿔 읽으면 `3.59%`(PSC를 평균 순현금으로)·`3.19%`(분모를 기준일 잔액으로)가 되어 갈립니다. 정의서 안에서 PSC 처리가 정해지지 않은 것이 남은 문제입니다.

  정의서 안에서도 PSC 처리가 갈립니다. 배치 항목은 `평균순현금`을 산출한다고 적었는데 PSC는 `EC들의 합`으로 정의돼 있습니다. 합으로 보면 140,000,000(20,000,000 × 7일), 평균으로 보면 20,000,000이고 결과가 1.3%p 넘게 벌어집니다.
- 왜 묻는지 : 제안서에 실리는 수익율 지표라, 같은 실적이 2.24%로도 3.59%로도 읽힙니다. 1.60배 차이입니다.
- 원문 근거 : `투자자산 대비 ty수익율 (이미지의 ⑤) = (이미지의 ④ x PSA) / (PSA + PSC)` / `PSC = 위 선택한 기간의 EC들의 합` / `... w금융일수(SDD-1), ty수익율, 평균순현금 산출해 DB 업데이트`
- 선택지 : ④ = 3.99%, PSA = 179,970,919 고정
  - A안 — PSC를 기간 EC 합 140,000,000으로. ⑤ = 2.2450% → `2.24%` (정의서 문자 그대로 · 현행 화면)
  - B안 — PSC를 평균 순현금 20,000,000으로. ⑤ = 3.5921% → `3.59%`
  - C안 — 분모를 기준일 잔액으로. ④ × 투자실행액 ÷ 투자자산 = 3.1931% → `3.19%`

**Q-2. 가맹점별 투자자산 표의 `비중` 열을 어떻게 합니까**

- 현재 상태 : 한 화면에 `비중`이라는 같은 이름의 열이 두 개 있고 분모가 다릅니다. 현황표 2행은 분모가 투자자산 100,000,000(80.0% / 20.0%), 가맹점별 8행은 분모가 투자실행액 80,000,000(합 100.0%)입니다. 분모가 다르다는 단서는 화면에도 엑셀 6종에도 없습니다. 정의서의 비중은 투자실행액과 순현금 2행만 규정하고 가맹점별 축은 언급이 없습니다.

  아울러 8행을 소수 1자리로 반올림한 합이 100.0%에서 어긋나면 최대잉여법으로 맞춥니다 — 0.1%p 단위로 내린 뒤 남는 눈금을 소수부가 큰 행부터 하나씩 나눠 줍니다. 지금 데이터에서는 눈금 5개가 그렇게 배분됩니다. 이 표는 투자자산 증명서 PDF에도 그대로 실립니다.
- 왜 묻는지 : 증명서 PDF 8건 · 엑셀 1종 · Figma 2프레임이 이 열 하나에 함께 걸려 있어, 정해지기 전에는 재발행을 못 합니다.
- 원문 근거 : `투자 실행액의 비중 = 투자실행액 / (투자실행액 + 순현금)` / `순현금의 비중 = 순현금 / (투자실행액 + 순현금)`
- 선택지 :
  - A안 — 존치하되 열 이름을 분리(예: `투자실행액 대비 구성비`). 8행 합계 100.0% 유지, 숫자 변동 없음
  - B안 — 분모를 투자자산으로 통일. 8행 합계 100.0% → 80.0%, 최대 행 24.2% → 19.3%
  - C안 — 폐기. 증명서 PDF와 엑셀에서 열 삭제

**Q-3. 조달이자형(연 12%) 산식 카드를 계속 둡니까**

- 현재 상태 : 화면 11개가 산식 카드 2종을 나란히 두고 있습니다. `수수료 배분형 0.11%`와 `조달이자형 투자실행금 × 연 12% × 사용일수 ÷ 365`입니다. 정의서는 채권매입수수료 기반 1모델만 제시하고 연 12%를 언급하지 않습니다.
- 왜 묻는지 : 두 모델이 동시에 걸리는 것인지 둘 중 하나를 고르는 것인지에 따라 투자수익 열의 산출 근거가 달라집니다.
- 원문 근거 : 정의서에 연 12%를 언급한 문장이 없습니다. 병기는 이전 결정 D-1에서만 나옵니다.
- 선택지 :
  - A안 — 2모델 병기 유지
  - B안 — 정의서에 맞춰 채권매입수수료 1모델로 접고 조달이자형 카드 삭제(화면 11개)

**Q-4. 화면의 0.11%를 단서 없이 인쇄해도 됩니까**

- 현재 상태 : 정의서는 `0.11% 예정`으로 적었습니다. 화면 제목은 `수익 산정 기준`이고 요율에 붙는 각주는 0건입니다. 화면은 `0.11%`를 단서 없이 인쇄합니다. 정의서의 할인율은 유동화투자자 단위 단일값입니다.
- 왜 묻는지 : 제안서 첨부용 화면이라 단서 없는 `0.11%`가 대외에 확정 요율로 읽힙니다.
- 원문 근거 : `유동화투자자의 할인율 = 0.11% 예정`
- 선택지 :
  - A안 — 현행 유지. 화면은 `0.11%`만 인쇄합니다
  - B안 — `예정` 단계임을 제안서 본문에 적고 화면은 그대로 둡니다

**Q-5. 전자서명 결과물을 어떤 파일 형식으로 받습니까**

- 현재 상태 : 계약기록의 행별 다운로드와 `선택 문서 다운로드`를 비활성으로 막아 두었습니다. 지금까지 내려주던 전자서명 결과 텍스트는 원문 해시와 서명값이 화면을 만들면서 지어낸 문자열이라 실제 전자서명 산출물이 아닙니다. 형식이 정해지기 전에는 실물을 걸지 않습니다. `계약서보기`의 계약서 원문 열람과 투자자산 증명서 PDF, 엑셀 8종은 그대로 내려옵니다.
- 왜 묻는지 : 8/28 미팅에서 "이미지는 조작 가능하므로 전자서명 텍스트가 본질"까지는 정해졌고 이 결과물을 어떤 파일로 받는지는 확인 필요로 남았습니다. 투자자가 보관·제출용으로 받는 유일한 계약 증빙이라, 형식이 정해져야 계약기록 다운로드를 다시 엽니다.
- 원문 근거 : `이미지는 조작 가능하므로 전자서명 텍스트가 본질. 이 결과물을 어떤 파일로 받아야 하는가 확인 필요` (2026-08-28 미팅 결론)
- 선택지 :
  - A안 — 텍스트 1건. 계약서 원문·서명값·서명검증 회신전문을 한 파일에 담습니다
  - B안 — 원문·서명값·회신전문을 각각 파일로 두고 압축 1건으로 묶습니다
  - C안 — PDF 1건. 서명값과 회신전문을 문서 본문에 인쇄합니다

### §7 사내 대조로 닫은 3건 — 현행 구조

| 항목 | 현행 구조 |
|---|---|
| 번호 마커 | 스토리보드 캡처 2장의 번호와 1:1로 맞췄다(`marker_legend.md`). 투자 수익 화면은 `현황` 표와 `일별 투자수익` 표가 각각 1번부터 다시 세고, 대표 산식의 번호는 그 산식이 등장하는 문맥으로 갈린다. ⑥의 내부 `③`은 일별 표 3열 `투자실행금`이다. ④와 ⑥은 동명이의가 아니라 같은 지표의 집계 단위 차이(기간 집계 / 하루치)다 |
| 채권매입수수료 | 수수료 코드 `MARGIN` 통 하나를 `MARGIN × INVESTOR / PAYHUG / UPPER / LOWER / SALES` 5행으로 폭포수 배분한다. 요율 숫자는 코드에 리터럴이 없고 DB `PolicyRate.rateBps`에서 내려온다 — **계약별로 달라지는 파라미터**라 하드코딩이 없는 것이 정상이다. 투자자 몫은 요율 `investorRate`, 금액 `Payout.margin` 중 `role === "INVESTOR"` 행. 채권매입수수료는 면세, 시스템이용료·이체수수료는 과세라 투자자 배분액의 VAT 여부가 여기서 갈린다 |
| 미지급금·과지급금 | 어드민 정산 로직에 이미 있는 개념이다. **미지급금** = 선정산 지급 대상인데 배치에서 빠져 아직 못 준 금액 — 미정산 누락 도메인(`MissedSettlementsData.totalAmount`), 화면 라벨 `미지급`·엑셀 헤더 `미지급액`. **과지급금** = 더 나간 금액 — 선정산 후 취소 환수(`CANCEL_CLAWBACK`)·현장결제 중복 수령이 발생 원인이고, 회수하지 못하고 남은 잔액은 `미회수 이월(carryForward)`로 따로 잡힌다. 정책서 6대 개념의 `미지급금`·`과지급`과 **같은 개념**이다 |

## 회신이 오면 열리는 것

| 회신 | 열리는 작업 |
|---|---|
| Q-1 | `투자자산 대비 Ty수익율` KPI 1개 값 확정 |
| Q-2 | 가맹점별 표 · 증명서 PDF 8건 · 엑셀 1종 재발행 |
| Q-3 | 산식 카드 화면 11개 |
| Q-4 | 요율 게이트 |
| Q-5 | 계약기록 행별 다운로드 6건 · 묶음 2건 |

Q-1 ~ Q-4 는 표기·선택의 문제라 회신을 기다리는 동안에도 개발 착수를 막지 않는다. Q-5 는 계약기록 다운로드 하나를 붙잡고 있고, 나머지 화면과 산출물에는 걸리지 않는다.
