## 3. W금융일수 — 모집단을 바꾸고 표기를 2자리로 한다

### 3-A. 지금 구조로는 2.75가 나오지 않는다

현행 `daily_ledger.py` 는 W의 모집단을 **미회수 채권**으로 잡는다. 미회수 스냅샷은 만기가 긴 채권이 더 오래 남아 있어 발생 기준 평균보다 길다. 만기 d짜리 채권은 어느 기준일에서든 d일치 발생분이 미회수로 남으므로, 미회수 가중평균은 E[d²]/E[d] 가 된다.

대표 실측 분포로 계산하면 이렇다.

| 플랫폼 | E[d] | E[d²] | E[d²]/E[d] |
|---|---|---|---|
| 카드사 | 2.016438 | 6.109589 | 3.029891 |
| 배달의민족 | 3.350685 | 13.482192 | 4.023712 |
| 쿠팡이츠 | 4.747945 | 25.120548 | 5.290825 |
| 요기요 | 6.164384 | 40.761644 | 6.612444 |

```
미회수 기준 W = Σ(비중 × E[d²]) / Σ(비중 × E[d]) = 11.090180 / 2.750407 = 4.032218
Ty            = 0.11 × 365 / 4.032218 = 9.957%
```

대표 비중을 그대로 넣어도 미회수 기준으로는 **4.03일 · 9.96%** 가 나온다. 2.75일 · 14.60% 는 나오지 않는다.

역방향도 성립하지 않는다. 미회수 잔액의 플랫폼 구성을 대표 비중에 맞추면 W = Σ 비중 × E[d²]/E[d] = 3.621544 다. 어느 쪽으로 놓아도 2.75가 아니다.

### 3-B. 대표 정의서를 다시 읽으면 미회수 필터가 W에 걸려 있지 않다

> 투자 실행액: '… 순지급액들 중 **회수되지 않은** 순지급액 합계' × (1 − 할인율)
> w금융일수 = Σ Ai × Di / Σ Ai
> 대상정산금채권: 가맹점ID가 '…체결한 가맹점'의 ID이면서, **선정산일자가 상기 합의서상의 효력기간에 해당하는** 정산금채권

'회수되지 않은' 이라는 한정은 투자 실행액 줄에만 있다. 대상정산금채권의 정의에는 선정산일자 조건만 있고 회수 여부 조건이 없다. 그리고 대표가 직접 낸 엑셀 H41의 2.7504068548610725는 365일 전수 발생분의 가중평균, 곧 발생 기준이다.

### 3-C. 결정

**W금융일수의 모집단을 미회수 채권에서 대상정산금채권 전체(선정산일이 효력기간에 든 것)로 되돌린다.**

`verify_identity.js:388-397` 이 2026-08-29에 `잔액 = 유량 × 만기` 항등식 검사를 걷어낸 사유가 "이 검사를 통과시키려고 W 모집단이 대상정산금채권 전체로 잡혀 있었다 · 정의서 근거가 없는 검사가 정의서 해석을 밀어낸 자리다" 였다. 이번에는 정의서 원문과 대표 실측 엑셀 양쪽이 발생 기준을 가리키므로, 판단이 반대로 선다. 항등식은 부수 결과로 되살아난다.

```
투자실행액 = 하루 투자실행금 × W
80,000,000 = 29,086,605.81 × 2.750406854861…   (오차 0)
```

가맹점별 투자금액은 계속 미회수 기준이다. 미회수 잔액 = 하루 선정산액 × (1 − 할인율) × 그 가맹점의 만기이므로, W와 잔액은 같은 E[d] 를 쓴다. 두 값이 어긋나지 않는다.

### 3-D. 표기 자릿수 — 소수 1자리에서 2자리로

`W = 2.750406854861…` 을 소수 1자리로 적으면 **2.8**이 된다. 세 갈래를 놓고 본다.

| 갈래 | W 표기 | Ty | 화면 두 칸으로 되짚기 | 대표 값 14.60%와 |
|---|---|---|---|---|
| ① 1자리 · Ty를 표기 W에서 (현행 규칙) | 2.8 | 40.15 / 2.8 = **14.34%** | 성립 | 어긋난다 |
| ② 1자리 · Ty를 raw W에서 | 2.8 | **14.60%** | 40.15/2.8 = 14.34 ≠ 14.60, 깨진다 | 맞다 |
| ③ **2자리 · Ty를 표기 W에서** | **2.75** | 40.15 / 2.75 = **14.60%** | 성립 | 맞다 |

③을 택한다. 40.15 ÷ 2.75 = 14.6 이 나누어떨어져, 화면에 뜬 W 한 칸과 할인율 한 칸으로 Ty가 정확히 되짚어지면서 대표 raw 값 14.597840% 의 2자리 반올림과도 같은 자리에 앉는다. S입금부족율·Ty수익율이 이미 소수 2자리라 자릿수도 통일된다.


## 5. 순현금과 비중

순현금은 쿠콘 가상계좌 현금잔액이라 채권과 무관한 별개 스톡이다(D-18b). 원장이 만들지 않고 상수로 받는다.

```
순현금   CASH  = 20,000,000
투자실행액 EXEC = 80,000,000
투자자산       = 100,000,000

투자실행액 비중 = 80,000,000 / 100,000,000 = 80.0%
순현금   비중 = 20,000,000 / 100,000,000 = 20.0%
합            = 100.0%
```

대표가 말한 "순현금은 전체의 20~30%" 의 하한에 정확히 앉는다.

### 5-A. 잔액 기준 Ty 2종

```
투자실행금액 대비 Ty = 할인율 × 365 / W = 0.11 × 365 / 2.75 = 14.60%
투자자산   대비 Ty = 14.60 × 80,000,000 / 100,000,000 = 11.68%
```

### 5-B. 기간 기준 Ty 2종 — 화면 ④·⑤

대표 정의서 [2번 이미지]의 ④·⑤는 유량이다. `PSC` 가 순현금 잔액이 아니라 조회 기간의 EC 합계라 잔액 기준 11.68%와 다른 값이 나온다.

```
하루 투자실행금 = EXEC / W                  = 29,086,606원
하루 순지급액   = 29,086,606 / 0.9989        = 29,118,636원
하루 투자수익   = floor(29,118,636 × 0.0011) = 32,030원

PSMR = 0.0011 / 0.9989 = 0.110121%   (기간 길이와 무관)
PSD  = 2.750407
④ = 0.110121 × 365 / 2.750407 = 14.613916%  →  14.61%
```

| 조회 기간 | PSA | PSM | PSC | ④ | ⑤ |
|---|---|---|---|---|---|
| 기본 일주일 7일 | 203,606,240 | 224,210 | 140,000,000 | 14.61% | **8.66%** |
| 원장 전 구간 180일 | 5,235,589,045 | 5,765,400 | 3,600,000,000 | 14.61% | **8.66%** |

```
⑤ = ④ × PSA / (PSA + PSC) = 14.613916 × 203,606,240 / 343,606,240 = 8.659576%  →  8.66%
```

④가 잔액 기준 14.60%보다 0.01%p 큰 것은 채권매입수수료 앵커가 순지급액이고(D-31) 투자실행금은 순지급액 × (1 − 할인율) 이라 분모가 그만큼 작기 때문이다. 현행에서도 같은 자리에 같은 크기의 차가 있다.

## 6. S입금부족율 — 8개 값을 그대로 쓴다

### 6-A. 규모 무관성 확인

`UNPAID` · `OVERPAID` 는 순지급액 대비 **비율**이다. 산식이 `S = Σ SLi / Σ SAi` 이고 `SLi` · `SAi` 둘 다 순지급액에 비례하므로 분자·분모에서 규모가 약분된다. 규모를 1억으로 줄여도 값이 바뀌지 않는다. **8개 그대로 둔다.**

방향도 그대로다 — 미팅 0번이 미지급 = 플랫폼이 투자자 락계좌에 덜 넣은 것, 과지급 = 더 넣은 것으로 확정했고, 8개 값은 전 플랫폼에서 미지급 > 과지급 > 0 을 지킨다.

### 6-B. 값이 움직이는 것은 구성비 때문이다

```
Σ 비중 × (미지급률 − 과지급률)
 = 0.65×0.00015 + 0.20546559×0.00095 + 0.09862348×0.00155 + 0.04591093×0.00225
 = 0.00009750 + 0.00019519 + 0.00015287 + 0.00010330
 = 0.00054886
S = 0.00054886 / 0.9989 × 100 = 0.054946%  →  표기 0.05%
```

| | 현행 | 새 값 |
|---|---|---|
| 전체 S (raw) | 0.067942% | 0.054946% |
| 전체 S (표기) | 0.07% | 0.05% |
| 가맹점별 S 범위 | 0.04 ~ 0.17% | 0.03 ~ 0.10% |
| 할인율 0.11% 대비 | 여유 0.042%p · 가맹점 3곳이 할인율 초과 | 여유 0.055%p · **초과 0곳** |

카드 비중이 26.4%에서 65%로 오르면서 부족율이 낮은 플랫폼 쪽으로 무게가 옮겨 전체 부족율이 내려간다. `sRaw < rate` 불변식이 더 넓은 여유로 성립한다.

### 9-G. 딸린 조정 — 틸트 진폭

`daily_ledger.py:116-118` 의 `TILT` 진폭 합 0.35는 카드 비중 26.4% 시절에 잡은 값이다. 카드 65%에서는 같은 진폭이 하루치 만기를 더 크게 흔든다.

```
Δ만기 = 카드비중 × 틸트 × (배달 가중만기 − 카드 만기)
현행: 0.264 × 0.35 × 2.10 = 0.194
새 값: 0.650 × 0.35 × 2.097 = 0.477
```

`FLOOR` 2.0은 깨지지 않으므로 그대로 두어도 된다. 흔들림을 현행 수준으로 맞추려면 진폭 3개에 0.63을 곱해 `(0.120, 0.057, 0.044)` 로 둔다. 규모가중 평균 0 정규화를 거치므로 전체 W는 어느 쪽이든 2.75 그대로다.
