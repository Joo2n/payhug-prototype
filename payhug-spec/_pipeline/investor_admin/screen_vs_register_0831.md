| C4 예상 지급 차액 | 정의 미확정 | **화면 두 차액은 C4와 다른 것.** C4는 가맹점 화면 라벨로 추가 지급(+)과 과지급 회수(−)를 순액 합산한 것이고, 화면의 둘은 수수료 차액 축이다. `거래 수수료 차액` = 거래일 기준·실제−예상·대상액에 이미 반영(지급액 산식 항 아님), `정산 반영 수수료 차액` = 지급일 기준·지급액 산식 항 | **C4 미확정 유지 + 동형 사례 추가.** `정산 반영 수수료 차액`은 취소 환수(CANCEL_CLAWBACK)를 흡수해 순액 표기한다. 취소 환수는 과지급 성격이라 **C4가 지적한 순액 합산 위반이 어드민 축에도 있다.** 07 §7-1 직결 |

## 5. 코드 내부 불일치 1건

`payhug-admin-web/app/settlement/overview/PreSettlementTab.tsx:76-95`

```
const PAYOUT_FORMULA_TEXT =
  `${PAYOUT_TERMS.base} + ${PAYOUT_TERMS.feeDiff}(${PAYOUT_TERMS.feeDiffNote}) - ${PAYOUT_TERMS.offline} - ${PAYOUT_TERMS.adDeduction} + ${PAYOUT_TERMS.refund}`;
```

`PAYOUT_TERMS.carryForward`(미회수 이월)를 정의해 놓고 이 정적 문구에는 안 넣었다. 요약 카드의 동적 산식(462-470행)은 이월 항을 넣는다. 같은 파일 78행 주석이 「두 문구가 갈리지 않게 이름을 여기서 한 번만 정한다」고 적어 둔 그 갈림이 실제로 나 있다.

결과 — `검증 차이` 툴팁이 설명하는 산식에 이월 항이 빠져 있어, 이월 때문에 생긴 차이를 툴팁이 설명하지 못한다. 이 문구는 `types/settlement.ts:385` JSDoc과는 일치하고 같은 파일 `carryForwardTotal` JSDoc과는 어긋난다.

판정 `불일치`. 맞는 쪽은 `carryForwardTotal` JSDoc과 동적 산식(이월 포함). 근거는 이 기간 잔여항 순합 −2,457,392원이 이월 없이는 검산되지 않는 구조이고, 툴팁 자신이 「차감액이 지급액보다 커서 0원 처리된 뒤 이월된 경우」를 원인으로 들면서 정작 산식에서 그 항을 빼고 있기 때문이다.

## 6. 앵커 판정 충돌 — §0 역산과 코드 근거가 어긋난다

`frontend_settlement_cards.md` §3-4가 코드 직접 근거로 **앵커 = 선정산대상액**을 냈다. §0의 역산(순지급액 × 0.811%)과 결론이 다르다.

| | 근거 | 성격 |
|---|---|---|
| 앵커 = 순지급액 | 역산 0.811062%가 C1 후보 0.81%와 0.0011%p 차 | **수치 일치.** 간접 |
| 앵커 = 선정산대상액 | `TaxInvoiceTab.tsx:30-31` `pct = (row.supply / row.baseAmount) × 100`, 그 `baseAmount` 열 헤더가 문자 그대로 `선정산대상액`(`:238`), 타입 JSDoc `요율 산정 기준액` | **코드 직접.** 직접 |

코드 근거가 이긴다. §0의 0.811% 일치는 **우연일 소지가 크다.**

이유 — 역산의 분자 `marginFeeAmt`는 실제 차감액이고 분모는 면제 가맹점까지 포함한 전량이다. 면제분이 섞이면 블렌디드 요율이 실제 요율보다 낮게 나온다. 곧 실제 요율은 0.9096%보다 **높다.** 면제분이 대상액의 약 9%면 실제 요율은 1.0%가 되어 C1 후보 `스토리보드 표기 1.0%` 및 계약 서명 화면 placeholder `예: 1.0`과 붙는다.

따라서 §1 TP-68 행과 C1 행의 판정을 아래로 바꾼다.

| 항목 | 바뀐 판정 |
|---|---|
| TP-68 앵커 = 순지급액 | **`확정` 근거 흔들림.** 근거로 삼은 `merchants/[id]/page.tsx:674`의 `estimatedAmount`가 수수료인지 지급액인지 `frontend_settlement_cards.md` §4에서 **확인 불가**로 남았다. 코드가 요율을 실제로 계산하는 유일한 자리(TaxInvoiceTab)는 대상액을 기준액으로 쓴다 → **`확인필요`로 강등** |
| C1 수수료율 | **후보가 안 좁혀졌다.** 0.811% 일치를 근거로 쓸 수 없다. 면제 가맹점 비율을 모르는 한 실제 요율은 0.9096% 이상의 어떤 값이며 1.0%도 살아 있다 → 미확정 그대로, **좁혀졌다는 §1 서술을 철회** |

가르려면 **가맹점별 `선정산대상액`과 `marginFeeAmt` 쌍**이 필요하다. 면제 가맹점을 빼고 역산해야 단일 요율이 드러난다. 계산서 발행 탭이 행별 요율을 이미 계산해 보여주므로 그 화면 한 장이면 확정된다.
