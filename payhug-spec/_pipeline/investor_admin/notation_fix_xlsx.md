## 1. openpyxl 시험 — 셀 안 일부 글자만 아래첨자가 되는가

| 항목 | 결과 |
|---|---|
| openpyxl | 3.1.5 |
| `CellRichText` · `TextBlock` · `InlineFont(vertAlign='subscript')` 임포트 | 된다 |
| 셀 안 일부 글자만 아래첨자로 쓰기 | 된다 |
| 저장 후 다시 읽어 서식 잔존 (`load_workbook(rich_text=True)`) | 된다 |
| 굵게 + 흰색 + 아래첨자 혼합 런 | 된다 |
| 같은 셀에 셀 단위 폰트·채우기·테두리 병행 | 된다 |
| 같은 통합문서 안 수식 셀 영향 | 없다 |

생성 XML — 리치텍스트 셀은 `t="inlineStr"` 이 되고 런마다 `rPr` 이 붙는다.

```xml
<c r="C1" s="1" t="inlineStr"><is>
  <r><rPr><b val="1"/><color rgb="00FFFFFF"/><sz val="10"/></rPr><t>SB</t></r>
  <r><rPr><b val="1"/><color rgb="00FFFFFF"/><sz val="10"/><vertAlign val="subscript"/></rPr><t>D-1</t></r>
  <r><rPr><b val="1"/><color rgb="00FFFFFF"/><sz val="10"/></rPr><t> 상환액</t></r>
</is></c>
```

**채택 규약 — 아래첨자 서식.** 괄호 규약은 안 쓴다.

### 다만 글자열은 바꾸지 않았다

아래첨자 서식은 **런의 `vertAlign` 속성**만 더한다. 평문으로 읽으면 지금과 같은 글자다.
`−`(U+2212)로 바꾸거나 쉼표를 넣지 않은 이유는 둘이다.

| 근거 | 내용 |
|---|---|
| `symbol_glossary.json` 별칭 | 정본 기호 `A_i` · `B_{D-1,i}` · `SB_{D-1}` 의 별칭이 `Ai` · `BD-1i` · `SBD-1` 로 **ASCII 하이픈·쉼표 없음** 이다 |
| 리포지터리 문자열 대조 검증기 | `verify_batch_symbols.py` 가 일별 열머리를 `str(h).split(' ')[0]` 으로 잘라 `SBD-1`·`SAD-1`·`SMD-1`·`SMRD-1`·`SDD-1` 평문과 대조하고, 채권 열머리를 `'Ai'`·`'금융일수 Di'`·`'Ai x Di'` 평문 키로 찾는다 |

글자를 바꿨다면 그 검증기들이 대상을 못 찾아 무너졌다. 그래서 **글자는 그대로, 서식만 갈랐다.**
그 대신 평문으로는 이 고침이 안 보이므로, `audit_xlsx_check.py` 에 `rich_text=True` 로 다시 읽어
글자별 아래첨자 여부로 판정하는 검사를 새로 넣었다(§5).

### 아래첨자를 쓸 수 없는 자리

| 자리 | 왜 | 처리 |
|---|---|---|
| 수식 문자열 (`=` 로 시작) | 수식 안 글자에는 서식이 안 붙는다 | 평문 유지 |
| 시트 이름 | 서식 개념이 없다 | 평문 유지 (§6) |
| 이름정의 (`만기범위` 등) | 수식이 이름으로 참조한다 | 평문 유지 (§6) |
| 데이터 유효성 목록 문자열 | 수식(`formula1`) 자리다 | 평문 유지 |

## 2. 런 분해 규약

`(?<![A-Za-z0-9])기호(?![A-Za-z0-9])` 로 잡아 (본체, 아래첨자) 두 런으로 가른다.

| 평문 | 본체 | 아래첨자 | 화면 |
|---|---|---|---|
| `Ai` | `A` | `i` | A<sub>i</sub> |
| `Di` | `D` | `i` | D<sub>i</sub> |
| `SLi` | `SL` | `i` | SL<sub>i</sub> |
| `SAi` | `SA` | `i` | SA<sub>i</sub> |
| `Api` | `A` | `pi` | A<sub>pi</sub> |
| `Dpi` | `D` | `pi` | D<sub>pi</sub> |
| `BD-1i` | `B` | `D-1i` | B<sub>D-1i</sub> |
| `AD-1i` | `A` | `D-1i` | A<sub>D-1i</sub> |
| `MD-1i` | `M` | `D-1i` | M<sub>D-1i</sub> |
| `DD-1i` | `D` | `D-1i` | D<sub>D-1i</sub> |
| `SBD-1` | `SB` | `D-1` | SB<sub>D-1</sub> |
| `SAD-1` | `SA` | `D-1` | SA<sub>D-1</sub> |
| `SMD-1` | `SM` | `D-1` | SM<sub>D-1</sub> |
| `SMRD-1` | `SMR` | `D-1` | SMR<sub>D-1</sub> |
| `SDD-1` | `SD` | `D-1` | SD<sub>D-1</sub> |

손대지 않은 것 — `PSA` `PSM` `PSD` `PSMR` `PSC` `EC` `W` `S`, 그리고 원문의 `(D-1)` 한정어.

적용 통로는 `put()` · `head()` 한 곳이다. `rich()` 가 값이 문자열이 아니거나 `=` 로 시작하면 그대로 돌려준다.
파이썬 쪽 딕셔너리 키(`AGG` · `PER` · `MB` · `SVF` · `MARK`)는 변환 전 평문을 그대로 쓴다 — 조회가 안 깨진다.

### 「만기 도래분」 — 조어로 남긴다

원문에 대응 낱말이 **없다.** 원문은 `정산예정일이 전일자(D-1)인` 하루치 모집단만 정의하고
(`ceo_definitions.md` 32·34·36·38·41·42행), 기준일까지 **누적해 도래한** 모집단을 부르는 낱말이 없다.
`미회수 잔량만`은 원문 `회수되지 않은 순지급액`(10행)에 대응이 있고, `만기 도래분만`만 대응이 없다.

남긴 자리 6칸.

| 셀 | 값 |
|---|---|
| 입력 C18 | `대상정산금채권 전체 / 만기 도래분만 / 미회수 잔량만` (스위치 ① 선택지) |
| 채권 R1 | `만기 도래` |
| 기간집계 A26 | `만기 도래분 Σ Ai` |
| 기간집계 A27 | `만기 도래분 Σ(Ai x Di)` |
| 기간집계 A28 | `W금융일수 — 만기 도래분만` |
| 기간집계 A46 | `Ty — 만기 도래분만(%)` |

조어 표시는 **기간집계 출처 열(D)** 에 넣었다 — 새 문구 블록이 아니라 이미 있는 출처 칸을 채운 것이다.

| 셀 | 값 |
|---|---|
| 기간집계 D26 · D27 · D28 · D46 | `조어 — 원문 대응 낱말 없음` |

입력 C18 · 채권 R1 은 출처 열이 없어 남기지 않았다. 그 자리는 이 문서와 검증기 화이트리스트가 근거다.

**스위치 ① 선택지 문자열은 바꾸지 않았다.** `=IF(SW_모집단="만기 도래분만",…)` 수식과
데이터 유효성 목록이 그 글자로 짝지어져 있다 — 라벨만 바꾸면 스위치가 죽는다.

## 4. `Mi` · `Bi` — 우리가 지어낸 약칭

### 수정 금지 여부 판정 → **고칠 수 있다**

`verifiers.md:84` 을 직접 읽었다. 원문은 `verify_weighting.js` 행의 「판정하지 않는」 칸이다.

> `검산_투자자어드민_20260901.xlsx` 안의 **금지값** — 수정 금지 대상(지시)이라 판정해도 고칠 수 없다.
> 그 파일은 `audit_xlsx_check.py` 소관이라 곳수와 표식 유무만 찍는다.

| 확인 | 사실 |
|---|---|
| 무엇이 「금지값」인가 | `verify_weighting.js:216` 의 `BANX = 65% \| 2.7504 \| 14.60%` — 대표 엑셀 MAU 참고값이다 |
| 그 「수정 금지 지시」의 출처 | 프로젝트 상시 규칙 — MAU 비중은 시장 평균 참고값이라 **지우지도 계산에 쓰지도 않는다** |
| 대상 | 그 **값 셀들** 이지 통합문서 전체가 아니다 |
| 같은 행이 무엇이라 하는가 | 「그 파일은 `audit_xlsx_check.py` 소관」 — 문지기 검증기가 따로 있다는 뜻이고, 재생성 없이 문지기는 성립하지 않는다 |

판정 — **산출 `.xlsx` 를 손으로 여는 것이 금지**이고, 정본 생성기를 고쳐 재생성하는 것은 정상 경로다.
이번 변경은 MAU 참고값 셀을 지우지도 옮기지도 않았다(§7 에서 잔존 2건 확인).

### 열머리 참조 확인

`채권` O·P 열은 **셀 범위**로만 참조된다 — `RNG = {c: '채권!$%s$2:$%s$%d'}` 는 2행부터 시작하고,
구조적 표 참조도 `SUMIFS(범위, 열머리, …)` 도 없다. 열머리 문자열을 읽는 수식 **0건**.

### 교체

| 셀 | 지금까지 | 바꾼 것 | 평문화 |
|---|---|---|---|
| 채권 O1 | `투자수익 Mi` | `투자수익 M` + 아래첨자 `D-1i` | `투자수익 MD-1i` |
| 채권 P1 | `상환액 Bi` | `상환액 B` + 아래첨자 `D-1i` | `상환액 BD-1i` |

## 5. 검증기 갱신 — `audit_xlsx_check.py`

글자열을 안 바꿨으니 기존 문자열 검사로는 이 고침이 안 보인다. 못 찾아서 통과하는 구조를 두지 않으려고
`rich_text=True` 로 다시 읽어 **글자별 아래첨자 여부**로 판정하는 검사를 새로 넣었다.

실행 — `python3 audit_xlsx_check.py notation` (단독) · `python3 audit_xlsx_check.py all` (게이트에 포함)

| 판정 항목 | 기준 |
|---|---|
| 대상 0건 아님 | 기호를 담은 셀 > 0 |
| 아래첨자 글자 0건 아님 | 아래첨자 글자 수 > 0 |
| 규약 어긴 자리 0건 | 기호마다 머리 글자는 전건 평서 · 꼬리 글자는 전건 아래첨자 |
| 조어(만기 도래) 밖 「만기」 0건 | 화이트리스트 `만기 도래` 밖의 「만기」 셀 0건 |
| 채권 열머리에 `Mi`·`Bi` 0건 | 조어 약칭 잔존 |
| 자기시험 판별력 | 같은 글자열에서 아래첨자를 떼면 3자리를 잡고, 제대로 단 벌은 0자리 |

`all` 게이트의 `ok` 식에 `s4['통과']` 를 넣었다 — 이 검사가 깨지면 종료코드 1 이다.

## 6. 시트 이름·이름정의 때문에 못 고친 자리 — 보고만 한다

**시트 이름 — 바꿔야 할 자리 없음.** 시트 9장(`입력` `플랫폼` `가맹점` `채권` `일별` `기간집계`
`가중치 대조` `화면대조` `산식`) 에 `만기` 도 평문 기호도 없다.

**이름정의 `만기범위` — 바꾸지 않았다.**

| 항목 | 내용 |
|---|---|
| 정의 | `플랫폼!$D$9:$D$12` (플랫폼별 평균 금융일수 E[d]) |
| 참조 수식 | 5개 자리 — 플랫폼 B17, 가맹점 O열 8행, 가중치 대조 B열 4행 · W금융일수 3칸, 민감도 F열 5행 |
| 왜 | 수식이 **이름 문자열로** 참조한다. 이름을 바꾸면 그 수식 문자열을 전부 같이 고쳐야 한다 |
| 상태 | 열머리(D8)는 `평균 금융일수 E[d]` 로 고쳤고 이름정의만 옛 낱말로 남았다. 엑셀 이름 상자에는 `만기범위` 로 보인다 |

**스위치 ① 선택지 `만기 도래분만`** — §3 대로 수식·데이터 유효성과 짝이라 그대로 뒀다.
낱말 자체가 조어라 바꿀 대상도 아니다.
