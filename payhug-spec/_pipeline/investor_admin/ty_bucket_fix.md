# 버킷 Ty수익율 산식 정정 — 일자별 ty 가중평균 → `SMR × 365 / SD`

대상: 투자자 어드민 `투자 수익` 화면의 주별·월별 표, 표 합계 행, 현황 카드 ④, 엑셀 총계.
발견: 2026-08-28, 집계 단위에 주별을 넣으면서 드러났다.
개발 이관 대상 — 백엔드 집계 쿼리도 같은 실수를 하기 쉬운 자리다.

## 1. 무엇이 틀렸나

여러 날을 한 덩이로 묶은 행(주 버킷·달 버킷·합계 행·현황 카드)의 `Ty수익율` 을
**일자별 `ty` 의 투자실행금 가중평균**으로 냈다.

```
ty_버킷 = Σ(ty_i × exec_i) / Σexec_i          ← 틀림
```

대표 정의서(`ceo_definitions.md` [2번 이미지])의 산식은 다르다.

```
전일자(D-1) 대상정산금채권의 투자수익율(SMR)  = Σ M / Σ A
전일자(D-1) 대상정산금채권의 w금융일수(SD)    = Σ(A × D) / Σ A
전일자(D-1) 대상정산금채권의 ty수익율          = SMR × 365 / SD
```

기간 합계(④)도 같은 꼴이다.

```
투자실행금액 대비 ty수익율 = PSMR × 365 / PSD
  PSMR = PSM / PSA
  PSD  = Σ(Api × Dpi) / PSA
```

즉 **`SMR` 과 `SD` 를 각각 먼저 합산·가중평균한 다음, 그 둘로 `ty` 를 만든다.**
`ty` 를 먼저 만들어 놓고 다시 가중평균하는 것이 아니다.

```
ty_버킷 = (Σprofit / Σexec × 100) × 365 / (Σ(w_i × exec_i) / Σexec_i)     ← 맞음
```

## 2. 왜 값이 달라지나

`ty(w) = 0.11% × 365 / w` 는 `w` 에 대해 볼록(convex)하다.
볼록 함수의 가중평균은 가중평균의 함숫값보다 항상 크거나 같다(옌센 부등식).

```
Σ(ty(w_i) × a_i) / Σa_i  ≥  ty( Σ(w_i × a_i) / Σa_i )
```

그래서 종전 산식은 버킷 안 `w` 가 흩어질수록 `Ty수익율` 을 **위로 밀어 올린다.**
같은 행에 나란히 적힌 `W금융일수` 로 되짚으면 값이 맞지 않는다 —
표를 읽는 사람이 `0.11% × 365 ÷ W` 를 계산해 봐도 옆 칸 숫자가 나오지 않는다.

## 3. 왜 지금까지 안 보였나

원장 생성기 `daily_ledger.py` 의 `solve_w()` 가 **달 버킷에 한해** 두 값이 어긋나지 않는 해만
고르도록 짜여 있다.

```python
# 월 행은 집계 행이라 W·Ty가 그 달 일자들의 투자금액 가중평균이다.
# 두 가중평균이 표기 자리에서 서로 어긋나지 않는 해만 고른다.
raw_ty = (fx_ty + sum(ty_of(w) * D(e) for w, e in zip(ws, execs))) / den
rank = (0 if r2(raw_ty) == tgt_ty else 1, amp, abs(raw - tgt))
```

일자별 `W금융일수` 를 그렇게 골라 놓았으므로 **달 단위에서는 두 산식의 결과가 소수 2자리에서
우연히 같았다.** 일별 표는 행 하나가 하루라 애초에 차이가 날 수 없었다.
화면에 달·일 두 단위만 있던 동안에는 결함이 값으로 드러날 자리가 없었다.

주별을 넣자 곧바로 드러났다. 주 경계는 `solve_w` 가 맞춰 둔 달 경계와 다르다.

```
FAIL 투자수익 항등식 · week/weekly   bad: ["2026-08-17 ~ 08-23 Ty"]
FAIL 투자수익 항등식 · month/weekly  bad: ["2026-08-03 ~ 08-09 Ty",
                                          "2026-08-10 ~ 08-16 Ty",
                                          "2026-08-17 ~ 08-23 Ty"]
```

데이터가 우연히 가려 준 결함이지 데이터가 만든 결함이 아니다.
실데이터에서는 달 버킷에서도 어긋난다.

신설 헬퍼:

```js
function tyOfRows(rs){
  var ex = sum(rs, 'exec'), pf = sum(rs, 'profit'), w = rs.length ? wavg(rs, 'w', 'exec') : 0;
  return (ex && w) ? (pf / ex * 100) * 365 / w : 0;
}
```

엑셀 실물 생성기 `build_xlsx.py` 의 `bucket()` 도 같은 산식을 쓴다.
`W금융일수` 는 그대로 투자실행금 가중평균이다 — 그쪽은 정의서와 일치하고 있었다.

## 6. 회귀 방지

`verify_identity.js` 가 표에 찍힌 값만 보고 되짚는다.

- 일자 행: `ty === tyOf(w)` 를 정확히 요구
- 버킷 행(주·달): `|ty − (profit/exec×100)×365/w| ≤ 0.03` — 화면의 `W` 가 소수 1자리로 잘려
  있어 되짚은 값에 남는 잔차만큼만 허용
- 합계 행·카드 ④: 같은 산식으로 대조
- 검사 조합에 `week/weekly`·`month/weekly` 를 넣어, 주 경계에서 다시 어긋나면 즉시 FAIL

## 7. 개발 이관 시 유의

1. 백엔드가 D-1 배치로 `SMRD-1`·`SDD-1` 을 저장하고, 화면이 기간 합계 `PSMR`·`PSD` 를 만드는
   구조다. **저장된 `ty` 를 평균 내지 말고 `SMR`·`SD` 를 합산해 다시 나눠야 한다.**
2. 같은 이유로 `Ty수익율` 은 DB에 집계 컬럼으로 두더라도 상위 집계에서 재사용하면 안 된다.
   상위 집계는 `ΣM`·`ΣA`·`Σ(A×D)` 세 값에서만 파생시킨다.
3. `W금융일수` 는 반대로 가중평균이 맞다(`SD = Σ(A×D) / ΣA`). 두 값의 성질이 다르다는 점이
   이 결함의 뿌리다.
4. 표기 반올림은 마지막에 한 번만 한다. 중간값을 잘라 다음 계산에 넣으면 ⑤ 가 흔들린다.
