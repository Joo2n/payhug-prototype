## 1. 결론 — 어디까지 되는가

**둘 다 된다. 투자 자산은 표 전체가 닫히고, 투자 수익은 일별 표까지 닫힌다.**

| 화면 | 판정 | 닫히는 범위 | 닫히지 않는 것 |
|---|---|---|---|
| 투자 자산 | **전량** | 요약 카드 4개 · `현황` 표 2행 + 합계행(자산 구분·금액·W금융일수·S입금부족율·Ty수익율·비중·보관) | `가맹점별 투자자산` 표 — 산식은 닫히나 행마다 가맹점 배정 입력이 필요해 이번 폼에서 제외 |
| 투자 수익 | **전량** | `수익 현황` 지표 4블록(검색대상기간·투자실행금·투자수익·Ty수익율 2분할) · `일별 투자수익` 표 + 합계행 | 없음. 단 일별 행은 입력한 채권의 정산예정일에만 생긴다 |

닫히는 이유는 하나다. **대표 정의서의 원자 단위가 채권 1건이고, 채권 1건은 `순지급액 · 선정산일 · 정산예정일` 세 값으로 끝난다.** 이 셋을 행 단위로 입력받으면 Ai · Di · W · 상환액 · 투자수익 · PSA · PSM · PSD · PSMR · ④ · ⑤ 가 전부 그 위에서 나온다. 원장 전체를 요구하는 항목은 두 개뿐이고 둘 다 소수 입력으로 대체된다.

| 원장이 필요해 보이는 것 | 대체 입력 | 왜 결과가 같은가 |
|---|---|---|
| S입금부족율 — 표본집합(선정산일 D-20~D-11) 채권 전량 | 미지급률 `u`(%) · 과지급률 `o`(%) 두 값 | `S = Σ(미지급−과지급) ÷ Σ(순지급액×(1−r)) = (u−o)×Σ순지급액 ÷ (1−r)×Σ순지급액 = (u−o)/(1−r)`. 금액이 약분돼 표본 건수·금액과 무관하게 같은 값 |
| PSC — 기간 EC(전일자 자정 순현금) 일별 원장 | 순현금 1개 값 | `PSC = 순현금 × 기간 일수`. 현행 통합본의 `tyAssetOf`·`ecDays`(build_app.py:1729-1733)가 이미 같은 취급 |

**투자 자산과 투자 수익은 입력 한 벌을 공유한다.** 종료일을 기준으로 갈린다.

```
정산예정일 >  종료일           → 회수되지 않은 순지급액  → 투자 자산
시작일 ≤ 정산예정일 ≤ 종료일   → 만기 도래                → 투자 수익
```

대표 정의서에서 투자 실행액은 "회수되지 않은 순지급액"의 함수이고, 투자 수익은 "정산예정일이 전일자(D-1)인" 채권의 함수다. 두 집합은 서로 겹치지 않으므로 한 벌의 채권 입력이 두 화면을 동시에 먹인다. 기준일 입력을 따로 두지 않고 종료일이 그 자리를 맡는다.

## 3. 도출 과정

### 3-1. 산식 의존 그래프

대표 정의서 [1번 이미지]·[2번 이미지] 전문에서 입력(◇)과 계산 결과(●)를 갈랐다.

```
◇ 순지급액        ─┬─→ ● Ai = 순지급액 × (1 − r)          ─┬─→ ● 투자실행액 = Σ Ai
◇ 할인율 r        ─┘                                        │
                   └─→ ● 채권매입수수료 = 순지급액 × r       │
◇ 선정산일  ─┐                                              │
◇ 정산예정일 ─┴─→ ● Di = 정산예정일 − 선정산일             ─┴─→ ● W = Σ(Ai×Di) ÷ Σ Ai
                                                                    │
◇ 미지급률 u ─┬─→ ● SLi = (u−o) × 순지급액 ──→ ● S = ΣSLi ÷ ΣSAi   ├─→ ● Ty = r × 365 ÷ W
◇ 과지급률 o ─┘   ● 차감 = max(0, (u−o) × 순지급액)                 │
                                                                    │
              ● Mi = 채권매입수수료 − 차감  ──→ ● PSM = Σ Mi        │
              ● Bi = 순지급액 − 차감        ──→ ● 상환액 = Σ Bi     │
                                                 ● PSA = Σ Ai (만기)│
                                                 ● PSMR = PSM ÷ PSA │
                                                 ● PSD  = Σ(Api×Dpi) ÷ PSA
                                                 ● ④ = PSMR × 365 ÷ PSD
◇ 순현금 ─┬─→ ● PSC = 순현금 × 기간 일수 ──→ ● ⑤ = ④ × PSA ÷ (PSA + PSC)
          └─→ ● 투자자산 = 투자실행액 + 순현금 ──→ ● 비중
◇ 시작일 ─┬─→ ● 기간 일수 · 만기/미회수 분류
◇ 종료일 ─┘
```

입력 ◇ 은 **8종**이고 그중 3종이 채권 행 단위, 5종이 전역이다. 나머지는 전부 ● 이다.

### 3-2. 금융일수 규칙 확정

대표 정의서 [1번 이미지] 예시는 `선정산일 260827, 정산예정일 260808 → 1`로 적혀 있어 날짜가 거꾸로다. [2번 이미지] 예시 `선정산일 20260824, 정산예정일 20260826 → 2`가 규칙을 확정한다.

```
Di = 정산예정일 − 선정산일   (일 단위 차, +1 하지 않는다)
```

[1번 이미지]의 `260808`은 `260828`의 오기로 읽어야 두 예시가 같은 규칙이 된다(08-27 → 08-28 = 1).

### 3-3. 채권 행 기본값 도출

행 기본값은 두 제약을 동시에 만족시켜 뽑았다.

제약 1 — 금융일수는 플랫폼 실측 만기 범위 안. `platform_duration.py` DURATION(조현준 슬랙 2026-08-28 실측): 카드사 2.0 · 배달의민족 3.4 · 쿠팡이츠 4.7 · 요기요 6.2. 채권 1건의 금융일수는 정수이므로 반올림해 **2 · 3 · 5 · 6**.

제약 2 — 금액가중 W가 로스터 16건 전체 채권의 금액가중 W와 같은 자리(3.1일)에 떨어질 것. 구성비 `x`를 풀면

```
2x₁ + 3x₂ + 5x₃ + 6x₄ = 3.1,  Σx = 1
x = (0.40, 0.40, 0.10, 0.10)  →  0.8 + 1.2 + 0.5 + 0.6 = 3.1
```

40 : 40 : 10 : 10 을 미회수 10억, 만기 5억에 각각 적용해 8행을 만들었다. 두 묶음 모두 W = 3.1이고 Ty = 0.11 × 365 ÷ 3.1 = **12.95%**.

`투자 자산` 화면의 3.7일 · 10.85%와는 다른 값이다. 그쪽은 로스터 16건 중 **미회수분만** 센 W이고, 여기 8행은 미회수 4행 · 만기 4행을 같은 구성비로 깔아 두어 두 묶음이 같은 W를 낸다. 시뮬레이션은 사용자가 넣은 행에서만 W를 내므로 두 화면이 같은 자리를 말할 이유가 없다 — `simRun` 의 W도 미회수 묶음(`out`)만 센다.

### 3-4. 미지급률·과지급률 기본값 도출

세 조건으로 좁혔다.

| 조건 | 식 | 결과 |
|---|---|---|
| 투자수익이 양수 | `u − o < r = 0.11%` | 상한 0.11%p |
| S입금부족율 열이 0.00%로 굳지 않을 것 | `u ≠ o` | 하한 0.01%p |
| 과지급이 미지급보다 작을 것 | `o < u` | 부호 고정 |
| S가 투자 자산 화면과 같은 값일 것 | `(u − o) ÷ (1 − r) = 0.07%` | `u − o = 0.07%p` |

마지막 조건이 값을 하나로 묶는다. 투자 자산 화면의 투자실행액 행 S가 0.07%이므로 시뮬레이션도 같은 자리에 서게 `u − o = 0.07%p`로 두고, 과지급을 미지급의 8분의 1로 잡아 **u = 0.08% · o = 0.01%**.

```
S = (0.08 − 0.01) ÷ (1 − 0.0011) = 0.0700771%  →  0.07%
채권당 수익률(순지급액 대비) = 0.11% − 0.07% = 0.04%
```

`S 0.07% < 할인율 0.11%`이라 투자수익은 양수를 유지한다.

|---|---|---|
| L-1 | 앵커는 **순지급액** 하나다 — `채권매입수수료 = 순지급액 × 할인율`(D-31). 시뮬레이션 `simBond` 와 일별 원장 `daily_ledger.py` `_daily` 가 같은 앵커를 쓴다 | 두 화면의 같은 열이 한 산식에서 나온다. 투자실행금을 앵커로 두면 `(1 − 할인율)`배만큼 작아져 2026-08-21행에서 552,400원 대 551,793원(592원), 기본 조회 기간 합계에서 3,866,428원 대 3,862,175원(4,253원)으로 갈렸다 |
| L-2 | `상환액 = 순지급액 − max(0,미지급−과지급)`, `투자수익 = 순지급액×r − max(0,미지급−과지급)`. 차감이 같은 크기로 두 곳에 들어가므로 **`상환액 = 투자실행금 + 투자수익`이 미지급 유무와 무관하게 항등**이다 | 계산 끝에 assert로만 둔다. 화면에는 쓰지 않는다 |
| L-3 | `S입금부족율 > 할인율`이면 정의서 산식상 **투자수익이 음수**가 된다. 투자 자산 화면의 투자실행액 행은 S = 0.07% · 할인율 0.11%이고, 투자 수익 표는 차감 항 없이 채권매입수수료만 싣는다 | 시뮬레이션 기본값을 `u−o = 0.07%p`로 잡아 화면 S와 같은 자리에 두면서 양수를 보장한다. 사용자가 0.11%p를 넘기면 음수가 그대로 나온다 — 산식을 고치지 않는다 |
| L-4 | 자산 쪽 `Ty = 할인율 × 365 ÷ W`는 **순지급액 대비**, 수익 쪽 `④ = PSMR × 365 ÷ PSD`는 **투자실행금 대비**다. 미지급이 0이어도 `1/(1−r) = 1.0011`배 어긋난다(같은 W를 걸었을 때 12.95% 대 12.97%). `투자 자산` 화면에서는 여기에 모집단 차이(미회수 W 3.7일 대 기간 만기분 PSD 3.1001일)가 더해져 10.85% 대 12.97%가 된다 | 정의서 그대로의 결과. 두 값을 맞추려 들지 않는다. 앵커(L-1)와는 다른 자리다 — 앵커는 하나이고 여기서 갈리는 것은 분모다 |
| L-5 | 금융일수 예시가 [1번 이미지]와 [2번 이미지]에서 서로 어긋난다 | §3-2 확정. `Di = 정산예정일 − 선정산일` |

### 4-4. 계산 로직

`build_app.py` JS 규약(`var` · 함수 선언 · ES5)으로 옮긴다. 상수·유틸은 기존 것을 그대로 쓴다(`fmt` `fx` `pct` `sum` `ratios` `wavg` `dt` `addDays`).

```js
var SIM = {
  r: 0.11, cash: 105300000, unpaid: 0.08, over: 0.01,
  from: '2026-08-21', to: '2026-08-27',
  rows: [ /* {plat, amt, sd, dd} 8건 */ ],
  result: null, running: false
};
var SIM_DUR = {card: 2, bm: 3, cpe: 5, yo: 6};   /* round(DURATION) */

function simDays(a, b){ return Math.round((dt(b) - dt(a)) / 86400000); }

/* 채권 1건 — 대표 정의서 [1번 이미지] Ai · Di, [2번 이미지] Mi · Bi */
function simBond(row, r, dedRate){
  var A   = Math.floor(row.amt * (1 - r));
  var D   = simDays(row.sd, row.dd);
  var fee = Math.floor(row.amt * r);
  var ded = Math.floor(Math.max(0, dedRate) * row.amt);
  return {plat: row.plat, amt: row.amt, sd: row.sd, dd: row.dd,
          D: D, A: A, fee: fee, ded: ded, M: fee - ded, B: row.amt - ded};
}

function simRun(){
  var r = SIM.r / 100, ded = (SIM.unpaid - SIM.over) / 100;
  var bonds = SIM.rows.map(function(x){ return simBond(x, r, ded); });
  var out = bonds.filter(function(b){ return b.dd > SIM.to; });                       /* 미회수 */
  var mat = bonds.filter(function(b){ return b.dd >= SIM.from && b.dd <= SIM.to; });  /* 만기 */

  /* ── 투자 자산 ── */
  var EXEC = sum(out, 'A');
  var W    = EXEC ? out.reduce(function(t,b){ return t + b.A * b.D; }, 0) / EXEC : 0;  /* Σ Ai×Di ÷ Σ Ai */
  var TY   = W ? SIM.r * 365 / W : 0;                                                  /* 할인율 × 365 ÷ W */
  var S    = (SIM.unpaid - SIM.over) / (1 - r);                                        /* Σ SLi ÷ Σ SAi */
  var TOT  = EXEC + SIM.cash;
  var SH   = ratios([{amount: EXEC}, {amount: SIM.cash}], TOT);                        /* 잔차 흡수 → 합 100.0 */

  /* ── 투자 수익 ── */
  var PSA  = sum(mat, 'A'), PSM = sum(mat, 'M'), PSB = sum(mat, 'B');
  var PSD  = PSA ? mat.reduce(function(t,b){ return t + b.A * b.D; }, 0) / PSA : 0;
  var PSMR = PSA ? PSM / PSA * 100 : 0;
  var TY4  = PSD ? PSMR * 365 / PSD : 0;                                               /* ④ */
  var ECD  = simDays(SIM.from, SIM.to) + 1;
  var PSC  = SIM.cash * ECD;
  var TY5  = (PSA + PSC) ? TY4 * PSA / (PSA + PSC) : 0;                                /* ⑤ */

  /* ── 일별 ── */
  var day = {}, keys = [];
  mat.forEach(function(b){
    var g = day[b.dd];
    if(!g){ g = day[b.dd] = {d: b.dd, A: 0, M: 0, B: 0, wx: 0}; keys.push(b.dd); }
    g.A += b.A; g.M += b.M; g.B += b.B; g.wx += b.A * b.D;
  });
  keys.sort();
  var rows = keys.map(function(k){
    var g = day[k];
    g.W  = g.A ? g.wx / g.A : 0;
    g.TY = (g.A && g.W) ? (g.M / g.A * 100) * 365 / g.W : 0;
    return g;
  });

  SIM.result = {bonds: bonds, out: out, mat: mat,
                EXEC: EXEC, W: W, TY: TY, S: S, TOT: TOT, SH: SH,
                PSA: PSA, PSM: PSM, PSB: PSB, PSD: PSD, PSMR: PSMR,
                TY4: TY4, TY5: TY5, ECD: ECD, PSC: PSC, rows: rows};
}
```

표기 규칙은 현행 화면과 동일 — 금액 `fmt` · 금융일수 `fx(v,1) + '일'` · 비율 `pct(v,2)` · 비중 `fx(v,1) + '%'`. 반올림하지 않은 값을 담아 두고 표기할 때만 자른다(`rollupBy` 주석과 같은 규칙).

## 6. 못 하는 것

| 항목 | 사유 | 어디까지 되는가 |
|---|---|---|
| 가맹점별 투자자산 표 | 채권을 가맹점에 배정하는 입력이 행마다 더 필요하다. 8행 × 5칸이 8행 × 6칸이 되고, 로스터 16건을 폼에서 재구성하는 것은 산식 확인이라는 목적을 넘는다 | 산식은 닫혀 있다. 행에 가맹점 select 1칸을 더하면 그대로 나온다. 이번 폼에서만 뺀다 |
| 투자자산 증명서 | 발급 대상이 가맹점별 표다. 위 항목에 종속 | 동상 |
| EC 일별 변동 | 일별 순현금 잔액 원장이 없다. 하루씩 다른 잔액을 입력받으려면 기간 일수만큼 칸이 필요하다 | `PSC = 순현금 × 기간 일수`로 닫힌다. 현행 화면의 `tyAssetOf`와 같은 취급이라 두 화면이 갈리지 않는다 |
| 표본집합(D-20~D-11) 실물 | 표본집합은 잔액 채권 집합과 다른 집합이라 입력 행으로 덮을 수 없다 | `S = (u−o)/(1−r)`로 금액과 무관하게 닫힌다. 표본 건수·금액을 알아도 결과가 같다 |
| 주별·월별 집계 | 어드민 시뮬레이션에 집계 단위 토글이 없다. 버킷 산식은 현행 `rollupBy`와 동일해 새로 확인할 것이 없다 | 일별 고정. 기간을 넓히면 일별 행이 늘어난다 |
| 시스템 이용료 · 이체 수수료 | 대표 정의서 산식에 없다. 투자자 몫은 채권매입수수료 하나뿐(D-31) | 어드민 시뮬레이션의 `SYSTEM_FEE` · `TRANSFER_FEE` 블록에 대응하는 것을 만들지 않는다 |
| 실패 경로 | D-2 — 성공 경로만 | 입력 검증은 버튼 비활성과 안내 한 줄까지 |
| 서버 계산 | 어드민은 `POST /admin/settlement/simulate`로 서버가 계산한다. 투자자 어드민은 프론트 단독 | 산식이 전부 클라이언트에 있으므로 결과는 동일하게 나온다. 300ms 지연으로 진행 상태만 흉내낸다 |
