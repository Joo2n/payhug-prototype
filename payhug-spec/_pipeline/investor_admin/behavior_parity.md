정적 화면 3종은 이미 네이티브로 전환됐고 `app.html`과 `merchants--filter-open.html`만 커스텀이 남았다. 같은 화면을 두 산출물에서 보면 컨트롤이 달라 보인다.

### 근거 3. 커스텀 쪽의 품질은 문제가 아니다

18:15:02판 커스텀 드롭다운은 죽어 있지 않다. 실측 — 옵션 렌더, 선택 반영, 칩 생성, 바깥 클릭·Esc 닫힘, `role=combobox/listbox/option`, `aria-expanded`, roving tabindex, Enter/Space/↑↓ 키 조작이 모두 동작한다. **품질 미달이 아니라 방식 불일치가 문제**다. 잘 만든 커스텀 컨트롤이라도 원본이 쓰지 않는 방식이면 "다르다"에 해당하고, 유지보수 대상도 하나 늘어난다.

### 결론

1. `app.html`의 업종 필터를 **네이티브 `<select class="input">`**로 바꾸고, `채권매입업체`와 동일한 마크업·클래스를 쓴다.
2. `merchants--filter-open.html`은 **커스텀 드롭다운 열림 상태를 그리기 위해서만 존재하는 화면**이므로, 전환과 함께 폐기하거나 네이티브 select의 열림 상태를 다루지 않는 다른 상태로 대체한다(브라우저 기본 팝업은 화면설계 대상이 아니다).
3. 커스텀 드롭다운에만 있던 **적용 조건 칩**(§1-5-11)은 select와 무관하므로 그대로 남긴다.
4. 날짜 필터의 커스텀 달력(D-5)도 같은 원칙으로 정리 대상 — 원본은 `input[type=date]` 단독이다.
