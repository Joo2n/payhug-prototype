## 3. ⑤ 산식 — 고칠 자리 **1곳**

`termsdoc_seed.json` 최상위 `pending_formula` 한 블록.

```
pending_formula
  ├ basis_formula  ⑤ = (④ × PSA) / (PSA + PSC)      8/27 원문 산식 기록
  ├ formula        ⑤ = (④ × PSA) / (PSA + PSC)      ← 대표 산식이 오면 여기만 고친다
  ├ our_value      2.24%
  ├ status         미확정
  └ depends[0]     no 45 · ⑥ = (④ ÷ ③) × 365 ÷ ⑤ · uses ⑤
```

42항·45항은 `formula` 를 들고 있지 않다. `formula_ref: "pending_formula"` 로 이 블록을 가리킨다.

**대체 여부는 따로 적어 두지 않고 `formula` 와 `basis_formula` 를 견줘 낸다.**
`replaced` 같은 깃발을 두면 산식을 갈 때 깃발도 함께 갈아야 해서 고칠 자리가 둘이 된다.
두 문자열이 같은 동안만 `미확정` 이 붙고, 다르면 저절로 사라진다.

시험 — `formula` 한 줄만 갈고 두 생성기를 돌렸다.

| 확인 | 결과 |
|---|---|
| 워드 42항 산식 | 새 산식으로 바뀜 |
| 워드 45항 산식 | 새 산식으로 바뀜 |
| 워드 `미확정` 표시 | 저절로 사라짐 |
| 편집판 원고 | 새 산식으로 바뀜 |
| 되돌린 뒤 md5 | 그대로 |

`pending` 에 ⑤ → ⑥ 의존을 명시했다 (`no: [42, 45]`).
42항·45항 `note` 에도 「⑤ 가 바뀌면 ⑥ 이 함께 바뀐다」를 적었다.

편집판에는 미결 상자 안에 ⑤ 한 칸을 뒀다. 그 칸만 고칠 수 있고 42·45항 산식 줄은 고칠 수 없다.
두 곳에서 따로 고쳐 어긋나는 길을 막았다.
