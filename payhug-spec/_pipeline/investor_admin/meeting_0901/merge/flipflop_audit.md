# 판단 뒤집힘 전수 감사 — 용어·기호

읽기 전용. 이 파일 하나만 썼고 다른 파일은 열어 보기만 했다. 값을 다시 계산하지 않았고 미확정을 확정으로 올린 자리는 없다. 기호표를 바꾸자는 제안도 없다.

곳수는 전부 이 감사가 다시 센 것이다. 다른 조 보고서의 숫자를 옮기지 않았다.

## 0. 감사 도중에 정본이 또 한 번 바뀌었다

이 감사를 시작할 때 받은 정본표는 가중평균 금융일수를 `D` · `PD` 로 못 박고 있었다. 세는 도중에 `wD` · `wD(d-1)` · `PwD` 로 갈렸다. 까닭은 `w` 를 `wPYMR` 에 쓰기로 했으니 같은 성질의 자리에 전부 쓴다는 것이다.

곧 4번 자리의 이력은 이렇게 된다.

```
SD·PSD → WAD·PWAD → wD·PwD → D·PD → wD·PwD
```

**다섯 단계에 네 번 뒤집혔고 되돌아온 자리가 하나다.** 3단계(`wD·PwD`)와 5단계(`wD·PwD`)가 같은 값이다.

같은 회차에 투자실행액 합 표기도 한 번 더 움직였다 — `EX` → 이름 없음 → `Σ Ai`. 감사 시작 시점 정본표는 「이름 없음」이었다.

이 사실 자체가 이 감사의 첫 발견이다. 산출물을 고치는 조가 어느 시점 판단으로 작업했는지에 따라 결과가 갈리고, 지금 산출물이 낡은 까닭도 대부분 여기 있다.

### 11번 근거

`symbol_glossary.json` `notation_canon` 「아래첨자 표기」 항이 아직 이렇게 적고 있다.

> canonical: 원문은 `SAD-1` · `AD-1i` 처럼 평문으로 붙여 쓴다
> drift: … 서술 자리는 괄호형으로 통일한다 … 이 사전의 symbol 값도 마크다운 표기를 정본으로 삼고, 이전 평문·괄호 표기는 aliases 에 남긴다

같은 항 안에서 「괄호형으로 통일」과 「마크다운(`_{ }`) 표기를 정본으로」가 함께 서 있다. `symbol_notation_audit.md` §2-5 는 이 겹침을 이미 잡아 「괄호형 701건이 아직 남아 있다 … 안 되면 문서 세 벌(평문·괄호형·아래첨자)이 공존한다」고 적었다. 지금 정본이 다시 괄호형으로 돌아왔으므로, 아래첨자로 바꾸느라 든 작업이 되돌려져야 하는 자리다.
