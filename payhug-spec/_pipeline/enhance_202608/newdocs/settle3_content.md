## 화면 1. 선정산 결과 (AD_SETTLE)

### ① 메뉴 위치·진입 경로

- **경로** | 어드민 사이드바 [정산] 그룹 > 정산 현황(`/settlement/overview`)의 **6탭 중 1번째·기본 탭**. 페이지 진입 시 자동으로 이번 달 1일~오늘 범위로 요약이 조회된다 (page.tsx:106-112, hook:413-422).
- **탭 구성** | 선정산 결과 · 정산 상세 · 차액 정산 · 이체 내역 · 계산서 발행 · VOC 대응. 이 중 정산 상세·계산서 발행·VOC는 내부(ADMIN/PAYHUG)만 노출 (page.tsx:270-325).
- **총판 노출** | 총판/참여자(PARTNER·SALES_ORG 등) 로그인 시에도 이 탭은 **노출**된다. 단 화면 안의 '미정산 누락 추적' 배너와 바로이체/이미지급 처리는 내부 어드민만 (`enableMissedSettlements: isAdmin`, `showMissedSettlements`) (page.tsx:127-133, 474).
- **리다이렉트** | `/settlement`·`/settlements` 접근 시 `/settlement/overview`로 자동 이동 (discovery/code_inventory.md ②).

### ② 화면 내용·구성

- **공통 필터 바** | 기간 프리셋 7종(오늘~최근 3개월, 기본=이번 달) + 시작/종료일 + 가맹점명·사업자번호 부분일치 검색 + 에이전시 셀렉트(옵션은 조회 결과에서 동적 추출, '미지정' 포함) (page.tsx:328-364). 가맹점/에이전시 필터는 클라이언트 필터이며, 행만 거르지 않고 **일별·전체 합계를 화면에서 재집계**한다 (page.tsx:223-238).
- **정렬·엑셀** | 콘텐츠 우측 상단에 매출일 정렬 토글(기본 최신순)과 엑셀 다운로드(5시트) (PreSettlementTab:430-438).
- **요약 카드 8장** | 총 매출액 → 총 수수료(카드+배달 분해) → 순 지급액 → 선정산 제외액 → 선정산 대상액 → 선정산 수수료(4종 분해) → 정산 반영 수수료 차액(± 부호색) → **선정산 지급액(강조, 산식 sub)** (PreSettlementTab:442-481).
- **수수료 차액 정산 배너** | "오늘 반영 N건(±금액) / 대기 중(다음 반영 예정) M건(±금액)". 반영·대기 건이 있을 때만 노출, 가맹점 필터 시엔 건수가 기간 전역 집계라 배너를 숨긴다 (PreSettlementTab:484-517, page.tsx:82-87).
- **미정산 누락 추적 배너(내부 전용)** | 빨간 배너에 가맹점 수·건수·금액 요약. 펼치면 가맹점>날짜>거래 3단 목록 + 체크 선택 → [미리보기] [바로이체] [이미지급(기록만)] (PreSettlementTab:1008-1160).
- **날짜별 아코디언** | 헤더 "`{정산일}` 정산 (`{매출일}` 매출 기준)" + '예상매출 N건 포함' 배지 + 우측 분해(매출→수수료→선정산제외→선정산대상→선정산수수료→오프라인차감→플랫폼차감→플랫폼환급→선정산) (PreSettlementTab:525-583).
- **가맹점 행 10컬럼** | 가맹점 / 카드 매출 / 배달 매출 / 수수료 / 순지급액 / 선정산 제외액(잔차 시 점선 툴팁) / 선정산 대상액 / 선정산 수수료(hover 분해+면제 배지) / 선정산 지급액(하단 서브라인: 이미지급·오프라인 차감·정산 반영 수수료 차액·플랫폼 차감(구성 툴팁)·플랫폼 환급·검증 차이) / 상태(이체완료·이체대기·정산전) (PreSettlementTab:588-728).
- **건별 상세 펼침 패널** | 행 클릭 시 12컬럼 거래 목록(매출원/승인·주문번호/카드사·앱/매출액/수수료/수수료유형/순지급액/거래 수수료 차액/선정산 제외액/선정산 대상액/매입상태/정산 상태) + 플랫폼 차감 섹션 + 플랫폼 환급 섹션 + 대기 중 차액 정산 목록 (PreSettlementTab:1251-1402).

### ③ 로직

- **조회 흐름** | 조회 버튼 → `GET /admin/settlement/pre-settlement-summary?dateFrom&dateTo` 1회로 전체 요약(totalOverview)+일별 데이터(dailyData)를 받는다 (hook:155-174). 내부 어드민은 `GET /admin/settlement/missed-settlements`를 병행 조회 (hook:346-358).
- **펼침 조회** | 가맹점 행 클릭 시 해당 매출일 하루 범위로 `GET pre-settlement-detail/{bizNo}` 재조회. 한 번에 1개 행만 펼침, 같은 행 재클릭 시 접힘 (page.tsx:135-144, hook:176-205). 응답은 통째로 담고 기본값만 채운다 — 필드를 골라 담으면 서버 신규 필드(adRefunds)가 조용히 사라진 전력 (hook:190-199).
- **미정산 누락 처리** | 체크 선택 → `POST missed-settlements/resolve` (action: TRANSFER=실제 이체 / RECORD_ONLY=원장 기록만). 미리보기는 `POST resolve/preview`(이체·기록 부작용 없음). 처리 후 누락 목록+요약 자동 재조회 (hook:360-410). 미리보기 규칙: 가맹점별 여러 거래일을 **합산해 1회 이체**하되 원장은 거래일별로 기록 (PreSettlementTab:1211-1232).
- **필터 재집계** | 가맹점·에이전시 필터 시 일별 overview를 필터된 행으로 다시 합산하고(aggregateDayOverview), 전체 합계도 재집계. 단 차액 반영/대기 건수는 기간 전역 집계라 분해 불가 → 건수 0으로 두고 배너 숨김, 금액만 Σ adjustmentAmt로 복원 (page.tsx:33-89).
- **엑셀 5시트** | 선정산요약(22컬럼, 화면 필터 반영) / 건별상세(기간 전체 재조회 — 요약 시트와 모집단 다름 주석 명시) / 플랫폼차감 / 플랫폼환급 / 미정산누락 (PreSettlementTab:152-363).
- **상태 배지 판정** | 행 상태 3종(이체완료/이체대기/정산전), 건별 정산 상태 6종(선정산/대기/바로이체/이미지급/선정산차감/미대상) (PreSettlementTab:36-50). 플랫폼 조정의 '정산 미반영' 원문 뱃지는 `eligible === false`일 때만 노출 — 한글 리터럴 비교는 폐기 (PreSettlementTab:868-875).

### ④ 기획자가 파악해야 하는 계산식

**(1) 선정산 지급액 산식 [확정]** — 카드 sub와 검증 차이 툴팁이 같은 상수(PAYOUT_TERMS)를 공유하고, 0인 가감 항목은 표기에서 생략된다 (PreSettlementTab:63-71, 413-420).

> **선정산 지급액 = 선정산 대상액 − 선정산 수수료 + 정산 반영 수수료 차액 − 오프라인 차감 − 플랫폼 차감 + 플랫폼 환급**

| 항목 | 쉬운 말 | 원어(코드 필드) | 근거 |
|---|---|---|---|
| 선정산 대상액 | 선정산 배치에 실제로 들어간 금액 = 채권 매입 금액 | preSettlementTargetAmt | types:237-238 |
| 선정산 수수료 | 페이허그가 떼는 수수료 4종의 합(아래 (4)) | preSettlementFeeAmt | PreSettlementTab:471 |
| 정산 반영 수수료 차액 | 이 지급에 함께 반영된 과거 수수료 차액 보정(+환급/−차감) | adjustmentAmt (지급일 기준) | types:323-324 |
| 오프라인 차감 | 만나서결제 등 현장결제 건을 지급액에서 차감 | offlineDeductionAmt | PreSettlementTab:698-700 |
| 플랫폼 차감 | 배달 플랫폼이 정산액에서 회수하는 항목(광고비 등) | adDeductionAmt | types:308-314 |
| 플랫폼 환급 | 플랫폼이 가산해 주는 항목 + 우리가게클릭 순환급 | refundAdditionAmt + cpcRefundAmt | PreSettlementTab:57-59 |

**(2) 순 지급액 [확정]** — 순 지급액 = 총 매출액 − 총 수수료. 취소 건은 순 지급액에서 차감된다(카드 sub 안내) (PreSettlementTab:445-455).

**(3) 선정산 제외액 부호 규약 [확정]** — 제외액 = 선정산 대상액 − 정산 반영액. **제외되는 금액 = 음수**이며 실질은 바로이체 건이다(이미지급은 recordOnlyAmt로 분리돼 제외액에 안 들어감). **양수 잔차 = 확인 필요**(정산 후 취소·예상매출 선정산 등으로 대상액 스냅샷과 지급 기록이 어긋난 금액) — 잔차 존재 시(제외액 ≠ −바로이체) amber 안내+점선 툴팁 (types:229-245, PreSettlementTab:456-469, 754-763). 엑셀 헤더에도 "선정산제외액(-제외 / +확인 필요)"로 명시 (PreSettlementTab:259).

**(4) 선정산 수수료 4종 분해 [확정]** — 선정산 수수료 = 채권매입(marginFeeAmt) + 시스템 이용료(systemFeeAmt) + 이체 수수료(transferFeeAmt) + 차액 대상 수수료(adjMarginFeeAmt, 0이 아닐 때만 표시). 명칭은 labels 한 곳에서 정의(배지 '차액대상') (PreSettlementTab:471, 674-688; labels:9-23). 수수료 면제 가맹점은 금액을 기록만 하고 실제 차감하지 않는다('면제' 배지+툴팁 안내) (types:319-320, PreSettlementTab:682-686).

**(5) '차액' 4용어 분리 [확정]** — 이름이 비슷한 4개 값은 모집단·부호 규약이 전부 다르다. 혼용 금지.

| 용어 | 정의 | 기준 | 부호 규약 | 근거 |
|---|---|---|---|---|
| 거래 수수료 차액 | feeDiffAmt = 정산 반영액 − 순지급액 = 실제 − 예상 수수료 | 거래일 | **양수=추가차감(빨강) / 음수=환급(파랑)** | types:356-363 |
| 정산 반영 수수료 차액 | adjustmentAmt = 이 날짜 배치가 지급하며 반영한 차액 | 지급일 | 양수=환급 가산 / 음수=차감 | types:323-324 |
| 배분 수수료 차액 | payout.feeAdjustment = 이해관계자 배분에 실린 차액 | 배치 배분 | ± (화면 2 참조) | BatchDetailTab:628 |
| 차액 대상 수수료 | adjMarginFeeAmt = 차액 보정분에 대한 수수료(선정산 수수료 구성요소) | — | ± | labels:22 |

주의: 거래 수수료 차액은 카드 원장 `fee_adjustment_amt`(예상−실제)와 **값은 같고 부호가 반대**다. 배달은 원장에 차액을 안 남기므로 이 값에서만 드러난다 (types:356-363).

**(6) 검증 차이 [확정]** — unexplainedDiffAmt = 실제 지급액 − 위 (1) 산식 결과. 0이 아니면 표시하고 '확인 필요'로 취급한다. 발생 예: 차감액이 지급액보다 커서 0원 처리된 뒤 이월된 경우 (types:321-322, PreSettlementTab:714-724).

**(7) 플랫폼 차감 구성의 한계 [확정]** — 행 하단 '플랫폼 차감' 구성 툴팁의 항목 금액은 조정 **원금**이다. 배치별 회수액은 저장되지 않아 한 조정이 여러 배치에 걸쳐 회수되면 원금 합 ≠ 실제 회수 총액 → 총액(adDeductionAmt)만을 진실로 두고, 어긋나면 "원금 기준 — 부분회수로 총액과 다름"을 밝힌다. 항목이 비면 '구성 미상' (PreSettlementTab:801-928, types:310-314).

### ⑤ 정책 (확정/가설/확인필요)

- **[확정] 6대 개념 분리 유지** | 선정산 제외금액(preSettlementExcludedAmt)·바로이체(directTransferAmt)·이미지급(recordOnlyAmt)이 코드 필드로 분리돼 있고, 이미지급은 제외액에 합산되지 않는다 (types:239-245).
- **[확정] C5 — '회수' 3종 별개** | 이 화면의 플랫폼 차감 '회수'(광고비 등 조정 원금 회수)는 과지급 회수와도, 어드민 매출 회수(락계좌→모계좌 스윕)와도 다른 개념이다 (labels:57-66).
- **[확인필요] C1 — 수수료율** | 이 화면은 금액 분해만 보여주고 **요율을 노출하지 않는다**. `policyRate` 필드는 존재하나 미사용 (types:304). 1% / 0.604% / 0.6+0.11+0.1% / 0.25% 병존 상태 그대로 — 어느 값도 채택 금지.
- **[확인필요] C2 — 지급 캘린더** | "`{정산일}` 정산 (`{매출일}` 매출 기준)" 분리 표기로 D+n이 데이터로만 드러나고 규칙은 미확정 (PreSettlementTab:542-551). 미정산 누락의 "**이틀** 이상 지난 건은 선정산이 아니라 수수료만 제외한 순지급액 전액 이체" 문구는 코드 확정이나 정책 근거 미정 (PreSettlementTab:1035-1039).
- **[확인필요] C4 — 예상 지급 차액** | 가맹점 웹 라벨 '예상 지급 차액'(ST_DIFF)과 이 화면의 차액 4용어(특히 거래/정산 반영 수수료 차액)의 대응은 정의 미확정 — 값·매핑 단정 금지.
- **[가설] 이미지급 증빙** | 이미지급(RECORD_ONLY)은 "이미 수동이체된 건으로 간주해 원장에만 지급 완료 기록"(확인 모달 문구, PreSettlementTab:986-991) — 증빙·대사 절차는 운영 관행으로 추정, 확인 필요.
- **[신규 → 07 등재 후보]** | '검증 차이'는 정책서에 없는 감시값(6대 개념 어디에도 매핑 안 됨). 발생 시 처리 절차·책임 주체 미정.

### ⑥ 고려해야 할 점

- **모집단이 다른 숫자 3쌍** | ⑴ 요약 시트(화면 필터 반영) vs 건별상세 시트(기간 전체 재조회) ⑵ 정산 반영 수수료 차액(지급일) vs 거래 수수료 차액(거래일) ⑶ 펼침 패널 건수(선정산 제외 건 포함 전량) vs 요약 롤업 건수. 운영자가 두 값을 대조하면 "왜 다르지"가 반드시 나온다 — 문서·교육에 선제 안내 필요 (PreSettlementTab:183-186, 1268).
- **잔차 상쇄 함정** | 제외 건 존재 판정은 합계가 아니라 가맹점별 OR로 한다 — 가맹점 간 잔차가 상쇄되면 합계 0인데 제외 건은 있다. 같은 이유로 잔차 성분끼리 상쇄되면 툴팁이 숨을 수 있다(수용한 한계) (PreSettlementTab:564-566, 754-763).
- **음수 지급·이월** | 차감이 지급액을 초과하면 0원 처리 후 이월 → 검증 차이 양수로 표출(예: 민속보쌈 지급 0원 + 검증 차이 +372,300). 이월 반복 한도 정책 미정.
- **입금예정일 경과는 추정** | 미정산 누락의 '예정일 경과' 배지는 참고용 추정 — 실제 입금 확인은 별도 판단(화면 안내 명시) (PreSettlementTab:1038).
- **바로이체 권한 사고 방지** | 바로이체는 실제 이체가 나가는 조작이라 확인 모달(warning)+미리보기를 거치지만, 부분 실패 시 "N건 이체 실패 — 재시도 필요" 상태가 남는다. 실패 건 후속 처리 동선(이체 내역 탭 대조) 교육 필요 (hook:373-385).
- **동명 필드 반대 부호** | 배치 상세 `AdDeduction.adAmount`(절댓값) vs 선정산 상세 `PreSettlementAdCharge.adAmount`(부호 포함) — 이중 마이너스(--) 버그 전력. 서버 규약 통일 여부 확인 필요 (types:127-133 vs 422-428).

### ① 메뉴 위치·진입 경로

### ② 화면 내용·구성

- **좌 1/3 — 정산 목록** | 정산일(closedAt) 기준 날짜 그룹핑(미정산 배치는 "{매출일} 매출 (미정산)"). 그룹 헤더 = N개 가맹점·N건·합계. 행 = 가맹점명+에이전시 배지+바로이체/이미지급 배지+상태(정산완료/진행중/대기)+매출일·건수·금액 (BatchDetailTab:330-413, 12-22).
- **우 2/3 — 배치 헤더** | "{가맹점} | {정산일} 정산 ({매출일} 매출 기준) | N건" + 총액 | 오프라인 차감 | 플랫폼 차감 | 배분 수수료 차액 | **실 지급**(각 항목 값 있을 때만 병기) (BatchDetailTab:418-456).
- **조건부 섹션 3종** | ⑴ 미회수 차액 이월 안내(amber) ⑵ 현장결제 차감 내역 표 ⑶ 플랫폼 차감 내역 표(매출원/구분 배지/정산일/기간/차감액/회수액/상태/부가세 + 회수액 합계 tfoot) — 해당 데이터가 있는 배치에서만 (BatchDetailTab:458-607).
- **이해관계자 배분 요약** | 참여자(법인/사업자 배지)/역할/채권매입/시스템 이용료/이체 수수료/배분 수수료 차액/배분액/상태(이체완료·이체대기·이체실패·부채상계·기록용). 기록용은 최하단 정렬, tfoot 합계 (BatchDetailTab:609-675, 24-37).
- **수수료 원장 상세** | 아코디언 3층: 시스템 이용료(건별 합산) → 거래별 원장(카드/배민 배지·'예상' 배지) → 배치 레벨 원장(이체·차액 수수료). 각 표 컬럼: 참여자/역할/(유형)/매출/원가/수익/VAT/순수익/배분액+소계 (BatchDetailTab:744-928).
- **정렬·엑셀** | 정산일 정렬 토글 + 엑셀 4시트(정산목록/이해관계자 배분/가맹점별 이해관계자 합계/수수료 원장 상세) (BatchDetailTab:216-292).

### ③ 로직

- **2단 lazy 조회** | 탭 진입 시 `GET /admin/settlement/batches?dateFrom&dateTo` → 배치 클릭 시 `GET batches/{id}/payouts`(배분+오프라인/플랫폼 차감+이월액 1호출) → 이어서 `GET batches/{id}/ledgers`(원장) (hook:232-272).
- **가맹점·에이전시 필터** | 클라이언트 필터(가맹점명·merchantId·사업자번호 부분일치) (BatchDetailTab:70-75).
- **시스템 이용료 건별 합산** | 거래별 SYSTEM_FEE 원장을 참여자(payee+role) 단위로 화면에서 합산해 배치 레벨 요약으로 노출 (BatchDetailTab:716-742).
- **납부자/전달금 배지** | 음수 배분(payout<0)인 SYSTEM_FEE/TRANSFER_FEE 원장은 '납부 → 수취자' 배지(가맹점이 납부 주체), passthrough>0 행은 "{수취자} 지급 N원" 전달금 배지 (BatchDetailTab:850-894).
- **전달금 재귀속** | 하위파트너가 수익 0인 형식 참여(폭포수 정책)일 때 전달금·순수익을 상위파트너로 재귀속해 표시. **배분액(payout)은 불변** — 표시 보정일 뿐 원장 데이터는 그대로 (ledgerLib:14-69). MARGIN·FEE_ADJUSTMENT 유형에만 적용 (ledgerLib:15).
- **엑셀 일괄 조회** | 화면 노출 배치 대상 `GET batch-payouts`·`GET batch-ledgers` 기간 일괄 API. 한쪽 실패해도 나머지 시트는 생성 (BatchDetailTab:98-109, hook:274-290).

### ④ 기획자가 파악해야 하는 계산식

**(1) 원장 행 구조 [확정]** — 참여자별 원장 한 행 = 매출(revenue) / 원가(cost) / 수익(profit) / VAT(profitVat) / 전달금(passthrough+passthroughVat) / 순수익(netProfit) / 배분액(payout) (types:75-92). 원장은 "이 수수료를 누가 걷어 누구와 나누는가"의 분해다.

**(2) 배분 폭포수 [확정]** — 채권매입(MARGIN)·배분 수수료 차액(FEE_ADJUSTMENT)은 하위→상위 폭포수 배분: 하위파트너 몫에서 영업조직 전달금이 나가고, 하위가 형식 참여(수익 0)면 실제 지급 주체는 상위파트너 (ledgerLib:15-27). 시스템 이용료·이체 수수료는 가맹점이 **납부자**(음수 원장)이고 페이허그·파트너 등이 수취자 (BatchDetailTab:851-858).

**(3) 실 지급 [확정]** — 배치 헤더의 '실 지급'은 계산식이 아니라 **가맹점 직접 지급 payout.totalPayout(수수료·차감·환급이 모두 반영된 확정 이체액)을 그대로** 쓰며, 총액과 다를 때만 병기한다. 구판의 "총액−차감" 즉석 계산은 폐기 (BatchDetailTab:311-316, 449-453).

**(4) 배분 수수료 차액 [확정]** — 헤더 병기값 = Σ(role=MERCHANT인 payout.feeAdjustment). 카드 수수료 예상↔실제 차액의 환급/차감이 실제 이체액에 포함되므로 별도 표기 (BatchDetailTab:311-314, 441-448).

**(5) 배치 회수액 규약 [확정]** — 플랫폼 차감 표의 두 금액 열은 서로 다른 값이다.

| 열 | 뜻 | 규약 |
|---|---|---|
| 차감액 (adAmount) | 조정 **원금** 전액 | 절댓값(서버 .abs), 표시할 때 − 접두. PARTIAL 이월 행은 이 배치 회수액보다 큼 |
| 회수액 (recoveredAmount) | **이 배치가** 실제 회수한 몫(회수 원장 take) | 양수 크기. Σ회수액 = 헤더 합계(adDeductionAmount)는 V57 배포 이후 회수분에만 성립 |

- 백필된 과거 회수는 누적 전액이 마지막 배치 하나에 몰려 기록 → 앞 배치는 내역이 비고 마지막 배치는 합계 초과 가능. 회수액 합계 tfoot이 헤더 합계와 다를 때만 이 사유를 표시 (types:126-146, BatchDetailTab:77-80, 559-603).
- 회수액 < 차감액은 status와 무관 — 다른 배치가 나머지를 회수한 행은 '회수완료' 배지여도 이 배치 몫만 보인다 (BatchDetailTab:560-566).
- 차감액 열에는 합계를 두지 않는다 — 조정 원금이라 회수액과 애초에 다른 값 (BatchDetailTab:582-586).

**(6) 미회수 차액 이월(CARRY_FORWARD) [확정]** — 차액 환수가 당일 지급액을 초과하면 지급액 0원 처리 + 미회수분은 다음 정산에서 차감. 이월액은 배치 헤더 아래 amber 박스로 안내 (BatchDetailTab:458-469, hook:265).

**(7) 전달금 재귀속 조건 [확정]** — 같은 배분 체인(feeType×거래)에서 LOWER의 profit=0이고 passthrough≠0이면: LOWER는 전달금 0·순수익 profit+VAT로, UPPER는 전달금 +pass·순수익 −pass로 바꿔 표시 (ledgerLib:41-68).

### ⑥ 고려해야 할 점

- **회수액 열 오독** | "회수액 합계 ≠ 헤더 합계"가 정상인 경우(백필)와 비정상인 경우를 운영자가 구분해야 한다. 화면은 다를 때만 사유를 띄우지만, 과거 기간 조회 시 빈 내역·초과 합계가 반복 노출됨 — CS 대응 문구 준비 필요 (BatchDetailTab:596-601).
- **표시 보정 vs 원장 진실** | 전달금 재귀속·시스템 이용료 건별 합산은 화면 표시 보정이다. 엑셀 '수수료 원장 상세'도 재귀속을 반영하므로, 서버 원본 데이터와 대조하는 감사 시 차이가 난다는 점을 문서화해야 한다 (BatchDetailTab:150-175).
- **기록용(RECORD_ONLY) 배분** | 이미지급 배치의 배분은 실제 이체 없는 기록용 — 합계에 섞이면 이중 지급으로 오독. 최하단 정렬로 분리하지만 tfoot 합계에는 포함된다 (BatchDetailTab:32-37, 663-671).
- **미정산 배치** | closedAt 없는 배치는 매출일로 그룹핑되고 "(미정산)" 표기 — 정산일 필터·정렬 기준이 섞이는 지점 (BatchDetailTab:344-346).
- **부분 실패 내성** | 엑셀 일괄 조회는 배분/원장 한쪽이 실패해도 나머지를 내보낸다 — 빈 시트가 "데이터 없음"인지 "조회 실패"인지 구분 불가. 로그 확인 안내 필요 (BatchDetailTab:100-109).

### ④ 기획자가 파악해야 하는 계산식

**(1) 발행 단위 합산 [확정]** — 발행 1행 = **가맹점 × 발행 주체(payeeUserId) × 항목(feeType)**의 기간 합산. 정산 상세 원장의 참여자별 몫이 계산서 단위로 그대로 드러난다("계산서는 가맹점 단위로 발행" — BatchDetailTab:177 주석의 동일 사상) (types:180-205).

**(2) 요율 역산 표시 [확정·인용 금지]** — 화면 요율은 서버 금액에서 화면이 **역산**한 표시값이다 (TaxInvoiceTab:22-33).

> 요율(%) = 공급가액(supply) ÷ 선정산대상액(baseAmount) × 100 — 소수 3자리 반올림

- 1.004% 같은 값은 반올림 포함 근사 — **정책 요율로 인용 금지(C1)**. baseAmount가 없거나 0이면 "-".

**(3) 이체 수수료 표기 [확정]** — 배치당 정액 구조: 공급가 ÷ 배치수(batchCount)가 정수면 "단가×N회"(예: 300원×9회), 비정수면 "정액" 표기 (TaxInvoiceTab:24-29).

**(4) 면세/과세 분해 [확정]** — 채권매입(MARGIN) = TAX_FREE → 면세계산서(세액 0) / 시스템 이용료·이체 수수료 = TAXABLE → 세금계산서(세액 = VAT). 합계(total) = 공급가+세액. 판정값은 서버 필드 (types:189-193).

**(5) 발행 합계 [확정]** — 가맹점 카드 헤더·tfoot의 발행 합계 = Σ invoiceRows.total (TaxInvoiceTab:168, 273-279).

**(6) 두 기준액의 구분 [확인필요]** — 카드 헤더의 '선정산대상 X원'(totalSalesAmount)과 각 발행 행의 기준액(baseAmount)은 별개 필드다. 원천값은 선정산 결과 탭의 '선정산 대상액'과 동일하다고 프론트 주석이 확정했지만(types:237-238), 행 단위 baseAmount와 머리 합계의 일치 여부·서버 정의는 확인 필요.

### ⑤ 정책 (확정/가설/확인필요)

- **[확정] 면세/과세 2분류** | 채권매입=면세, 시스템·이체=과세. 단 채권매입 면세의 법·세무 근거(금전채권 양수도 부가세 면제 해석?)는 코드 밖 — 세무 검토 여부 확인 필요.

- **[확인필요] 발행 실행 프로세스** | 실제 발행(홈택스 연동/수기), 발행 주기(월?), 정정 발행 절차가 시스템에 없음 — 운영 프로세스 확인 필요.

### ⑥ 고려해야 할 점

- **요율 오인 리스크** | 화면 요율이 "계약 요율"로 인용되면 C1 혼선이 가중된다. 역산 표시값·소수 3자리 반올림임을 자료 배포 시 명기해야 한다 (TaxInvoiceTab:30-33).

- **발행-원장 대사 부재** | 발행 합계와 정산 상세 원장 배분액의 대사 절차·불일치 시 처리 규칙이 시스템에 없음 — 월 마감·정정 프로세스와 함께 확인 필요.
- **개인 참여자 행** | isBusiness=false 참여자 행이 발행 자료에 섞여 나올 수 있다(mock에 개인 영업사원 존재) — 발행 불가 대상의 구분 규칙 필요.

### ⑦ 엮여 있는 메뉴·화면

| 구분 | 화면 ID | 관계 |
|---|---|---|
| 같은 페이지 탭 | AD_SETTLE | '선정산 대상액' 카드("계산서 발행에 따른 채권 매입 금액")와 같은 원천값 — 탭 간 1:1 대조 |
| 같은 페이지 탭 | AD_SETTLE_DETAIL | 원장(발행 근거의 원천) + 엑셀 '가맹점별 이해관계자 합계'와 동일 집계 사상 |
| 같은 페이지 탭 | AD_SETTLE_TRANSFER | 이체 수수료 횟수(batchCount)의 실체인 이체 실행 기록 |
| 어드민 연관 | AD_PARTNER (_PROFILE) | 발행 주체 마스터 — 법인/사업자 구분, 인감·사업자등록증 첨부 |
| 어드민 연관 | AD_PRODUCT | 요율의 정책 원천(rateBps) — 단 정책 확정값 아님(C1) |
| 가맹점 웹 대응 | (직접 대응 없음) | 내부 전용. 가맹점 측에는 채권 매입 계약(MC_CONTRACT_SIGN 계열 전자계약)이 법적 근거로 연결되고, 수수료 자체는 ST_MA의 수수료·시스템 이용료 행으로 노출 |

**데이터 흐름** | 정산 원장(AD_SETTLE_DETAIL) → 서버 기간 합산(tax-invoice-summary) → **본 화면(발행 근거 자료·엑셀)** → 실제 발행은 시스템 밖(홈택스/수기 — 확인 필요).

### ⑧ 핵심 용어 정리

| 용어 | 정의 (원어 병기) |
|---|---|
| 발행 단위 | 가맹점 × 발행 주체(payeeUserId) × 항목(feeType)의 기간 합산 1행 |
| 발행 주체 | 계산서를 발행하는 참여자(페이허그·파트너·영업조직 등, payee) |
| 선정산대상액(기준액) | 요율 산정 기준액 (baseAmount, 이체 수수료는 null) — 선정산 결과 탭 대상액과 동일 원천 |
| 요율 | 공급가 ÷ 기준액 × 100의 화면 역산 표시값 — 정책 요율 아님(C1) |
| 공급가액/세액/합계 | supply / vat / total — 계산서 기재 금액 3종 |
| 면세계산서 / 세금계산서 | TAX_FREE(채권매입) / TAXABLE(시스템 이용료·이체 수수료) |
| batchCount | 기간 내 이체 수수료가 발생한 배치 수 — "단가×N회" 표기의 분모 |
| 매출유형 구분 | 신용카드(CARD) / 배달앱(DELIVERY) — 요약 표의 행 축 (TaxInvoiceTab:10-13) |
