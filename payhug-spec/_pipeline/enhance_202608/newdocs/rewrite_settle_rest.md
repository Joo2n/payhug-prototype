## 주제 ① 차액 정산 탭

### 1. 한 줄 정의
선정산 때 적용한 예상수수료와 이후 확정된 실제 수수료의 차이(차액)를 유형별로 모아, 환급·차감 순액과 반영 상태를 기간 축으로 한눈에 보는 정산 현황의 세 번째 탭 (관리자·총판 공용).

### 2. 용어
- 차액 = 예상수수료 − 실제 수수료. 금액은 절댓값으로 저장, 방향(환급/차감)은 유형이 결정.
- 유형 8종 = 카드수수료 환급 / 카드수수료 차감 / 배달수수료 환급 / 배달수수료 차감 / 취소 환수 / 예상매출 환급 / 예상매출 차감 / 미회수 이월.
- 대분류 5종(하위 탭·요약 카드 단위) = 카드 수수료 차액 / 배달 수수료 차액 / 취소 환수 / 예상매출 대사 / 미회수 이월.
- 상태 2종 = 대기 중 / 반영 완료(반영일 병기).
- "차액" 4용어 구분 — 절대 하나로 부르지 말 것:
  - 거래 수수료 차액 : 거래일 축 건별 값. 양수 = 추가 차감(빨강), 음수 = 환급(파랑). 선정산 결과 건별 상세·엑셀 건별상세에 노출.
  - 정산 반영 수수료 차액 : 지급일 축, 배치에 반영된 환급 − 차감 순액. 지급액 산식의 더하기 항. 선정산 결과 요약 카드·지급액 하단·엑셀 선정산요약에 노출.
  - 배분 수수료 차액 : 배치의 참여자 배분 축. + 파랑 / − 빨강. 정산 상세 배분 요약·배치 머리글·엑셀에 노출.
  - 차액 대상 수수료 : 차액이 아니라 수수료 구성 항목의 하나(표식 "차액대상"). 수수료 분해·원장 유형 표식에 노출.
- (본 탭의) 건별 차액 : 위 4용어의 모집단이 되는 원장 값. 반영 완료되면 지급일 축으로 "정산 반영 수수료 차액", 참여자 배분 축으로 "배분 수수료 차액"에 나타남.

### 3. 정책
- 노출 범위 — 총판 노출 (확정). 총판(파트너·영업조직·영업·제휴·투자자)은 정산 현황 6탭 중 선정산 결과·차액 정산·이체 내역 3탭만 봄. 탭 진입 시 최초 1회 자동 조회, 이후 조회 버튼·필터 변경으로 재조회.
- 필터 구성 — 공용 기간 필터 + 가맹점명·사업자번호 검색 + 에이전시 선택. 이 탭에서만 "매출 유형(복수 선택)" 단추 5종(전체/카드/배달의민족/요기요/쿠팡이츠)과, 카드 선택 시 하위 "카드사(복수 선택)" 단추가 추가됨. 카드사 선택지 목록은 필터 적용 전 전체 기준으로 서버가 내려줌 — 선택해도 선택지가 줄지 않음.
- 집계 이원화 (확정) — 매출 유형·카드사 필터는 서버로 보내 요약 지표·차트·목록 전부에 반영(변경 즉시 자동 재조회). 에이전시·가맹점명 필터는 목록 행만 화면에서 거름 — 요약 지표·차트에는 반영되지 않음.
- 필터 가드 — 매출 유형에서 카드를 빼면 하위 카드사 선택을 자동으로 "전체"로 초기화(빈 결과 방지).
- 요약 지표 카드 — 4열 배열. ① 전체 차액(순액·전체 건수·대기 건수) + ② 대분류별 카드(순액·건수·대기 건수). 카드 수 = 1 + 대분류 수 — 서버 응답에 따라 가변(개발 주석은 "4개"로 남아 있으나 실제는 가변).
- 일별 추이 차트 — 막대 3계열: 환급(파랑) / 차감(빨강) / 취소환수(보라). 0원 기준선, 만 단위 축약 표기, 데이터가 2일 이상일 때만 표시.
- 하위 탭 6종 — 전체 + 대분류 5종. 각 탭에 건수 병기.
- 상세 목록 — 거래일 / 가맹점(에이전시 표식 + 사업자번호) / 승인번호 / 유형(전체 탭에서만 대분류 표식) / 카드사 / 예상수수료 / 실제수수료 / 차액(+ 파랑 = 환급, − 빨강 = 차감) / 구분(유형 8종 표식) / 상태(반영완료 + 반영일 / 대기중).
- 정렬·엑셀 — 거래일 정렬 전환(최신/오래된순), 2차 정렬은 등록 순번. 엑셀은 단일 시트 "차액정산" 12항목(거래일~상태), 차액 항목에 환급 + / 차감 − 부호를 입혀 내보냄.
- 매출 유형 필터 안내 문구 (확정) — "특정 매출 유형을 선택하면 원장과 연결된 건만 표시. 예상매출 대사처럼 원장 미연결 건은 전체에서만 확인".
- 미회수 이월 규칙 (화면 문구 확정) — 환수가 당일 지급액을 초과하면 지급액 0원 처리 후 잔여를 다음 정산에서 차감, 매일 자동으로 잔액 0까지 반복. 정책서 원천 조항과의 대조는 (확인 필요).

### 4. 계산식
- 전체 차액(순액) = 환급 총액 − 차감 총액 (서버 계산). 예시: 환급 120,000원 − 차감 45,000원 = +75,000원.
- 대분류 순액 = 해당 대분류의 환급 합 − 차감 합 (서버 계산). 예시: 카드 수수료 차액 환급 30,000원 − 차감 12,000원 = +18,000원.
- 건별 차액 = 예상수수료 − 실제 수수료. 예시: 예상 4,400원 − 실제 4,150원 = +250원(환급).
- 목록 표시 부호 = 유형이 환급 계열이면 +(파랑), 아니면 −(빨강). 저장값은 절댓값 — 부호는 유형에서 유도.

### 5. 케이스·예외
- case1) 에이전시·가맹점명 필터 사용 : 목록만 줄고 요약 지표·차트는 전체 기준 유지 → 화면 안 모집단 불일치 발생 (확정).
- case2) 예상매출 대사 건 + 매출 유형 선택 : 원장 미연결 건이라 목록에서 사라짐 → 전체 선택에서만 확인 가능.
- case3) 미회수 이월 발생 : 환수 > 당일 지급액 → 당일 지급 0원 + 잔여 이월, 다음 정산부터 매일 잔액 0까지 반복 차감.
- case4) 대기 중 건 존재 : 순액에 대기 건이 포함되는지(반영 예정액인지 반영 확정액인지) 미확정 — 서버 집계 (확인 필요).
- case5) 기간 내 대분류가 많은 경우 : 요약 카드 수 가변으로 4열 배열이 2줄로 흐를 수 있음. 0건 대분류의 카드 노출 여부는 (확인 필요).

### 6. 운영 확인 포인트
- 요약 지표·차트는 "서버 전체 기준"임을 화면설계서에 주석 — 또는 목록 필터와 집계 일치화 개선 검토.
- 예상매출 대사 필터 함정(유형 선택 시 소실)을 운영 가이드에 반영 — 안내 문구만으로는 놓치기 쉬움.
- "차액" 4용어 구분 표를 관련 화면설계서에 반드시 병기 — 오독 방지.
- 대기 건의 순액 포함 방식 서버 확인 후 라벨(반영액/반영 예정액) 확정.

### 8. 【미확정】
- 수수료율 근거 — 예상수수료·실제 수수료의 요율은 화면에 없음. 특정 요율 채택 서술 금지 (쟁점 1).
- "예상매출 대사"의 정의와 가맹점 노출 라벨 "예상 지급 차액"의 정의 일치 여부 — 이 탭 수치로 쟁점 4를 확정하지 말 것.
- 대기 중 건의 순액 포함 여부 (서버 집계).
- 0건 대분류 카드의 노출 여부 (서버 응답).
- 미회수 이월 화면 문구와 정책서 원천 조항의 대조.
- 총판 조회 결과가 소속 가맹점으로 한정되는지 (서버 소관).

## 주제 ② 이체 내역 탭 · VOC 대응 탭

### 1. 한 줄 정의
이체 내역 = 지급·매출 회수·수동 지급의 실제 이체 실행 기록을 날짜별로 확인하는 탭(관리자·총판 공용), VOC 대응 = 가맹점 1곳·기간을 지정해 정산 상세 보고서(엑셀)를 뽑는 관리자 전용 탭.

### 2. 용어
- 지급 이체 = 페이허그 → 가맹점 계좌로의 선정산 지급 이체.
- 매출 회수 = 락계좌의 매출대금을 모계좌로 옮기는 자금 옮김(출금 + 입금 2단계). 정책의 과지급 회수 아님 (쟁점 5).
- 수동 지급 = 어드민이 수동 이체 창으로 실행한 지급. 집계상 지급 묶음에 포함.
- 2단계 짝 = 매출 회수 1건이 만드는 출금·입금 기록 2건의 묶음. 화면은 1행, 엑셀은 2행.
- 상태 5종 = 성공 / 확인 완료 / 실패 / 요청 중 / 시간 초과. 요청 중·시간 초과는 성공도 실패도 아닌 중간 상태.
- 미지급계정 = 매출 회수의 중간 경유 계정(락계좌 → 미지급계정 → 모계좌). 실체(은행 가상계좌인지 내부 계정인지) (확인 필요). 6대 개념의 "미지급금"과 이름이 비슷하나 동일시 금지.
- VOC 정산 상세 엑셀 = 가맹점 1곳·기간 지정 정산 상세 보고서(서버 생성). 내용·항목 구성은 서버 소관.
- 실지급 합계 = VOC 조회 결과 상자의 지급 합계. 정의(참여자 배분 합인지 선정산 지급액 합인지) (확인 필요).
- 표시 전용 항목 = 정산 금액에 반영되지 않는 표시 전용 조정 행. VOC 보고서에만 노출.

### 3. 정책
【이체 내역 탭】
- 노출 범위 — 총판 노출 (확정). 정산 현황 4번째 탭, 진입 시 최초 1회 자동 조회.
- 요약 지표 4카드 — 지급 이체(성공 건/전체 건 + 성공 금액) / 매출 회수(성공 건/전체 건 + 성공 금액) / 전체 성공(건수·금액) / 전체 실패(건수·금액).
- 날짜별 카드 — 머리글: 날짜 + "○건 (성공 ○건)" + 지급/회수 × 성공·실패 금액 분해(금액 0원인 구분은 숨김, 실패만 0원이면 실패만 숨김). 본문: 시간/구분/가맹점/금액/수취 은행/수취 계좌/수취인/상태/거래번호 9항목 목록.
- 회수 짝 행 — "회수" 표식 + "2단계" 보조 라벨. 클릭 시 하위 2행 펼침: ① 출금(락계좌 → 미지급계정) ② 입금(미지급계정 → 모계좌), 각각 시간·계좌·상태·거래번호 표시.
- 짝 매칭 규칙 — 이체 대행(쿠콘)의 회수 흐름은 출금이체 + 입금이체 기록 2건을 남기지만 실제 입금은 1회 → 같은 가맹점 + 같은 금액으로 짝을 찾아 1행으로 묶음. 짝이 없으면 단독 행 유지. 먼저 찾은 짝이 선점.
- 짝 대표값 — 대표 금액 = 출금액. 대표 상태 = 둘 다 성공·확인 완료 → 성공 / 하나라도 실패 → 실패 / 그 외 → 출금 상태를 따름.
- 이체 유형 3종 — 지급 / 회수 / 수동 지급. 집계에서 수동 지급은 지급 묶음에 포함(회수가 아니면 전부 지급).
- 집계 방식 — 화면이 짝 묶음 후 재계산(서버 집계값 미사용). 성공 = 성공 + 확인 완료. **실패 카드는 건수·금액 모두 "실패 상태"만 합산.** 요청 중·시간 초과는 성공에도 실패에도 미포함.
- 실패 집계 이원화 (확정) — 날짜 머리글의 "실패"는 비성공 잔여(실패 + 요청 중 + 시간 초과) 기준 → 요약 지표의 실패 카드(실패 상태만)와 기준이 다름. 개발 주석엔 "동일 기준"이라 남아 있으나 변경 이후 낡은 주석.
- 실패 행 표시 — 거래번호 자리에 이체 대행 오류 문구(20자 초과 시 말줄임, 올려두면 전체 표시).
- 엑셀 — 짝을 묶지 않고 원천 기록 그대로 출력(회수 1건 = 2행). 11항목(일자/시간/구분/가맹점명/에이전시/금액/수취은행/수취계좌/수취인/상태/거래번호).
- 화면 필터 — 에이전시·가맹점명(가맹점 번호·사업자번호 포함) 필터는 날짜별 기록에 적용 후 빈 날짜 제거. 요약 지표도 필터된 행으로 재계산 → 이 탭은 지표·목록이 일치 (차액 정산 탭과 다름).

【VOC 대응 탭】
- 노출 범위 — 관리자 전용 (확정). 정산 현황 6번째 탭. 상단 공용 기간 필터를 쓰지 않고 탭 안 자체 필터 사용.
- 구성 — 단일 카드 "VOC 정산 상세 엑셀": 가맹점 선택 상자(불러오는 중 문구 포함) + 시작일 + 종료일 + [조회] 버튼.
- 가맹점 후보 — 계약 상태가 승인이고 사업자번호가 있는 가맹점만 (확정).
- 2단계 흐름 — ① 조회로 자료 존재 확인(없으면 "해당 기간에 정산 내역이 없습니다") → ② 다운로드로 서버 생성 엑셀 수신. 빈 파일 다운로드를 막는 구조.
- 조회 결과 상자 — 가맹점명(사업자번호) + "기간 · 배치 ○건 · 거래 ○건 · 실지급 합계 ○원" + [엑셀 다운로드]. 완료 시 "다운로드가 완료되었습니다" 안내.
- 오류 표시 — 가맹점 미선택 / 기간 내 정산 내역 없음 / 조회·다운로드 실패를 빨간 상자로 표시.
- 상태 초기화 — 가맹점·기간 변경 시 결과·오류·완료 상태 초기화.
- 무음 실패 — 가맹점 목록 조회 실패는 안내 없이 넘어가 선택 상자가 빈 채 남음 (결함 후보).
- 라벨 3곳 동기화 규약 (확정) — 플랫폼 조정 항목 라벨은 화면 라벨 정의 / 서버 조정 항목 정의 / VOC 보고서 라벨 3곳을 함께 갱신해야 함. 표시 전용 3종(광고비 보전·결제대행사 수수료 환급·손실보상 환급)은 화면·엑셀엔 내려오지 않고 VOC 보고서에만 나옴.
- 계산 없음 — 배치 수·거래 수·실지급 합계·보고서 내용 전부 서버 산출 (확정). 보고서 내부 산식은 서버 소관 (확인 필요).

### 4. 계산식
- 지급(회수) 성공 금액 = 성공·확인 완료 상태 건의 금액 합. 예시: 지급 성공 12건 8,400,000원.
- 전체 성공 = 지급 성공 건수 + 회수 성공 건수, 금액도 합산. 예시: 지급 12건 + 회수 3건 = 15건 9,900,000원.
- 전체 실패 = 실패 상태 건만 건수·금액 합산. 예시: 실패 2건 300,000원 (요청 중 1건 200,000원은 미포함).
- 날짜 머리글 실패 = 그 날짜 전체 − 성공 = 실패 + 요청 중 + 시간 초과. 예시: 실패 1건 100,000원 + 시간 초과 1건 200,000원 → 머리글 실패 300,000원, 요약 지표 실패 100,000원 (이원화 예시).
- 짝 대표 금액 = 출금 기록의 금액. 예시: 출금 500,000원 / 입금 500,000원 → 화면 표시 500,000원 1행.
- VOC 탭 = 화면 계산 없음 (전부 서버 산출값 표시).

### 5. 케이스·예외
- case1) 요청 중·시간 초과 건 존재 : 성공 + 실패 건수 합 ≠ 전체 건수 (확정) — 중간 상태가 양쪽 어디에도 안 잡힘.
- case2) 같은 날 같은 가맹점의 동일 금액 회수 2건 : 짝이 교차로 묶일 수 있음(먼저 찾은 짝 선점). 표시 문제일 뿐 원장 데이터 불변 — 다만 상태 종합이 섞일 수 있음.
- case3) 출금·입금 중 짝이 없는 회수 기록 : 단독 행으로 표시.
- case4) 화면과 엑셀 대사 : 화면은 짝 1행, 엑셀은 원천 2행 → 행 수 불일치. 대사 시 혼동 주의.
- case5) VOC 조회 — 기간 내 자료 없음 : 안내 문구 표시, 다운로드 진행 불가.
- case6) VOC 가맹점 목록 조회 실패 : 무음 실패 → 선택 상자가 비어 있어도 원인 안내 없음.
- case7) VOC 기간 입력 — 시작일 > 종료일 : 화면 검증 없음(서버 응답에 의존).
- case8) VOC 다운로드 완료 표시 : 예외 없이 끝났다는 뜻일 뿐 파일 내용 검증 아님.

### 6. 운영 확인 포인트
- 실패 집계 기준 이원화(요약 지표 = 실패 상태만 / 날짜 머리글 = 비성공 잔여)를 화면설계서에 두 기준 모두 명시 — 통일 여부는 기획 결정 사항.
- 요청 중·시간 초과가 많은 날은 머리글 실패 금액 > 요약 지표 실패 금액이 정상 동작임을 운영에 공유.
- "성공"과 "확인 완료"의 업무 차이(이체 완료 ↔ 입금 확인) 정의 확인.
- 이체 내역과 모계좌 입금 내역 대조 시 회수 ② 입금(→ 모계좌) 기준으로 대조.
- VOC 보고서가 가맹점에게 그대로 전달되는 자료라면, 내부 운영 용어 ↔ 가맹점 노출 용어 매핑을 보고서 항목에서 검증.
- 플랫폼 조정 항목 라벨 변경 시 3곳 동시 갱신 규약 준수 — 누락 시 화면·보고서 라벨 불일치 발생.

### 7. 연계 화면
| 관계 | 화면(한글명) | 내용 · 캡처 지시문 |
|---|---|---|
| 본 화면 | 정산 현황 > 이체 내역 탭 | 캡처: 요약 지표 4카드 + 날짜별 카드가 함께 보이게 1장, 회수 짝 행의 2단계 펼침 상태 1장 |
| 본 화면 | 정산 현황 > VOC 대응 탭 | 캡처: 조회 전 기본 상태 1장, 조회 결과 상자(배치·거래·실지급 합계) 표시 상태 1장 |
| 상류 | 선정산 결과 탭 | 지급 이체의 원천(선정산 지급) — 이체완료/이체대기 상태와 교차 확인 |
| 상류 | 미정산 누락 추적(주제 ③)의 바로이체 | 실행 결과가 지급 이체 기록으로 이 탭에 남음 (가설 — 이체 유형 매핑은 서버 확인) |

### 8. 【미확정】
- 이체 시각과 지급 캘린더의 관계 — 날짜 묶음은 이체 요청일 기준일 뿐, 기준일·지급일 정의가 아님 (쟁점 2).
- 미지급계정의 실체(은행 가상계좌 ↔ 내부 계정).
- 성공 ↔ 확인 완료의 업무적 차이.
- 바로이체 실행분이 이 탭에 기록되는 이체 유형 매핑 (가설 상태).
- VOC "실지급 합계"의 정의(참여자 배분 합 ↔ 선정산 지급액 합).
- VOC 보고서의 항목 구성·내부 산식 (서버 소관).
- VOC 보고서의 가맹점 직접 제공 여부와 노출 용어 검증.

## 주제 ③ 미정산 누락 추적

### 1. 한 줄 정의
정산 배치가 끝난 날짜에 뒤늦게 도착해 선정산에서 빠진 매출 건을 전 기간 단위로 모아, 바로이체(실제 이체) 또는 이미지급(기록만)으로 정리하는 선정산 결과 탭 상단의 관리자 전용 배너.

### 2. 용어
- 미정산 누락 = 배치 완료 후 뒤늦게 도착해 선정산 처리가 누락된 매출 건. 6대 개념의 "미지급금"과의 매핑 미확정.
- 바로이체 = 선정산 수수료 없이 순지급액 전액을 즉시 이체하는 처리(6대 개념의 "바로이체"). 실제 자금 이동 + 원장 기록.
- 이미지급(기록만) = 이미 수동이체된 건으로 간주해 이체 없이 원장에만 지급 완료로 기록하는 처리. 선정산 제외액 아님 — 지급액 하단 가감 항목.
- 순지급액 전액 = 매출액 − 카드/배달 수수료 (선정산 수수료는 떼지 않음).
- 미리보기 = 이체·원장 기록 없이 처리 예상 결과만 보여주는 무부작용 조회.
- 예정일 경과 = 입금예정일이 지난 건의 참고용 추정 표식. 실제 입금 확인 아님 (화면 고지).
- "해당일 정산완료 - 누락" = 그 날짜의 배치는 이미 돌았는데 이 건만 빠졌다는 표식.

### 3. 정책
- 노출 범위 — 관리자 전용 (확정). 조회 자체를 관리자만 수행하고 표시도 관리자 한정 — 실제 지급(바로이체) 권한이 페이허그 내부에만 있기 때문.
- 모집단 — 조회 기간과 무관한 전 기간 누락 건 (확정 — 조회 조건에 기간 없음). 기간을 좁혀도 배너 숫자 불변.
- 고지 문구 (원문 확정) — "정산 배치가 완료된 날짜에 뒤늦게 도착하여 선정산 처리가 누락된 건입니다. 이틀 이상 지난 건은 선정산이 아니라 카드/배달 수수료만 제외한 순지급액 전액을 그대로 이체합니다." + "입금예정일 경과 여부는 참고용 추정이며, 실제 입금 확인은 별도로 판단해야 합니다."
- 배너 구성 — 경고 표시 + "미정산 누락 추적" + "○개 가맹점 · ○건" 표식 + 총액 + 펼침 화살표. 클릭 시 아래로 펼침.
- 3단 목록 — 가맹점 카드(가맹점명·에이전시·사업자번호·합계) > 날짜 묶음(날짜·건수·"해당일 정산완료 - 누락" 표식·매출·미지급) > 건별 행(선택 칸/매출원 표식/주문번호/카드사·매장명/입금예정일 + "예정일 경과" 표식/미지급액).
- 실행 줄 — 전체 선택 + "선택 ○건 · ○원" + [미리보기](테두리 초록) [바로이체](초록) [이미지급(기록만)](회색). 선택 0건이면 전부 비활성.
- 처리 2경로 (확정) — 바로이체 = 실제 이체 + 원장 기록 / 이미지급 = 이체 없이 원장에만 지급 완료 기록. 결과는 각각 "바로이체 배치" / "이미지급 기록 배치"로 남고, 선정산 결과에서 바로이체는 선정산 제외액(음수)의 실질, 이미지급은 지급액 하단 가감 항목으로 표시.
- 확인 창 2종 — 바로이체: "가맹점 계좌로 순지급액 전액을 실제 이체합니다"(경고) / 이미지급: "이미 수동이체된 건으로 간주하여 이체 없이 원장에만 지급 완료로 기록합니다"(안내).
- 미리보기 (확정) — 저장·이체 없이 예상 결과만: 총 이체예정 금액·실제 이체 횟수·처리 건수 3지표 + 가맹점별 카드("거래일 ○일치(○건)를 합산하여 1회 이체 · 원장은 거래일별로 기록" + 제외 ○건 + 거래일별 배치 표).
- 이체 묶음 규칙 — 같은 가맹점의 여러 거래일 건을 합산해 1회 이체, 원장은 거래일별 배치로 나눠 기록. 이체액 0원이면 이체 0회.
- 처리 흐름 — 선택 건 처리 요청 → 완료 시 알림 + 선택 해제 + 누락 목록·선정산 요약 동시 재조회. 부분 실패 시 "○건 처리 중 △건 이체 실패 - 실패 건은 이체 재시도가 필요합니다" 안내 후 선택 유지(재시도용). 어떤 건이 실패했는지 행 단위 표시는 없음.
- 엑셀 연동 — 선정산 결과 엑셀의 5번째 시트 "미정산누락" 13항목(매출일/가맹점명/사업자번호/에이전시/매출원/주문번호/카드사·매장/입금예정일/매출액/미지급액/매입상태/정산여부/입금추정).

### 4. 계산식
- 선택 합계 = 선택한 건들의 순지급액 합. 예시: 3건 152,000 + 98,000 + 50,000 = 300,000원.
- 순지급액 전액 = 매출액 − 카드/배달 수수료. 예시: 매출 500,000원 − 수수료 12,000원 = 488,000원 (선정산 수수료 미차감).
- 가맹점별 이체 금액 = 그 가맹점의 선택 건 전체를 거래일 무관 합산한 1회 이체액 (서버 계산).
- 이체 횟수 = 가맹점당 1회. 예시: 거래일 3일치 5건 → 이체 1회, 원장 배치 3개. 이체액 0원이면 0회.

### 5. 케이스·예외
- case1) 바로이체 실행 : 실제 이체 + 원장 기록 → 선정산 결과 제외액·정산 상세 "바로이체" 표식·이체 내역 기록 발생.
- case2) 이미지급 실행 : 이체 없이 원장에만 지급 완료 기록 → 지급액 하단 가감 항목으로 표시. 제외액 아님.
- case3) 부분 실패 : 실패 안내 반환 + 선택 유지 → 재시도 가능. 행 단위 실패 표시 없음 (개선 후보).
- case4) 이체액 0원 가맹점 : 이체 0회, 원장 기록만 생성.
- case5) 조회 기간 축소 : 배너 숫자 불변 (모집단이 전 기간이므로) — 오해 방지 주석 필요.
- case6) 총판 열람 : 선정산 결과 탭은 보여도 배너는 안 보임 — 누락 존재 사실의 총판 공유 여부는 기획 결정 사항.

### 6. 운영 확인 포인트
- 바로이체는 실제 자금 이동 — "미리보기 → 바로이체" 순서를 운영 가이드로 굳힐 것 (화면은 순서를 강제하지 않음).
- 부분 실패 시 실패 건 행 단위 표시 개선 검토.
- "이틀" 규칙의 판정 기준(달력일/영업일, 기산점) 확정 전에는 이 문구로 지급 캘린더를 설명하지 말 것.
- 배너 모집단이 전 기간임을 화면설계서에 명시 (기간 필터와 무관한 이유 설명).
- 이미지급 처리 전 실제 수동이체 이력 존재 확인 절차 마련 — 화면은 간주 처리일 뿐 검증하지 않음.

### 7. 연계 화면
| 관계 | 화면(한글명) | 내용 · 캡처 지시문 |
|---|---|---|
| 본 화면 | 선정산 결과 탭 — 미정산 누락 배너 | 캡처: 배너 접힘 1장, 펼침(3단 목록 + 실행 줄) 1장, 미리보기 창 1장, 바로이체·이미지급 확인 창 각 1장 |
| 하류 | 선정산 결과 탭 | 처리 결과가 요약 카드(제외액·바로이체·이미지급)와 일자별 표에 반영 — 처리 직후 자동 재조회 |
| 하류 | 정산 상세 탭 — 배치 목록 | 바로이체·이미지급 배치가 각각의 표식으로 목록에 등장 |

### 8. 【미확정】
- "이틀" 규칙의 판정 기준 — 달력일/영업일 여부, 기산점(매출일 ↔ 배치 완료일). 지급 캘린더와 연동 (쟁점 2).
- 바로이체 수수료 면제의 정책 근거 — 지연 보상인지 선정산 미제공의 대가인지 정책서 대조 필요.
- 배너의 "미지급 ○원"과 운영 6대 개념 "미지급금" 정의의 일치 여부 — 임의 확정 금지.
- 입금 추정(예정일 경과)의 판정 로직 — 참고용 추정임만 확정.
- 누락 존재 사실의 총판 공유 여부 (기획 결정).
- 바로이체 실행분의 이체 내역 유형 매핑 (서버 확인).

## 주제 ④ 수수료 원장 — 건별·배치 원장, 전달금 재귀속, 시뮬레이션 원장

### 1. 한 줄 정의
정산 배치 1건의 수수료가 참여자별로 어떻게 배분됐는지 기록한 장부(원장)를 실 배치 화면·엑셀·사전 시뮬레이션 세 곳에서 같은 규칙(전달금 재귀속 포함)으로 보여주는 관리자 전용 체계.

### 2. 용어
- 원장 = 수수료 1유형 × 참여자 1명의 배분 기록 줄. 이체 원장·회수 원장과는 다른 표.
- 수수료 4종 (명칭 일원화, 확정) = 채권매입 수수료 / 시스템 이용료 / 이체 수수료 / 차액 수수료(표식 "차액대상"). 화면설계서도 이 명칭만 사용.
- 역할 8종 = 투자자 / 페이허그 / 상위파트너 / 하위파트너 / 영업조직 / 상위영업 / 하위영업 / 가맹점.
- 납부 = 가맹점 대신 수수료를 부담하는 음수 배분 줄. 시스템 이용료·이체 수수료에서만 발생. "납부 → 상대방" 표식 병기.
- 전달금 = 참여자가 계산상 통과시켜 기록용 참여자에게 지급할 몫. "장부에만 남는 값" 아님 — 지급 상대 표식으로 노출.
- 기록용 참여자 = 폭포수 배분·부과 집계에서 제외되는 참여자 줄. 배분 합산 제외·표 하단 정렬. 단, 전달금의 실지급 상대로는 표시됨.
- 직접배분 = 배분액을 실제로 받는 참여자 줄 (기록용의 반대).
- 폭포수 배분 = 하위 → 상위로 원가를 넘기며 배분하는 방식. 적용 유형: 채권매입 수수료·차액 수수료.
- 재귀속 = 형식 하위파트너의 전달금·순수익을 상위파트너 줄로 옮겨 보여주는 표시 보정.
- 형식 참여자 = 수익 0으로 자리만 차지하는 정책상 참여자.
- 예상 표식 = 예상값 기반 거래에 붙는 표식. 예상 → 확정 전환 시 생기는 보정이 곧 차액 수수료.
- 스킵 = 시뮬레이션에서 정책이 처리하지 못한 거래("스킵: 사유" 표기). 수수료 부과 제외.
- 부과 = 가맹점 부담 기준의 수수료 합(받는 쪽 양수 배분의 합).

### 3. 정책
【공통 · 부과 구조】
- 노출 범위 — 정산 상세 탭·시뮬레이션 메뉴 모두 총판 비노출 (확정). 시뮬레이션의 주소 직접 접근 차단 여부는 (확인 필요 — 화면 자체 가드 없음).
- 부과 구조 (확정) — 채권매입 수수료·시스템 이용료 = 거래 건별 부과 / 이체 수수료 = 배치당 1회 / 차액 수수료 = 실 정산에서만 발생(시뮬레이션 결과엔 없음). 요율 값은 화면 어디에도 없음 — 서술 금지 (쟁점 1).

【정산 상세 — 수수료 원장 상세】
- 진입 — 정산 상세 탭(관리자 전용) > 좌측 정산 목록에서 배치 선택 → 우측 하단 "수수료 원장 상세" 카드. 배치 선택 시 배분 집계 조회 후 원장을 별도로 조회하는 2단 조회. 엑셀은 기간 일괄 조회.
- 펼침 3계층 — (가) "시스템 이용료 (건별 합산)": 거래별 시스템 이용료 원장을 참여자 단위로 합산한 요약(○건 합산 표기) / (나) 거래별 원장: 매출원 표식(카드 = 남색/배달 = 주황) + 주문번호 + 매장명 + "예상" 표식, 우측에 정산액·배분 합계 — 채권매입·시스템 이용료가 건별로 붙음 / (다) 배치 단위 원장: 거래에 안 붙는 유형(이체 수수료 등)이 배치 줄로만 표시. 즉 건별 원장 = 채권매입·시스템 이용료, 이체 수수료 = 배치 줄 (확정).
- 원장 표 — 참여자(표식 2종: "납부 → 상대방", "{기록용 참여자} 지급 ○원" 전달금 표식) / 역할 / 유형(여러 유형이 섞인 표에서만) / 매출 / 원가 / 수익 / 부가세 / 순수익 / 배분액 + 소계 행. 배분액 색: + 초록 / − 빨강 / 0 회색.
- 납부자 판정 — 배분액이 음수이면서 유형이 시스템 이용료·이체 수수료인 줄 = 가맹점 대신 수수료를 부담하는 납부자. 같은 유형에서 양수 배분을 받는 참여자를 "납부 → 상대 참여자명"로 병기.
- 전달금 표식 — 전달금 + 부가세 > 0인 줄에 같은 유형의 기록용 참여자명으로 "{기록용 참여자명} 지급 ○원" 표시. 식별 안 되면 "영업조직"으로 표기.
- 시스템 이용료 합산 — 거래별 원장을 참여자(수취인 + 역할) 단위로 전 항목 합산해 배치 요약을 화면에서 생성. 같은 원장이 건별 표와 합산 표 두 곳에 보임.
- 엑셀 "수수료 원장 상세" 시트 — 18항목(정산일/매출일/가맹점명/에이전시/주문번호/매출원/매장명/거래금액/수수료 유형/참여자/역할/매출/원가/수익/부가세/전달금/순수익/배분액). 화면과 같은 순서(거래별 → 배치 단위)·같은 재귀속 보정 적용.

【전달금 재귀속 — 공통 표시 보정 규칙】
- 성격 — 화면이 아니라 원장 표시 보정 공통 규칙(2026-08-07 신설). 적용 3곳: 정산 상세 원장 표 / 정산 상세 엑셀 / 시뮬레이션 원장 표. 화면설계서에는 세 화면의 공통 규칙 상자로 기재.
- 왜 필요한가 (확정) — 원장은 영업조직 몫을 항상 하위파트너의 전달금으로 기록. 하위가 실재하지 않는 형식 정책에서는 상위가 실제 지급 주체인데, 그대로 보여주면 하위 순수익이 음수로 뜨고 상위의 지급 의무가 드러나지 않음.
- 적용 범위 — 폭포수 배분 유형(채권매입 수수료·차액 수수료)만. 묶음 식별 = 수수료 유형 + 거래 단위(엑셀 일괄에서는 거래 식별값이 없으면 배치 단위).
- 발동 조건 3가지 (전부 충족 시) — ① 묶음 안에 하위·상위 참여자가 모두 존재 ② 하위의 전달금 + 부가세 ≠ 0 ③ 하위의 수익 = 0 (형식 참여자).
- 보정 내용 — 하위: 전달금·전달금 부가세를 0으로, 순수익 = 수익 + 부가세로 재계산 / 상위: 전달금·부가세를 넘겨받고 순수익에서 그만큼 차감. **배분액은 건드리지 않음** — 가맹점 차감액과 무관.
- 한계 (확정) — 원장 데이터는 그대로 두는 화면 표기 보정. 실제 자금 이동 주체·서버 원장의 의미는 (확인 필요) — 화면 표기를 근거로 자금 흐름을 확정하지 말 것.

【정산 시뮬레이션 — 원장 표·배분 요약】
- 진입 — 정산 메뉴 > 정산 시뮬레이션. 정책 상품 선택 → 거래 입력 → 실행 → 결과 영역에 원장 표 표시. 저장 없는 계산 전용 (확정 — 상단 안내 문구 존재).
- 정산 요약 4카드 — 총 거래금액 / 거래 건수 / 총 수수료(가맹점 부담) + 하단 "부과: 채권매입 ○ · 시스템 ○ · 이체 ○" 분해 / 가맹점 지급액(강조).
- 건별 원장 카드 — 거래마다 번호 + 유형·금액 + 수수료·정책명 또는 "스킵: 사유" → 채권매입 수수료 표 + 시스템 이용료 표. 건별 원장은 이 두 종류만 (확정).
- 시스템 이용료 건별 합산 — 실 배치와 같은 방식의 참여자 단위 합산 뷰.
- 이체 수수료 — "배치당 1회" 제목의 배치 줄 하나(건별 없음).
- 원장 표 10항목 — 참여자(기록용 표시 + 전달금 표식) / 역할 / 매출 / 매출 부가세 / 원가 / 원가 부가세 / 수익 / 부가세 / 순수익 / 배분액. 정산 상세 표보다 부가세 분해 항목이 2개 많음.
- 이해관계자 배분 요약 — 참여자(법인·사업자(부가세) 표식) / 역할 / 유형(기록용 = 주황·기울임 / 직접배분 = 파랑) / 채권매입 / 시스템 이용료 / 이체 수수료 / 총 배분액. **이 표는 재귀속 미적용** — 원장 표만 보정.
- 요율 결정 (확정) — 결과는 선택한 정책 상품이 결정. 특정 요율 값 채택 금지 (쟁점 1).
- 기록용 ↔ 직접배분 (확정) — 기록용은 폭포수 배분·부과 총액 집계에서 제외(회색 기울임·주황 표시). 단 "장부에만 남는 기록"이라고 단정하지 말 것 — 원장 표에서 전달금의 실지급 상대로 표시됨(화면 표기 확정 · 실제 자금 이동 주체는 서버 확인 필요).

### 4. 계산식
- 순수익 = 수익 + 수익 부가세 − 전달금 − 전달금 부가세 (재귀속 후에도 유지되는 항등식). 예시: 10,000 + 1,000 − 3,000 − 300 = 7,700원.
- 수익 = 매출 − 원가 (가설 — 서버 계산, 화면은 표시만). 예시: 매출 15,000원 − 원가 5,000원 = 수익 10,000원.
- 유형별 부과액 = 기록용 제외, 배분액이 양수(받는 쪽)인 줄의 합. 예시: 시스템 이용료 양수 배분 2줄 3,000 + 1,500 = 부과 4,500원.
- 총 수수료(가맹점 부담) 분해 = 채권매입 부과(거래별 수수료 합, 스킵 건 제외) + 시스템 이용료 부과 + 이체 수수료 부과. 예시: 5,000 + 4,500 + 500 = 10,000원.
- 구획 배분 합계 = 그 구획 줄들의 배분액 합 / 소계 = 표 전체 배분액 합. 예시: 소계 = +7,700 − 500 + 2,800 = 10,000원.
- 엑셀 "전달금" 항목 = 전달금 + 전달금 부가세 합산값. 예시: 3,000 + 300 = 3,300원.
- 가맹점 지급액(시뮬레이션 요약) = 서버 요약값 (화면 계산 아님).

### 5. 케이스·예외
- case1) 형식 하위파트너(수익 0 + 전달금 있음 + 상·하위 동시 존재) : 재귀속 발동 → 전달금·순수익이 상위파트너 줄로 옮겨 표시.
- case2) 실재 하위파트너(수익 > 0) : 재귀속 미발동 → 원본 귀속 그대로 표시.
- case3) 서버 원본 자료 직접 추출 : 전달금 귀속이 화면·엑셀과 다름 → 대사 시 "표시 보정 적용 여부"를 항상 명시.
- case4) 시스템 이용료 이중 노출 : 같은 원장이 건별 표와 합산 표 양쪽에 보임 → 두 표를 더하면 이중 집계.
- case5) 단일 유형 구획 : 유형 항목이 숨음 → 화면 캡처 간 항목 수가 달라 보이는 이유를 설계서에 명시.
- case6) 시뮬레이션 스킵 거래 : "스킵: 사유" 표기 + 수수료 부과에서 제외.
- case7) 새 폭포수 배분 유형 추가 : 재귀속 대상 목록 갱신 필요 — 누락 시 구 표기로 회귀.
- case8) 배분 요약 ↔ 원장 표 : 배분 요약(기록용 줄의 총 배분액, 주황)은 재귀속 미적용, 원장 표는 적용 → 서로 다른 관점임을 주석.
- case9) 기록용 참여자 줄 : 배분 합산 제외 + 표 하단 정렬. 전달금 실지급 상대로만 표에 등장.

### 6. 운영 확인 포인트
- 정밀 대사는 엑셀·시뮬레이션으로 유도 — 정산 상세 화면 표는 매출 부가세·원가 부가세를 생략(축약형).
- 시뮬레이션 ≠ 실제 정산 — 오프라인 차감·플랫폼 차감·차액 정산이 없는 순수 수수료 배분 계산. 실 배치와 나란히 캡처할 때 차이 명시.
- 상품 변경 전 검증 동선: 시뮬레이션으로 사전 확인 → 실 배치 원장과 대조.
- 시스템 이용료 이중 집계 주의 주석을 화면설계서에 포함.
- 서버 원본과 화면·엑셀의 전달금 귀속 차이를 운영·개발 공동 인지 — 자료 추출 요청 시 보정 적용 여부 명시 관행화.

### 7. 연계 화면

### 8. 【미확정】
- 원장 항등식의 서버 정의 — 수익 = 매출 − 원가 여부, 부가세 산출 방식 (화면은 검증하지 않음).
- 실제 자금 이동 주체 — 재귀속·기록용 표기는 화면 표시일 뿐, 서버 원장의 의미와 실지급 주체는 별도 확인.
- 시뮬레이션 주소 직접 접근 차단 여부 (화면 자체 가드 없음).
- 수수료 요율 값 일체 (쟁점 1) — 정책 상품 정의 확인 전 서술 금지.

## 주제 ⑤ 차액 정산 내역 화면 2종 — 선정산 축 · 가맹점 축

### 1. 한 줄 정의
같은 차액 원장을 선정산 1건 축으로 보는 독립 화면(진입 경로 없는 고아 화면 — 결함 포함)과, 가맹점 축으로 보는 이력 화면(가맹점 상세의 진입 카드 포함) 2종.

### 2. 용어
- 정산적용 수수료 = 선정산 시점에 실제로 적용한 수수료. 차액 정산 탭·가맹점 이력의 "예상수수료"와 같은 값·다른 이름 (라벨 불일치).
- 원래 선정산 = 이 차액이 최초 발생한 선정산 건. 미회수 이월처럼 다른 선정산에서 발생해 넘어온 건의 출처 표시 (가설 — 항목 용도 기준).
- 추가 차감 = 실제 수수료가 적용치보다 커서 더 떼는 방향. "차감" 단독 사용 금지 — 플랫폼 차감·오프라인 차감과 혼동 위험.
- 상태 3종 = 대기 / 완료 / 취소. 완료 시 정산일 병기. 취소의 발생 조건·업무 의미 (확인 필요).
- 차액 정산 현황 카드 = 가맹점 상세의 요약 진입 카드. 이력 0건이면 미표시.
- 유형 8종 = 주제 ① 용어와 동일.

### 3. 정책
【선정산 축 — 선정산 차액 정산 내역】
- 위치 — 독립 화면 주소. 특정 선정산 1건에 물린 차액 건만 모아 보는 화면 (제목 "선정산 #번호 차액 정산 내역").
- 진입 경로 (결함, 확정) — 현행 어드민 전 화면에 이 화면으로 가는 연결이 없음(들어오는 연결 0건). 주소 직접 입력으로만 도달 가능한 고아 화면 — 의도된 동선(알림·외부 연결)이 있는지 (확인 필요).
- 권한 — 메뉴에 없음 + 화면 자체 권한 가드 없음 — 접근 정책 (확인 필요).
- 구성 — 머리글(← 돌아가기 + 제목) / 통계 4카드: 전체 건수 · 환급(+, 파랑) · 추가 차감(−, 빨강) · 순 차액(±) — 값은 서버 집계 / 목록 8항목: 거래일 · 승인번호 · 카드사 · 정산적용 수수료 · 실제 수수료 · 차액(부호는 유형이 결정) · 구분(유형 8종 표식) · 원래 선정산(번호 연결). **상태 항목 없음** — 반영 여부 확인 불가.
- 유형 안내 상자 (화면 문구 확정) — 카드수수료 환급/차감: "정산 당시 적용 수수료와 매입 확정 시 실제 수수료 차이" / 예상매출 환급/차감: "주말/장애로 예상 매출 기반 정산 후 실제 데이터와의 차이" / 미회수 이월: "당일 이체액으로 차액을 전부 회수하지 못해 다음 날로 이월된 금액" + "매일 자동 처리, 잔액 0까지 반복".
- 동작 — 필터·정렬·엑셀 없음(단순 조회). 빈 데이터면 "이 선정산에는 차액 정산 내역이 없습니다" + 돌아가기.
- 깨진 연결 (결함, 확정) — "원래 선정산" 연결이 존재하지 않는 화면 주소로 이동 → 오류(404) 발생. 수정 대상.

【가맹점 축 — 카드 수수료 차액 정산 이력】
- 진입 — 가맹점 관리 > 가맹점 상세의 "카드 수수료 차액 정산 현황" 카드 > [차액 이력 보기]. 다중 탭 모드에서는 "차액 이력" 탭으로 열림. 카드의 [매출 내역 보기]는 매출 조회 화면으로 이동.
- 노출 범위 — 카드·이력 화면 모두 총판 열람 가능 (확정 — 조회 전용, 조작 버튼 없음).
- 진입 카드 — 차액 정산 대기(건수 + 예정 금액, 노랑) / 이번 달 누적 / 전체 누적 3행 + "상세 통계 보기" 펼침(총 환급/총 추가 차감/순 차액) + 하단 "차액 정산이란?" 3단계 설명. **이력 0건이면 카드 자체를 숨김** (확정).
- 이력 화면 구성 — 제목 + 가맹점명 / 통계 4카드(전체 건수 · 환급 ○건 + 금액 · 추가 차감 ○건 + 금액 · 순 차액) / 상태 필터 3종(전체·완료·대기 — 서버 재조회, 취소 필터 없음) / 목록 9항목(거래일·승인번호·카드사·정산적용 수수료·실제 수수료·차액·구분·상태(대기/완료/취소)·정산일).
- 차액 3단계 수명주기 (화면 문구 확정) — "1. 선정산 단계: 정산 당시 적용수수료로 선정산 지급 / 2. 매입 확정: 실제 수수료 확인 후 차액 계산 (정산적용 − 실제) / 3. 다음 선정산: 차액 환급 또는 추가 차감". 진입 카드와 이력 화면이 같은 문구 사용.
- 필터 연동 통계 — 상태 필터를 바꾸면 목록 재조회 + 통계 카드도 필터된 목록으로 재계산. "대기" 필터에서는 통계도 대기 건만. 이 방식은 이 화면뿐 — 차액 정산 탭 요약 지표는 서버 전체 기준 (화면 간 집계 기준 상이).
- 통계 모집단 한정 (확정) — 환급·추가 차감·순 차액 통계가 유형이 정확히 "환급"/"차감"인 건만 집계. 배달·예상매출·이월·환수 유형이 응답에 섞이면 전체 건수에는 잡히되 환급·차감·순 차액에서 빠짐 → **통계 왜곡 가능성**.
- 라벨 불일치 — 같은 값을 이 화면 계열은 "정산적용 수수료", 차액 정산 탭·가맹점 웹 이력은 "예상수수료"로 부름. 용어 통일 검토 (의미상 "정산적용" 쪽이 정확).

### 4. 계산식
- 순 차액(선정산 축) = 환급 총액 − 차감 총액 (서버 집계). 예시: 환급 15,000원 − 차감 6,000원 = +9,000원.
- 순 차액(가맹점 축) = 환급 유형 금액 합 − 차감 유형 금액 합 (화면 계산 — 두 유형만 집계). 예시: 환급 3건 9,000원 − 차감 2건 4,000원 = +5,000원.
- 건별 차액 = 정산적용 수수료 − 실제 수수료 (안내 문구 기준). 예시: 4,400원 − 4,150원 = +250원(환급).
- 표시 부호 = 유형별 부호(+/−)를 절댓값 앞에 붙임. 환급 계열 + 파랑, 나머지 − 빨강.
- 진입 카드 요약(대기/이번 달/전체 누적) = 서버 집계.

### 5. 케이스·예외
- case1) "원래 선정산" 연결 클릭 : 존재하지 않는 화면으로 이동 → 오류(404) (확정 — 깨진 연결, 수정 대상).
- case2) 선정산 축 화면 진입 : 들어오는 연결 0건 → 주소 직접 입력 외 도달 불가. 실사용 동선 불명 — 폐기 또는 연결(예: 선정산 결과 행에서 연결) 기획 결정 필요.
- case3) 이력 0건 가맹점 : 진입 카드 미표시 → "차액 정산이 없는 상태"를 화면에서 확인할 수 없음 (기획 의도 여부 확인).
- case4) 환급·차감 외 유형이 응답에 포함 : 전체 건수 ≠ 환급 건수 + 차감 건수 → 통계 왜곡 (확정 — 집계 구조상).
- case5) 취소 상태 건 : 취소 필터가 없어 "전체"에서만 확인 가능.
- case6) 상태 필터 변경 : 통계도 함께 변동 — "대기" 필터의 통계는 대기 건 기준임을 오독하지 않도록 주석.
- case7) 미회수 이월 건 : 다른 선정산에서 발생해 이 선정산에 반영 — 원래 선정산 번호로 출처 추적 (가설).

### 6. 운영 확인 포인트
- 고아 화면 처리 방침 결정 — 폐기 또는 정식 연결(선정산 결과 행에서 진입 등). 화면설계서에는 "진입 경로 확인 필요" 명시.
- 깨진 "원래 선정산" 연결 수정.
- 서버 응답의 유형 범위("카드"만인지 8종 전부인지) 확정 후 통계 집계식 보강 — 통계 왜곡 여부가 여기에 달림.
- 취소 상태의 발생 조건·업무 의미 확인 + 취소 필터 추가 여부 검토.
- 화면 간 집계 기준 차이(필터 연동 통계 ↔ 서버 전체 기준)를 설계서에 명시.
- 선정산 축 화면의 상태 항목 부재(반영 여부 확인 불가) — 보강 후보.
- 개발용 기록 출력 잔존 — 정리 대상 (경미).
- "정산적용 수수료" ↔ "예상수수료" 라벨 통일 검토.

### 7. 연계 화면
| 관계 | 화면(한글명) | 내용 · 캡처 지시문 |
|---|---|---|
| 본 화면 | 선정산 차액 정산 내역(선정산 축) | 캡처: 통계 4카드 + 목록 + 유형 안내 상자 1장. 주소 직접 입력으로 진입 후 캡처 — 화면 내 진입 경로 없음을 주석 |
| 본 화면 | 가맹점 차액 이력(가맹점 축) + 상태 필터 변형 | 캡처: 통계 4카드 + 상태 필터 + 목록 1장, 완료·대기 필터 상태 각 1장 |
| 본 화면 | 가맹점 상세 — 차액 정산 현황 카드 | 캡처: 기본 3행 + 상세 통계 펼침 상태 각 1장 |
| 병렬 | 차액 정산 탭(주제 ①) | 같은 원장의 기간 축 뷰 — 선정산 축·가맹점 축과 삼각 대응 |
| 병렬 | 선정산 결과 탭 — 가맹점 펼침 | 반영/대기 차액 목록과 동일 데이터 계열 |
| 병렬 | 매출 조회 — 차액 펼침 | 같은 가맹점 차액을 매출일 축으로 보는 화면 |
| 원천 | 카드사별 수수료 관리 계열 | 정산적용(예상) 수수료의 원천 요율 관리 — 쟁점 1 관련 |
| 가맹점 측 | 가맹점 웹 > 예상 지급 차액 계열 | 동일 건의 가맹점 노출 화면 — 내부 "차액 정산" ↔ 노출 "예상 지급 차액" 매핑 (확인 필요 · 쟁점 4) |

### 8. 【미확정】
- 선정산 축 화면의 의도된 진입 동선 존재 여부 (알림·외부 연결 등).
- 선정산 축 화면의 접근 권한 정책 (가드 부재).
- 가맹점 축 화면의 "카드" 한정 여부 — 서버가 카드 유형만 내려주는지 8종 전부인지. 통계 왜곡 여부 직결.
- 취소 상태의 발생 조건·업무 의미.
- 정산적용 수수료의 요율 근거 — 카드사별 수수료 관리 값과의 관계 (쟁점 1).
- 내부 "차액 정산" ↔ 가맹점 노출 "예상 지급 차액"의 용어 매핑 (쟁점 4).
- 진입 카드 숨김 규칙(이력 0건 시)의 기획 의도.

```
[차액 원장]
  발생 원인: 매입 확정 차이 · 예상매출 대사 · 취소 환수 · 미회수 이월
    ├→ 차액 정산 탭 (기간 축 — 요약 지표·차트·하위 탭)          … 주제 ①
    ├→ 선정산 차액 정산 내역 (선정산 1건 축 — 고아 화면)          … 주제 ⑤
    ├→ 가맹점 차액 이력 (가맹점 축 — 진입: 가맹점 상세 카드)      … 주제 ⑤
    └→ 반영 완료 시 → 선정산 결과 "정산 반영 수수료 차액"
                    → 정산 상세 "배분 수수료 차액"

[수수료 원장]
  정산 배치 확정 시 생성 (건별: 채권매입·시스템 이용료 / 배치: 이체 수수료)

    ├→ 정산 시뮬레이션 원장 표 (사전 계산 — 저장 없음)             … 주제 ④
    └→ 공통 표시 보정: 전달금 재귀속 (표기만 이동, 배분액 불변)     … 주제 ④

[이체 기록]
  선정산 지급·수동 지급·바로이체 = 지급 묶음 / 락계좌 자금 옮김 = 회수(출금+입금 짝)
    └→ 이체 내역 탭 (요약 지표 = 실패 상태만 / 날짜 머리글 = 비성공 잔여) … 주제 ②

[미정산 누락 건]
  배치 완료 후 늦게 도착한 매출 건 (전 기간 모집단 · 관리자 전용)
    └→ 누락 추적 배너 → 미리보기(무부작용) → 바로이체(실제 이체) / 이미지급(기록만) … 주제 ③
        → 선정산 결과 제외액·가감 표시 / 정산 상세 배치 표식 / 이체 내역 기록
```
