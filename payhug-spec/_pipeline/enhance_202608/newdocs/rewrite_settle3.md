# 정산 현황 정책서 원고 (1/2) — 선정산 결과 · 정산 상세 · 계산서 발행

- 작성 기준: 어드민 참고 화면 2026년 8월 10일자 확인분. 화면 속 금액·요율은 목데이터 — 구조 확인용, 값 인용 금지.
- 표기 원칙: 모든 서술은 【확정】·【가설】·【확인필요】·【미확정】 구분. 별도 태그 없는 서술 = 확정.
- 여섯 개념(미지급금 · 선정산 제외금액 · 바로이체 · 과지급 · 미회수금 · 환급) 분리 유지. '차액' 네 용어 혼용 금지. '회수' 세 갈래 구분.
- 개발 근거 대응표는 별도 부록(비노출, 같은 폴더 추적 문서)에 보관 — 본문에는 개발 용어 미기재.

---

## 탭 1. 선정산 결과

### ① 한 줄 정의

- 정산 현황 여섯 탭(선정산 결과 · 정산 상세 · 차액 정산 · 이체 내역 · 계산서 발행 · VOC 대응)의 첫 번째이자 기본 탭. 매출일 단위로 실행된 선정산의 결과 — "얼마를, 왜 그만큼 지급했는가" — 를 기간 합계 → 날짜 → 가맹점 → 거래 건 순으로 내려가며 확인하고, 뒤늦게 도착해 누락된 건을 처리(바로이체 · 이미지급)하는 화면.

### ② 용어

| 용어 | 정의 |
|---|---|
| 선정산 대상액 | 선정산 실행에 실제로 들어간 금액 = 채권 매입 금액 |
| 선정산 제외액 | 선정산 대상액 − 정산 반영액. 음수 = 제외(실질은 바로이체 건) / 양수 = 확인 필요 잔차 |
| 바로이체 | 선정산을 거치지 않고, 수수료만 제외한 순 지급액 전액을 실제 이체하는 처리 |
| 이미지급 | 실제 이체 없이 장부에만 지급 완료로 기록하는 처리. 별도 항목으로 분리되어 선정산 제외액에 합산되지 않음 |
| 선정산 수수료 | 채권매입 수수료 + 시스템 이용료 + 이체 수수료 + 차액 대상 수수료의 합 |
| 순 지급액 | 총 매출액 − 총 수수료 |
| 오프라인 차감 | 만나서 결제 등 현장 결제 건을 지급액에서 차감하는 항목 |
| 플랫폼 차감 / 플랫폼 환급 | 배달 플랫폼 정산 조정 재무 항목을 부호로 가른 두 묶음 — 차감(광고비 등 플랫폼이 회수) / 환급(플랫폼이 가산 + 우리가게클릭 순환급) |
| 검증 차이 | 실제 지급액 − 지급 산식 결과. 0이 아니면 확인 필요 |
| 미정산 누락 | 선정산 실행이 끝난 뒤 뒤늦게 도착해 선정산에서 빠진 매출 건 |
| 수수료 면제 | 수수료를 기록만 하고 실제로는 차감하지 않는 가맹점 우대 처리 |
| 예상 매출 | 확정 전 추정 매출. 예상값 / 확정값 / 실제 지급값은 항상 구분 |

**'차액' 네 용어 — 기준·부호가 전부 달라 혼용 금지.**

| 용어 | 정의 | 기준 시점 | 부호 규약 |
|---|---|---|---|
| 거래 수수료 차액 | 정산 반영액 − 순 지급액 = 실제 수수료 − 예상 수수료 | 거래일 | [+] 양수 = 추가 차감(빨강) / [−] 음수 = 환급(파랑) |
| 정산 반영 수수료 차액 | 해당 날짜의 지급이 함께 반영한 과거 수수료 차액 보정 | 지급일 | [+] 양수 = 환급 가산 / [−] 음수 = 차감 |
| 배분 수수료 차액 | 이해관계자 배분에 실린 수수료 차액 (탭 2 참조) | 정산 묶음 배분 | ± |
| 차액 대상 수수료 | 차액 보정분에 대해 붙는 수수료 — 선정산 수수료의 구성 요소 | — | ± |

- 주의: 거래 수수료 차액은 카드 장부의 수수료 차액(예상 − 실제)과 **값은 같고 부호가 반대**. 배달은 장부에 차액을 남기지 않아 이 값에서만 드러남.

**'회수' 세 갈래 — 전부 다른 개념, 문서·화면에서 반드시 구분.**

| 갈래 | 뜻 |
|---|---|
| 플랫폼 차감 회수 | 광고비 등 플랫폼 조정 원금을 정산액에서 거둬 가는 것 (이 화면의 회수) |
| 과지급 회수 | 지급 완료 후 음수가 된 건을 가맹점에서 돌려받는 것 |
| 매출 회수 | 가맹점 수금 계좌의 매출을 모계좌로 옮기는 자금 이동 (어드민 이체 업무) |

### ③ 정책

**노출 규칙**

- 여섯 탭 중 정산 상세 · 계산서 발행 · VOC 대응은 내부 관리자 전용. 총판 · 영업조직 등 외부 계정은 선정산 결과 · 차액 정산 · 이체 내역 세 탭만 노출.
- 본 탭은 총판 계정에도 노출. 단 화면 안의 '미정산 누락 추적' 배너와 바로이체 · 이미지급 처리는 내부 관리자 전용.
- 페이지 진입 시 이번 달 1일~오늘 범위로 자동 조회. 이전 정산 주소로 접근해도 본 화면으로 자동 이동.

**화면 구성 원칙**

- 공통 필터: 기간 미리 지정 7종(오늘~최근 3개월, 기본 = 이번 달) + 시작 · 종료일 + 가맹점명 · 사업자번호 부분 일치 검색 + 에이전시 선택(선택지는 조회 결과에서 동적 추출, '미지정' 포함).
- 가맹점 · 에이전시 필터는 화면에서 거르는 방식 — 행만 거르지 않고 일별 · 전체 합계를 화면에서 다시 집계.
- 우측 상단: 매출일 정렬 전환(기본 최신순) + 엑셀 내려받기(다섯 시트).
- 요약 카드 여덟 장(순서 고정): 총 매출액 → 총 수수료(카드 · 배달 분해) → 순 지급액 → 선정산 제외액 → 선정산 대상액 → 선정산 수수료(네 종 분해) → 정산 반영 수수료 차액(부호별 색) → **선정산 지급액(강조, 산식 부제 병기)**.
- 수수료 차액 정산 배너: "오늘 반영 ○건(±금액) / 다음 반영 예정 ○건(±금액)" — 반영 · 대기 건이 있을 때만 노출.
- 미정산 누락 추적 배너(내부 전용): 빨간 배너에 가맹점 수 · 건수 · 금액 요약. 펼치면 가맹점 > 날짜 > 거래 3단 목록 + 선택 → [미리보기] [바로이체] [이미지급(기록만)].
- 날짜 묶음(접이식): 머리글 "○일 정산(○일 매출 기준)" + '예상 매출 ○건 포함' 배지 + 우측 아홉 단 분해(매출 → 수수료 → 선정산 제외 → 선정산 대상 → 선정산 수수료 → 오프라인 차감 → 플랫폼 차감 → 플랫폼 환급 → 선정산).
- 가맹점 행 열 컬럼: 가맹점 / 카드 매출 / 배달 매출 / 수수료 / 순 지급액 / 선정산 제외액(잔차 시 점선 말풍선) / 선정산 대상액 / 선정산 수수료(마우스 올림 분해 + 면제 배지) / 선정산 지급액(하단 부가 줄: 이미지급 · 오프라인 차감 · 정산 반영 수수료 차액 · 플랫폼 차감(구성 말풍선) · 플랫폼 환급 · 검증 차이) / 상태.
- 행 펼침(건별 상세): 거래 열두 컬럼(매출원 / 승인 · 주문번호 / 카드사 · 앱 / 매출액 / 수수료 / 수수료 유형 / 순 지급액 / 거래 수수료 차액 / 선정산 제외액 / 선정산 대상액 / 매입 상태 / 정산 상태) + 플랫폼 차감 내역 + 플랫폼 환급 내역 + 다음 반영 예정 차액 목록.

**처리 원칙**

- 조회는 한 번의 요청으로 기간 전체 요약 + 일별 자료를 함께 수신. 내부 관리자는 미정산 누락 목록을 병행 조회.
- 행 펼침 시 해당 매출일 하루 범위로 건별 상세를 다시 조회. 한 번에 한 행만 펼침, 같은 행 재클릭 시 접힘.
- 상세 조회 응답은 전체 보존 — 항목을 골라 담는 방식은 금지(골라 담다가 서버 신규 항목이 화면에서 조용히 사라진 전력).
- 미정산 누락 처리: 선택 건 → 바로이체(실제 이체 실행) 또는 이미지급(장부 기록만). 미리보기는 이체 · 기록 어느 쪽도 일으키지 않음. 처리 후 누락 목록 + 요약 자동 재조회.
- 이체 묶음 규칙: 같은 가맹점의 여러 거래일 누락은 **합산해 1회 이체**하되, 장부는 거래일별로 나눠 기록.
- 바로이체는 실제 자금이 나가는 조작 — 경고 확인 창 + 미리보기를 반드시 거침.
- 엑셀 다섯 시트: 선정산 요약(스물두 컬럼, 화면 필터 반영) / 건별 상세(기간 전체 재조회 — 요약 시트와 모집단이 다름을 시트에 명시) / 플랫폼 차감 / 플랫폼 환급 / 미정산 누락.

**부호·상태 규약**

- 선정산 제외액: [−] 음수 = 제외(실질 바로이체) / [+] 양수 = 확인 필요 잔차. 엑셀 머리글에도 "(−제외 / +확인 필요)" 명기.
- 거래 수수료 차액: [+] 추가 차감(빨강) / [−] 환급(파랑). 정산 반영 수수료 차액: [+] 환급 가산 / [−] 차감.
- 가맹점 행 상태 세 종: 이체완료 · 이체대기 · 정산전. 건별 정산 상태 여섯 종: 선정산 · 대기 · 바로이체 · 이미지급 · 선정산차감 · 미대상.
- 플랫폼 조정의 '정산 미반영' 배지는 서버가 내려주는 반영 대상 여부 값이 '아님'일 때만 노출 — 화면 글자 비교로 판정하는 방식은 폐기.

### ④ 계산식

**산식 1. 선정산 지급액** — 요약 카드 부제와 검증 차이 안내가 같은 항 목록을 공유. 0원인 가감 항목은 표기에서 생략.

> 선정산 지급액 = 선정산 대상액 − 선정산 수수료 + 정산 반영 수수료 차액 − 오프라인 차감 − 플랫폼 차감 + 플랫폼 환급

- (예시) 1,000,000 − 11,300 + 2,000 − 30,000 − 50,000 + 5,000 = 915,700원

**산식 2. 순 지급액** — 취소 건은 순 지급액에서 차감(카드 부제에 안내).

> 순 지급액 = 총 매출액 − 총 수수료

- (예시) 1,200,000 − 40,000 = 1,160,000원

**산식 3. 선정산 제외액**

> 선정산 제외액 = 선정산 대상액 − 정산 반영액

- (예시) 900,000 − 950,000 = −50,000원 → 바로이체로 5만 원이 선정산에서 제외됐다는 뜻
- 이미지급은 별도 항목이라 제외액에 들어가지 않음. 제외액 ≠ −바로이체이면 잔차 존재 → 주황 안내 + 점선 말풍선.

**산식 4. 선정산 수수료 네 종 분해** — 명칭은 한 곳에서만 정의(차액 대상 수수료는 '차액대상' 배지, 0이 아닐 때만 표시).

> 선정산 수수료 = 채권매입 수수료 + 시스템 이용료 + 이체 수수료 + 차액 대상 수수료

- (예시) 9,000 + 2,000 + 300 + 0 = 11,300원
- 수수료 면제 가맹점은 금액을 기록만 하고 실제 차감하지 않음('면제' 배지 + 말풍선 안내).

**산식 5. 거래 수수료 차액**

> 거래 수수료 차액 = 정산 반영액 − 순 지급액 = 실제 수수료 − 예상 수수료

- (예시) 실제 수수료 23,000 − 예상 수수료 21,500 = +1,500원 → 추가 차감(빨강)

**산식 6. 검증 차이**

> 검증 차이 = 실제 지급액 − 산식 1의 계산 결과

- (예시) 실제 지급 0원 − 산식 결과 −372,300원 = +372,300원 (차감이 지급액을 초과해 0원 처리 후 이월된 경우)

**규약 1. 플랫폼 차감 구성 금액의 한계** — 행 하단 '플랫폼 차감' 구성 말풍선의 항목별 금액은 조정 **원금**. 정산 묶음별 회수액은 따로 저장되지 않아, 한 조정이 여러 묶음에 걸쳐 회수되면 원금 합 ≠ 실제 회수 총액. 총액만을 진실로 두고, 어긋나면 "원금 기준 — 부분 회수로 총액과 다름"을 밝힘. 항목이 비면 '구성 미상' 표기.

- (예시) 구성 원금 합 80,000원 ↔ 차감 총액 50,000원 → 부분 회수 안내 노출

### ⑤ 케이스·예외

- case1) **제외액이 양수로 남는 경우** : 정산 후 취소 · 예상 매출 선정산 등으로 대상액 기록 시점과 지급 기록이 어긋난 잔차 → 주황 안내 + 점선 말풍선, '확인 필요' 처리.
- case2) **잔차 상쇄** : 제외 건 존재 판정은 합계가 아니라 가맹점별 각각 판정 — 가맹점 간 잔차가 상쇄되어 합계가 0이어도 제외 건은 존재. 단 한 가맹점 안에서 잔차 성분끼리 상쇄되면 안내가 숨을 수 있음(수용한 한계).
- case3) **검증 차이가 0이 아닌 경우** : 값을 표시하고 '확인 필요'로 취급. 발생 시 처리 절차 · 책임 주체는 미정 【미확정】.
- case4) **차감 초과 이월** : 차감 합이 당일 지급액보다 크면 지급 0원 처리 + 남은 차감분은 다음 정산에서 차감 → 검증 차이 양수로 표출. 이월 반복 한도 규칙 없음 【미확정】.
- case5) **미정산 누락 — 이틀 규칙** : 이틀 이상 지난 누락 건은 선정산이 아니라 **수수료만 제외한 순 지급액 전액 이체**. 화면 동작은 확정이나 정책 근거 미정 【미확정】.
- case6) **입금 예정일 경과 배지** : 참고용 추정일 뿐 — 실제 입금 확인은 별도 판단(화면에 명시).
- case7) **바로이체 부분 실패** : "○건 이체 실패 — 재시도 필요" 상태가 남음 → 이체 내역 탭에서 대조 후 재시도.
- case8) **가맹점 필터 중 차액 배너** : 반영 · 대기 건수가 기간 전체 집계라 가맹점별로 분해 불가 → 배너 숨김, 금액만 반영분 합으로 복원.
- case9) **예상 매출 포함 날짜** : '예상 매출 ○건 포함' 배지 노출 — 예상값과 확정값 구분 유지.
- case10) **수수료 면제 가맹점** : 수수료를 기록만 하고 차감하지 않음 — 지급액 검산 시 면제 여부 먼저 확인.

### ⑥ 운영 확인 포인트

- 매일 : 선정산 지급액 카드 ↔ 실제 이체 결과(이체 내역 탭) 대조. 검증 차이 0 여부. 미정산 누락 배너 발생 여부와 당일 처리.
- 매일 : 제외액 양수 잔차(주황 안내) 발생 여부 — 발생 시 원인(정산 후 취소 등) 확인 후 기록.
- 수시 : **모집단이 다른 숫자 세 쌍** 오독 주의 — ⑴ 요약 시트(화면 필터 반영) ↔ 건별 상세 시트(기간 전체 재조회) ⑵ 정산 반영 수수료 차액(지급일 기준) ↔ 거래 수수료 차액(거래일 기준) ⑶ 행 펼침 건수(제외 건 포함 전량) ↔ 요약 건수. 두 값을 맞대면 반드시 "왜 다르지"가 나옴 — 문서 · 교육에 선제 안내.
- 수시 : 바로이체 실패 건 후속 처리 완료 여부. 이미지급 처리 시 증빙 확보(절차 【미확정】).
- 점검 : 같은 이름의 차감 항목이 화면에 따라 부호 규약이 다름(정산 상세의 차감액 = 크기만 / 본 화면 건별 상세 = 부호 포함) — 이중 음수 표기 오류 전력, 서버 규약 통일 여부 확인.

### ⑦ 연계 화면

**붙일 캡처** : 캡처 3907 「정산 현황 > 선정산 결과 탭」 전체 화면.
- 볼 곳 ① 상단 요약 카드 여덟 장 — 마지막 '선정산 지급액' 카드의 산식 부제(산식 1과 동일 문구).
- 볼 곳 ② 날짜 묶음 머리글의 "○일 정산(○일 매출 기준)" 이중 날짜 — 지급 캘린더 【미확정】의 실데이터 노출면.
- 볼 곳 ③ 가맹점 행의 선정산 지급액 하단 부가 줄 — 가감 항목과 검증 차이 표기.

### ⑧ 미확정

- 【미확정】 **수수료율(충돌 대장 1번)** : 본 화면은 금액 분해만 보여주고 요율을 노출하지 않음. 정책 요율 자리는 있으나 미사용. 1% / 0.604% / 0.6+0.11+0.1% / 0.25% 병존 상태 그대로 — 어느 값도 채택 금지.
- 【미확정】 **지급 캘린더(충돌 대장 2번)** : "정산일 ↔ 매출일" 분리 표기로 며칠 뒤 지급인지 데이터로만 드러나고 규칙은 미확정. 미정산 누락의 이틀 규칙(case5)도 정책 근거 미정.
- 【미확정】 **예상 지급 차액(충돌 대장 4번)** : 가맹점 화면 명칭 '예상 지급 차액'과 본 화면 '차액' 네 용어(특히 거래 · 정산 반영 수수료 차액)의 대응 정의 미확정 — 값 · 대응 단정 금지.
- 【가설】 **이미지급 증빙** : "이미 수동 이체된 건으로 간주해 장부에만 지급 완료 기록"(확인 창 문구) — 증빙 · 대사 절차는 운영 관행 추정, 확인 필요.
- 【미확정】 **검증 차이 처리 절차** : 정책서에 없는 감시값(여섯 개념 어디에도 대응 안 됨) — 발생 시 처리 절차 · 책임 주체 미정. 미확정 질문 대장 등재 후보.
- 【미확정】 **이월 반복 한도** : 차감 초과 이월(case4)이 반복될 때의 한도 · 중단 규칙 없음.

## 탭 2. 정산 상세

### ① 한 줄 정의

- 정산 현황 여섯 탭의 두 번째, 내부 관리자 전용. 가맹점×매출일 단위의 정산 묶음 한 건을 골라 "이 돈이 참여자별로 어떻게 나뉘었고, 수수료는 누가 걷어 누구와 나눴는가"(이해관계자 배분 + 수수료 장부)를 검증하는 화면.

### ② 용어

| 용어 | 정의 |
|---|---|
| 정산 묶음 | 가맹점×매출일 단위의 선정산 실행 한 건. 상태 = 정산완료 · 진행중 · 대기 |
| 배분 | 정산 묶음 금액을 이해관계자별로 나눈 지급 집계(채권매입 · 시스템 이용료 · 이체 수수료 · 배분 수수료 차액 · 배분 총액) |
| 수수료 장부 | 수수료 유형×참여자별로 매출 · 원가 · 수익 · 부가세 · 전달금 · 순수익 · 배분액을 분해한 기록 |
| 실 지급 | 가맹점 몫 배분 총액 — 수수료 · 차감 · 환급 반영이 끝난 **확정 이체액**. 계산식이 아님 |
| 전달금 | 참여자가 계산상 거쳐 다른 참여자에게 지급하는 금액 — 재귀속 표시 보정의 대상 |
| 납부자 | 수수료를 부담하는 쪽. 배분이 음수인 시스템 이용료 · 이체 수수료 행은 가맹점이 납부자 |
| 차감액(조정 원금) | 플랫폼 조정의 원금 전액. 크기로 기록, 표시할 때 − 접두 |
| 정산 묶음 회수액 | 이 묶음이 실제로 회수한 플랫폼 조정 몫. 양수 크기 |
| 미회수 차액 이월 | 환수가 당일 지급액을 초과할 때 초과분을 다음 정산에서 차감하는 처리 |
| 부채상계 | 배분 상태값의 하나 — 발동 조건 미정 【가설】 |
| 기록용 | 실제 이체 없는 배분 기록(이미지급 묶음의 배분) |
| 역할 여덟 종 | 투자자 · 페이허그 · 상위파트너 · 하위파트너 · 영업조직 · 상위영업 · 하위영업 · 가맹점 |

- '회수' 구분 재확인: 본 탭의 회수 = **플랫폼 조정 원금 회수** — 과지급 회수와도, 매출 회수(수금 계좌→모계좌 자금 이동)와도 별개.

### ③ 정책

**노출 규칙**

- 내부 관리자 전용 — 관리자가 아니면 탭 버튼 자체가 노출되지 않음. 총판은 선정산 결과 · 차액 정산 · 이체 내역 세 탭만.
- 탭 최초 진입 시 자동 조회, 이후 좌측 목록에서 정산 묶음 클릭 → 우측 상세 로드.

**화면 구성 원칙**

- 좌 3분의 1 — 정산 목록: 정산일 기준 날짜 묶음(정산일 없는 묶음은 "○일 매출(미정산)" 표기). 묶음 머리글 = 가맹점 수 · 건수 · 합계. 행 = 가맹점명 + 에이전시 배지 + 바로이체 · 이미지급 배지 + 상태(정산완료 · 진행중 · 대기) + 매출일 · 건수 · 금액.
- 우 3분의 2 — 묶음 머리글: "가맹점 | ○일 정산(○일 매출 기준) | ○건" + 총액 | 오프라인 차감 | 플랫폼 차감 | 배분 수수료 차액 | **실 지급** — 값이 있는 항목만 병기.
- 조건부 구역 세 종(해당 자료가 있는 묶음에서만): ⑴ 미회수 차액 이월 안내(주황) ⑵ 현장 결제 차감 내역 표 ⑶ 플랫폼 차감 내역 표(매출원 / 구분 배지 / 정산일 / 기간 / 차감액 / 회수액 / 상태 / 부가세 + 회수액 합계).
- 이해관계자 배분 요약: 참여자(법인 · 사업자 배지) / 역할 / 채권매입 / 시스템 이용료 / 이체 수수료 / 배분 수수료 차액 / 배분액 / 상태(이체완료 · 이체대기 · 이체실패 · 부채상계 · 기록용). 기록용은 최하단 정렬, 표 하단 합계.
- 수수료 장부 상세: 접이식 세 층 — 시스템 이용료 건별 합산 → 거래별 장부(카드 · 배민 배지, '예상' 배지) → 묶음 단위 장부(이체 · 차액 수수료). 각 표 컬럼: 참여자 / 역할 / (유형) / 매출 / 원가 / 수익 / 부가세 / 순수익 / 배분액 + 소계.
- 정산일 정렬 전환 + 엑셀 네 시트(정산 목록 / 이해관계자 배분 / 가맹점별 이해관계자 합계 / 수수료 장부 상세).

**처리 원칙**

- 두 단계 조회: 목록 먼저 → 묶음 선택 시 배분(오프라인 · 플랫폼 차감 · 이월액 포함) 로드 → 이어서 수수료 장부 로드.
- 가맹점 · 에이전시 필터는 화면 거름(가맹점명 · 가맹점 번호 · 사업자번호 부분 일치).
- 시스템 이용료는 거래별 장부를 참여자 단위로 화면에서 합산해 묶음 요약으로 노출 — 표시용 합산.
- 엑셀 일괄 조회는 배분 · 장부 중 한쪽이 실패해도 나머지 시트는 생성.

**표시 보정 규약 — 전달금 재귀속**

- 하위파트너가 수익 0의 형식 참여(폭포수 정책)일 때 전달금 · 순수익을 상위파트너로 옮겨 **표시**. 배분액은 불변 — 표시 보정일 뿐 장부 원본 데이터는 그대로. 채권매입 · 배분 수수료 차액 유형에만 적용.

**부호·상태 규약**

- 음수 배분의 시스템 이용료 · 이체 수수료 장부 행 = '납부 → 수취자' 배지(가맹점이 납부 주체). 전달금 양수 행 = "(수취자) 지급 ○원" 전달금 배지.
- 차감액 = 조정 원금 크기(표시 시 − 접두) / 회수액 = 이 묶음 몫 양수 — 두 열은 서로 다른 값(산식 5).

### ④ 계산식

**산식 1. 장부 한 행의 구조** — "이 수수료를 누가 걷어 누구와 나누는가"의 분해.

> 장부 한 행 = 매출 / 원가 / 수익 / 부가세 / 전달금 / 순수익 / 배분액

- (예시) 매출 10,000 / 원가 6,000 / 수익 4,000 / 부가세 400 / 전달금 1,000 / 순수익 3,400 / 배분액 4,400원

**산식 2. 배분 폭포수**

> 채권매입 · 배분 수수료 차액 = 하위 → 상위 폭포수 배분 / 시스템 이용료 · 이체 수수료 = 가맹점 납부(음수 배분), 페이허그 · 파트너 등이 수취

- 하위파트너 몫에서 영업조직 전달금이 나가고, 하위가 형식 참여(수익 0)면 실제 지급 주체는 상위파트너.
- (예시) 채권매입 수수료 9,000원: 하위파트너 몫 9,000 중 전달금 2,000은 영업조직으로, 남은 7,000이 하위 순수익

**산식 3. 실 지급** — 계산식이 아니라 확정값. 구판의 "총액 − 차감" 즉석 계산은 폐기.

> 실 지급 = 가맹점 몫 배분 총액 그대로(수수료 · 차감 · 환급이 모두 반영된 확정 이체액). 총액과 다를 때만 병기

- (예시) 총액 1,000,000원 / 실 지급 915,700원 → 두 값 병기

**산식 4. 머리글의 배분 수수료 차액**

> 배분 수수료 차액(머리글) = 가맹점 역할 배분에 실린 수수료 차액의 합

- (예시) +1,500 + (−500) = +1,000원
- 카드 수수료 예상 ↔ 실제 차액의 환급 · 차감이 실제 이체액에 포함되므로 별도 표기.

**산식 5. 차감액 · 회수액 규약** — 플랫폼 차감 표의 두 금액 열은 서로 다른 값.

| 열 | 뜻 | 규약 |
|---|---|---|
| 차감액 | 조정 **원금** 전액 | 크기로 기록, 표시 시 − 접두. 부분 회수 이월 행은 이 묶음 회수액보다 큼. 이 열에는 합계를 두지 않음(원금이라 회수액과 애초 다른 값) |
| 회수액 | **이 묶음이** 실제 회수한 몫 | 양수 크기. 회수액 합 = 머리글 차감 합계는 특정 배포 시점 이후 회수분에만 성립 |

- (예시) 조정 원금 30,000원 중 이번 묶음 회수 12,000원 — 남은 18,000원은 다른 묶음에서 회수
- 회수액 < 차감액은 상태와 무관 — 다른 묶음이 나머지를 회수한 행은 '회수완료' 배지여도 이 묶음 몫만 보임.

**산식 6. 미회수 차액 이월**

> 차액 환수가 당일 지급액 초과 → 지급 0원 처리 + 미회수분은 다음 정산에서 차감. 이월액은 머리글 아래 주황 상자로 안내

- (예시) 지급 예정 200,000 − 환수 250,000 → 지급 0원, 이월 50,000원

**산식 7. 전달금 재귀속 조건**

> 같은 배분 사슬(수수료 유형×거래)에서 하위 수익 = 0이고 전달금 ≠ 0이면 → 하위: 전달금 0 · 순수익 = 수익+부가세 / 상위: 전달금 +해당액 · 순수익 −해당액으로 바꿔 표시

- (예시) 하위(수익 0 · 전달금 2,000) → 표시상 하위 전달금 0 · 순수익 0, 상위 전달금 +2,000 · 순수익 −2,000 (배분액은 불변)

### ⑤ 케이스·예외

- case1) **회수액 합계 ≠ 머리글 합계** : 과거분 소급 기록은 누적 전액이 마지막 묶음 하나에 몰려 기록됨 → 앞 묶음은 내역이 비고 마지막 묶음은 합계 초과 가능. 화면은 다를 때만 사유를 표시. 정상(소급)인지 비정상인지 운영자가 구분해야 함.
- case2) **'회수완료' 배지인데 회수액 < 차감액** : 다른 묶음이 나머지를 회수한 정상 케이스 — 이 묶음 몫만 표시된 것.
- case3) **미회수 차액 이월 발생** : 지급 0원 처리 + 주황 안내 + 다음 정산에서 차감(탭 1 case4와 동일 사건의 배분 측 표현).
- case4) **기록용 배분** : 실제 이체 없음 — 합계에 섞이면 이중 지급으로 오독. 최하단 정렬로 분리하지만 **표 하단 합계에는 포함**됨.
- case5) **미정산 묶음** : 정산일이 없어 매출일로 묶이고 "(미정산)" 표기 — 정산일 필터 · 정렬 기준이 섞이는 지점.
- case6) **엑셀 일괄 조회 한쪽 실패** : 빈 시트가 "자료 없음"인지 "조회 실패"인지 화면만으로 구분 불가 — 기록 확인 안내 필요.
- case7) **형식 참여 하위파트너(재귀속)** : 화면 · 엑셀 모두 재귀속을 반영 — 서버 원본 자료와 대조하는 감사에서는 차이가 남(표시 보정임을 문서화).

### ⑥ 운영 확인 포인트

- 매일 : 배분 상태 '이체실패' 존재 여부 → 이체 내역 탭 대조 · 재시도.
- 정기 : 회수액 합계 ↔ 머리글 합계 불일치 건 점검 — 소급 기록 여부 판단, 과거 기간 조회 시 빈 내역 · 초과 합계가 반복 노출되므로 고객 응대 문구 준비.
- 정기 : 기록용 배분이 합계에 포함된 표를 근거 자료로 쓸 때 이중 지급 오독 방지.
- 정기 : 미정산 묶음(정산일 없는 묶음) 잔존 여부 점검.
- 감사 대응 : 재귀속 · 건별 합산은 표시 보정 — 엑셀 '수수료 장부 상세'도 재귀속 반영이라 서버 원본과 차이 난다는 점 사전 문서화.

### ⑦ 연계 화면

**붙일 캡처** : 캡처 3905 「정산 현황 > 정산 상세 탭」(묶음 미선택 상태).
- 볼 곳 ① 좌측 정산 목록의 바로이체 · 이미지급 배지 행 — 탭 1 누락 처리 결과의 유입 지점.
- 볼 곳 ② 날짜 묶음 머리글의 가맹점 수 · 건수 · 합계 — 탭 1 날짜 합계와 대조하는 자리.

| 구분 | 화면(한글명) | 관계 |
|---|---|---|
| 같은 페이지 탭 | 정산 현황 > 선정산 결과 탭 | 원천 — 그 화면의 날짜×가맹점이 여기 정산 묶음 한 건. 바로이체 · 이미지급 건이 배지로 유입 |
| 같은 페이지 탭 | 정산 현황 > 이체 내역 탭 | 배분 상태의 실제 이체 기록 · 실패 확인 |
| 같은 페이지 탭 | 정산 현황 > 계산서 발행 탭 | 엑셀 '가맹점별 이해관계자 합계'의 집계 단위(가맹점×참여자×역할)가 계산서 발행 단위와 동일한 사고방식 |
| 하위 상태 | 묶음 선택 후 우측이 채워진 상태 | 본 탭의 하위 상태 |
| 어드민 연관 | 정산 상품 관리(일반 · 다우) | 정산 상품(수수료 정책 · 참여자 · 상품 요율)이 배분 · 장부 규칙의 원천 |
| 어드민 연관 | 정산 시뮬레이션(단건 · 복수) | 같은 장부 구조로 배분을 사전 모의 |
| 어드민 연관 | 파트너 관리 | 참여자 명부 — 법인 · 사업자 구분 · 소개 정보 |
| 어드민 연관 | 모계좌 잔액 | 이체 자금의 원천 계정 |
| 가맹점 앱 대응 | (직접 대응 없음) | 내부 전용. 수수료 · 차감 결과는 미리 받는 돈 화면의 차감액 · 수수료 행으로만 노출 |

**데이터 흐름** : 선정산 실행 → 배분 집계 + 수수료 장부 생성 → **본 화면(검증)** → 이체 실행(이체 내역 탭) → 기간 합산(계산서 발행 탭의 근거).

### ⑧ 미확정

- 【미확정】 **수수료율(충돌 대장 1번)** : 배분율 · 요율은 본 화면에도 노출되지 않음. 정산 상품 관리의 상품 요율이 원천이나 정책 확정값 아님.
- 【미확정】 **지급 캘린더(충돌 대장 2번)** : 목데이터의 정산 마감 시각(새벽 4시 30분대)과 운영의 하루 두 번(11시 30분 · 18시) 확정 체계의 관계 미확정.
- 【확인필요】 **장부의 원가(조달 원가)** : 채권매입 장부의 참여자별 원가 분해(투자자 조달 원가 구조 암시)의 산출 근거 · 투자자 수익 배분 구조는 시스템에 근거 없음.
- 【가설】 **부채상계** : 배분 상태값으로만 존재하고 발동 조건 없음 — 미지급금 · 미회수금 등 여섯 개념과의 대응 미정, 과지급 회수 정책과의 연결 확인 필요.
- 【확인필요】 **수수료 부담 주체의 계약 근거** : 시스템 이용료 · 이체 수수료의 가맹점 부담 구조(납부자 장부)와 계약 용어(과정산금 · 미정산금)의 대응은 임의 확정 금지 — 계약서 · 약관 명문 대조 필요.

## 탭 3. 계산서 발행

### ① 한 줄 정의

- 정산 현황 여섯 탭의 다섯 번째, 내부 관리자 전용. 기간의 정산 장부를 계산서 발행 단위(가맹점 × 발행 주체 × 항목)로 합산해 **면세 · 세금계산서 발행의 근거 자료를 만드는** 화면 — 발행 실행 기능은 없음(탭 이름도 '계산서 발행', 세금계산서 발행 아님).

### ② 용어

| 용어 | 정의 |
|---|---|
| 발행 단위 | 가맹점 × 발행 주체 × 항목의 기간 합산 한 행 |
| 발행 주체 | 계산서를 발행하는 참여자(페이허그 · 파트너 · 영업조직 · 별도 법인 등) |
| 항목 | 수수료 유형 — 채권매입 / 시스템 이용료 / 이체 수수료 |
| 기준액 | 요율 산정의 기준 금액(이체 수수료 행은 없음). 선정산 결과 탭 '선정산 대상액'과 같은 원천 |
| 요율 | 공급가액 ÷ 기준액 × 100의 **화면 역산 표시값** — 정책 요율 아님 |
| 공급가액 · 세액 · 합계 | 계산서에 기재되는 금액 세 가지 |
| 면세계산서 / 세금계산서 | 면세(채권매입) / 과세(시스템 이용료 · 이체 수수료) — 판정값은 서버 제공 |
| 이체 횟수 | 기간 내 이체 수수료가 발생한 정산 묶음 수 — "단가×○회" 표기의 분모 |
| 매출 유형 | 신용카드 / 배달앱 — 요약 표의 행 축 |

### ③ 정책

**노출 규칙**

- 내부 관리자 전용 — 관리자가 아니면 탭 버튼 · 내용 모두 미노출. 총판 미노출.
- 탭 최초 진입 시 자동 조회, 이후 기간 변경 후 조회 버튼.

**성격·처리 원칙**

- 발행 **실행** 기능 없음 — 발행 근거 자료 생성 전용. 실제 발행은 시스템 밖(홈택스 연동 또는 수기 — 【미확정】).
- 조회 한 번으로 서버가 발행 단위 합산과 면세 · 과세 판정까지 내려줌 — **화면은 표시 전용**(판정 로직 없음).
- 공통 필터 중 가맹점명 · 사업자번호 · 에이전시만 화면에서 거름.
- 엑셀 두 시트: 정산 요약(가맹점 × 매출 유형) / 계산서 발행 내역(가맹점 × 발행 주체 × 항목, 요율 포함).

**화면 구성 원칙**

- 상단 안내문 고정: "매출일 기준 ○기간 정산 장부를 계산서 발행 단위(가맹점 × 발행 주체 × 항목)로 합산한 자료. 채권매입은 면세 계산서, 시스템 이용료 · 이체 수수료는 세금계산서 대상." + 엑셀 내려받기.
- 가맹점 펼침 카드(기본 펼침): 가맹점명 · 사업자번호 · 에이전시 배지 + "선정산 대상 ○원" + "발행 합계 ○원". 클릭으로 접고 펼침.
- 매출 유형 요약 표: 구분(신용카드 · 배달앱) / 선정산 대상액 / 채권매입 수수료 / 시스템 이용료(부가세 포함) / 이체 수수료의 공급가 · 부가세 · 소계 — 이체 수수료는 가맹점 단위 정액이라 첫 행에 병합 표기.
- 참여자별 발행 내역 표: 발행 주체(법인 · 사업자 배지) / 항목 / 기준액 / 요율 / 공급가액 / 세액 / 합계 / 비고(발행 구분 배지). 정렬 = 채권매입 → 시스템 이용료 → 이체 수수료, 같은 항목 안에서는 공급가 큰 순. 표 하단 = 가맹점별 발행 합계.
- 비고 배지 두 종: 면세계산서 발행(초록) = 채권매입 / 세금계산서 발행(파랑) = 시스템 이용료 · 이체 수수료.

**부호·상태 규약**

- 면세 행 세액 = 0. 과세 행 세액 = 부가세. 기준액이 없거나 0이면 요율 "-" 표기.

### ④ 계산식

**산식 1. 발행 단위 합산** — 정산 상세 장부의 참여자별 몫이 계산서 단위로 그대로 드러남("계산서는 가맹점 단위로 발행"과 동일한 사고방식).

> 발행 한 행 = 가맹점 × 발행 주체 × 항목의 기간 합산

- (예시) ○○분식 × 페이허그 × 채권매입 — 한 달 합산 공급가 10,000원이 한 행

**산식 2. 요율 역산 표시** — 서버 금액에서 화면이 역산한 표시값. **정책 요율로 인용 금지.**

> 요율(%) = 공급가액 ÷ 기준액 × 100 — 소수 셋째 자리 반올림

- (예시) 10,040 ÷ 1,000,000 × 100 = 1.004% → 반올림 포함 근사치일 뿐, 계약 요율 아님

**산식 3. 이체 수수료 표기**

> 공급가 ÷ 이체 횟수가 정수면 "단가×○회", 정수가 아니면 "정액" 표기

- (예시) 2,700 ÷ 9회 = 300원 → "300원×9회"

**산식 4. 면세·과세 분해**

> 채권매입 = 면세 → 면세계산서(세액 0) / 시스템 이용료 · 이체 수수료 = 과세 → 세금계산서(세액 = 부가세). 합계 = 공급가액 + 세액

- (예시) 시스템 이용료 공급가 2,000 + 세액 200 = 합계 2,200원

**산식 5. 발행 합계**

> 발행 합계(카드 머리글 · 표 하단 동일) = 발행 행 합계의 총합

- (예시) 채권매입 10,000 + 시스템 이용료 2,200 + 이체 수수료 330 = 12,530원

### ⑤ 케이스·예외

- case1) **요율이 어중간한 값(1.004% 등)** : 역산 · 반올림 근사 — 계약 요율로 인용하면 수수료율 혼선 가중. 자료 배포 시 역산 표시값임을 명기.
- case2) **기준액이 없거나 0** : 요율 "-" 표기(이체 수수료 행은 상시 해당).
- case3) **공급가 ÷ 이체 횟수가 정수가 아님** : "정액" 표기로 대체.
- case4) **기간 절단** : 매출일 기준 합산이라 월 마감 · 발행 주기와 어긋난 기간을 잡으면 합계가 실제 발행분과 달라짐. 마감일 개념이 화면에 없음.
- case5) **바로이체 · 이미지급 처리 건** : 누락 처리로 생긴 정산 묶음이 이체 횟수에 들어가는지 미확인 — "단가×○회" 검산이 어긋날 수 있음 【확인필요】.
- case6) **개인(비사업자) 참여자 행** : 발행 자료에 섞여 나올 수 있음(목데이터에 개인 영업사원 존재) — 발행 불가 대상의 구분 규칙 필요 【확인필요】.
- case7) **머리글 '선정산 대상'과 행 기준액** : 별개 값 — 원천이 같다는 주석은 있으나 상호 일치 여부 · 서버 정의는 확인 필요 【확인필요】.

### ⑥ 운영 확인 포인트

- 발행 주기마다(월 추정 — 주기 자체 【미확정】) : 조회 기간이 마감 · 발행 주기와 일치하는지 확인 후 자료 생성.
- 발행 전 : 발행 합계 ↔ 정산 상세 장부 배분액 대사 — 대사 절차 · 불일치 처리 규칙이 시스템에 없어 수기 수행 【미확정】.
- 발행 전 : 개인(비사업자) 참여자 행 걸러내기. 이체 수수료 "단가×○회" 검산.
- 자료 배포 시 : 요율이 역산 표시값 · 소수 셋째 자리 반올림임을 반드시 명기(요율 오인 방지).

### ⑦ 연계 화면

**붙일 캡처** : 캡처 3906 「정산 현황 > 계산서 발행 탭」.
- 볼 곳 ① 참여자별 발행 내역 표의 요율 열 — 역산 표시값(인용 금지)의 실제 모습.
- 볼 곳 ② "300원×○회"류 이체 수수료 셀 — 단가 표기 규칙의 노출면.
- 볼 곳 ③ 비고 열의 면세 · 세금계산서 배지 두 종.

| 구분 | 화면(한글명) | 관계 |
|---|---|---|
| 같은 페이지 탭 | 정산 현황 > 선정산 결과 탭 | '선정산 대상액' 카드("계산서 발행에 따른 채권 매입 금액")와 같은 원천값 — 탭 간 일대일 대조 |
| 같은 페이지 탭 | 정산 현황 > 정산 상세 탭 | 장부 = 발행 근거의 원천. 엑셀 '가맹점별 이해관계자 합계'와 동일한 집계 사고방식 |
| 같은 페이지 탭 | 정산 현황 > 이체 내역 탭 | 이체 횟수의 실체인 이체 실행 기록 |
| 어드민 연관 | 파트너 관리(소개 정보 포함) | 발행 주체 명부 — 법인 · 사업자 구분, 인감 · 사업자등록증 첨부 |
| 어드민 연관 | 정산 상품 관리 | 요율의 정책 원천(상품 요율) — 단 정책 확정값 아님 |
| 가맹점 앱 대응 | (직접 대응 없음) | 내부 전용. 법적 근거는 가맹점 전자계약(채권 매입 계약)으로 연결되고, 수수료는 미리 받는 돈 화면의 수수료 · 시스템 이용료 행으로 노출 |

**데이터 흐름** : 정산 장부(정산 상세 탭) → 서버 기간 합산 → **본 화면(발행 근거 자료 · 엑셀)** → 실제 발행은 시스템 밖(홈택스 연동 또는 수기 — 확인 필요).

### ⑧ 미확정

- 【미확정】 **수수료율(충돌 대장 1번)** : 화면 요율(1.004% · 0.402% 등)은 실서버 계약 자료의 역산 추정 — 정책 병존값(1% / 0.604% / 0.6+0.11+0.1% / 0.25%)과 어느 것도 일치 확정 불가. 목데이터 씨앗값(0.6 / 0.3 / 0.1% + 300원) · 실자료 · 정책 문서 세 곳이 서로 불일치. 해소 전까지 본 화면 값의 정책 인용 금지.
- 【미확정】 **이체 수수료 단가** : 목데이터 안에서도 정산 묶음당 300원 ↔ 하루 500원 불일치 — 실단가 미확정, 계약 · 정책 근거 대조 필요.
- 【확인필요】 **채권매입 면세의 세무 근거** : 금전채권 양수도 부가세 면제 해석으로 추정되나 시스템 밖 사안 — 세무 검토 이력 확인 필요.
- 【미확정】 **발행 실행 프로세스** : 실제 발행 방식(홈택스 연동 / 수기) · 발행 주기(월?) · 정정 발행 절차가 시스템에 없음 — 운영 프로세스 확인 필요.
- 【가설】 **비사업자 참여자 처리** : 법인 · 사업자 배지는 발행 가능 여부 판단 맥락으로 추정. 개인 참여자 처리(발행 불가 · 원천징수?)는 근거 없음 — 실무 확인 필요.
- 【미확정】 **정책서 등재** : '발행 단위(가맹점 × 발행 주체 × 항목)'와 면세 · 과세 두 분류는 현행 정책서(용어 · 정산 로직 문서)에 없는 개념 — 등재 후보. 계약 용어(과정산금 등)와의 대응 미확정, 임의 대응 금지.
