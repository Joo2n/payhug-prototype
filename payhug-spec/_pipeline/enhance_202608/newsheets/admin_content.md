## AD_SALES_DT_ADD_RESULT
- page_title: 매출 조회 상세 — 수기/엑셀 등록 결과 요약
- page_id: AD_SALES_DT_ADD_RESULT
- flow: 로그인 > 매출 조회 > 가맹점 상세 > [수동 매출 등록]·[엑셀 매출 업로드] > 저장 > 결과 요약
- note: 7/24 신설된 공용 결과 스텝(시트 빌드 이후 보강분) — 단건과 엑셀이 같은 요약 UI(성공/중복/실패/기타)로 결과를 보고한다.
- keynote: 8행
  1. 결과 스텝 전환 | 단건 등록은 입력→결과 2스텝, 엑셀은 업로드→미리보기→결과 3스텝의 마지막 화면. 등록 API가 성공 응답을 주면 자동 전환.
  2. 아이콘·제목 판정 | 실패 0건·주의 없음이면 초록 체크에 "등록/업로드 완료", 실패가 있으면 "(일부 실패)", 경고성 항목이 있으면 "(확인 필요)"에 앰버 경고 아이콘.
  3. 건수 3분류 | 성공(초록)/중복(앰버)/실패(빨강) 건수와 "전체 N건" 부제.
  4. 중복 안내 | 중복과 성공이 동시에 있으면 "중복은 기존 원장을 갱신한 건수입니다 (성공 건수와 겹칠 수 있습니다)" 부연 노출.
  5. 기타 블록 | 0건이 아닌 항목만 나열 — 취소 참조 행 / 선정산 완료 건 보호 / 이미 취소(되돌림 방지) / 미처리 취소 / 환수 생성 실패 5종. 경고 성격 2종(미처리 취소·환수 실패)은 앰버 표기.
  6. 배달 라벨 분기 | 데이터 유형이 배달(DELIVERY)이면 "이미 매입취소"·"매입 행으로 반영", 카드면 "이미 승인취소"·"승인 행으로 반영" — 같은 사유를 매출 유형별 용어로 표기.
  7. 경고 목록 | 서버가 내려준 경고 문구(warnings)를 앰버 리스트로 가공 없이 그대로 표시.
  8. 확인=재조회 | [확인] 버튼이나 배경 클릭으로 닫으면 매출 목록 재조회(onSuccess) 후 모달 종료 — 결과를 읽고 닫든 그냥 닫든 목록 갱신이 보장됨.
- deep_summary: 수기 매출 등록은 이미 지급된 선정산과 충돌할 수 있는 위험 작업인데, 이 화면이 "무엇이 반영되고 무엇이 보호·스킵됐는지"를 등록 직후 운영자에게 강제로 보여주는 안전판이다. 특히 '선정산 완료 건 보호'와 '이미 취소 되돌림 방지'는 지급 완료된 데이터를 수기 입력으로 덮지 않는다는 정책의 UI 표현이다. 단건·엑셀이 같은 요약 포맷을 쓰게 되면서(7/24 공용화) 운영자가 결과를 판독하는 기준이 입력 경로와 무관하게 통일됐다.
