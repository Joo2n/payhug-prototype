## MC_CONTRACT_SIGN_GATE
- page_title: 비대면 계약 — 매출 연동 게이트 모달
- page_id: MC_CONTRACT_SIGN_GATE
- flow: /contract(허브) 또는 직접 URL → /contract/terms 진입 직후 → (게이트 발동) → /contract/register-accounts 회송
- note: 비대면 계약(6단계) 진입 시 매출 연동 성공(ACTIVE) 계정이 0개면 차단 — edit·resign 흐름은 검사 생략, 확인 시 5단계(플랫폼 계정 등록)로 강제 회송
- keynote: (8행)

| 영역명 | 설명 |
|---|---|
| 배경 화면 | 계약 약관 동의(1/4단계) 화면 위에 모달이 덮임. 모달이 열려도 배경은 약관 화면 그대로 |
| 진입 검사 | 페이지 진입 직후 자동 실행. 사업자 목록 조회 → 대상 사업자의 연동 계정 조회 → 성공 계정 유무 판정 |
| 게이트 모달 | 오류 톤(type=error) 모달. 제목 "매출 연동을 먼저 완료해주세요" |
| 안내 문구 | "계약서 작성 전에 매출처(카드/배달앱) 연동 인증을 완료해야 합니다. 매출 연동 단계로 이동합니다." |
| 확인 버튼 | "매출 연동하러 가기" 1개. 누르면 /contract/register-accounts로 이동(replace), businessId 파라미터 유지 |
| 닫기 동작 | 배경·닫기(X)도 동일하게 register-accounts로 이동. 모달을 닫고 계약 화면에 머무를 방법 없음 |
| 예외 흐름 | ?edit=true(서류 수정) 또는 ?resign=true(재서명) 진입은 검사 자체를 건너뜀 — 이미 승인된 가맹점이므로 |
| 실패 시 통과 | 계정 조회가 실패(네트워크 등)하면 게이트를 강제하지 않음(fail-open). 주석상 서버 저장 API가 최종 방어선 |

- deep_summary: 매출 연동(스크래핑 계정)이 하나도 살아있지 않은 상태로 계약서를 쓰면 선정산 산정의 근거 데이터가 없는 계약이 만들어진다. 이 게이트는 그 상태를 계약서 작성 전에 잡아 5단계로 되돌리는 프론트 보조 장치이며, 정상 플로우(5단계에서 1개 이상 인증 후 진입)에서는 보이지 않고 직접 URL 진입·사후 연동 실패를 잡는 안전망으로 추정된다. 입금계좌 게이트(MC_CONTRACT_DEPOSIT_GATE)와는 검사 대상·문구·이동 목적지가 모두 다른 별개 모달이다.
- deep: (13행)

## MC_CONTRACT_BIZ_TYPEFIX
- page_title: 사업자등록증 업로드 — 사업자 유형 자동 교정 모달
- page_id: MC_CONTRACT_BIZ_TYPEFIX
- flow: /contract(허브) → [1] /contract/upload-business → 사진 첨부·OCR 분석 → (판정≠선택 시 모달) → /contract/confirm-business
- note: OCR로 읽은 사업자번호의 가운데 두 자리(80~89=법인) 규칙으로 개인↔법인을 판정 — 라디오 선택과 다르면 안내 후 자동 전환, 사용자가 거부할 방법 없음
- keynote: (8행)

| 영역명 | 설명 |
|---|---|
| 유형 라디오 | 개인사업자/법인사업자 2택, 기본값 개인. 단 최종 유형은 시스템 판정이 우선이라 사실상 참고 입력 |
| 사진 첨부 | 사업자등록증 사진 최대 3장. 첫 장 미리보기 + 나머지는 "+N장" 뱃지 표시 |
| 분석 실행 | "사진 첨부하기" → OCR 서버(FastAPI /ocr/analyze-business)로 전송, "사업자등록증을 분석하고 있어요" 전체 화면 오버레이 |
| 자동 판정 | OCR로 읽은 사업자번호의 4~5번째 자리(가운데 코드)가 80~89면 법인, 아니면 개인. 번호가 5자리 미만이면 OCR의 법인 플래그로 보조 판정 |
| 교정 모달 | 판정 유형 ≠ 라디오 선택일 때만 노출. 제목 "사업자 유형 확인", 완료 톤(type=success) — 오류가 아닌 자동 처리 안내 |
| 문구 분기 | "사업자번호 확인 결과 법인사업자입니다. 법인사업자로 자동 변경하여 진행합니다." / 개인이면 개인 문구 |
| 확인·닫기 | 확인 버튼·배경 닫기 모두 교정된 유형으로 다음 화면 이동. 원래 선택을 유지하거나 재업로드로 되돌아가는 분기 없음 |
| 다음 화면 | confirm-business로 OCR 필드(번호·상호·대표자·주소 등)+entity(판정 유형)를 쿼리로 전달. 법인이면 법인등록번호 등 추가 필드 동봉 |

- deep_summary: 사업자 유형(개인/법인)은 확인 화면의 입력 필드 구성(법인 +4필드), 국세청 검증, 이후 계약서 서식까지 갈라놓는 분기 키인데, 이 모달은 그 판정 권한을 사용자 선택이 아니라 사업자번호 규칙에 둔다는 선언이다. 사용자가 거부할 수 없는 강제 교정이므로, 판정 규칙(가운데 코드 80~89)이 국세청 분류와 완전히 일치하는지가 이 화면의 신뢰도 전부를 좌우한다. 번호 인식 실패 시 기본값이 '개인'으로 흐르는 경로도 함께 봐야 한다.
- deep: (13행)
