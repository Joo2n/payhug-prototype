| 갱신 | 2026-09-06 |

**배경·문제**

선정산 이후 취소건 회수 로직 파악에 따라 의사결정된 내용을 개발 로직에 반영한다.

**결정된 것**

원칙: 채권매입 후 발생한 원거래 취소에 따른 원금 손실은 가맹점이 부담하고, 이미 발생한 채권매입수수료는 환급하지 않는다.

티켓에 적힌 예시 그대로.

| 항목 | 금액 |
|---|---|
| 순지급액 | 10,000원 |
| 채권매입수수료 | 100원 |
| 시스템이용료 | 11원 |
| 이체 수수료 | 330원 |
| 선정산 지급액 (미리받는돈) | 9,889원 |
| 회수해야할 금액 | 10,000원 (전액 회수) |

이체수수료는 취소와 관계없이 부담주체가 일별 발생비용을 부담한다.

가맹점이 실수령한 금액은 9,889원인데 회수액은 10,000원이므로, 차액 111원(채권매입수수료 100 + 시스템이용료 11)은 취소가 나도 가맹점이 부담한다.

**미결**

- 이체수수료 330원의 부담 주체가 누구인지 티켓에 이름으로 적혀 있지 않다 `확인 필요`
- 회수 실패 시(락계좌 잔액 부족·가압류 등) 처리 경로가 이 티켓에 없다 `확인 필요` — PAYHUG-251·PAYHUG-250 의 부분 회수 알림과 연결 지점

**정책서 반영 지점**

- 03 정산로직: 취소 발생 시 회수액 산식 = 순지급액 전액. 수수료 비환급 원칙
- 04 예외케이스: 「지급 후 음수 = 회수 검토」 계열에 원거래 취소 케이스의 회수 금액 기준을 확정 문단으로 등재
- 02 용어·상태값: 순지급액 / 채권매입수수료 / 시스템이용료 / 이체수수료 / 선정산 지급액(미리받는돈) 5개 항목의 상하 관계를 수식으로 고정

### PAYHUG-186 — [기획] 플랫폼별 선정산 대상 구분 표시

| 항목 | 값 |
|---|---|
| 상태 | 진행 중 (스토리) |
| 라벨 | 어드민_관리자 |
| 연결 | 하위작업 PAYHUG-259 [개발] 일부 플랫폼 선정산 시 정산상태 분류 (진행 중) / relates PAYHUG-185 [운영] 플랫폼별 일부 선정산 시 정산상태 분류 기획 요청 (진행 중) / relates PAYHUG-188 [이슈] 어바웃피자&비어 용죽비전점 락계좌 출금이체 실패 (Backlog) |
| 갱신 | 2026-09-05 |

**배경·문제**

다란채는 카드와 배달의민족만 선정산 중이고 쿠팡이츠는 선정산 계획이 없는 미개시 상태인데, 가맹점 측 테스트 등록으로 매출이 잡혔다. 금액은 제외되는데 상태 표기는 선정산 대상으로 나온다.

- 쿠팡이츠 2건 8,607원 = 가맹점 [선정산 제외액] -8,607원과 일치
- 나머지 4건 26,477원 = [선정산 대상액] 26,477원과 일치

| 거래 | 매출액 | 선정산 대상액 | 매출 상세 `선정산대상` | 정산현황 `정산 상태` |
|---|---|---|---|---|
| 쿠팡이츠 | 4,000원 | 없음 | 대상 | 선정산 |
| 쿠팡이츠 | 13,500원 | 없음 | 대상 | 선정산 |
| 롯데카드 | 4,000원 | 3,984원 | 대상 | 선정산 |
| 신한카드 | 11,000원 | 10,956원 | 대상 | 선정산 |
| 삼성카드 | 8,000원 | 7,968원 | 대상 | 선정산 |
| 배달의민족 | 4,000원 | 3,569원 | 대상 | 선정산 |

원인은 거래의 선정산 대상 여부가 가맹점 단위 선정산 여부를 따르는 것. 가맹점이 선정산 중이면 미개시 플랫폼의 거래도 대상으로 표기된다. 다란채 쿠팡이츠는 락계좌 등록 전이라 선정산 미대상으로 분류돼야 한다.

선정산요약 엑셀의 배달매출 21,500원에 선정산하지 않는 쿠팡이츠 17,500원이 포함되어 선정산 대상 매출로 표시된다.

**결정된 것**

- 선정산 개시 방식 (2026-08-21 확정): 플랫폼을 하나씩 순차 개시하는 방식을 중단하고, 가맹점이 등록한 모든 플랫폼의 연결이 완료된 후 일괄 개시
- 기존에 일부 플랫폼만 선정산 중인 가맹점(다란채 등)은 그대로 유지되므로 구분 표기가 필요
- [선정산 시작 전] 표시 및 조정금액 자동 제외 (2026-08-22 배포)
- 대상 판정 기준: 조회 시점이 아니라 **거래가 발생한 날** 해당 플랫폼이 선정산 중이었는지

| 판단 | 조건 |
|---|---|
| 대상 | 거래일에 해당 플랫폼이 선정산 중 |
| 미대상 | 거래일에 해당 플랫폼이 선정산 미개시 |

- 표기 방식: 현행 `미대상` 표기를 유지하고 사유를 함께 표기. 현행 `미대상`은 취소 건을 의미하므로 사유 없이 플랫폼 미개시 건을 담으면 두 상황이 한 배지에 섞인다

| 사유 | 대상 거래 |
|---|---|
| `취소` | 승인취소·매입취소 건 (현행 미대상) |
| `선정산 미적용` | 해당 플랫폼을 선정산하지 않음 (다란채 쿠팡이츠) |
| `선정산 시작일 이전` | 거래일이 해당 플랫폼 선정산 시작일 이전 |

- 화면·엑셀 표기 개선

| 위치 | 현재 | 개선 |

### PAYHUG-253 — [운영] 바이패스 운영 기준 정립 및 어드민 지급 버튼 활성화

| 항목 | 값 |
|---|---|
| 상태 | 진행 중 (스토리) |
| 라벨 | 없음 |
| 컴포넌트 | Operations (조사 대상 중 유일하게 Product 아님) |
| 연결 | is blocked by PAYHUG-208 [기획] 선정산 시작 전 입금분 바이패스 자동 감지 및 어드민 지급 처리 (완료), PAYHUG-209 [개발] 바이패스 자동화 (완료) |
| 갱신 | 2026-09-03 |

**배경·문제**

바이패스는 선정산 상환 전용계좌로 입금된 매출대금 중 선정산 대상에 포함되지 않는 금액을 확인해 해당 가맹점에 별도 지급하는 운영 업무다.

- 운영자가 빠른계좌조회 입금내역, 입금 회수, 매출내역, 여신금융협회, 배달 플랫폼 정산내역을 직접 대조해 대상과 금액을 산출하고 있다
- 동일 일자에 추가 입금이 발생하면 반복 확인·재지급이 필요하고, 바이패스로 이미 지급한 거래가 선정산 대상에 다시 포함되면 이중 지급이 발생할 수 있다
- 8/20 청목황금갈비·김성관화덕구이에서 바이패스 지급 후 동일 거래가 선정산 대상에 포함되어 **230,694원 중복 지급** 발생 (PAYHUG-208 기준 71,252원 + 159,442원, 8/19 거래일 하나카드 입금분)

**결정된 것**

1차 개발 범위: 바이패스 전 과정 자동화가 아니라, 조회된 바이패스 대상에 대해 운영자가 어드민에서 확인 후 직접 지급하도록 `[바이패스 지급]` 버튼을 활성화하는 것.

발생 구간 2개

| 구간 | 정의 |
|---|---|
| ① 최초 선정산 시작 전 | 선정산 상환 전용계좌 연동 → 최초 선정산 시작(ON) 사이 발생 거래 |
| ② 선정산 중단 후 재개 전 | 선정산 중단 → 선정산 재개(ON) 사이 발생한 선정산 미적용 거래 |

바이패스 대상

- 최초 선정산 시작(ON) 전 발생한 거래의 입금분. 예: 7/12 거래 → 7/15 상환 전용계좌 연동 → 7/23 선정산 시작 → 7/25 입금인 경우 7/12 거래분은 바이패스 대상
- 선정산 중단 기간 동안 발생하여 선정산이 적용되지 않은 거래의 입금분
- 선정산이 적용되지 않은 플랫폼·카드사의 거래 입금분
- 기존 가맹점이 신규 카드사·배달 플랫폼을 추가한 경우 해당 플랫폼·카드사의 선정산 적용 전 발생 거래 입금분

바이패스 제외

- 선정산이 정상 적용되는 기간에 발생한 선정산 대상 거래
- 이미 선정산 지급이 완료되어 선정산 상환 전용계좌로 입금된 금액 중 회수 대상에 해당하는 경우

판정 원칙: 입금일만으로 판단하지 않고 실제 거래 발생 시점에 선정산 적용 대상이었는지를 기준으로, 거래일 / 선정산 시작일 / 중단·재개 시점 / 플랫폼·카드사별 선정산 적용 여부 / 해당 거래의 선정산 지급 여부를 함께 확인

- 가맹점별 바이패스 대상 금액을 합산해 지급. 플랫폼·카드사별 개별 지급이 아닌 **가맹점 기준 총액 합산 지급**

자동화 개발 전 임시 운영 기준 12항목이 티켓에 확정 문구로 적혀 있다(상환 전용계좌 연동 시점부터 관리 시작, 매일 오전 1회 11:40 전후, 시작 전 거래는 후입금이어도 바이패스, 중단 시 중단 시점부터 재시작, 미적용 플랫폼은 시작·재개 여부와 무관하게 바이패스, 오전 지급 이후 추가분은 익일 오전, 지급 내역은 `#시스템-알림-운영` 기록, 선정산 대상 중복 반영 여부 별도 확인 등).

**미결**

- 선행 티켓 PAYHUG-208 은 상태가 완료지만 기능은 완결되지 않았다. 코멘트 2026-09-02 이서준이 "바이패스 자동화 사용 이력이 있는지, 지급 실행 버튼과 사용 화면을 체크해보고 이상 없으면 기획쪽도 완료 처리하려 한다"고 물었고, 같은 날 윤지애가 **"지급실행버튼도 고도화해야 하는 것이고, 자동화 사용이 아니라 현재는 지급 조회성입니다"**라고 정정했다. 208 본문의 "[바이패스 지급] 버튼 → 확인 모달 → 이체 실행"은 현재 동작하지 않으며, 253 이 이를 1차 목표로 다시 잡은 상태다
- PAYHUG-208 의 확인 요청사항 3번 미해결: 선정산 시작 전 조정금액(광고비 등)의 경우 바이패스 지급액 산출 시 조정금액을 차감해야 하는 케이스가 있는지 `확인 필요` (208 의 1·2번은 각각 「수동 바이패스 처리 확정」, 「상품 배정이 되어야 선정산이 시작됨」으로 해소되어 취소선 처리됨)
- 바이패스 대상 자동 판정·자동 감지는 후속 고도화 범위. 고도화 시 최초 선정산 시작일뿐 아니라 중단·재개 이력과 플랫폼·카드사별 적용 상태까지 반영해 판정하도록 검토한다는 방향만 있음
- 중복 지급 230,694원의 회수 완료 여부가 티켓에 없다 `확인 필요`
