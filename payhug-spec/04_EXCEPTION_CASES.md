# 플랫폼별 예외 케이스

## 1. 배달의민족 우리가게클릭비

### 정상 케이스

- 우리가게클릭비는 광고비
- 플랫폼 정산에서 `-`
- 선정산 지급액에서 차감

### 예외 케이스

`우리가게클릭비 특별프로모션` 환급이 동일 항목 안에 포함됨.

- 일반 광고비: `-`
- 특별프로모션 환급: `+`
- 환급액이 차감액보다 크면 최종 순액이 `+`가 될 수 있음
- 기존 시스템은 우리가게클릭비를 무조건 차감 처리
- 지급해야 할 금액까지 회수하여 과회수 발생
- 이후 정정하여 재지급

### 개발 필요사항

- 동일 품목이라도 금액 부호에 따라 지급·차감 분기
- 가능하면 일반 광고비와 프로모션 환급 세부 항목 분리
- 합산 순액 기준인지 세부 항목 기준인지 정책 확정
- 이미 차감한 후 환급이 확인되면 추가 지급 처리

## 2. 가게배달 정산금

### 정상 케이스

- 항상 `+`
- 선정산 지급액에 포함

### 예외 케이스

- `-` 금액 발생
- 정산액에서 차감했어야 하나 기존 음수 처리 로직 부재

### 개발 필요사항

- 지급 전 `-`: 당일 지급액 차감
- 지급 후 `-`: 회수건 생성
- `+ / -` 방향에 따라 자동 분기

## 7. 바이패스

### 예외 처리 기준

`확정` `PAYHUG-208 본문` 「정책 및 예외사항」 표.

| 상황 | 처리 |
|---|---|
| 바이패스 지급 완료 후 동일 거래가 선정산 대상에 포함되는 경우 | 선정산 배치에서 제외 (이중 지급 차단) |
| 바이패스 지급 후 같은 날 추가 입금 발생 | 추가분만 신규 바이패스 대상으로 감지 (다음날 오전에 지급) |
| 쿠콘 출금등록(회수) 미완료 가맹점 | 바이패스 대상으로 노출하되 지급 버튼 비활성 또는 경고 표시 |
| 선정산 토글 OFF 가맹점 | 회수 미동작 상태이므로 동일하게 경고 표시 |
| 계약·수수료율 미확정으로 상품 미배정 가맹점 | 상품 배정이 되어야 선정산이 시작됨 |

`확정` 선정산 진행 중인 가맹점이 카드사 또는 배달 플랫폼을 추가하면 수동 바이패스로 처리한다. (`PAYHUG-208 본문`)

### 확인 필요

- 선정산 시작 전 조정금액(광고비 등)을 바이패스 지급액 산출에서 차감해야 하는 케이스가 있는지 미확정 (07 §7-15)
- 위 표의 `회수`는 쿠콘 출금등록을 가리키는 표기다. 어드민 `매출 회수`(락계좌→모계좌 스윕)와 정책 `과지급 회수` 중 어느 축인지 데이터 정의 대조 전까지 바꿔 적지 않는다

- 같은 날 오후 선정산 시작

- 바이패스 지급 버튼과 원장 기록이 운영에 나가기 전까지의 이중 지급 방지 수단 (07 §7-16)
- 중복 지급 230,694원의 회수 완료 여부가 티켓에 없다 (`PAYHUG-253 본문`)

## 9. 선정산 지급 후 원거래 취소

### 처리 원칙

`확정` 채권매입 후 원거래가 취소되면 원금 손실은 가맹점이 부담하고 이미 발생한 채권매입수수료는 환급하지 않는다. (`PAYHUG-260 본문`)

- 회수 대상: 순지급액 전액
- 수수료 환급: 없음
- 가맹점 부담: 회수액과 실수령액의 차이, 곧 채권매입수수료와 시스템이용료의 합
- 이체수수료: 취소와 관계없이 부담주체가 일별 발생비용으로 부담

산식과 검산 예시는 03 §8.

`확정` 이 케이스는 「지급 후 음수 = 회수 검토」 계열이다. 지급 전 취소는 당일 지급액 차감으로 처리한다(03 §6).

### 확인 필요

- 락계좌 잔액 부족·가압류 등으로 회수가 실패할 때의 경로가 티켓에 없다 (07 §7-22)
- 회수액을 6대 개념 중 과지급으로 등재하는지 미회수금으로 등재하는지 (07 §7-22)
- 승인취소와 매입취소에 같은 전액 회수 원칙을 적용하는지. `PAYHUG-189 본문`은 처리 분기를 설계서 노드(`IFX4GRC60ibOVCWNrd6VQt` `4465-680`) 참조로만 두고 문장으로 적지 않는다

## 10. 선정산 시작 전 발생분

`확정` 운영 배포일 2026-08-22. (`PAYHUG-171 본문`)

### 발생 사례 (2026-08-05 정산·매출대사)

`확정` 처갓집양념치킨 의정부중앙점은 8/5부터 선정산을 시작했다. 시작 시점에 이전 3일치 데이터를 함께 수집하면서 시작 전에 발생한 배달의민족 차감 내역이 선정산에 반영됐다. (`IFX4GRC60ibOVCWNrd6VQt` `4146:395` 슬랙 캡처)

| 우리가게클릭(광고비) 발생일 | 금액 |
|---|---|
| 7/31~8/2 | −10,082원 |
| 8/3 | −2,919원 |
| 8/4 | −33원 |
| 합계 | −13,034원 |

`확정` 이 금액은 모두 선정산 시작 전 발생분이라 선정산금에서 차감되지 않았어야 한다. 대사 결론은 선정산 시작일 기준으로 이전 거래·환급·차감 내역을 마감해 제외하는 기준과 로직이 필요하다는 것이다. (`4146:395`)

`확인 필요` 실제 차감 여부를 확인한 뒤 차감된 것으로 확정되면 해당 금액을 가맹점에 수동이체로 지급하는 방향까지 적혀 있고, 처리 완료 여부는 원문에 없다. (`4146:395`)

### 판정 기준

`확정` 시작 전 여부는 조정이 발생한 날이 아니라 그 조정이 어느 거래분의 정산금에 섞여 나갔는지(대상 주문 시작일)로 가른다. 시작 전 발생분은 이미 플랫폼 정산금으로 가맹점에 전달된 돈이라, 선정산에서 다시 ±하면 차감은 이중 차감이 되어 가맹점이 손해를 보고 환급은 이중 지급이 되어 당사가 손실을 본다. (`PAYHUG-171 본문`)

`확정` 조정금액은 플랫폼이 날짜 없이 주문번호만 주므로 원장에서 주문일을 찾아 원 주문일 기준으로 시작 전·후를 판정한다. 취소 주문이라 원장에 없으면 주문번호 체계에서 역산한다. (`PAYHUG-171 본문`)

### 조정금액 자동 제외

`확정` 대상 주문 시작일 기준으로 시작 전 발생분을 감지해 지급액에서 뺀다. 차감과 환급 모두 제외 대상이다. 제외된 금액은 관리자 어드민 선정산 상세에 `선정산 시작 전`으로 표기된다. (`PAYHUG-171 본문`)

### 광고 기간이 시작일에 걸치는 건

`확정` 배민 광고비는 기간 묶음으로 오므로 걸침 건은 전액 제외하고 경고 로그로 집계한다. 회사가 부담하는 방향이며 가맹점에 피해가 가지 않는다. (`PAYHUG-171 본문`)

`확정` 배민 응답에 일자별 내역이 함께 와서 걸침 건을 일자별로 나눌 수 있다. 배달 스크래퍼는 일자별 내역을 받고 있고 정산 측 분해 로직은 리뷰 단계다. (`PAYHUG-171 본문`)

### 플랫폼 하향 정정

`확정` 재수집에서 배민이 광고비를 줄이거나 0원으로 정정하면 해당 조정의 회수를 자동 중단하고, 이미 더 뗀 금액은 다음 정산에서 `배달수수료 환급`으로 자동 지급한다. (`PAYHUG-171 본문`)

### 주문 취소 환수

`확정` 그 주문에 실제로 붙었던 조정만 환수액에 반영한다. 같은 취소가 두 번 처리되지 않도록 DB 수준 안전장치를 이중으로 둔다. (`PAYHUG-171 본문`)

### 수집·정산 동시 실행

`확정` 수집·정산·데이터 리셋은 같은 가맹점에 대해 순서대로 처리된다. 잠금 규약이 하나로 통일되어 있다. (`PAYHUG-171 본문`)

### 확인 필요

- 일부 회수가 진행된 건이 뒤늦게 시작 전으로 판정되면 부분이라도 선정산 이전인 건은 막고 알림을 띄우는 방향까지 정해져 있고, 알림과 회수의 연결은 미정 (`PAYHUG-171 본문`)
- 광고비 일자별 분해의 정산 측 로직 배포 여부가 티켓에 없다 (`PAYHUG-171 본문`)

## 11. 가맹점 선정산 중 · 일부 플랫폼 미개시

### 발생 사례

`확정` 다란채는 카드와 배달의민족만 선정산 중이고 쿠팡이츠는 선정산 계획이 없는 미개시 상태인데, 가맹점 측 테스트 등록으로 쿠팡이츠 매출이 잡혔다. 금액은 제외되는데 상태 표기는 선정산 대상으로 나온다. (`PAYHUG-186 본문`)

| 묶음 | 매출액 합계 | 화면 금액 |
|---|---|---|
| 쿠팡이츠 2건 | 17,500원 | [선정산 제외액] -8,607원 |
| 카드 3건 + 배달의민족 1건 | 27,000원 | [선정산 대상액] 26,477원 |

`확정` 원인은 거래의 선정산 대상 여부가 가맹점 단위 선정산 여부를 따르는 것이다. 가맹점이 선정산 중이면 미개시 플랫폼의 거래도 대상으로 표기된다. 다란채 쿠팡이츠는 락계좌 등록 전이라 선정산 미대상으로 분류돼야 한다. (`PAYHUG-186 본문`)

`확정` 선정산요약 엑셀의 배달매출에 선정산하지 않는 쿠팡이츠 금액이 합산되어 선정산 대상 매출로 표시된다. (`PAYHUG-186 본문`)

거래일 기준 판정은 02 §5, 바이패스와의 경계는 03 §7.

### 확인 필요

- 미대상 사유 어휘 (07 §7-19)
- 플랫폼별 선정산 개시일 기록 존재 여부 (07 §7-24)
- 두 사유를 데이터로 구분할 수 있는지. 구분이 어려우면 사유 없이 미대상만 표기 (`PAYHUG-186 본문`)
- 제외 플랫폼이 여러 개일 때의 표기 방식 (`PAYHUG-186 본문`)

## 12. 락계좌 전액 회수 실패

### 발생 내용

`확정` 선정산 상환전용 계좌로 들어온 금액은 회수 시 전액 출금을 기준으로 운영한다. 가압류·압류로 전액 회수가 불가능한 경우가 있다. 김성관화덕구이에서 일부 금액만 회수된 것을 운영자가 확인하고 추가로 살펴보다 가압류 사실을 알았다. (`PAYHUG-250 본문`)

`확정` 여기서 쓰는 회수는 어드민 「매출 회수」(락계좌→모계좌 스윕) 축이다. 정책의 과지급 회수와 다른 개념이므로 바꿔 적지 않는다.

### 확인 필요

`확인 필요` 회수 예정금액보다 실제 회수금액이 적으면 운영자에게 알림을 띄우는 요청이 접수되어 있다. 요청 예시 금액은 회수 대상 1,000,000원 / 실제 회수 696,375원 / 미회수 303,625원이다. 기획 티켓 본문이 비어 있어 수신자·채널·발송 시점·중복 억제·판정 임계값·미회수 잔액의 후속 경로가 전부 미정이다 (07 §7-23). (`PAYHUG-250 본문`·`PAYHUG-251 본문`)

## 13. 계좌 등록 값 오류

### 현행

`확정` 하나은행 계좌이면 계좌 종류와 무관하게 등록이 통과한다. (`PAYHUG-223 본문`)

- 선정산 상환전용 계좌 자리에 하나은행 입출금 계좌를 넣어도 통과
- 입출금 계좌 자리에 하나은행 선정산 상환전용 계좌를 넣어도 통과
- OCR 뒤 입력 필드를 가맹점주가 바꿔 두 계좌를 같은 값으로 넣어도 통과

잘못 등록된 계좌는 회수가 동작하지 않는 상태로 이어진다.

### 확인 필요

- 두 계좌 동일값 차단과 `62291`로 시작하는 하나은행 계좌만 상환전용으로 등록하는 방어 로직은 티켓에 제안으로 적혀 있고 승인 문구가 없다 (`PAYHUG-223 본문`)
- 입출금 계좌의 허용 은행 범위가 티켓에 없다 (`PAYHUG-223 본문`)
- `62291` 외 상환전용 계좌 번호 대역이 있는지 (`PAYHUG-223 본문`)

## 14. 카드 미매입 (승인O · 매입X)

### 대상

`확정` 선정산 대상(승인 있음, 매입 없음)인데 지급예정일에 매입이 들어오지 않은 건이다. 늦게 들어온 경우와 아예 들어오지 않은 경우를 함께 담는다. (Figma `EUK2P3tDOkprcnRmMqNns4` `5:59`)

### 회수 시점

`확정` 승인일(=거래일) D+5 영업일에 선정산 금액에서 차감한다. (`5:59`)

`확정` 내역은 지급예정일이 지난 뒤부터 노출하며, 안내 문구는 「승인일(=거래일) D+5 영업일 후 선정산 금액에서 차감돼요」다. (`5:59`)

`확정` 배달은 기준이 다르다. 승인일(=거래일)에 입금이 되지 않으면 다음 선정산 금액에서 차감한다. (`5:60`)

`확정` D+5 영업일은 지급 주기가 아니라 회수 시점이다. 지급 기산일 축(C2)과 섞어 읽지 않는다.

### 확인 필요

- 차감 이후 대금이 들어온 경우의 처리를 원문이 「바로이체 (바이패스)」로 두 낱말을 겹쳐 적는다. 02 §2는 바로이체와 바이패스를 다른 개념으로 가르므로 어느 축인지 대조 전까지 바꿔 적지 않는다 (`5:59`)
- D+5 영업일의 기산 방식(승인일 포함 여부)과 회수 대사일 19시(03 §5)와의 실행 순서가 원문에 없다

## 15. 선정산 완료 후 매입취소 상계

### 발생 사례 (2026-08-05 정산·매출대사)

`확정` 8/4 현대카드 입금 대사에서 예상 입금액 6,285,875원과 실제 입금액 5,900,360원 사이에 385,515원 차이가 확인됐다. 단일 −390,000원 거래가 아니라 두 건이 합산된 금액이다. (`IFX4GRC60ibOVCWNrd6VQt` `4146:395` 슬랙 캡처)

| 거래일 | 거래 금액 | 지급예정액 |
|---|---|---|
| 7/24 | −400,000원 | −395,400원 |
| 7/30 | +10,000원 | +9,885원 |
| 상계 합계 | | −385,515원 |

`확정` 검산이 맞는다. −395,400 + 9,885 = −385,515이고, 6,285,875 − 385,515 = 5,900,360으로 실제 입금액과 일치한다.

`가설` 원문은 이 건을 매입완료 → 선정산 지급 → 사후 매입취소 → 카드사 정산대금 상계 케이스로 판단된다고 적는다. 385,515원이 즉시 차감되지 않고 보류됐다가 8/4 현대카드 정산대금에서 상계된 것으로 보되, 원거래 상태와 선정산 지급 여부는 개발과 최종 대조 예정이라고 함께 적는다. (`4146:395`)

`확정` 같은 대사에서 펠리치타스 정산현황 차액이 함께 확인됐다. 현대카드 395,400원(매입완료 후 매입취소에 따른 회수차액), 삼성카드 39,540원(선정산 대상이나 매입대기), 하나카드 494,250원(선정산 대상이나 매입대기)이며 총 차액 표기는 909,420원이다. 세 건의 단순 합 929,190원과의 차이 19,770원은 7/20 바이패스 처리분으로 제외된 금액이라고 같은 글이 적는다. (`4146:395`)

### 시스템 미비

`확정` 선정산 완료 후 매입취소가 발생했을 때 회수채권을 생성·추적하는 로직이 없다. 대사 결론은 해당 금액을 회수금으로 반영하고 이후 회수·카드사 상계 내역을 추적할 수 있는 로직이 필요하다는 것이다. (`4146:395`)

`확정` 원문이 적은 운영 처리 방향은 회수 로직이 없는 동안 미정산금을 이미지급(기록만) 방식으로 회수하고, 회수금액에 근접했을 때 남는 잔여 차액을 수동이체로 정리하는 것이다. 실행 완료 여부는 원문에 없다. (`4146:395`)

### 확인 필요

- 385,515원을 6대 개념 중 과지급으로 등재하는지 미회수금으로 등재하는지 (07 §7-22와 같은 판정)
- 회수채권 생성·추적 로직의 범위와 어드민 표시 자리
- 이미지급을 회수 대용으로 쓰는 처리의 허용 범위 (07 §7-9)
- 원문이 쓰는 「미정산금」이 계약 용어인지 내부 운영 용어인지 갈리지 않는다. 대응표가 서기 전까지 6대 개념 중 어느 것으로도 옮겨 적지 않는다 (07 §7-20)
