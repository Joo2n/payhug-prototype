# 플랫폼별 예외 케이스

## 1. 배달의민족 우리가게클릭비

### 정상 케이스

- 우리가게클릭비는 광고비
- 플랫폼 정산에서 `-`
- 선정산 지급액에서 차감

### 예외 케이스

`우리가게클릭비 특별프로모션` 환급이 동일 항목 안에 포함됨.

- 일반 광고비: `-`
- 특별프로모션 환급: `+`
- 환급액이 차감액보다 크면 최종 순액이 `+`가 될 수 있음
- 기존 시스템은 우리가게클릭비를 무조건 차감 처리
- 지급해야 할 금액까지 회수하여 과회수 발생
- 이후 정정하여 재지급

### 개발 필요사항

- 동일 품목이라도 금액 부호에 따라 지급·차감 분기
- 가능하면 일반 광고비와 프로모션 환급 세부 항목 분리
- 합산 순액 기준인지 세부 항목 기준인지 정책 확정
- 이미 차감한 후 환급이 확인되면 추가 지급 처리

## 2. 가게배달 정산금

### 정상 케이스

- 기존에는 항상 `+`
- 선정산 지급액에 포함

### 예외 케이스

- `-` 금액 발생
- 정산액에서 차감했어야 하나 기존 음수 처리 로직 부재

### 개발 필요사항

- 지급 전 `-`: 당일 지급액 차감
- 지급 후 `-`: 회수건 생성
- `+ / -` 방향에 따라 자동 분기

## 3. 배달 플랫폼 환급 미지급

### 발생 내용

- 총 8건
- 총 435,263원
- 가맹점에게 지급해야 하는 금액
- 시스템에서 정상 지급되지 않음
- 수동이체 일괄 처리 검토

### 확인 필요

- 플랫폼별 건수
- 품목별 금액
- 모두 같은 로직 오류인지
- 미반영인지 오차감인지
- 수동이체 완료 기록 위치
- 중복 지급 방지 기준
- 개발 완료 전 재발 점검 방식

## 4. 쿠팡이츠 과지급

### 발생 사례

- 당사 지급액: 172,200원
- 플랫폼 지급액: 158,108원
- 차액: 14,092원
- 선정산 완료 후 스크래핑 데이터 갱신
- 과지급 발생
- 기존 미회수분과 합산하여 총 15,809원 관리

추가 확인된 미정산 카드 금액:
- 하나카드 1,946원
- 하나카드 13,525원
- 합계 15,471원

### 정책 필요사항

- 플랫폼 과지급과 카드 미정산금을 합산 관리할지
- 총 미회수금과 상세 발생건을 분리 보관할지
- 회수 순서
- 일부 회수
- 차기 지급 자동 상계
- 회수 완료 판단 기준

## 5. 쿠팡이츠 정산 출금

### 현재 파악

- 매일 오전 6시 관련 작업 수행
- 플랫폼 입금예정금액 = 매출금액 - 플랫폼 수수료
- 배민·요기요·카드는 자동으로 락계좌 입금
- 쿠팡이츠는 정산금액을 락계좌로 출금하는 별도 행위가 있음

### 확인 필요

설명이 아래처럼 혼재되어 있음.

- UI에서 출금 버튼을 누름
- 시스템이 오전 6시에 자동 수행
- 쿠팡이츠가 등록된 락계좌로 정산

실제 자동화 주체와 계좌 흐름 확정 필요.

## 6. 바로이체

### 현재 제안 정책

- 입금예정일 당일 지급 원칙
- 늦어도 익일까지 정산 완료
- 익일까지 미지급 시 미지급 상태로 관리

### 확인 필요

- 대상 생성 조건
- 지급 주체
- 지급 계좌
- 플랫폼 입금 전 선지급 가능 여부
- 주말·공휴일 기준
- 실패·재처리
- 회수금과 상계 가능 여부
