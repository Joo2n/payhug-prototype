# PayHug 서비스 정책·화면 검토용 마스터 문서

## 목적

이 문서는 PayHug 선정산 서비스의 정책, 용어, 정산 로직, 예외 케이스, 관리자 기능, 가맹점 화면, 알림톡 정책을 정리한 기준 문서다.

Claude Code는 다음 업무에 사용한다.

1. Figma 화면과 정책 문서 대조
2. 누락된 화면·항목·상태 확인
3. 화면 문구 정제
4. 정책 충돌 및 예외 케이스 확인
5. 개발 요청사항 작성
6. Jira 티켓 작성
7. 테스트 케이스 작성

## 문서 구조

```
payhug-spec/
├─ 00_README.md              ← 이 문서 (마스터)
├─ 01_SERVICE_OVERVIEW.md    ← 서비스 개요
├─ 02_TERMS_AND_STATUS.md    ← 용어 및 상태값
├─ 03_SETTLEMENT_LOGIC.md    ← 정산 로직
├─ 04_EXCEPTION_CASES.md     ← 플랫폼별 예외 케이스
├─ 05_UI_REQUIREMENTS.md     ← 가맹점 선정산 UI 요구사항
├─ 06_ADMIN_AND_NOTIFICATION.md ← 회수 어드민 및 알림톡
└─ 07_OPEN_QUESTIONS.md      ← 미확정 및 미팅 협의사항
```

## 문서 해석 기준

각 내용은 아래 세 상태로 구분한다.

- `확정`: 현재 운영 또는 기존 협의에서 확인된 내용
- `가설`: 현재까지 파악한 내용을 기반으로 한 기획안
- `확인 필요`: 운영·개발·책임자와 추가 협의가 필요한 내용

Claude Code는 `확인 필요` 내용을 임의로 확정하지 않는다.

## 화면 검토 원칙

Figma 화면을 검토할 때 다음 순서로 판단한다.

1. 이 화면의 사용자와 목적
2. 화면에 표시되는 기준일
3. 금액의 출처
4. 금액이 예상값인지 확정값인지
5. 지급·차감·환급·회수 중 어떤 방향인지
6. 상태값이 무엇인지
7. 예외 상황에서 어떻게 바뀌는지
8. (⚠️ 원문 유실 — 확인 필요: 원본 붙여넣기에서 이 항목 이후 01_SERVICE_OVERVIEW.md 본문까지 텍스트가 끊김)

## 핵심 정리 원칙

문서의 모든 내용은 반드시 세 종류로 구분한다.

1. 현재 확인된 사실
2. 기획자가 제안한 정책
3. 미팅에서 확정해야 할 내용

가장 위험한 부분은 **미지급, 선정산 제외, 바로이체, 과지급, 미회수, 환급**을 서로 비슷하게 사용해온 점이다. Claude Code는 이 여섯 개념을 임의로 하나로 합치지 않으며, 문서상 명시적으로 분리된 정의(02_TERMS_AND_STATUS.md)를 따른다.

이번 작업의 핵심은 단순 화면 수정이 아니라:

> 운영 엑셀의 실제 정산 판단 기준을 서비스 정책으로 변환하고, 그 정책이 가맹점 UI·회수 어드민·알림톡에 동일하게 반영되게 만드는 것

## 부록 A. Claude Code 초기 지시문

> 새 세션 시작 시 아래 지시문을 사용한다.

너는 PayHug 선정산 서비스의 서비스기획 검토자다.

현재 프로젝트 폴더에는 다음 자료가 있다.

1. PayHug 정책 및 용어 문서
2. 정산·지급·환급·회수 로직 문서
3. 플랫폼별 예외 케이스
4. 회수 어드민 및 알림톡 정책
5. Figma에서 추출한 화면 또는 HTML
6. 아직 확정되지 않은 미팅 질문

작업 원칙:

- 정책 문서에 없는 내용을 임의로 확정하지 말 것
- `확정`, `가설`, `확인 필요`를 구분할 것
- 운영 내부 용어와 가맹점 노출 용어를 구분할 것
- 동일 품목도 금액 부호와 지급 완료 여부에 따라 처리 방향이 달라질 수 있음을 반영할 것
- 지급 전 음수는 차감, 지급 후 음수는 회수 가능성으로 검토할 것
- 예상값, 확정값, 실제 지급값을 구분할 것
- 스크래핑 시각, 지급 시각, 기준일, 최종 업데이트 일시를 혼동하지 말 것

먼저 전체 화면을 분석하여 아래 형식으로 보고하라.

1. 화면 목록
2. 화면별 목적
3. 현재 표시 항목
4. 정책상 필요한 항목
5. 누락 항목
6. 잘못된 용어
7. 정책과 충돌하는 부분
8. 예외 상태 누락
9. 수정 제안
10. 추가 확인 질문

수정 작업 전에는 반드시 분석 결과를 먼저 제시하고 승인받을 것.

## 부록 B. 화면 하나씩 수정할 때 쓰는 명령

현재 Figma 화면과 PayHug 정책 문서를 대조해 이 화면을 검토해줘.

검토 항목:

- 화면 목적
- 사용자
- 기준일
- 금액 기준
- 예상값/확정값 구분
- 지급·환급·차감·회수 구분
- 상태값
- 예외 케이스
- 내부 용어와 가맹점 용어
- 상세 화면 이동
- 알림톡 연결
- 운영 어드민 데이터 연결

결과는 아래로 구분해줘.

1. 유지
2. 수정 필요
3. 추가 필요
4. 삭제 검토
5. 정책 확인 필요

정책 확인이 필요한 내용은 임의로 수정하지 말고 질문 목록으로 남겨줘.
