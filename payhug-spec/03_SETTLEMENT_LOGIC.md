# PayHug 정산 로직

## 1. 기본 산식

기본 구조:

```
전일 매출
- 카드 수수료
- 배달 플랫폼 수수료
- PayHug 채권매입수수료
- 이체수수료
+ 플랫폼 환급
+ 추가 지급
- 선정산 제외금액
- 이전 과지급 회수금
= 최종 선정산 지급액
```

## 2. 카드 선정산 산식

기존 협의에서 파악된 산식:

```
최종 선정산금액
= (전일 전체 매출 - 카드수수료)
× (1 - PayHug 수수료율)
- 이체수수료 300원
```

다만 실제 서비스에서는 플랫폼별·항목별 수수료 계산 순서와 버림 정책을 재확인해야 한다.

## 3. 수수료

### PayHug 수수료

- 채권매입수수료
- 서비스 이용 수수료
- 건별 또는 비율 기반으로 적용

### 전산 수수료

- 가맹점 1개 기준 하루 1회
- 이체수수료 300원

### 외부 수수료

- 카드사 수수료
- 배달 플랫폼 수수료
- 배달앱 건별 수수료
- 광고비 등 플랫폼 차감 항목

## 4. 버림·반올림 정책

카드사별 순지급액에 수수료율을 적용한 금액과 전체 합계 기준 계산 사이에 차이가 발생할 수 있다.

확인 필요:
- 건별 버림
- 카드사별 버림
- 일별 합계 후 버림
- 소수점 처리 단위
- 화면 표시값과 실제 지급값의 차이

## 5. 지급 시점

- 전일 매출 기준
- 매일 오전 10시 데이터 업데이트
- 다음날 오전 11시 30분 지급
- 가맹점별 하루 1회 지급

## 6. 정산 후 변동

선정산 완료 후 다음 변동이 발생할 수 있다.

- 매입 지연
- 추가 매입
- 승인 취소
- 매입 취소
- 환불
- 플랫폼 정정
- 프로모션 환급
- 광고비 환급
- 스크래핑 데이터 갱신
- 실제 입금액 변경

처리 방향:

- 추가 지급 필요: 차기 지급 또는 바로이체
- 초과 지급 발생: 회수건 생성
- 지급 전 음수 발생: 당일 지급액에서 차감
- 지급 후 음수 발생: 미회수금으로 관리
