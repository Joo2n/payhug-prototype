key note
이전 선정산이 예상 수수료율로 미리 지급된 뒤, 실제 카드사·배달앱 정산이 확정되며 생긴 차액을 건별로 모아 보여주는 화면이다. 상단에 이번 입금일에 반영된 차액 합산액(환급 +, 차감 −)을 크게 띄우고, 아래에 거래별 차액 내역을 최신순으로 나열한다.
No이름설명
1헤더·뒤로가기제목은 예상 지급 차액. 좌측 화살표로 이전 화면(정산/대시보드)으로 복귀한다.
2반영일 + 합산 차액{입금일} 반영 라벨과 함께 이번 배치에 반영된 차액 합계를 부호와 함께 크게 표기. 예시는 −14,000원(차감 우세). 환급이 크면 +로 표기.
3안내 배너연두색 배너로 원리 안내. 선정산은 예상 카드 수수료율 기준으로 지급되고, 실제 정산 후 차액은 다음 선정산 금액에 자동 반영된다는 고정 문구.
4차액 내역 행각 행은 좌측에 거래일·카드사/배달앱명, 우측에 승인번호(카드)/주문번호(배달)와 차액 금액. 카드·배달 건이 함께 섞여 최신순 정렬된다.
5차액 금액(부호·밑줄)금액은 부호(+/−)와 밑줄로 표기되며 탭하면 계산 근거 툴팁이 열린다. +는 추가 입금될 환급, −는 다음 지급에서 차감.
6만나서결제 회수 행현장(만나서)결제 지연 회수분이 편입된 행. 명칭은 만나서 결제 회수이며 금액은 항상 차감(−). 금액 툴팁은 수수료가 아닌 예정/실제 차감일을 보여준다.
7더 불러오기내역은 10건씩 페이징. 더 있으면 하단에 내역 더 불러오기 버튼이 노출된다(예시 화면엔 미노출). 내역이 없으면 '반영된 차액 내역이 없어요' 안내.
정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
이 화면은 GET /business/settlement/adjustments(bizNo, date=YYYYMMDD, page 10건 단위)로 특정 입금일 배치의 차액 내역을 받아 그린다. 합산 totalAdjustment와 건별 items(카드/배달 공통 구조)로 구성되며, 각 건은 예상값(예상 수수료 또는 예상 입금예정금)과 실제값의 차이를 amount로 담는다. 정책상 이 '예상 지급 차액'의 정의 자체가 미확정(C4)이며, 화면은 추가 환급(+)과 과지급 회수(−)를 단일 순액으로 합산해 노출하고 있어 6대 개념 분리 원칙과 충돌한다.
연결데이터 출처·구조
API
GET /business/settlement/adjustments?bizNo=&date=YYYYMMDD&page=Ndate 미지정 시 오늘 입금일 기준. page는 0부터, 10건씩.응답: date(입금일), totalAdjustment(합산), items[], hasMore확정
건별 필드
transactionDt(차액 발생 거래일), name(카드사/배달앱명), refNo(카드=승인번호/배달=주문번호), isCardamount(차액: 입금 +, 차감 −), estimated(예상값), actual(실제값)현장결제 회수건: isOfflineRecovery, scheduledDeductionDate(예정차감일), actualDeductionDate(실제차감일, 미회수 시 null)확정
페이징·빈 상태
hasMore=true면 '내역 더 불러오기' 버튼, 클릭 시 다음 page 이어붙임items 비면 '반영된 차액 내역이 없어요' 문구확정
계산차액 계산·부호 규칙
카드 차액
차액 = 예상 수수료 − 실제 수수료. 실제 수수료가 예상보다 낮으면 +(환급), 높으면 −(차감).예: 예상 수수료 15,000 · 실제 11,800 → +3,200 (사장님께 덜 뗀 만큼 돌려드림)확정
배달 차액
차액 = 실제 입금예정금 − 예상 입금예정금 계열. 라벨은 '예상/실제 입금예정금'으로 표기(카드와 다름).실제 정산액이 예상보다 크면 +, 작으면 −가설
합산 부호
totalAdjustment = 건별 amount 합. 예시는 −14,000원으로 이번 배치 순차감.화면은 추가 지급(+)과 과지급 회수(−)를 한 값으로 합산 노출확정
정책정책 지뢰·용어
예상 지급 차액 정의 (C4)
'예상 지급 차액'의 정의가 정책상 미확정. 방향별(추가 지급 / 이전 지급 조정) 분리 없이 단일 순액으로 합산 표기 중.재기획 방향: 항목 폐기 또는 방향별 분리 명문화 필요.확인필요
예상 수수료율 (C1)
안내 배너의 '예상 카드 수수료율' 실제 값이 미확정(1%/0.604%/0.6+0.11+0.1%/0.25% 병존).차액 자체가 이 요율에 의존하므로 요율 확정 없이 계산 근거를 못 박을 수 없음.확인필요
6대 개념 분리
+ 방향은 '환급/추가 지급', − 방향은 '과지급 회수' 성격이 섞여 있음. 두 개념을 한 라벨로 합치면 안 됨(원칙).'만나서 결제 회수' 차감은 선정산 제외/미회수 성격이라 별도 취급 필요.확인필요
반영일 라벨
'{date} 반영'의 date가 입금일인지 반영시각 기준일인지 표기 명확화 필요. 하루 2회 지급(11:30·18:00, C2)과의 연계도 미표기.확인필요
