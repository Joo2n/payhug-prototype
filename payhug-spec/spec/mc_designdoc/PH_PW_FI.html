비밀번호를 잊은 가맹점주가 휴대전화 본인인증으로 계정을 확인하는 진입 화면. 상단 2단계 진행 인디케이터의 1단계로, 번호 입력 후 KCB 본인인증을 통과하면 자동으로 2단계(비밀번호 재설정)로 넘어간다.
No이름설명
1진행 단계 인디케이터상단 중앙에 점 2개로 전체 흐름 표시. 현재 1단계가 파란색 길쭉한 점으로 활성, 2단계는 회색. 인증 성공 시 2단계 점이 활성화된다.
2안내 문구제목 '비밀번호를 잊으셨나요?'와 부제 '본인 확인 후 비밀번호를 재설정할 수 있어요'로 화면 목적을 안내.
3휴대전화번호 입력'숫자만 입력' 플레이스홀더. 입력 시 자동으로 하이픈(010-0000-0000) 포맷팅. 최대 13자.<br>Enter 키로도 인증 요청 가능(12자 이상일 때).
4본인 인증 버튼번호가 12자 이상이면 연두색으로 활성화. 미만이면 흐린 비활성 상태.<br>클릭 시 가입 여부 확인 후 KCB 본인인증 팝업(430x640) 호출. 인증 완료 시 버튼 라벨이 '인증 완료'로 바뀐다.
5인증 완료 토스트KCB 인증 성공 시 상단에 '본인인증이 완료 되었어요' 성공 토스트가 약 1.5초 노출된 뒤 자동으로 2단계로 전환.
정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
본인인증은 3단계로 진행된다. (1) 입력 번호가 가입된 계정인지 조회(/auth/check-phone), (2) 가입 확인 시 KCB 인증 토큰 발급(/auth/kcb/token), (3) 외부 KCB 팝업(safe.ok-name.co.kr)에서 실인증. 팝업 결과는 window message(postMessage)로 부모 창에 전달되며, 성공 시 CI값을 받아 다음 단계로 넘긴다. 이 CI는 2단계 비밀번호 재설정 요청의 본인 식별 키로 사용된다. 정책 문서에는 비밀번호 찾기/본인인증 절차 규격이 명시되지 않아 코드 기준 기술이다.
연결본인인증 처리 흐름
가입 여부 조회
GET /auth/check-phone?phoneNumber={하이픈 제거 번호}응답 exists=false면 '가입되지 않은 번호' 모달 노출(FI_NONE variant)exists=true여야 인증 토큰 발급 단계로 진행확정
KCB 인증 토큰 발급
POST /auth/kcb/token, RETURN_URL은 백엔드 콜백 주소응답 RSLT_CD='B000'일 때만 성공, 그 외 실패 alertCP_CD·MDL_TKN을 팝업 폼 파라미터로 전달확정
KCB 실인증 팝업
외부 https://safe.ok-name.co.kr/CommonSvl 로 POST 폼 전송팝업 차단 시 '팝업 차단을 해제해 주세요' alert결과는 postMessage로 수신(KCB_AUTH_SUCCESS / KCB_AUTH_FAILED)확정
인증 결과 처리
성공: CI 저장 + 성공 토스트 1.5초 후 2단계 자동 이동실패: '본인인증에 실패했습니다. 다시 시도해 주세요.' alert확정
정책입력·활성화 규칙
번호 입력 검증
자동 하이픈 포맷, 최대 13자버튼 활성 기준은 length>=12(하이픈 포함 문자열 길이)빈 값으로 인증 시도 시 '휴대전화번호를 입력해 주세요' alert가설
본인인증 수단
현재 코드는 KCB(오케이네임) 휴대폰 본인인증만 구현정책 문서에 본인인증 수단·대체수단 규격 명시 없음확인필요
