key note
정보 확인(info) 단계에서 '1원 계좌 인증하기'를 누른 뒤 같은 화면이 인증번호 입력 단계로 전환된 변형. 통장 적요에 찍힌 숫자 3자리를 입력해 입금받을 계좌 등록을 완료한다. (info 대비 차이 중심)
No이름설명
1헤드라인 전환'사장님의 정보가 맞나요?' → '1원 인증번호를 입력해주세요'로 바뀌고, 안내가 '통장 적요(메모)에서 숫자 3자리를 입력'으로 변경.
2기존 입력칸 잠금계좌주명·은행명·계좌번호 세 칸이 비활성(흐림) 처리되어 수정 불가.
3인증번호 입력칸숫자 3자리 전용 입력(가운데 정렬·자간 강조). '페이허XXX' 형태 적요에서 숫자만 입력 안내. 숫자 외 문자 자동 제거.
4인증번호 확인 버튼3자리 입력 전 비활성. 누르면 보관된 통장 파일과 인증정보를 함께 전송해 계좌 등록 확정, 성공 시 '등록 완료' 모달.
5다시 인증 요청하기info 단계로 되돌려 1원 인증을 다시 요청.
6[신규] 인증 요청 실패 오류캡처된 화면은 인증 단계 대신 'Cannot read properties of undefined (reading verifyTrDt)' 오류 모달을 노출. 1원 인증 요청 응답 구조 불일치로 추정되는 런타임 오류.
정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
info와 동일 URL·컴포넌트에서 상태만 verify로 바뀌는 변형이다. 완료 처리는 인증값(거래일자·거래번호·적요 3자리)과 임시 보관 통장 파일을 하나의 폼으로 묶어 확정 API에 전송한다. 캡처된 스크린샷은 정상 verify 화면이 아니라 1원 인증 요청 응답에서 data가 비어 발생한 런타임 오류 모달이 떠 있는 상태로, 실제 결함으로 별도 확인이 필요하다.
정책info 대비 차이
화면 전환 방식
별도 라우팅 없이 같은 화면 내부 단계값(info→verify) 전환. 계좌 입력 3칸은 잠금.확정
적요 코드 형식
통장에 '페이허XXX' 형태로 입금된 메모의 숫자 3자리를 입력. 숫자만 허용(비숫자 자동 제거).확정
연결등록 확정 처리
확정 전송 데이터
사용자·계좌·용도(SETTLEMENT)·거래일자·거래번호·적요값을 JSON으로, 임시 보관 통장 파일을 함께 멀티파트로 전송(confirmAndRegisterBankAccount).확정
통장 파일 유실 방어
임시 저장소에 통장 파일이 없으면 '통장 사진이 유실되었습니다. 다시 첨부해 주세요' 안내 후 중단.확정
성공 후 분기
성공 시 임시파일 삭제·'등록 완료' 모달. edit/addBusiness 파라미터에 따라 계약 화면 또는 플랫폼 등록 화면으로 이동.확정
연결캡처 상태의 오류
verifyTrDt undefined
'Cannot read properties of undefined (reading verifyTrDt)' — 1원 인증 요청 응답에서 data 객체가 비어 res.data.verifyTrDt 접근 시 오류.정상이라면 verify 단계 UI가 떠야 하나 캡처는 오류 모달만 표시.신규
원인 후보
백엔드 응답 스키마 불일치 또는 목업/프록시 응답 형태 차이로 추정. 실제 서버 연동 시 재현 여부 확인 필요.확인필요
