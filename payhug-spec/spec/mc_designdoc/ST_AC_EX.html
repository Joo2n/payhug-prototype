key note
계좌 입금 내역에서 선정산 제외액 행을 클릭했을 때 열리는 상세. 해당 입금일의 제외액 총액과, 그 제외액을 구성한 카드/배달 거래 단위 내역을 나열하고 발생 이유를 배너로 설명한다.
No이름설명
1입금일·총액상단에 입금일(YYYY.MM.DD)과 선정산 제외액 총액을 크게 표기. 앞 화면 목록 행의 금액과 동일한 값.
2안내 배너'매일 오전 11시 30분 정산이 완료된 후 수집된 내역은 미리 받는 돈에서 제외되며, 정산금은 기존 금액 그대로 이체돼요.' 제외액의 발생 원리를 설명하는 고정 문구.
3제외 거래 행각 행은 개별 거래. 왼쪽에 매입일과 카드사/플랫폼명(예: KB카드, 배달의 민족), 오른쪽에 승인번호와 실지급액(밑줄). 밑줄 금액에 마우스를 올리면 툴팁.
4승인번호카드는 승인번호, 배달은 주문번호가 같은 자리에 표기(예: B로 시작). 값이 없으면 '-'.
5내역 더 불러오기제외 거래도 10건씩 페이징. hasMore일 때만 버튼 노출.
정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
base(계좌 입금 내역) 대비 이 화면은 payoutId로 특정된 선정산 제외액 입금 1건을 거래 단위로 분해하는 상세다. GET /business/settlement/account/excluded에서 총액 + 거래 배열을 받으며, 각 거래는 매출액·카드수수료·제외액(실지급액)의 3요소로 구성돼 툴팁으로 노출된다. 배너 문구가 '11시 30분 정산 완료 후 수집분'이라는 캘린더 근거를 담고 있어 C2(지급 캘린더) 검토 대상이며, 수수료 구성(카드수수료만 차감·페이허그 수수료 표기 없음)의 정책 근거 확인이 필요하다.
연결데이터 출처
조회 API
GET /business/settlement/account/excluded?bizNo=&payoutId=&page= (fetchExcludedPayout)진입 파라미터 payoutId는 base 목록 행의 SettlementPayout id응답: date, totalAmount, items[], hasMore (10건 페이징)확정
거래 행 구조
ExcludedPayoutItem: date(매입일), name(카드사/플랫폼), approvalNo(승인/주문번호), sales(매출액), cardFee(카드수수료), amount(선정산 제외액=실지급액)행 본문엔 amount만 표기, sales·cardFee는 툴팁에서만 노출확정
정책제외액 발생 원리(배너)
11:30 기준 문구
'매일 오전 11시 30분 정산 완료 후 수집된 내역은 미리 받는 돈에서 제외, 정산금은 기존 금액 그대로 이체'정기 정산 배치가 돌 때 아직 수집 안 된 매출이 다음에 별도 지급된다는 의미로 읽힘계약 '매일' vs 운영 D+1 vs 설계 D+2 캘린더 병존(C2)과 이 11:30 문구의 정합성 확인 필요확인필요
6대 개념 분리
여기서 다루는 '선정산 제외금액'은 미지급금·바로이체·과지급·미회수금·환급과 별개 개념'제외됐다가 별도 지급'이 바로이체(선입금)와 혼동되지 않도록 용어 구분 유지확정
계산제외액 산식
거래 단위 구성
툴팁 기준: 매출액 − 카드수수료 = 선정산 제외액(실지급액) (예: 15,000 − 450 = 14,550)행 amount는 카드수수료만 차감한 값으로 보이며 페이허그(채권매입) 수수료 항목은 이 화면에 표기 없음가설
수수료율 근거
차감된 카드수수료율의 근거(1%/0.604%/0.6+0.11+0.1%/0.25% 병존, C1)가 이 화면에서 확정되지 않음제외액에 페이허그 수수료가 적용되는지/면제인지 정책 확인 필요확인필요
