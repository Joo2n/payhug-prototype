key note
배달앱별 상세의 주문 한 건을 누르면 열리는 주문 단위 상세. 카드 거래 상세와 동일 골격에 만나서결제 부호 처리와 하단 고정 안내 문구가 추가된다.
No이름설명
1주문 헤더·금액타이틀 배달의 민족 내역, 상단에 주문일시와 미리 받는 돈 큰 숫자.
2주문 식별 정보주문번호·결제수단(바로결제/만나서 결제) 노출. 주문번호 없으면 '-'.
3차감액 분해어제 매출액 → 차감액(플랫폼 차감액 + 페이허그 수수료) → 미리 받는 돈. 카드와 달리 signedFee로 부호 처리.
4만나서결제 부호 규칙만나서결제(isOffline)면 어제 매출액은 괄호(매출 제외)로, 차감액·미리 받는 돈은 음수(-N원)로 노출해 차감으로 읽히게 한다. 바로결제는 일반 표기.
5하단 고정 안내연초록 박스 고정 문구: '[만나서 결제]는 선정산 대상이 아니며 매출액에서 제외'. 배민(source=BM)이면 '[배민원 주문] 매출액은 고객 배달팁 제외' 문구 추가.
정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
fetchDeliveryOrder(bizNo, id)로 주문 단건을 조회한다. 계산식은 배달앱별 상세와 같으나(차감액=배달사 차감액+페이허그 수수료, 미리 받는 돈=net−페이허그 수수료) 만나서결제/배민원 특성을 문구와 부호로 명시하는 게 차이. 광고비는 이 화면 계산엔 안 들어간다(플랫폼 집계 레벨 항목).
연결데이터 출처
API
fetchDeliveryOrder(bizNo, id) → GET /business/settlement/delivery/orderid=UnifiedPurchaseLedger id, source로 배민 분기 문구 결정확정
계산부호·계산
만나서결제 처리
deliveryFee(만나서결제=net), signedFee로 음수는 그대로/양수는 −부착어제 매출액은 isOffline이면 괄호 표기(매출 제외 의미)확정
분해식
deduction = 배달사 차감액 + 페이허그 수수료transferAmount = net − 페이허그 수수료 (현장결제는 음수)확정
정책정책 안내
만나서결제 선정산 제외
만나서결제=선정산 대상 아님, 매출액에서 제외 → 사후 회수 대상고정 안내 문구로 명시확정
배민원 배달팁 제외
배민(BM) 주문 매출액은 고객 배달팁이 빠진 금액임을 안내확정
