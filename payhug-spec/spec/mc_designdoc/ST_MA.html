key note
입금일 하루치 미리 받은 돈(실제 이체액)을 상단에 크게 보여주고, 그 아래를 카드 · 배달앱 · 페이허그 세 블록으로 분해해 보여주는 정산 상세 메인 화면. 카드사/배달앱 행을 누르면 각 상세로, 예상 지급 차액을 누르면 차액 내역으로 내려간다.
No이름설명
1날짜 네비 + 반영시간입금일을 26년 7월 18일 (토) 형식으로 표기하고 좌우 화살표로 전일·다음일 이동(hasPrev/hasNext 있을 때만 화살표 노출). 날짜는 URL에 보존돼 하위 뎁스에서 뒤로가기 시 유지된다. 아래 회색 글씨는 반영 상태로 내역 반영 시간 11:30(반영 후) 또는 내역 반영 전 11:30(반영 전).
2미리 받는 돈 총액그날 실제로 이체된 금액을 파란색 대형 숫자로 노출(transferAmount). 예시 1,847,200원. 이 값이 화면 최상위 지표이고 아래 세 블록 합계와 정합해야 한다.
3어제 매출액수수료 차감 전 총매출을 회색 박스로 병기(totalSales). 집계 전이면 금액 대신 어제 매출액 집계중 문구. 미리 받는 돈과 대비되는 참고값.
4카드 블록9개 카드사(KB·농협NH·롯데·비씨·우리·하나·신한·삼성·현대)를 0원도 포함해 고정 노출. 각 행은 카드사명·건수·미리 받는 돈. 우측 합계는 카드 total. 승인 있거나 금액 0 아닌 행만 밑줄+클릭 가능 → 카드사별 상세.
5추가 선정산 표기당일 조회 시 오후 6시 추가 선정산으로 지급된 몫이 있으면 금액 아래 파란색 (+12,000원)으로 병기(additionalAmount). 음수면 (-N원). 이미 위 금액에 포함된 내역 표기다.
6배달앱 블록3개 플랫폼(배달의 민족·쿠팡이츠·요기요) 고정 노출, 구조는 카드와 동일. 만나서결제 차감만 있어 승인 0건이어도 금액이 있으면 상세 진입 가능. 행 클릭 → 배달앱별 상세.
7페이허그 블록페이허그가 떼는 항목 묶음. 우측 합계는 페이허그 total(대개 음수). 하위에 예상 지급 차액·수수료 부가세(VAT)·전산 수수료·시스템 이용료가 조건부로 표기된다. 각 항목은 0이거나 해당 없으면 숨김.
8예상 지급 차액 + 툴팁expectedAdjustment가 0이 아닐 때만 노출. 라벨 옆 ? 아이콘 툴팁, 금액은 밑줄 클릭 → 예상 지급 차액 내역 화면(/settlement/adjustments). 아래 파란 (-2,000원)은 추가 선정산분 차액(additionalAdjustment).
정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
이 화면은 백엔드 /business/settlement/detail 한 번의 응답을 카드/배달/페이허그 3블록으로 렌더한다. 총액 = 카드 total + 배달 total + 페이허그 total 구조이며, 만나서결제 차감·광고비는 각 플랫폼 금액에 이미 흡수돼 페이허그 total에는 중복 계산되지 않는다. 화면에 노출되는 수수료율(카드/페이허그)·지급 시각(11:30/18:00)·'예상 지급 차액' 정의는 모두 미확정 3대 지뢰(C1·C2·C4)에 직접 걸린다.

총액 정합
미리 받는 돈 = 카드 total + 배달 total + 페이허그 total페이허그 total은 대개 음수(수수료·차액 차감분)가설
만나서결제·광고비 흡수
만나서결제 차감·배민 광고비는 각 배달 플랫폼 금액에 이미 반영됨payhug.total에 별도 합산 안 함 → 이중차감 방지(코드 주석 근거)확정
추가 선정산(18:00) 병기
additionalAmount/additionalAdjustment/additionalTransferFee는 상위 금액에 이미 포함된 '그 중 18시 배치분'당일 조회 시에만 내려옴(과거일 조회 시 없음)확정
정책미확정 지뢰
수수료율 (C1)
화면의 '전산 수수료'·카드/페이허그 수수료 계산에 쓰이는 요율이 문서마다 병존(1%/0.604%/0.6+0.11+0.1%/0.25%)가맹점 고지 요율과 내부 배분 요율 관계 미확정 → 임의 확정 금지확인필요
지급 캘린더 (C2)
운영 확정: 익일 11:30·18:00 하루 2회, 주말·공휴일 포함reflectedTime 11:30은 오전 배치, additionalAmount는 18시 배치 반영단 DB 설계(D+2)·계약(매일) 정합은 미확정확인필요
예상 지급 차액 정의 (C4)
expectedAdjustment는 추가 지급(+)과 과지급 회수(−)를 단일 순액으로 합산 → 6개념 분리 원칙 위반의 실물방향별(추가 지급 예정 / 이전 지급 조정) 분리 표기 필요'예상 지급 차액' 라벨 존치·재정의 미확정확인필요
페이허그 하위 항목 표기 규칙
수수료 부가세(VAT)=marginFee(면제 시 미노출), 전산 수수료=transferFee(면제 시 '면제'), 시스템 이용료=systemFee(0이면 미노출)각 명칭이 6개념/계약 용어와 어떻게 매핑되는지 미확정확인필요
