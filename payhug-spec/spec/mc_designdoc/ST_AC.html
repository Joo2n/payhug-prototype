key note
정산 전용 계좌(하나은행)로 실제 입금된 내역을 날짜·시각별로 나열하는 통장 성격의 화면. 각 행은 미리 받는 돈(11:30 정기 이체) 또는 선정산 제외액(11:31 별도 입금)으로 라벨링되며, 선정산 제외액 행만 상세로 진입한다.
No이름설명
1뒤로가기헤더 왼쪽 화살표. 직전 화면으로 복귀. 히스토리가 없으면 메인(대시보드)으로 이동.
2입금 계좌 정보입금 계좌는 항상 하나은행(정산 전용 계좌)으로 코드에 하드코딩(로고 고정). 은행명과 계좌번호를 표기하며, API가 값을 주면 사용하되 없으면 '하나은행'으로 기본 표기.
3입금일 컬럼행 왼쪽에 'M.D' 축약 날짜. 같은 날짜의 연속 행은 첫 행에만 날짜를 노출하고 이후 행은 비워 그룹처럼 보이게 함.
4입금처·시각입금처명(기본 '페이허그')과 입금 시각(HH:MM)을 표기. 정기 이체는 11:30, 선정산 제외액은 11:31로 시각이 분리되어 나타남.
5미리 받는 돈 배지초록색 배지. 매일 11:30 정기 선정산으로 이체된 정산금. 이 행은 클릭 불가(상세 없음)이며 금액에 밑줄도 없음.
6선정산 제외액 배지파란색 배지. 11:30 정산 완료 후 수집돼 정기 정산에서 빠졌다가 별도 입금된 금액. 금액에 밑줄이 있고 행 전체가 버튼으로, 클릭 시 선정산 제외액 상세로 이동.
7내역 더 불러오기연두색 버튼. 한 번에 10건씩 페이징 로드. 추가 데이터가 있을 때만(hasMore) 노출되며 로딩 중엔 '불러오는 중...'.
정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
이 화면은 예상·확정값이 아니라 실제 계좌 입금 결과를 보여주는 통장 뷰로, GET /business/settlement/account에서 계좌정보 + 입금 항목 배열을 받아 렌더한다. 핵심 정책 포인트는 한 정산 사이클이 계좌 관점에서 두 건의 입금(11:30 '미리 받는 돈' + 11:31 '선정산 제외액')으로 분리 기록된다는 점이며, 이는 6대 개념 중 '선정산 제외금액'을 별도 이체로 다룬다는 신호다. 은행이 하나은행으로 고정되어 있어 계좌 유형·복수계좌 정책과의 정합성 확인이 필요하다.
연결데이터 출처·페이징
조회 API
GET /business/settlement/account?bizNo=&page= (fetchAccountDeposits)응답: bankName, accountNumber, items[], hasMore10건 단위 무한스크롤 방식(더 불러오기 버튼)확정
행 항목 구조
AccountDepositItem: payoutId, date, time, payerName, amount, label, excludedpayoutId는 선정산 제외액 상세 진입용 식별자(SettlementPayout id)label(노출 텍스트)과 excluded(분기 플래그)가 별도 필드확정
제외액 행 진입
excluded=true인 행만 onClick 활성 → /settlement/account/excluded?bizNo=&payoutId= 이동excluded=false('미리 받는 돈')는 상세 없음·클릭 불가확정
정책입금 계좌 고정
하나은행 고정
코드 주석·로고가 '입금 계좌는 항상 하나은행(정산 전용 계좌)'로 하드코딩bankName이 null이면 '하나은행'으로 폴백 표기복수 정산계좌·타행 정산계좌 케이스가 있는지 정책 확인 필요확인필요
정책두 건 분리 입금
미리 받는 돈 vs 선정산 제외액
같은 입금일에 11:30(미리 받는 돈)·11:31(선정산 제외액) 두 행으로 기록'선정산 제외금액'은 6대 개념 중 하나로 미지급금·바로이체 등과 통합 금지선정산 제외액이 왜 별도 이체되는지의 업무 정의는 상세 화면 배너에서 설명됨확정
입금 시각 표기
미리 받는 돈=11:30, 선정산 제외액=11:31로 노출이 시각이 실제 이체 시각인지 표기용 상수인지 확인 필요확인필요
