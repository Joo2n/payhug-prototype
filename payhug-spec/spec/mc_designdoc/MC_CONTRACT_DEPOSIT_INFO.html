key note
통장 사진 OCR로 자동 추출된 입금받을 계좌(정산계좌)의 예금주·은행·계좌번호를 확인·수정하고 1원 인증을 시작하는 화면. 계약 5단계 중 4단계이나, 코드상 이 화면의 진행바는 5칸 전부 초록으로 렌더된다(4단계 표기와 불일치 — 확인필요).
No이름설명
1진행 인디케이터상단 5칸 막대가 코드상 전부(5/5) 초록으로 렌더 — '4단계' 표기와 불일치(확인필요).
2안내 문구'사장님의 정보가 맞나요?' / '입금 받을 계좌 정보가 맞는지 확인해 주세요'. 입금받을 계좌(정산계좌)임을 명시.
3계좌주명OCR 추출값이 채워진 수정 가능 입력칸. 통장 예금주명.
4은행명OCR 추출 은행명. 인증 요청 시 내부적으로 은행코드로 변환되며, 미지원 은행이면 오류 안내.
5계좌번호OCR 추출 계좌번호. 사장님이 직접 수정 가능.
6OCR 자동입력 안내 토스트'OCR로 자동 입력되었어요 / 잘못 인식된 값이 있으면 직접 수정해주세요'. 진입 후 약 10초간 노출되고 사라진다.
71원 계좌 인증하기주 액션. 입력값으로 1원 입금을 요청하고 성공 시 같은 화면에서 인증번호 입력 단계로 전환.
8다시 첨부하기통장 업로드 화면으로 되돌아가 사진을 다시 첨부.
정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
이 화면은 정산금을 실제로 받을 '입금받을 계좌(SETTLEMENT)' 등록의 첫 단계다. OCR 추출값은 부정확할 수 있으므로 사용자 수정을 전제로 하고, '1원 계좌 인증하기'가 은행에 1원 입금 요청을 걸어 적요 3자리 코드를 발급받는다. 통장 원본 파일은 브라우저 임시 저장소에 보관됐다가 최종 등록 단계에서 함께 전송된다.
연결입력값 출처와 인증 요청
초기값 출처
계좌주명·은행명·계좌번호는 통장 OCR 분석 결과가 URL 파라미터로 넘어와 채워짐(holder/bank/number).purpose=SETTLEMENT 고정 — 입금받을 정산계좌 용도.확정
은행코드 변환
입력 은행명을 내부 은행코드로 매핑. 매핑 실패 시 '지원하지 않는 은행입니다' 안내로 요청 중단.확정
1원 인증 요청
1원 인증 요청 API(requestAccountVerification)에 사용자·계좌 정보 전송 → 응답으로 거래일자·거래번호를 받아 인증 단계로 전환.확정
통장 파일 보관
앞 화면에서 저장한 통장 파일이 브라우저 임시 저장소에 남아 있다가 최종 등록 때 함께 전송.확정
정책용어·정책
입금받을 계좌 정의
정산금을 실제 수령하는 일반 입출금 계좌(정산계좌). 출금 전용 락계좌(전용계좌)와 구분된다.확정
OCR 값 신뢰도
OCR 추출값은 오인식 가능성을 전제로 사용자 수정을 허용. '직접 수정' 안내 상시 필요.확정
예금주 실명 대조
1원 인증만으로 예금주 실명 일치를 어디까지 검증하는지(입력 계좌주명 vs 실제 예금주) 정책 확인 필요.확인필요
