key note
선정산금이 입금될 하나은행 락계좌(출금전용)와 정산금을 받을 사업자 입출금계좌 2개를 개설하도록 안내하는 진입 화면. PC에서는 하나은행 My브랜치 QR을 띄워 휴대폰으로 개설을 유도하고, 개설 후 돌아와 다음 단계로 넘어간다.
No이름설명
15단계 진행바 (3/5)계약 전체 5스텝 중 3번째(선정산 락계좌) 진입 지점을 표시. 앞 2칸은 완료(진녹색), 현재 칸은 연녹색.
2펌뱅킹 출금전용 계좌 안내선정산금이 입금되는 전용 계좌. 사장님이 임의 출금할 수 없는 락(잠금) 계좌라는 성격을 아이콘·문구로 강조.
3입출금 사업자계좌 안내락계좌에서 스윕된 정산금을 최종 입금받을 계좌. 두 계좌의 역할이 다름을 분리해 설명.
4하나은행 My브랜치 QRPC에서는 계좌 개설 페이지가 모바일 전용이라 QR을 스캔해 휴대폰에서 개설하도록 유도. 모바일 접속 시에는 바로가기 버튼으로 대체.
5개설 순서 안내문출금전용 계좌를 먼저 개설 후 입출금 계좌 개설. 일반 입출금 계좌를 먼저 만들면 20일 뒤에야 출금전용 계좌 개설이 가능하다는 은행 정책 경고.
6계좌 개설 완료 버튼실제 개설 여부와 무관하게 다음 단계(통장 업로드)로 이동시키는 사용자 자기신고 버튼. 서버 검증 없음.
정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
이 화면은 하나은행 락계좌 인프라에 100% 의존한다. 락계좌는 선정산금이 입금되는 출금전용 계좌이며, 어드민에서 11:00·14:00 배치로 락계좌→모계좌 스윕(어드민 용어 '매출 회수', 정책의 '과지급 회수'와 전혀 다른 개념)이 일어나는 구조다. 개설 자체는 은행 앱에서 이뤄지고 PayHug는 개설 완료를 사용자 신고로만 받으므로, 실제 개설·검증은 후속 통장 업로드/1원 인증 단계에서 이뤄진다.
연결계좌 개설 흐름·이동
모바일/PC 분기
window.matchMedia('(max-width:767px)')로 판정. PC=QR 노출('휴대폰 카메라로 QR코드를 스캔'), 모바일=하나은행 My브랜치 바로가기 버튼('하나은행 My브랜치에서 계좌를 개설').QR·바로가기 대상 URL은 하나은행 My브랜치 특정 지점 페이지(m.hanabank.com) 하드코딩.확정
다음 단계 이동
'계좌 개설 완료' 클릭 시 /contract/upload-pre-payment(통장 업로드)로 이동. businessId·addBusiness·edit 쿼리를 이어붙여 다사업자/수정 플로우 유지.확정
개설 완료 검증 없음
버튼은 실제 개설 여부를 서버에 확인하지 않고 넘어감. 실제 검증은 이후 통장 OCR + 1원 인증에서 수행.가설: 잘못 눌러도 다음 화면에서 통장 미보유 시 걸러진다는 전제.가설
정책락계좌(출금전용) 성격
락계좌 = 출금전용
선정산금이 입금되는 하나은행 펌뱅킹 출금전용 계좌. 사장님이 자유롭게 출금 불가.어드민에서 락계좌→모계좌 스윕(11:00·14:00 배치)을 '매출 회수'로 부름 — 정책의 '과지급 회수'와 다른 개념(6대 개념 통합 금지).확정
2계좌 구조
① 락계좌(출금전용): 선정산금 입금 → ② 사업자 입출금계좌: 정산금 최종 수령. 역할 분리 유지 필요.확정
개설 순서 20일 제약
'일반 입출금 계좌를 먼저 개설하면 20일 뒤에 출금전용 계좌 개설 가능'은 하나은행 대포통장 방지 정책 추정.확인필요: 20일 수치의 정책 출처(은행 약관) 미확인 — 화면 문구로만 존재.확인필요
하나은행 전속
선정산 락계좌는 하나은행(은행코드 081)만 등록 가능. 후속 확인 화면에서 코드 081 아니면 등록 차단.확정
