## 1. 문서 구조 · 장표 순서

장표 프레임은 이름 앞에 번호 접두사(`00_` / `01.` / `02.` / `03_` / `04_`)를 붙여 순서를 관리한다. 배포 문서(PDF)는 이 순서대로 장표를 **복사하여 사용**한다.

| 순서 | 프레임 이름 (node id) | 역할 | 렌더 타이틀 |
|---|---|---|---|
| 1 | `00_Cover_start` (`1:228`) | 표지(시작) | `Main_title` / `sub_title` / `V.1.0.0` |
| 2 | `01.Document_history` (`1:185`) | 문서 변경 이력 | `Document History` |
| 3 | `02.Page_flow` (`1:166`) | 플로우차트 | `Flow-chart` |
| 4 | `03_Cover_mid` (`1:363`) | 섹션 표지(구분 표지) | `section_title` / `section_title_sub` |
| 5 | `04_contents_type01` (`1:83`) | 화면설계 프레임 — 목업+설명패널 2단 | (헤더 메타바) |
| 5' | `04_contents_type02` (`1:139`) | 화면설계 프레임 — 목업 풀폭(설명패널 없음) | (헤더 메타바) |
| 6 | `00_Cover_end` (`1:225`) | 종료 표지 | `FINISH` / `Copyright ⓒ 2025 Payhug, Inc.` |

즉 **표지(Main_title/sub/작성자/Date/Version) → Document history → Flow chart → section_title(섹션표지) → 화면설계 프레임(type01/type02 반복) → FINISH** 순서.

### 표지(00_Cover_start) 필드
- 좌상단: Pay hug 로고 + 강조 bar(퍼플)
- `Main_title` (검정, 대) → `sub_title` (회색) → `V.1.0.0` (버전)
- 우하단 작성자 블록(`Writer` `1:231`), 각 행 = 라벨 + 값:
  - `Date` — `2025.MM.DD`
  - `Depature` — `최지원`
  - (세 번째 `manager` 행은 hidden 처리, 필요 시 노출)

### 종료(00_Cover_end)
- 중앙 `FINISH`, 하단 `Copyright ⓒ 2025 Payhug, Inc.`

### 섹션 표지(03_Cover_mid)
- `section_title` (섹션명) + `section_title_sub` (섹션 부제)

## 2. 파일명 규칙 · 배포 절차

### 파일명 (node `1:55`, 원문)
```
파일명: 타이틀_V0.0.0_YYYYMMDD.pdf
```
버전 3자리 `V(1자리).(2자리).(3자리)` 자리수 의미:
- **1자리 →** 서비스 출시 및 고도화(출시 후 업데이트)
- **2자리 →** 기능 추가
- **3자리 →** 작은 업데이트

### 배포 준비 순서 (node `1:54` + 절차 그룹 `1:56`, 원문)
> "화면정의서는 PDF추출을 진행해야하므로, 아래 장표를 복사하여 사용 / 파일 배포 준비는 아래순서와 같음."

1. **PDF 추출** — 배포를 위한 PDF추출. 배포일자 필수기입
2. **Local file(.fig) 추출** — 산출물 관리 및 히스토리 파악을 위한 추출. 추출 후 드라이브에 업로드.
3. **Save to version** — 피그마 파일 내 버전관리 가능. 버전 선포 후. 해당 파일에서 계속해서 수정 및 보완 작업 진행.

## 3. 재사용 컴포넌트 (Document guide 범례, node `1:247`)

범례는 3행 그리드로 배치(제목에 순번 `1.`~`10.` 포함). 각 항목 = 예시 컴포넌트 + 캡션.

| # | 타이틀(원문) | 캡션(원문) | 컴포넌트 / 표기법 |
|---|---|---|---|
| 1 | 장표 개정이력 | 페이지 혹은 콘텐츠 등에 가장 강조되어야하는 부분에 사용함. 예. CTA, Primary button | `장표_히스토리`(`1:306`): 퍼플 바 `YYYY.MM.DD ─ V.0.0.0` + `• Text` 개정 표기 / `장표_신규`(`1:302`): 우상단 대각선 `NEW V0.0.0` 삼각 뱃지 |
| 2 | TBD | 지연, 미정 된 기능에 표시함 | `TBD`(`1:304`): 노란 박스 + 빨강 `TBD` 텍스트 |
| 3 | 삭제 | 삭제 된 기능에 표시함 | `DELETED`(`1:305`): 빨강 테두리 박스 + 빨강 `DELETED` 텍스트 |
| 4 | 디스크립션 번호 | N번 하위 번호의 경우 N-1, N-2..와 같이 순번지정 | `디스크립션 번호`(`1:249`): 원형 번호 마커. 색상 `color=blue`/`color=yellow`, 방향 `type=default/right/left/up/down`(화살표 달린 5종) |
| 5 | 영역표시 | 디스크립션 사용이나, 설명을 위한 영역을 표시할때 사용함 | `영역표시_화살표`(`1:317`, 세로 치수 화살표) + `영역표시_사각형`(`1:318`, 점선 사각형) |
| 6 | 인터랙션 | 애니메이션, 인터랙션 사용이나, 설명을 위해 표시함 | `interaction`(`1:308`): `type=tap`(그린 원) / `type=drag`(그린 원+화살표) |
| 7 | 화면생략 | N번 하위 번호의 경우 N-1, N-2..와 같이 순번지정 ⚠️ | `화면생략`(`1:303`): 물결(wavy) 라인. ⚠️ 캡션이 #4와 동일 — 템플릿 플레이스홀더 잔존으로 보임(실사용 시 재작성 필요) |
| 8 | 논의사항 노트패드 | 🔥 해당 컴포넌트는 작업시 논의사항을 파악하기 쉽게 만들어진 컴포넌트로, 화면설계서 문서 내에는 포함되지 않게 주의해주세요!😊 | `노트패드_논의사항`(`1:307`): `Notepad` 헤더 + `Summary` + `내용을 입력해주세요.` — **배포(PDF)에는 미포함** |
| 9 | IA 장표 상태표시 | IA 작성할때, 각 페이지별 상태 표시 | `문서 상태 표시`(`1:349`) 뱃지 6종 `Property 1=` : 신규(퍼플) · 완료(그린) · 삭제(레드) · 개선(블루) · 기존(그레이) · 지연(그레이) |

## 5. 화면설계 프레임 템플릿 (04_contents)

프레임 크기 `1920 × 1280`. 상단 메타바(`content/header`) + 본문 2단(type01) 또는 풀폭(type02).

### 상단 메타바 (`content/header`, `1:114`) — 2행 구성
좌측부터 라벨 셀(회색 배경) + 값 셀:

**1행:**
| 라벨 | 값(플레이스홀더) |
|---|---|
| `Page` | `page_title` |
| `Page ID` | `page_Id` |
| `System` | `mobile web/ native/ pc` |
| `Date` | `YYYY.MM.DD` |
| `Writer` | `name` |

**2행:**
| 라벨 | 값(플레이스홀더) |
|---|---|
| `Flow` | `page_Flow` |
| `Note` | `page_note` |

- 우측 끝: `LOGO` 셀 = **Pay hug** 로고(`Payhug_img`).

### 본문 배치
- **type01 (`1:83`)** — 2단:
  - **좌 = 화면 목업 영역** `contents`(`1:85`, 폭 1300). 내부에 `Frame(375*812)`(`1:113`) 모바일 목업 플레이스홀더.
  - **우 = 설명 패널** `Des_contents`(`1:84`, 폭 500) = `keynote`(`1:86`):
    - `key note` 헤더
    - `keynote_text`: `텍스트를 작성해주세요. 텍스트를 작성해주세요.`
    - 디스크립션 표 — 컬럼 `No` / `Name` / `Note`
      - 행 예: `1` | `타이틀` | `텍스트를 작성해주세요. 텍스트를 작성해주세요.`
      - 행 예: `2` | `타이틀` | `텍스트를 작성해주세요. 텍스트를 작성해주세요.`
      - 행 복사 후 사용(넘버 디스크립션 | 복사 후 사용).
- **type02 (`1:139`)** — 우측 설명 패널 없이 `contents` 풀폭(1820). 목업이 넓거나(PC/와이드) 별도 설명패널이 불필요한 화면용.

### 번호 마커 운용 규칙
- 목업의 지시 지점에 `디스크립션 번호`(파랑/노랑 원형 마커)를 찍고, 우측 설명 패널의 `No`와 매칭.
- 하위 번호는 `N-1, N-2 …` 형식으로 순번 지정(범례 #4).
