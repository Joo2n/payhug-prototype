# PayHug 화면설계서 keynote 작성 정책 (파일럿 역설계 확정본)

> 이 문서는 파일럿 1건(어드민 매출조회 목록 화면 `AD_SALES_LIST`)을 코드→keynote로 역설계하며 사람이 실제로 내린 판단을 규칙으로 굳힌 것이다. 208개 화면을 생성하는 에이전트는 **이 문서를 절차서로 삼아** 화면마다 그대로 반복한다. 예시는 전부 매출조회 화면에서 뽑았다 — 다른 화면에선 같은 규칙을 그 화면의 코드/캡처에 대입해 적용하라.

---

## 1. 작성 철학 (왜 이렇게 쓰는가)

keynote는 "코드가 무슨 일을 하는가(behavior/endpoint)"를 나열하는 개발 문서가 아니라, **기획자가 화면을 위→아래로 훑을 때 눈에 걸리는 것과 그 뒤에 숨은 판단 기준을 사람 말로 끌어올린 문서**다. 코드에만 있어서 화면만 봐선 모르는 사실 — 카운터가 검색해도 안 줄어든다는 것, 주소가 잘려 보인다는 것, 액션 버튼이 평소엔 숨어 있다는 것, 정산 활성/비활성을 무엇으로 판정하는지가 정해져 있지 않다는 것 — 을 발굴해 기획자 옆에 놓아 검토를 돕는 게 목적이다. 그래서 dev 식별자(`APPROVED`·`isSettlementActive`·`i+1`·`stopPropagation`)는 100% 한글 동작어로 번역하고, UI에 실제로 박히는 문구(제목·placeholder·빈상태·탭 라벨)는 요약하지 말고 원문 그대로 인용하며, 근거 없는 값(수수료율·지급일·활성 판정 기준)은 절대 창작하지 않고 요소 바로 옆에 빨강 `개발 확인 필요`로 남긴다. 문체는 개조식·명사 종결(~함/~됨/~이동)이고, 마케팅체·완결형 존댓말은 쓰지 않는다.

## 2. 한 화면을 처리하는 절차 (모든 화면 이 7단계 반복)

### 1단계 — 코드 정독 (원문째 수집)
해당 화면의 `page.tsx`와 연결된 `components`·`hooks`·`services`를 **JSX 렌더 순서 그대로** 읽는다. 화면에 그려지는 모든 것을 원문으로 수집한다: 정적 헤더·카운트, `placeholder`, 버튼/탭 라벨, 뱃지 값과 색, 상태 분기 문구(로딩/빈/에러), 이벤트 핸들러, 표시 파생 로직(`i+1`·`truncate`). md 문서는 이미 번역된 표현을 재활용하거나 교차검증하는 **2차 자료로만** 쓴다 — 1차 근거는 코드다.
> 예) 매출조회에서 `<h1>매출 조회`, `placeholder="가맹점명, 사업자번호, 대표자명으로 검색"`, `merchantSortPriority` 반환값 0/1/2, `filtered.map((m,i)=>...{i+1})`을 그대로 뽑아 둔다.

### 2단계 — 화면 요소(구획) 식별
렌더를 위→아래로 훑어 사용자가 보는 **시각 덩어리**로 나눈다. 이 덩어리가 곧 No 행이다(화면당 **3~5개**). API·동작 단위가 아니라 '보이는 구획' 단위로 묶는 것이 핵심.
> 표준 순서: ① 헤더(제목·안내문·카운트) → ② 검색/필터 → ③ 목록/본문(정렬·표 항목·상황별 문구·뱃지 서브) → ④ hover로 나타나는 숨은 액션 → ⑤ 행/항목 클릭 이동.
> 예) 매출조회는 정확히 이 5구획으로 떨어졌다.

### 3단계 — 누락 점검
아래 **§5 누락 점검표**를 순회하며 코드/캡처엔 있는데 초안에 빠진 것을 적발한다. 렌더된 캡처로 실제 문구를 교차검증한다.
> 예) `총 {merchants.length}개`는 필터 전 배열을 쓰므로 "검색해도 줄지 않음"을 명시. `truncate`로 주소가 …로 잘림을 발굴. 캡처를 세어 목업 14개임을 확보.

### 4단계 — 번역
dev 용어·식별자를 §4 사전으로 기획어 치환한다. 근거 없는 값은 창작 금지 — `개발 확인 필요`/`TBD`로 둔다.
> 예) `isSettlementActive` → 정산 활성/비활성, `i+1` → 위에서부터 다시 번호 매김, `stopPropagation` → 행 클릭과 따로 동작.

### 5단계 — 그룹핑
각 구획 No 아래에 소제목(정렬 순서 / 표 항목 / 상황별 문구 / 뱃지)으로 하위 동작을 묶고 `–` 한 단 들여쓰기 + 핵심어 볼드로 재구성한다. 개조식·명사 종결. 상단 memo에 화면 성격·데이터 출처(목업 N개)·자동 재조회를 먼저 적는다.

### 6단계 — 마커 매핑
No(3~5)를 좌측 목업의 영역선(대상 영역 높이만큼)+원마커와 1:1로 얹는다. 뱃지 등 컬럼 세부는 `3-1`/`3-2` 서브마커로 **컬럼 헤더 옆 빈 공간**에 단다(컬럼명을 가리지 않게).

### 7단계 — 검증 패스
생성 후 "코드/캡처엔 있는데 keynote엔 없는 요소·UI 문구·빈상태·조건 분기"를 다시 한 번 적발한다(파일럿에서 사람이 실제로 잡았던 것: 총N개=전체·empty-state 3종·placeholder·말줄임·hover). 걸리면 해당 구획 No 아래에 보완한다.

## 3. 반드시 코드에서 서피싱할 패턴 체크리스트

코드에서 아래 패턴을 만나면 **반드시** keynote로 끌어올린다. 좌측이 코드 신호, 우측이 keynote 표기 방식.

| # | 코드 패턴 | keynote로 반드시 이렇게 서피싱 | 매출조회 예시 |
|---|---|---|---|
| 1 | 조건부 렌더 `{cond && <요소>}` / `STATUS_MAP[x]` 분기 | **어떤 상태에서만** 노출되는지 명시. 조건은 케이스로, 상태는 기획어로 번역해 볼드 | `contractStatus==='PENDING' && <승인>` → "계약이 **대기**인 가맹점에만 → **[승인]** 버튼" |
| 2 | 정렬 함수 반환 우선순위 0/1/2 | **"정렬 순서"** 소제목으로 묶고 ①②③ 서술 + "사용자가 바꾸는 토글 없음" 여부까지 | ①승인+활성 ②승인+비활성 ③미승인, 토글 없음 |
| 3 | `isLoading` 분기 텍스트 | 상황별 문구로 원문 그대로 | 불러오는 중 → "로딩 중..." |
| 4 | 빈목록/0건 분기 `searchQuery ? A : B` | 두 경우를 나눠 원문 그대로 | 검색 0건 → "검색 결과가 없습니다." / 데이터 0건 → "등록된 가맹점이 없습니다." |
| 5 | `alert()`·에러 문구 | 막는 조건 + 문구 그대로 | "결과가 0건이면 알림(alert)을 띄우고 중단" (해당 화면에 있으면) |
| 6 | `opacity-0 group-hover:opacity-100` / `hover:bg-*` | **별도 불릿**으로: "평소엔 숨어 있다 마우스 올리면 나타남", "마우스 올리면 배경색 진해짐(누를 수 있다는 표시)" | 액션 버튼 hover 노출 / 행 hover 배경 강조 |
| 7 | `toLocaleString`·`formatBizNo`·표시 포맷 함수 | 표기 관용구로: "천단위 [,] 콤마 표기", "사업자번호를 형식에 맞춰 표기" | 금액 컬럼 콤마, 사업자번호 하이픈 |
| 8 | `truncate` / `max-w` / `ellipsis` | "길면 …로 줄여서 표시" (px·클래스명 숨김) | 주소 컬럼 …말줄임 |
| 9 | `router.push` / `openTab` 이동 | 이동 대상 화면명 + 대괄호 Page ID + 탭 모드 동작 병기 | 행 클릭 → 매출 상세 화면**[AD_SALES_DT]**, 탭 모드는 "○○가맹점 매출" 탭으로 열림 |
| 10 | `e.stopPropagation()` 안의 핸들러 | "행을 누르는 것(매출 이동)과는 **따로 동작**" | [승인] 버튼 클릭이 매출 이동으로 번지지 않음 |
| 11 | 필수/유효성 검증(`if(!field)`, `dateFrom>dateTo`, `accept=.xls,.xlsx`, 글자수) | 제한·필수·유효 조건 명시. 제한 없으면 "입력 글자수 제한 없음"도 명시 | 검색 input `maxLength` 없음 → "입력 글자수 제한 없음" |
| 12 | `useState(초기값)` / 초기 필터 | **"기본값(default : ...)"** 콜론 표기 | (기간 필터 있는 화면) default : 이달 1일 ~ 오늘 |
| 13 | `placeholder="..."` | "입력창 안내문 : \"...\"" 원문 그대로 | "가맹점명, 사업자번호, 대표자명으로 검색" |
| 14 | 클라이언트 filter/sort(서버 호출 없음) | "입력 즉시 걸러짐(서버에 다시 묻지 않음)" — 서버 재호출 여부 반드시 구분 | 검색은 로컬 필터, 서버 재호출 없음 |
| 15 | 전체 개수 vs 필터 후 개수 (`merchants.length`가 필터 전) | "검색과 상관없이 **전체 수**(검색해도 줄지 않음)" — 모수 명시 | 헤더 카운터는 `merchants.length`, 표는 `filtered` — 다른 변수 |
| 16 | 진입/포커스 자동 fetch (`useEffect`·`useTabFocus`) | "진입하면 자동으로 불러옴(다른 탭 갔다 돌아와도 다시 불러옴)" | mount + 탭 복귀 + 포커스 복귀 재로드 |
| 17 | 뱃지 색 매핑 (`bg-emerald/gray/red`) | 서브번호(3-1 등)로 묶고 "값=색" 나열 | 계약상태 승인=초록·대기=회색·거절=빨강 / 정산 활성=초록·비활성=회색 |
| 18 | 서버값 그대로 렌더 + 미확정 지뢰(수수료율/지급일/예상차액) | "화면은 서버값을 그대로 표시할 뿐"이라 적고, 판단 근거 미확정이면 **빨강**으로 "~는 개발 확인 필요"/TBD. 값 창작 금지 | 정산 활성/비활성 **판정 기준은 개발 확인 필요**(빨강) |

## 4. dev → 기획자 번역 사전

코드 식별자·패턴을 keynote에서 만나면 아래 우측 표현으로 바꾼다. **좌측 문자열은 keynote에 절대 노출 금지.**

| dev (코드) | 기획자 (keynote) |
|---|---|
| `APPROVED` / `ACTIVE` (contractStatus) | 승인 |
| `PENDING` (contractStatus) | 대기 |
| `REJECTED` (contractStatus) | 거절 |
| `isSettlementActive: true/false` | 정산 활성 / 비활성 |
| `map((m,i)=>...i+1` | 번호는 정렬·검색 후 위에서부터 다시 매겨짐 |
| `truncate` / `max-w-[200px]` / `ellipsis` | 길면 …로 줄여서 표시 |
| `e.stopPropagation()` | 행 클릭(매출 이동)과는 따로 동작 |
| `placeholder="..."` | 입력창 안내문 : "..." |
| `opacity-0 group-hover:opacity-100` | 평소엔 숨어 있다가, 행에 마우스를 올리면 오른쪽에 나타남 |
| `hover:bg-primary-50/30` (행) | 행에 마우스를 올리면 배경색이 진해짐 (누를 수 있다는 표시) |
| 클라이언트 `merchants.filter(...)` | 입력하는 즉시 목록이 걸러짐 (서버에 다시 묻지 않음) |
| `.includes(searchQuery)` | 일부만 입력해도 찾아줌 |
| `!searchQuery` 전체 반환 | 검색어를 지우면 전체 목록으로 복원 |
| `merchantSortPriority` / `.sort()` | 정렬 순서(위에서부터), 사용자가 바꾸는 토글 없음 |
| `useEffect(fetch)` / `isTabActive` / `useTabFocus` | 진입하면 목록을 자동으로 불러옴 (다른 탭 갔다 돌아와도 다시 불러옴) |
| `merchants.length` (총 개수) | 검색과 상관없이 전체 가맹점 수 (검색해도 줄지 않음) |
| `isLoading === true` | 불러오는 중 |
| `filtered.length === 0` | 검색 결과 없음 / 가맹점이 하나도 없음 |
| `openTab({...})` vs `router.push()` | 탭 모드에서는 새 탭으로 열림, 아니면 현재 화면을 전환 |
| `router.push(\`/sales/${bizNo}\`)` | 매출 상세 화면[AD_SALES_DT]으로 이동 (Page ID 대괄호) |
| `formatBizNo(businessNumber)` | 사업자번호를 형식에 맞춰 표기 |
| `toLocaleString()` / 천단위 | 천단위 [,] 콤마 표기 |
| `bg-emerald` / `bg-gray` / `bg-red` | 초록 / 회색 / 빨강 |
| `dateType TRANSACTION / PAYOUT` | 거래일 / 지급예정일 (기준 날짜) |
| `txStatus 전체/정상/취소` | 거래상태 (취소 = 승인취소 또는 매입취소) |
| `salesSource CARD / BM / YOGIYO / COUPANG` | 카드 / 배달의민족 / 요기요 / 쿠팡이츠 |
| `netPayoutAmt` | 순지급액 |
| `isPreSettlementTarget true/false` | 선정산 대상 / 미대상 |
| `dataSource MANUAL_SINGLE / MANUAL_EXCEL` | 수동 등록 태그 / 엑셀 등록 태그 |
| `useState(기본값)` / 초기 필터 | 기본값(default : ...) |
| `disabled` (버튼) | 버튼이 비활성화됨 |
| `alert("...")` | 알림(alert)으로 막아 실행되지 않음 |

> 사전에 없는 식별자를 만나면 임의 창작하지 말고, 같은 원칙(상태 상수→한글 라벨, CSS→동작·표기 관용구, 서버값→"서버값 그대로 표시")으로 번역하되 판정 근거가 코드에 없으면 빨강 처리.

## 5. 누락 점검표 — 모든 화면 공통 질문

화면마다 keynote 초안을 완성한 뒤 아래 질문을 **전부** 던진다. 하나라도 "아니오"면 그 요소를 해당 구획 No 아래에 보완한다.

1. **헤더 요소**: 화면 최상단의 제목·부제 안내문·카운트/요약 뱃지가 keynote에 '요소'로 잡혔나? 카운트/합계가 **전체 기준인지 필터 후 기준인지** 코드로 확인해 명시했나?
   > 매출조회: 제목 "매출 조회" + 안내문 원문 + "총 N개 가맹점"이 헤더 구획으로 잡혔고, 카운터가 `merchants.length`(전체)라 "검색해도 줄지 않음"을 명시.
2. **상황별 문구**: 로딩 중 / 검색 0건 / 데이터 0건 / 조회 실패(에러) 각각의 노출 문구를 **원문 그대로** 적고, 분기 조건(검색어 유무 등)을 명시했나?
   > "로딩 중..." / "검색 결과가 없습니다." / "등록된 가맹점이 없습니다." — 뒤 둘은 검색어 유무로 갈림.
3. **UI 원문**: placeholder·버튼 라벨·탭 라벨·안내문·툴팁을 뜻 요약이 아니라 **코드/캡처 원문 그대로** 옮겼나?
   > placeholder 원문, hover 링크 "매출 >", 탭 라벨 "○○가맹점 매출".
4. **뱃지 색**: 각 상태 뱃지/칩의 표시 색·스타일(초록/회색/빨강 등)을 값과 짝지어 적었나?
   > 계약상태 3색 + 정산 2색을 3-1·3-2 서브로.
5. **hover/포커스 인터랙션**: 마우스 올림/포커스/선택 시 새로 나타나거나(숨김 해제) 시각이 바뀌는 요소(숨은 액션 버튼·배경 강조·강조색)를 인터랙션으로 적었나?
   > "액션 버튼 평소 숨김→hover 시 나타남", "행 hover 배경 진해짐".
6. **리스트 파생 표시**: 행 번호의 기준(원본 순번 재매김 여부), 긴 텍스트 말줄임(…), 정렬·검색 후 순서/번호가 바뀌는 규칙을 적었나?
   > 번호는 정렬·검색 후 재매김(화면 순번, DB id 아님), 주소 …말줄임.
7. **복수 클릭 영역**: 한 행/카드 안에 클릭 목적지가 다른 영역이 둘 이상이면, 각각 어디로 가고 **서로 독립 동작(전파 분리)** 하는지 기획어로 적었나?
   > 행 전체→매출 상세[AD_SALES_DT], 행 안 [승인]→가맹점 상세[AD_MERCHANT_DT], 둘은 따로 동작.
8. **화면 성격·데이터 출처·재조회**: 진입/탭 복귀/포커스 시 재조회 트리거를 적고, 표시 데이터가 **실데이터인지 목업(예시)인지** 화면 성격 메모를 상단에 넣었나?
   > memo: "성격=가맹점 선택 관문", "예시(목업) 14개 기준", "진입 자동 로드+탭/포커스 복귀 재로드".
9. **미확정 값 플래그**: 각 요소별로 근거가 불명확한 값·판단 기준(무엇으로 활성 판정? 지급일 산정?)을 임의로 채우지 않고 **'개발 확인 필요/TBD'로 그 요소 옆에** 빨강 표기했나?
   > "정산 활성/비활성을 무엇으로 판단하는지는 개발 확인 필요"(빨강).

## 6. 가독성·포맷 규칙 (파일럿 클래스 사용법)

파일럿 목업의 keynote는 클래스로 위계를 표현한다. 아래대로 쓴다.

- **`.grp` (볼드 소제목) 그룹핑**: 한 No 행 안에 하위 항목이 **3개 이상** 묶이면 "정렬 순서" · "표 항목" · "상황별 문구" 처럼 볼드 소제목으로 구획. 하위가 1~2개면 소제목 없이 바로 불릿.
- **`.b` (부모 문장)**: 결론/동작을 담는 부모 불릿. 명사 종결.
- **`.i` (`–` 한 단 들여쓰기)**: 부모 아래 부연·예시·세부·원문 문구는 `–` 불릿으로 한 단 내린다. 부모=결론/동작, 자식=조건·예외·원문 문구.
- **`.red` (빨강)**: 판단 근거 미확정·개발 확인 필요·더미데이터·예외 정책에만. **3대 지뢰(수수료율·지급일·예상차액) 노출 지점은 반드시 빨강 또는 TBD.**
- **`.sb` (서브마커 3-1/3-2)**: 한 요소 안에서 다시 갈라지는 하위 요소(뱃지 종류 등)는 `3-1)`·`3-2)`로 매기고 좌측 목업 서브마커와 1:1 대응. 서브마커는 컬럼명을 가리지 않게 헤더 위/옆 빈 공간에.
- **핵심어 볼드**: 요소명·상태 라벨·조건어(**승인**/**활성**/**대기**, **[승인]**·**[매출>]** 버튼, **즉시**, **전체 가맹점 수**)만 볼드. 문장 전체·과한 볼드 금지.
- **대괄호 Page ID**: 화면 이동은 항상 `[AD_SALES_DT]`처럼 대괄호 Page ID로. 이동 대상 화면명 + 탭 모드 동작을 세트로.
- **콜론 스펙 표기**: 기본값·안내문·문구는 "필드 : 값" 콜론형 (`default : ...`, `입력창 안내문 : "..."`).
- **상단 memo 블록**: 화면 성격·데이터(목업/더미 여부)·진입 시 로드 동작은 표 위 memo 블록에 요약. 더미·운영이슈는 여기서 빨강.
- **No 행 개수**: 화면 요소 단위로 **3~5개**(헤더→검색→목록→hover 액션→행 클릭). 기능 나열이 아니라 눈에 보이는 영역 순서.

### 파일럿 골격 예시 (매출조회 목록 발췌)

```
[memo]  성격 : 매출·매입을 조회할 가맹점을 고르는 '선택 관문'
        데이터 : 예시(목업) 14개 가맹점 기준        ← .red
        로드 : 진입 자동 로드 + 탭/포커스 복귀 시 재로드

1  헤더
   • 제목 : "매출 조회"
   • 안내문 : "가맹점을 선택하여 매출/매입 데이터를 조회합니다"
   • 우측 카운트 : "총 N개 가맹점"
     – 검색과 상관없이 전체 가맹점 수 (검색해도 안 줄어듦)

2  검색
   • 가맹점명·사업자번호·대표자명으로 검색 (부분일치, 글자수 제한 없음)
   • 입력하는 즉시 걸러짐 (서버에 다시 묻지 않음) / 지우면 전체 복원
   • 입력창 안내문 : "가맹점명, 사업자번호, 대표자명으로 검색"

3  가맹점 목록
   [정렬 순서]  ①승인+활성  ②승인+비활성  ③미승인 (토글 없음)
   [표 항목]   번호·가맹점명·사업자번호·대표자·주소·계약상태·정산·(hover 버튼)
     – 번호는 정렬·검색 후 위에서부터 다시 매겨짐
     – 주소가 길면 …로 줄여서 표시
     – 행에 마우스 올리면 배경색 진해짐 (누를 수 있다는 표시)
   [상황별 문구]  로딩 → "로딩 중..." / 검색0건 → "검색 결과가 없습니다."
                / 데이터0건 → "등록된 가맹점이 없습니다."
   3-1) 계약상태 뱃지 : 승인=초록 · 대기=회색 · 거절=빨강
   3-2) 정산 뱃지 : 활성=초록 · 비활성=회색
        – 활성/비활성을 무엇으로 판단하는지는 개발 확인 필요   ← .red

4  마우스 올림 버튼 (평소 숨김 → hover 시 오른쪽에 나타남)
   • 계약이 대기인 가맹점에만 → [승인] : 가맹점 상세[AD_MERCHANT_DT]로 이동
     – 행 클릭(매출 이동)과는 따로 동작
   • 모든 행에 → [매출 >] 링크

5  행 클릭
   • 행을 누르면 그 가맹점 매출 상세[AD_SALES_DT]로 이동
     – 탭 모드에서는 "○○가맹점 매출" 탭으로 열림
```

## 7. 사람문체 DO / DON'T

### DO
- 개조식·명사 종결로 쓴다: ~함/~됨/~표시/~이동/~노출. 마침표 거의 안 씀.
- 코드에만 있던 로직을 기획자 관점으로 끌어올린다: 정렬 우선순위, 서버 재호출 여부, 자동 새로고침, 전체수 모수, hover 숨김 액션까지 전부 서술.
- dev 용어를 사람 말로 번역: `APPROVED`→승인, `isSettlementActive`→활성/비활성, `i+1`→위에서부터 다시 번호 매김.
- 조건 분기는 케이스로: "계약이 **대기**인 가맹점에만", "검색해도 줄지 않음".
- UI 문구(placeholder·빈상태·로딩)는 원문 그대로 큰따옴표로 인용.
- 괄호로 이유·의미를 덧붙여 사람처럼: "(누를 수 있다는 표시)", "(서버에 다시 묻지 않음)".
- 미확정은 솔직하게 빨강/개발 확인 필요/TBD로 남기고 값을 지어내지 않음.

### DON'T
- 완결형 존댓말 서술(~합니다/~됩니다/~할 수 있습니다)을 개조식 프레임에 섞지 않음(인증 정책 스펙북만 예외).
- 마케팅·설명체 금지: 직관적으로/원활하게/손쉽게/효율적으로/~를 통해 ~할 수 있습니다.
- 코드 용어·식별자 그대로 노출 금지: `APPROVED`/`PENDING`/`isSettlementActive`/`i+1`/`stopPropagation`/`200px`/`opacity-0`.
- 접속사·수식어로 문장 늘리기 금지(따라서/또한/그리고/한편), 이모지·과한 볼드·균일한 완전문장 단락 금지.
- 근거 없는 값 창작 금지 — 수수료율·지급일·예상 지급 차액 3대 지뢰는 채우지 않음.
- 존재하지 않는 상태 라벨·미구현 기능(랜딩 카피) 서술 금지, 라벨 순화·창작 금지(선정산 제외액을 '미반영 금액' 등으로 바꾸지 않음).
- "내용 완전추출"을 핑계로 길게만 쓰고 읽기 어렵게 만들지 않음 — 내용은 다 넣되 기획자 친화 문체·가독성 유지.

## 8. 근거 우선순위와 미확정 3대 지뢰 창작금지

### 근거 우선순위 : **코드 > 캡처 > md > IA**
- **코드**가 1차 진실. 렌더 순서·문구·조건 분기·표시 파생 로직은 코드에서 확정한다.
- **캡처**는 코드에 없는 실측값 확보용(예: 목업 행 수 14개는 코드에 건수가 없어 렌더 캡처를 세어 확보). 문구도 캡처로 교차검증.
- **md 분석 문서**는 이미 번역된 표현 재활용·교차검증용 2차 자료. md에 없는 요소(placeholder·empty-state·말줄임·hover)는 **코드 재정독으로만** 확보되므로, md만 믿고 넘어가지 않는다.
- **IA**는 화면 목록·Page ID 매핑 근거(이동 대상을 `[AD_SALES_DT]` 대괄호로 잇는 데 사용). 동작·문구의 근거로는 쓰지 않는다.
- 충돌 시 항상 상위 근거가 이긴다. 코드와 md가 어긋나면 코드를 채택하고, md 표현은 버린다.

### 미확정 3대 지뢰 — 어느 한 값도 채택·창작 금지
아래 셋은 문서·계약·DB 설계가 서로 다른 값을 병존시키는 지점이다(`analysis/00_종합.md` C1·C2·C4). keynote에 이 값이 필요한 자리가 나오면 **반드시 빨강 또는 TBD**로 남기고, 코드가 서버값을 그대로 표시만 한다면 "화면은 서버값을 그대로 표시할 뿐, 산정 근거는 개발 확인 필요"로 적는다.

| 지뢰 | 병존 상태 | keynote 처리 |
|---|---|---|
| **수수료율** (C1) | 1% / 0.604% / 0.6+0.11+0.1% / 0.25% 병존 | 수치 채우지 말 것. "수수료율 TBD — 근거 미확정"(빨강) |
| **지급 캘린더** (C2) | 계약 "매일" vs 운영 D+1 vs DB 설계 D+2 | 지급일 산정식 창작 금지. "지급일 산정 기준 개발 확인 필요"(빨강) |
| **예상 지급 차액** (C4) | 정의 미확정인데 화면 핵심 라벨 | 라벨은 원문대로 두되 정의·산식은 비우고 "정의 미확정"(빨강) |

> 그리고 지뢰 밖이라도, 코드가 서버값을 표시만 하고 산출 로직이 코드에 없는 값(파일럿의 정산 활성/비활성 판정 기준 같은 것)은 **똑같이** '개발 확인 필요'로 요소 옆에 붙인다. 값을 지어내는 순간 기획 검토가 오염된다 — 공백은 공백으로 정직하게 남기는 것이 이 문서의 최종 원칙이다.
