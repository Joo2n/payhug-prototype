## 1. 프레임 템플릿 스펙

한 화면 = **1 프레임 = 상단 메타바 + 좌측 목업(번호마커 오버레이) + 우측 설명패널(key note)**.
프레임은 Document guide의 `04_contents_type01`(2단) / `type02`(목업 풀폭)를 **복사해서** 쓴다. 새로 그리지 않는다.

| 항목 | 값 | 근거 |
|---|---|---|
| 프레임 크기 | **1920 × 1280** | 01 §5 (`1:83`) |

| 모바일 목업 플레이스홀더 | `Frame 375×812` (`1:113`) — 가맹점 모바일 화면용 | 01 §5 |

### 1-2. 상단 메타바 (`content/header`, `1:114`) — 2행 표 + 우측 로고

라벨 셀(회색) + 값 셀(흰색). **좌하단·우하단에도 동일 메타바를 풋터로 한 번 더** 반복. 우측 끝에 **Payhug 로고**를 2행 높이로 병합(`Payhug_img`).

**1행:** `Page` · `Page ID` · `System` · `Date` · `Writer`
**2행:** `Flow` · `Note`

| 필드 | 채우는 값 | 실제 예시 (근거) |
|---|---|---|
| **Page** | 화면명(=화면 타이틀). 계층은 `상위 > 하위` | `가맹점 선정산 메인` / `가맹점 메인 > 계좌 내역` (02) |
| **Page ID** | 접두 코드 (§1-3) | `ST_MA` `ST_AC` `PH_LO` |
| **System** | `mobile web / native / pc` 중 실제값 | 가맹점 선정산·인증 예시는 `pc` (02·03) |
| **Date** | `YYYY.MM.DD` 작성일 | `2026.06.21` / `2026.07.02` |
| **Writer** | 작성자명 | `최지원` / `이서준` |
| **Flow** | breadcrumb, `>` 로 연결(진입 경로) | `페이허그 소개 > 로그인 후 > 가맹점 선정산 메인` |
| **Note** | 특이사항, 보통 `-` | `-` |

### 1-3. Page ID 접두 규칙 (기존 체계 계승)

| 접두 | 대상군 | 예시 | 근거 |
|---|---|---|---|
| `ST_*` | 가맹점 선정산 | `ST_MA`(메인) `ST_AC`(계좌 내역) `ST_EP_LI`(미리 받은 돈) `ST_AC_EX`(선정산 제외액 내역) | 02 §1 |
| `PH_*` | 가맹점 인증/공통 | `PH_LO` `PH_JO_PW` `PH_PW_FI` `PH_PW_RE` | 03 §1-B |
| **어드민 신규** | 어드민 화면설계서(303:173) | 메뉴 접두를 새로 정의하되 `ST_*`/`PH_*` 네이밍 패턴을 이어 씀(예: `AD_*` 등 — 착수 시 확정) | 03 §1-B 지침 |

- 화면끼리 상호참조는 **대괄호 Page ID**로: `[ST_AC_EX]으로 이동`.

### 1-4. 본문 배치

- **type01(2단)**: 좌 목업 + 우 `key note` 패널. 대부분 이걸 쓴다.
- **type02(풀폭)**: 우 패널 없이 목업만. PC 와이드 화면·설명패널 불필요 시.
- **여러 상태 세로 나열**: 한 프레임에 정상/빈값/집계중 등 상태를 세로로 쌓되, **번호 마커는 대표 상태에만** 단다(반복 상태엔 안 단다).

### 1-5. 우측 설명패널 `key note` (위→아래 3단)

1. **`key note` 헤더** (회색 바)
2. **더미데이터/운영이슈 메모** (빨강, 있을 때만) — 예: `· 더미 데이터`, `· 6.16 선정산 제외액은 더미 데이터` (02 §1)
3. **디스크립션 표** — 헤더행 `No | Name | Note`
   - `No`(40px, 볼드) = 좌측 원마커 숫자와 1:1
   - `Name`(80px) = 요소 이름 2~6자 (`뒤로가기` `계좌 정보` `카드사별요약`)
   - `Note`(380px) = 불릿 중첩 리스트로 상세 스펙, 하위번호 `3-1) 3-2)`

## 2. 번호 마커 · 테두리 · 강조 표기법

컴포넌트는 Document guide 범례(`1:247`)에서 detach해서 쓴다. **테두리를 직접 그리지 않고 지정 컴포넌트·색으로** 강조한다.

### 2-1. 번호 마커 (`디스크립션 번호`, 26×26)

- **메인 마커**: 채워진 인디고/블루퍼플 **원(●)** + 흰 숫자 `1 2 3 4`. 색 `color=blue`(기본)/`color=yellow`, 방향 `type=default/right/left/up/down`(화살표 5종).
- **서브 마커**: 같은 색 **작은 알약 배지** `2-1` `3-4`. 주석 대상 요소 **바로 앞/위**에 얹음.
- **하위 번호**: `N-1, N-2 …` 순번 지정. 우측 표의 `3-1) 3-2)`와 좌측 서브마커가 1:1 대응.

### 2-2. 영역·연결선 (`영역표시`)

- **`영역표시_화살표`(`1:317`)**: 카드/섹션 **좌측 세로에 얇은 보라 치수선**(양끝 T캡)을 세워 "이 마커가 어느 영역 전체를 가리키는지" 범위 표시.
- **`영역표시_사각형`(`1:318`)**: 점선 사각형으로 영역 지정.
- 단건 요소는 선 없이 배지만 얹는다.

### 2-3. 상태·개정 뱃지

| 표기 | 컴포넌트 | 용도 |
|---|---|---|
| `TBD` (노란 박스+빨강 텍스트) | `1:304` | 지연·미정 기능 |
| `DELETED` (빨강 테두리+빨강 텍스트) | `1:305` | 삭제 기능 |
| `NEW V0.0.0` (우상단 대각 삼각) / `장표_히스토리` 퍼플 바 | `1:302`/`1:306` | 신규·개정 이력 |
| 인라인 보라 알약 `V.0.1.1 추가` | 02 §1-b | 본문 설명 중 신규 스펙 옆 |

- **빨강** = 이슈·더미데이터·예외 정책. **보라 배지** = 신규 버전. **회색 바** = 구획 헤더.

## 3. 디스크립션 작성 규칙 (가장 중요)

> 목표: **최지원 B안(02)·이서준 그린버전(03)의 사람 문체를 그대로 답습**한다. AI가 쓴 티가 나면 실패다.

### 3-1. 어투·문장 (DO)

- **개조식·명사 종결**. `~함/~됨/~이동/~표기/~노출/~미노출`. 마침표 거의 안 씀.
- **콜론 스펙 표기**: `필드 : 값/규칙` — `입금자명 (default : 페이허그)`, `default : 버튼 비노출`.
- **하위번호 체계**: 요소 `N-1) N-2)` → 세부 `-` 불릿 → 더 깊으면 `a. b.` 또는 `Case1) Case2)`.
- **화면 이동은 대괄호 Page ID**: `[ST_AC_EX]으로 이동`, `미리 받은 돈[ST_EP_LI]으로 이동`.
- **표기 관용구 반복**: `천단위 [,]콤마 표기`, `내림차순 정렬`, `[+] 표시`/`[-] 표시`, `? 아이콘 선택 시, 툴팁 노출`.
- **조건 분기는 부등호·케이스로**: `예상 수수료 > 실제 수수료`, `승인데이터O, 매입데이터O`, `Case3) 매입데이터만 있는 경우`.
- **줄바꿈**: 한 불릿 안에 케이스를 쌓을 땐 `<br>`로 강제 개행.
- **미완/추정 표시**: `개발 구현 현행화 예정`, `(6.21 확인)` 날짜 각주.
- **길이**: Name 2~6자. Note 한 불릿은 짧으면 4자(`YYYY.MM.DD`), 길면 조건+예외까지 한 줄. **화면당 No 행 3~5개**가 표준(뒤로가기 → 정보/날짜 → 리스트 본문 → 내역 더 불러오기).
- 인증 정책 문서(03)만은 예외적으로 **완결형 서술("~합니다")+표**를 쓴다(정책 스펙북 성격). 그 외 화면설계 프레임은 개조식.

### 3-2. 금지 (DON'T — AI 티 나는 표현)

- ❌ 완결형 존댓말 서술("~합니다/~됩니다/~할 수 있습니다")을 개조식 화면설계 프레임에 섞지 말 것(인증 정책 스펙북 제외).
- ❌ "사용자 경험을 향상시키기 위해", "직관적으로", "원활하게", "손쉽게", "효율적으로", "~를 통해 ~할 수 있습니다" 류 마케팅·설명체.
- ❌ 불필요한 접속사·수식어(따라서/또한/그리고/한편)로 문장 늘리기.
- ❌ 이모지, 과한 볼드, 균일한 완전문장 단락. (원문은 오타·구어도 그대로: `선전상 지급액`, `라밸문구`, `등등`)
- ❌ 근거 없는 값 창작(수수료율·지급일·차액 정의는 3대 지뢰 — 채우지 말 것).
- ❌ **코드 용어·식별자를 그대로 노출**(`APPROVED`/`PENDING`/`isSettlementActive`/`i+1`/`200px`/`이벤트 전파 차단` 등). **반드시 기획자가 아는 말로 번역**: 승인/대기 / 활성·비활성 / 위에서부터 다시 번호 매김 / …로 줄임 / (행 클릭과) 따로 동작.
- ❌ 내용을 추가한다고 **길게만 쓰고 읽기 어렵게** 만들기. "내용 완전추출"과 "개발자스러운 서술"은 다르다 — **내용은 다 넣되, 직전에 통과된 기획자 친화 문체를 유지**한다.

### 3-2b. 가독성 필수 (파일럿 교훈)
- **하위항목 들여쓰기**: 부모 불릿 아래 자식은 `–` 불릿로 한 단 들여쓴다.
- **소제목 그룹핑**: 여러 하위가 묶이면 "정렬 순서" "표 항목" "상황별 문구" 처럼 **소제목(볼드)** 으로 묶는다.
- **핵심어 볼드**: 요소명·조건·상태 라벨은 볼드. 문단이 길면 끊어서 여러 줄.
- 완전추출 기준 예시 = 어드민 매출조회 리스트(`app/sales/page.tsx`): 정렬 우선순위·상태별 문구 원문·hover 숨김 액션까지 전부 넣되 위 문체로.

### 3-2c. keynote 근거 = 코드 우선(md는 참조용) ★파일럿 교훈 확정
- **`spec/admin/*.md`·`spec/merchant/*.md`(기능명세)는 파일럿보다 먼저 작성돼 누락이 있다.** 실측: 매출조회 md에 **헤더/제목/안내문·총 N개(검색 무관 전체)·빈·로딩 상황별 문구 3종·검색 placeholder 원문·주소 말줄임·hover 배경**이 전부 없었고, 구조가 "기능 나열"이라 화면 요소 단위가 아님. 파일럿은 `app/sales/page.tsx`를 **다시 정독**해 이것들을 채우고 요소별로 재구성한 결과다.
- **따라서 keynote는 md를 재포맷하는 게 아니라, 해당 화면의 실제 소스코드를 정독해 "화면 요소별"로 새로 추출한다.** md는 (a)이미 사람문체로 번역된 표현 재활용, (b)교차검증(빠진 것 확인)용 2차 자료로만 쓴다.
- 근거 우선순위: **① 실제 코드(page.tsx/components/hooks) → ② 캡처(렌더된 실제 문구·요소·빈상태) → ③ 메뉴 md(문체·교차검증) → ④ IA(상태 목록)**. 값이 미확정이면 3대 지뢰 원칙대로 창작 금지·`TBD`.
- **누락 검증 필수**: 생성 후 "코드/캡처엔 있는데 keynote에 없는 요소·UI문구·빈상태·조건분기"를 적발하는 검증 패스를 돌린다(파일럿에서 사람이 지적해 잡았던 종류: 총N개=전체, empty-state 3종, placeholder, 말줄임, hover 등).

### 3-3. 원문 예시 (그대로 붙여 쓸 톤)

- `선택 시 히스토리 Back` / `메인에서 진입 시 메인으로 이동`
