## 1. 주제별 요약 (원문 인용)

### 1-A. 수수료·수익배분 (C1 발원지)

04 프레임(`774:1054`)의 **전자계산서 발행 배분표**가 이 캔버스의 수수료 정본. 채권매입 수수료는 **다단계 할인율(대납) 구조**로 흐른다.

- **하위총판 → 가맹점 (월1회)** (`821:23`): "면세 계산서 **1% (채권매입 수수료)** | VAT 없음 / 이체 수수료 부과 하는 케이스 (다우) 과세 계산서 이체수수료 (300원) | VAT 별도 +30원" — *하위총판 명의로 대신 발급(바로빌 총판 연동 API KEY 값으로)*
- **하위총판 → 상위총판 (월1회)** (`1126:776`): "면세 계산서 **0.45% (채권매입 수수료)** | VAT 없음(원가) / 과세 계산서 이체수수료 (300원) | VAT 별도 +30원"
- **페이허그 → 상위총판 (월1회)** (`821:13`): "과세 계산서 **0.1% (시스템 이용료)** | VAT 별도 + **0.01%(원가)** / 면세 계산서 **0.25% (채권매입 수수료)** | VAT 없음(원가) / 과세 계산서 이체수수료 (300원) | VAT 별도 +30원"
- **영업사원** (`1126:778`): "영업사원 개인 : 하위총판이 3.3% 떼고 줌 (6,000원) / 영업사원 법인 : 하위총판이 3.3% 떼고 VAT 떼고줌 (6,600원)"
- **이체수수료 부과 여부** (`3301:910`): "일반 계약서 : 이체 수수료 미부과 표시 / 다우 계약서 : 이체 수수료 부과 표시 / 채권 매입 주체가 어드민에서 선택"
- **발행 주기·주체** (`3301:918`·`3301:919`): "월 1회 (10일)" / "어드민에 세금계산서 보이는 UI 필요 페이허그는 발행 가맹점은 조회 (선택) - 가맹점 이메일 수집을 안하고 있음"
- **수익금 정산** (`862:139`): "수익금 정산 한달에 한번"

전체flow(`503:2`)의 요율 요약: "채권매입수수료율 **1%**"(`503:30`) → "채권매입수수료율 **0.25%**"(`503:31`) → "채권매입수수료율 **0.11% 또는 대출이자**"(`503:32`); "카드/배달 매입 수수료를 쪼개둠 (정산금 채권)"(`3301:893`).

> **VAT 원칙 (C3 부속 해소)**: 채권매입 수수료 = **면세·VAT 없음**, 시스템 이용료·이체수수료 = **과세·VAT 별도**. 이체수수료는 "300원 | VAT 별도 +30원" → **base 300원 + VAT 30원 = 330원**. 즉 300 vs 330 병존은 *VAT 전/후* 차이이며 **건당**(계약서 `771:795` "이체수수료 : 정산금 건당 N원").

> **⚠️ 캔버스 내부 충돌**: 현행 04 배분표(1%/0.45%/0.25%/0.1%)와 **구버전 02.Page_flow(`470:2`)의 "채권매입수수료율 0.65%"(`470:178`) / "수수료 0.35%"(`470:180`) / "수수료 0.11% (0.35안에 들어가있음)"(`470:181`)** 가 다른 모델. 계약서(`760:71`)는 요율을 고정하지 않고 "채권매입 수수료 : 정산금의 **N% : 어드민에서 입력**"(`771:795`)으로 처리 → **요율은 어드민 입력값**이라는 게 이 캔버스의 확정 설계.

## 5. 이 캔버스가 해소하지 못하는 것 (미확정 유지)

- **최종 대외 요율값**: 어드민 입력이라 캔버스는 값을 못 박지 않음(1% / 0.65% 두 모델 병존).
- **C2 D+1 vs D+2 택일**: 계약 '매일'·플로우 D+1 vs 정산채권DB D+2 — 캔버스가 "스케줄링 정리 필요"로 미정 자인.
- **바로이체 개념**: 단어 부재, 수동 출금 지시와의 동일성 미확정.
- **회수 예정일 정책**: `3301:903` "회수 예정일 정책 필요"로 명시적 공백.
- **가맹점 노출 라벨 매핑(05§5)**: 이 캔버스는 내부 용어(과정산금/미정산금/미수금)만 정의, 가맹점 순화 라벨은 다루지 않음.
