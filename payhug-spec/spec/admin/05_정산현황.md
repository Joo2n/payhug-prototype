## A. 화면 개요

- **목적**: 선정산 배치 결과를 6개 탭으로 확인하고 처리하는 내부 운영 화면이다. 6개 탭은 ① 선정산 결과(가맹점·건별·미정산누락) ② 정산 상세(배치·배분·원장) ③ 차액 정산(6개 서브탭) ④ 이체 내역(지급·회수) ⑤ 계산서 발행 자료 ⑥ VOC용 단건 엑셀로 구성된다. 목록 조회와 엑셀 내려받기는 물론, 미정산 누락 건을 바로이체하거나 기록만 남기는 처리까지 이 화면에서 수행한다.
- **진입·권한**:
  - `/settlements`로 접근하면 곧바로 `/settlement/overview`로 이동시킨다(`router.replace`, code 01_admin app/settlements/page.tsx:8).
  - 로그인한 사용자는 누구나 3개 탭(선정산 결과·차액 정산·이체 내역)을 볼 수 있다. 반면 **정산 상세·계산서 발행·VOC 대응** 3개 탭과 **미정산 누락 추적** 배너는 `userType`이 `ADMIN` 또는 `PAYHUG`인 경우(=`isAdmin`)에만 노출된다 (code 01_admin app/settlement/overview/page.tsx:39-42, 201, 233, 245, 404).
  - 미정산 누락 조회(`fetchMissedSettlements`)는 `enableMissedSettlements = isAdmin`일 때, 즉 실제 지급(바로이체) 권한이 있는 페이허그 내부에서만 실행된다 (code 01_admin page.tsx:69-71, hooks/useSettlementOverview.ts:394).

## D. 미확정 지뢰 관련

- **수수료율 (C1)**: 선정산 수수료 카드/tooltip은 서버가 계산한 채권매입·시스템이용료·이체수수료 금액을 **표시만** 하고, 계산서 탭 `rateLabel`은 `공급가/기준액×100`으로 **역산된 비율**(예: 0.6xx%류)을 그때그때 보여줄 뿐, 화면 어디에도 요율 상수를 채택하지 않는다. 1%/0.604%/0.6+0.11+0.1%/0.25% 중 어느 값도 이 문서에서 확정하지 않음. (code TaxInvoiceTab.tsx:22-33, PreSettlementTab.tsx:510-517)
- **지급 캘린더 (C2)**: 화면은 `settlementDate`(정산일)와 매출일(`targetDate`)을 함께 표기하지만 둘의 간격 규칙(매일/D+1/D+2)은 데이터에서 오고 코드가 규정하지 않는다. 미정산 누락 배너의 "이틀 이상 지난 건" 문구만 2일 경계를 암시. 캘린더 값 임의 채택 금지.
- **예상 지급 차액 (C4)**: 어드민에는 가맹점 화면의 단일 라벨 "예상 지급 차액"이 그대로 존재하지 않는다. 대응 가능성이 있는 것은 차액 정산의 **예상매출 대사(ESTIMATED_DIFF)** 서브탭과 **EST_REFUND/EST_DEDUCT** 유형(주말·장애 예상매출 후 실데이터 차이, code page.tsx:487-488, .../fee-adjustments/page.tsx:234-237)이나, 가맹점 노출 라벨과의 등가 여부는 미확정. 정의 확정 전 동일 개념으로 병합 금지.
- **6개념 분리 확인**: 이 화면에서 서로 다른 UI로 분리 유지됨 — 미지급금(미정산 누락 추적) · 선정산 제외금액(현장결제/오프라인차감) · 바로이체(missed-settlements TRANSFER, batchType DIRECT_PAYOUT) · 미회수금(CARRY_FORWARD·우리가게클릭비 outstandingAmount) · 환급(REFUND 계열). '과지급'은 이 화면에 독립 UI 없음(취소환수/차감으로 표출). 이체 내역의 '매출 회수(스윕)'는 6개념의 '과지급 회수'와 별개.
