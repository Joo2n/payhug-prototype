## A. 화면 개요

- **목적**: 운영자가 가맹점 하나를 골라 카드·배달앱 매출/매입 원장(purchase-ledger)을 기간·유형·상태별로 조회하는 화면이다. 선정산 대상·선정산 수수료·선정산 지급액·차액정산·실제 이체액을 건별과 합계로 확인할 수 있고, 누락되거나 잘못된 건은 **단건 또는 엑셀로 직접 보정 등록**하며, 조회 결과를 **엑셀로 내보낼** 수 있다. 요컨대 정산이 제대로 됐는지 검증하고 대사(對査)하는 화면이다.
- **진입·권한**: 어드민 사이드 메뉴의 '매출조회'로 들어온다. 화면은 `AdminLayout`으로 감싸여 있고, 모든 조회·등록은 관리자 인증 토큰을 실은 `authFetch`로 호출한다. 목록에서 행을 클릭하면 해당 가맹점의 상세 화면(`/sales/{사업자번호}`)으로 이동하며, 탭 모드에서는 새 탭으로 열린다. 상세 화면은 사업자번호(`bizNo`)를 라우트 파라미터로 받아 동작한다.

## D. 미확정 지뢰 관련

- **수수료율(C1)** — 나타남. `요약카드: 선정산 수수료`(채권매입/시스템/이체/차액수수료 분해, #27)와 `원장 선정산수수료 툴팁`(투자자·페이허그마진·페이허그시스템·상위/하위총판·영업사원 요율 %, preSettlementRate 합계, #40)에 라벨·계산으로 직접 노출. 표시값은 모두 서버(`feeBreakdown`, `preSettlementRate`, `preSettlementFee`)에서 내려온 값을 렌더할 뿐이며, 이 문서에서 특정 요율(1%/0.604%/0.6+0.11+0.1%/0.25%)을 **임의 채택하지 않는다**.
  - **⚠️ 모델 불일치**: 코드의 수수료 구조(정액 합산 + 다자 배분율 분해)는 정책 문서 `03 §2`의 단일 수수료율 곱셈 모델과 형태가 다르다. 정합은 미확정(C 섹션 "선정산 수수료 계산 모델 불일치" 항목 참조).
- **지급 캘린더(C2)** — 나타남. `날짜 기준 토글(지급예정일)`(#16), `지급일 컬럼`(#50), 단건 등록 `지급예정일` 필드(#56)가 payoutDt를 사용하나, D+1/D+2/매일 중 산정 기준은 **미확정**. 화면은 서버가 준 payoutDt를 표시할 뿐.
- **예상 지급 차액(C4)** — 조건부 관련. 본 화면의 "차액 반영/차액정산"은 카드수수료 예상↔실제 차액으로 코드 정의가 명확(#28·#34·#45·#47). 그러나 이를 정책의 정의 미확정 라벨 '예상 지급 차액'(가맹점 화면 핵심 라벨)과 **동일시하지 않는다** — 매핑은 확인 필요.
- **6개 개념 분리 주의** — 본 화면은 ① 선정산 대상/미대상 뱃지(#39), ② 바로이체 뱃지(settlementType=DIRECT_PAYOUT, #43), ③ 현장결제 회수/미회수(다음 배치, #30·#32), ④ 환급(ADJ_TYPE 라벨: 카드 환급/예상매출 환급/배달 환급, #34)을 **각각 별도 요소로 렌더**하며 하나로 합치지 않는다. 단, ①의 '미대상'이 정책 6개념의 '선정산 제외금액'과 동일한지, ③의 '현장결제 미회수'가 '미회수금(과지급 잔액)'·'과지급'·'선정산 제외금액' 중 무엇인지는 **매핑 미확정**(C 섹션)이므로 임의 동일시 금지. 특히 '현장결제 회수'·'취소 환수(CANCEL_CLAWBACK)'는 어드민 **'매출 회수'(락계좌→모계좌 스윕)와 다른 개념**이므로 혼동 금지.
