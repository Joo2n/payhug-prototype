## A. 화면 개요

- **목적**: 이 메뉴에서는 세 가지 일을 한다. 첫째, 정산에 적용할 **수수료 상품(정책)** 을 만들고 고치고 비활성화하거나 삭제한다(상품관리). 둘째, 특정 거래 여러 건을 **DB에 저장하지 않고 계산만 돌려보는 시뮬레이션**을 실행한다(시뮬레이션). 셋째, 선정산 후 발생한 **차액 정산 내역**을 조회한다(차액 탭). 수수료율과 배분 구조를 여기서 관리하기 때문에, 이 메뉴가 C1(수수료율)·C3(이체수수료) 지뢰의 진원지다.
- **진입·권한**: 어드민 웹 내부 메뉴다. 개발환경은 `authFetch`(더미 쿠키)로 동작해 화면 단계의 권한 게이트가 코드에서 확인되지 않는다(→ C 항목). `/settlement`로 들어오면 `router.replace`로 정산현황(overview)으로 곧바로 넘어가며, 상품관리·시뮬레이션 화면은 이 리다이렉트의 도착지가 **아니다**.
- **주요 상태 변형(캡처된 케이스, 01_IA.md A-04 node 목록 근거)**:

  - node 946:2 시뮬레이션 기본 · node 949:2 거래 다건 입력

## C. 정책 확인 필요 항목 (Open Questions)

- [ ] **수수료율 매트릭스**: 상품(정책)의 요율은 역할별로 분해되어 상품마다 다르게 저장·수정된다(예 목 데이터 상품 A = 채권매입 합 1%를 INVESTOR 0.6%+PAYHUG 0.2%+UPPER 0.12%+LOWER 0.05%+SALES 0.03%로 분해). 대외 고지 요율 vs 내부 배분 요율의 관계, 어떤 상품을 표준으로 삼을지 미확정 — 관련: 07 §2(정규 매니저, 예상 지급 차액 정의), analysis/00 C1. **임의 값 채택 금지.**
- [ ] **시뮬레이션/실정산 계산식·버림 정책**: 수수료·원장·배분 계산은 전량 서버(`POST admin/settlement/simulate`) 수행이라 프론트 코드로는 산식·버림 단위·소수점·VAT 적용순서를 확인할 수 없다 — 관련: 03 §2·§4, C1.
- [ ] **VAT 별도(SEPARATE)/포함(INCLUDED)** 요율 옵션의 실제 계산 반영 방식과 PAYHUG 역할에 VAT 선택이 없는 이유(항상 별도/면세인지) 미확정 — 관련: 03 §3, C3.
- [ ] **수수료 납부/수취 옵션의 실제 정산 반영**: 모달 안내문("모두 OFF면 가맹점 납부"·"모두 OFF면 페이허그만 수취")과 납부자(`systemFeePayer`/`transferFeePayer`=UPPER/LOWER)·수취(boolean) 토글은 payload에 반영되나, 실제 정산에서 누가 **부담/수취**하는지는 서버 계산 소관이라 프론트로 확정 불가 — 부담 주체=C3, 수취 배분=C1. 관련: 03 §3.
- [ ] **이체수수료**: TRANSFER_FEE 요율이 "원(₩) 단위"로 입력되고 목 데이터 기본 300원, 옵션 `transferFeeAmount:300`. 건당인지 가맹점당 1회인지, 부담 주체(가맹점/파트너 납부 토글), VAT 별도/포함(300 vs 330) 미확정 — 관련: 03 §3, C3.
- [ ] **상품 비활성화/삭제 정책**: "배정된 가맹점 이력 유지·신규 배정만 불가"(비활성)와 "배정된 가맹점 있으면 삭제 불가"는 확인 다이얼로그 문구 근거일 뿐 서버 규칙·상태 전이(isActive 필드) 확정 필요 — 관련: 07.

## D. 미확정 지뢰 관련

- **수수료율 (C1)** — 이 메뉴가 요율의 발원지다. `요율 설정` 표(PolicyFormModal)에서 채권매입(MARGIN)·시스템이용료(SYSTEM_FEE)·이체수수료(TRANSFER_FEE)를 **역할별·상품별로 편집**한다. 저장 단위는 `rateBps`(basis point, 100bps=1%; 표시 `rateBps/100`%), 이체는 원 단위. 목 데이터 상품 A는 채권매입 합계 1%를 역할 소요율로 분해(0.6/0.2/0.12/0.05/0.03%) — analysis/00 C1의 "실계산 요율(내부 배분)"과 정확히 같은 구조를 코드가 확증한다. **어느 값도 THE 요율로 확정하지 않는다**(상품별로 다름). 실제 amount×요율 계산은 서버.
- **이체수수료 300원 (C3)** — TRANSFER_FEE 요율 입력이 "원(₩)" 단위이고 옵션 `transferFeeAmount:300`, 목 요율 300원. 시뮬 결과는 "배치당 1회"로 표기(가맹점당 1회 전제). 단위·차감 위치·부담 주체·VAT(300 vs 330)는 C3대로 미확정 — 화면 라벨을 근거로 확정하지 않는다.
- **예상 지급 차액 (C4)** — 이 메뉴 자체에는 "예상 지급 차액" 라벨이 없다. 다만 차액 정산 탭(node 953:2)의 `ESTIMATED_DIFF`(예상매출 대사)·`CARRY_FORWARD`(미회수 이월)가 C4/6개념과 맞닿는다. 차액 탭의 정의·정책은 A-05(05_정산현황.md)에서 다루며, 순액 합산·방향 분리 원칙(C4)에 따라 여기서 임의 확정하지 않는다.
- **⚠️ 지급 캘린더(C2)** — 이 메뉴에는 나타나지 않음(해당없음).
