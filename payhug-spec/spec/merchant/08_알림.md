## A. 화면 개요

- **목적**: 정산 완료·회수·계약 같은 서비스 이벤트 알림을 가맹점주에게 인앱 한 곳으로 모아 보여주는 알림 센터다. 헤더의 알림 벨을 누르면 요약 드롭다운이 열리고, 드롭다운의 "더보기"를 통해 전체 목록 화면(`/notifications`)으로 이어진다. 다만 현재 코드는 알림 목록과 카운트가 모두 정적이어서(빈 상태·카운트 0 하드코딩), 실제 알림 데이터 조회·읽음 처리·발송 연동은 아직 구현되어 있지 않다.
- **진입·권한**: 헤더의 알림 벨은 로그인한 상태의 데스크톱 화면에서만 보인다(`hidden md:flex`). 벨을 누르면 드롭다운이 열리고, 드롭다운의 "더보기" 또는 모바일 메뉴의 "알림"을 통해 `/notifications` 전체 목록으로 이동한다. `/notifications` 페이지 자체에는 코드상 별도 인증 가드가 없지만(헤더를 통한 로그인 진입 동선을 전제로 함), 아직 표시할 알림 데이터는 없다.
- **주요 상태 변형(코드·Figma에서 확인된 케이스)** (01_IA.md M-08 / M-09):
  - 알림 전체 목록의 빈 상태(M-08, node 820:2) — "받은 알림이 없습니다."
  - 헤더 알림 드롭다운의 빈 상태(M-09 공통, node 910:2)

## B. 기능 명세 · 정책 표

> **상태 판정 주석**: 이 화면(인앱 알림 센터)에 대응하는 **정책 문서·조항이 존재하지 않는다.** 참조 문서 `06_ADMIN_AND_NOTIFICATION §3`은 **알림톡(카카오)** 정책이며 인앱 알림과는 별개 채널이고, 그마저 "정책 정비 1순위 과제"로 미확정 상태다. 따라서 코드로만 관찰되는 UI 동작(이동·표시·토글 등)은 `확정`(=코드+정책문서 둘 다) 요건을 충족하지 못하므로 모두 **`가설`(코드로만 관찰)** 로 표기한다. 향후 인앱 알림 정책이 확정되면 해당 행을 승격한다. ## D. 미확정 지뢰 관련

- **C1 수수료율 / C2 지급 캘린더 / C4 예상 지급 차액**: 이 화면(알림 목록·드롭다운)에는 수수료율·지급 캘린더·예상 지급 차액 라벨/계산이 **직접 노출되지 않음**(현재 정적 빈 상태). → 해당 없음. 단, 알림톡/인앱 알림 문구에 "데일리 선정산 예정액·지급 완료·추가 지급 예정·이전 지급 조정 예정"(06 §3) 등 **금액·지급 시점 문구가 포함될 예정**이므로, 실제 알림 문구 작성 시 확정된 수수료율(C1)·지급 캘린더(C2)·예상 지급 차액 정의(C4)와 반드시 동기화하고 미확정 값의 임의 채택을 금지한다.
- **6개 개념 분리**: 알림 케이스 후보에 걸친 개념(선정산 미반영=선정산 제외금액, 바로이체 완료=바로이체, 회수 완료=과지급 회수, 플랫폼 환급 지급=환급 등)을 **하나로 합치지 않는다**. 특히 정책 '회수'(과지급 회수) ≠ 어드민 '매출 회수'(락계좌→모계좌 스윕) 구분 유지.
- **내부 용어 ↔ 가맹점 노출 용어**: 알림 문구는 가맹점 노출 용어를 사용해야 하며, 내부 운영 용어(미지급금·과지급 등)를 그대로 노출하지 않도록 확정 필요(매핑: 문서 05 §5).
