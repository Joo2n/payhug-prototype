## A. 화면 개요

- **목적**: 로그인한 가맹점주가 자신의 계정·계약·연동·보안을 한곳에서 관리하는 허브 화면이다. 크게 네 가지를 다룬다. ① 이름·휴대전화번호 등 내 기본 정보 확인, ② 계약 정보 조회(등록 계좌·사업자 정보·신분증·증빙 서류·전자 계약서·약관 동의 내역 확인, 증빙과 약관 미리보기), ③ 연동 계정 관리(여신금융협회·배달앱 스크래핑용 계정 정보 변경 및 재검증), ④ 비밀번호 변경. 1:1 문의는 이 메뉴에서 진입만 하고, 상세 명세는 `07_문의.md`에서 다룬다.
- **진입·권한**: 내 정보의 모든 하위 화면은 인증 레이아웃(`MyInfoLayout` → `AuthGuard`)으로 감싸여 있고, 각 페이지도 저장된 로그인 정보가 없으면 로그인 화면(`/login`)으로 돌려보낸다(이중 가드). 계약·연동 화면은 진입할 때 사업자 목록을 불러와 승인 완료(`contractStatus === "APPROVED"`) 사업자를 우선 선택하고, 없으면 목록의 첫 사업자를 선택한다. 미승인 사업자도 화면 진입은 되지만, 실제로 보이는 데이터는 서버 응답에 따라 달라진다.

- [ ] **연동 계정 상태 용어 노출** — 이 화면은 `AUTH_FAILED`=인증실패, `SCRAPING_ERROR`/`ERROR`=일시 오류를 **가맹점에 그대로 노출**(#24). 그러나 05_UI_REQUIREMENTS §5는 스크래핑 오류를 "데이터 확인 중"으로 순화하도록 매핑. 정산 화면과 연동 계정 화면 간 상태 용어 정책의 일관성 확인 필요(내부 운영 용어 ↔ 가맹점 노출 용어 구분). 관련: 문서 05 §5
- [ ] **연동 계정 변경과 서비스 중지 사유의 관계** — archive_02 §2.2 이용계약 제8조는 "정산주체 접근 ID/PW 임의 변경"을 서비스 중지 사유로 열거. 이 화면의 자격증명 변경(#29)이 그 조항의 대상인지(=변경 시 중지·소명 트리거) 여부 확인 필요. 매출 수집용 스크래핑 계정 변경과 정산주체 계정 변경의 구분이 필요. 관련: archive_02 §2.2 제8조
- [ ] **"연결 상태 확인"의 재검증 기준** — 비밀번호 없이 `check-status`로 상태만 갱신(#26)하는 것과, 저장 시 매출 조회 검증(#29)을 거치는 것의 판정 기준(무엇을 ACTIVE로 볼지)이 서버측 로직에 의존. 상태 판정 규칙 문서화 필요. 관련: api POST /business-accounts/check-status
- [ ] **비밀번호 변경 후 강제 로그아웃 정책** — 변경 성공 시 1.5초 후 전 세션 clearAuth 후 재로그인(#38)은 코드 동작으로 확정이나, 다중 기기 세션·재로그인 강제의 명시 보안 정책 문서는 부재. 정책으로 확정할지 확인 필요. 관련: code app/my-info/change-password/page.tsx:60-63
- [ ] **미승인/미계약 사업자의 계약·연동 화면 표시** — 승인 사업자 우선 선택하되 없으면 첫 사업자로 조회(#7·#21). 계약 미완료·반려 상태에서 이 화면에 노출되는 데이터 범위(계좌·증빙 유무) 확인 필요. 관련: code contract/page.tsx:82-88

## D. 미확정 지뢰 관련

- **C1 수수료율**: 이 메뉴의 어느 화면에도 수수료율 라벨·계산이 **직접 노출되지 않음**. 다만 계약 정보 조회의 전자 계약서(선정산 서비스 이용계약서 = 양수도계약 계열)에는 채권매입수수료율이 담길 수 있으나, 화면은 PDF/이미지 **미리보기로만** 노출하고 화면 필드로 요율을 렌더하지 않음 → 임의 수수료율 채택 이슈 없음(해당 없음).
- **C2 지급 캘린더**: 이 메뉴에 지급 예정일·지급 캘린더 표기 없음 → 해당 없음.
- **C4 예상 지급 차액**: 이 메뉴에 "예상 지급 차액" 라벨·계산 없음(해당 라벨은 M-05 정산에 존재) → 해당 없음.
- **6개 개념 분리**: 이 메뉴는 정산 금액(미지급금·선정산 제외금액·바로이체·과지급·미회수금·환급)을 다루지 않음. ⚠️ "등록 계좌"(#12)의 UI 라벨(선정산 전용계좌/입출금 전용계좌)과 계약 용어(전용계좌=락계좌 / 입금계좌)의 대응은 **미확정**(어느 쪽이 락계좌인지 방향 모호) — 임의 매핑 금지(CLAUDE.md #7). 어느 쪽이든 금액 6개념과는 무관하므로 6개념 혼동은 없음. 이 메뉴에는 정책의 '회수'(과지급 회수)·어드민의 '매출 회수'(락계좌→모계좌 스윕) 개념도 등장하지 않음.
