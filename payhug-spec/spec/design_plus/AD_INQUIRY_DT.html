정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
답변 등록과 상태 변경이 서로 완전히 분리된 두 동작이라는 점이 이 드로어의 핵심이다. 답변을 보내도 상태는 그대로이고, 관리자가 상태 드롭다운으로 직접 바꿔야 한다. 두 동작은 서버 반영 방식도 달라서(답변=상세 다시 불러오기, 상태변경=화면만 즉시 반영) 표시가 어긋날 여지가 있다. 스레드 데이터는 현재 예시(목업)이고, 답변에는 로그인한 관리자 정보가 함께 실려 나가며 그 정보가 없으면 안내 없이 조용히 중단된다.
정책답변 등록과 상태 변경 — 분리된 두 동작
답변 후 상태 자동전이 없음
답변을 전송해도 문의 상태는 그대로 유지된다.'대기'나 '처리중' 문의에 답변을 달아도 자동으로 '답변완료'로 넘어가지 않음상태는 관리자가 우상단 드롭다운으로 직접 바꿔야 함 → 상태 관리가 온전히 사람 손에 달림 (누락 시 목록이 실제 처리 상황과 어긋남)확정
답변 전송 시 실제로 일어나는 일
① 답변을 메시지 한 건으로 등록 → ② 입력창 비움 → ③ 상세를 서버에서 다시 불러와 스레드 갱신 → ④ 목록도 새로고침 → ⑤ 맨 아래로 자동 스크롤.상태 값은 이 흐름에서 건드리지 않음확정
상태 변경 시 반영 방식이 답변과 다름
상태 드롭다운을 바꾸면 서버에 변경을 알린 뒤 화면의 상태 표시만 즉시 바꾸고, 상세를 다시 불러오지는 않음 (목록만 새로고침).답변은 상세를 재조회하는데 상태변경은 안 하는 비대칭 → 서버가 상태 외 다른 값을 함께 바꿨다면 이 드로어엔 반영 안 될 수 있음서버 반영 성공/실패의 실제 판정은 서버 몫가설
종료 상태의 답변 잠금
상태가 '종료'일 때만 입력창이 사라지고 '종료된 문의입니다.' 회색 안내로 대체.'대기·처리중·답변완료' 세 상태는 모두 답변 입력 가능잠금 기준은 오직 종료 여부 하나확정
연결발신자·관리자 정보 연결
말풍선 좌우 판별 기준
메시지마다 붙은 발신 주체 표시로 좌우를 가름 — 관리자면 오른쪽 초록, 그 외(가맹점)는 왼쪽 회색.발신자명이 없으면 관리자/가맹점 글자로 대체 표기확정
답변에 관리자 신원이 함께 실림
답변을 보낼 때 내용과 함께 로그인한 관리자 식별 정보를 서버로 보냄 → 누가 답변했는지 스레드에 남김.이 정보가 없으면 안내 한 마디 없이 전송이 조용히 중단됨 (버튼은 눌리는데 아무 일도 안 일어남) → 개발 확인 필요확정
가맹점명 링크의 이동 조건
헤더의 가맹점명을 누르면 가맹점 상세로 이동하되, 화면이 탭 방식으로 열려 있을 때만 동작.일반 방식에선 눌러도 반응 없음 → 개발 확인 필요확정
데이터데이터 출처·설정값
현재 스레드는 예시(목업)
이 화면에 보이는 대화는 실데이터가 아닌 예시다. 실제 문의 스레드 연동은 서버 확정 후 재검토 필요.가설
카테고리 값 5종
문의 분류는 일반 · 결제 · 정산 · 기술 · 계정 5가지로 고정.'정산' 카테고리가 별도로 존재 → 선정산 관련 문의가 이 갈래로 들어옴확정
상태 값 4종
대기 · 처리중 · 답변완료 · 종료. 드롭다운 선택지도 이 4개와 동일.확정
시각 표기는 브라우저에서 계산
'방금 전 / N분 전 / N시간 전 / N일 전', 일주일 넘으면 날짜로 표기 — 모두 보는 사람의 브라우저 시각 기준으로 계산.서버 시각과 단말 시각이 어긋나면 상대시간이 실제와 다르게 보일 수 있음확정
