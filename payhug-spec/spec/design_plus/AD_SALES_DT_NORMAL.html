거래상태 '정상' 필터 variant. 표·요약 골격은 베이스(AD_SALES_DT)와 동일하고, 이 화면만의 특수점은 (1) 정상/취소 필터가 클라이언트 숨김이 아니라 서버 재조회 조건이라 건수·요약·실제 이체액 구성까지 정상 거래 기준으로 다시 계산된다는 점, (2) '정상' 판정 경계(취소 판정 기준)가 프론트 표시용과 백엔드 실필터로 이원화되어 있다는 점, (3) 정상 필터로 취소 원거래를 화면에서 빼도 취소로 인한 과지급 회수 차액(취소 환수)은 요약 '차액 반영'에 잔상으로 남을 수 있다는 함정이다.
연결정상 필터의 동작 방식
필터 성격
클라이언트 숨김이 아니라 서버 재조회거래상태 토글에서 '정상' 선택 시 그 값을 조회 조건으로 서버에 넘겨 목록 전체를 다시 받아온다이미 받은 데이터를 화면에서 걸러 보여주는 방식이 아님확정
기본값
거래상태 기본은 전체. '정상'은 사용자가 명시적으로 고른 상태초기화 시 다시 전체로 되돌아감확정
동시 적용 조건
정상 여부는 기간·날짜기준(거래일/지급예정일)·매출유형·카드사·가맹점명 등 다른 조회 조건과 함께 서버로 전달정상만 따로 거르는 게 아니라 전체 조건의 한 축확정
엑셀 다운로드 연동
엑셀 다운로드도 현재 걸려있는 거래상태 값을 그대로 서버에 넘김정상 필터 상태로 내려받으면 정상 거래만 파일에 담김 (화면과 동일 범위)확정
정책'정상' 판정 경계
취소로 보는 기준
정상 = 취소가 아닌 것. 취소 판정은 카드 승인취소 또는 배달 매입취소이 둘 중 하나라도 걸리면 취소, 정상 필터에서 빠짐확정
판정 주체 이원화
화면 코드의 취소 판정은 표시(순지급액을 '-'로)용이고, 실제 목록에서 정상만 남기는 필터는 서버가 수행코드 주석상 둘의 기준이 '동일'하다고 명시했으나, 서버의 정확한 정상/취소 경계는 코드만으로 확정 불가확인필요
정상 필터에서 사라지는 표시
취소건이 원천 제외되므로 취소 전용 표시가 애초에 등장하지 않음순지급액·선정산지급액 칸의 취소용 '-', 승인취소/매입취소 배지 등확정
계산정상 필터가 요약·차액에 남기는 잔상
요약 카드 재계산
카드/배달/합계 건수, 순지급액, 선정산 수수료, 선정산 지급액, 실제 이체액 구성까지 서버가 정상 거래 기준으로 다시 산출화면이 취소분을 빼서 합치는 게 아니라 서버 계산 값을 그대로 표시확정
취소 환수 차액의 잔상 (함정)
정상 필터로 취소 원거래를 표에서 빼도, 그 취소로 발생한 과지급 회수 성격의 차액(취소 환수)은 요약 '차액 반영'에 남을 수 있음'원거래일이 조회 기간과 달라 위 표에 안 나타난다'는 안내와 같은 맥락표엔 없는데 차액 반영에는 숫자가 잡히는 상황을 운영자가 오해할 소지 (이 회수는 어드민 '매출 회수'=락→모계좌 스윕과 다른 개념)가설
정상 필터 시 차액정산 내역 범위
차액 반영 카드를 펼친 '차액정산 내역' 목록이 정상 필터에서 취소 환수 건을 포함/제외하는지는 서버 응답에 달림프론트는 서버가 준 목록을 그대로 렌더링만 함 → 서버 기준 확인 필요확인필요
최종 정산 산술
선정산 수수료율(C1)·지급 캘린더(C2)·예상 매출 차액(C4) 등 실제 지급 금액을 만드는 산술은 서버 전용정상 필터 여부와 무관하게 어드민 화면은 결과만 수신확인필요
