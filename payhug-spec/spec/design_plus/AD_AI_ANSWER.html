변형  질문을 보낸 뒤 대화 · 응답 화면 — 캡처는 응답 생성 중(로딩) 순간 (사용자 말풍선 + "쿼리 생성 중...") 데이터  응답 본문 · 조회 건수 · 조회 기간 · 원본 로그 · 쿼리는 전부 서버(AI) 스트리밍 산출값 — 화면은 받아서 표시만
No이름설명
1질문말풍선 보낸 질문이 우측 초록 말풍선으로 표시 최대 폭 80%까지, 길면 줄바꿈
2로딩표시 답변 카드 안에 점 3개 애니메이션 + 상태 문구 쿼리 만드는 단계 → "쿼리 생성 중..." 조회 쿼리(LogQL)가 도착한 뒤 분석 단계 → "분석 중..." 서버가 단계별로 밀어주는 스트리밍이라 문구가 순서대로 바뀜
3응답헤더 답변 상단 회색 띠에 조회 정보 표시 (쿼리 또는 조회기간이 도착하면 나타남) 조회 기간 "시작 ~ 종료" (서버가 돌려준 값 그대로) 건수 뱃지 "N건"  3-1 1건 이상=초록 / 0건=회색 우측에 [원본 로그] · [LogQL] 펼침 토글 (해당 데이터 있을 때만 노출)
4펼침토글 [LogQL] 펼침 : AI가 만든 로그 조회 쿼리 원문(어두운 배경 초록 코드) + 한 줄 설명 LogQL = 서버 로그 시스템에 던지는 조회식 — 어떤 조건으로 로그를 뽑았는지 확인용 [원본 로그] 펼침 : "원본 로그 (N건)" 헤더 + 로그 라인 나열 (많으면 영역 안에서 스크롤) 두 토글은 각각 독립으로 열고 닫음
5분석에러 본문에 AI 분석 결과를 마크다운으로 표시 (제목 · 목록 · 표 · 인용 · 코드블록) 에러 시 (빨강 박스, 분기별 원문) 요청 자체 실패 → "요청 중 오류가 발생했습니다." 서버 응답 오류 → "요청 실패 (상태코드)" 스트림 못 읽음 → "스트림을 읽을 수 없습니다" 새 메시지가 오면 화면이 자동으로 맨 아래로 스크롤
정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
이 화면은 어드민 본체(가맹점·정산 DB)와 다른 별도 로그분석 서버(FastAPI)에 자연어 질문을 던지고, 서버가 단계별로 밀어주는 스트리밍(SSE)을 받아 화면에 표시만 하는 구조다. 응답 본문·조회 쿼리·건수·원본 로그는 전부 서버(AI) 산출값이라 확인필요이며, 화면 쪽 로직으로 확정할 수 있는 건 오직 '질문 문구'와 '조회 시간범위' 두 입력의 계산·전송뿐이다. 제안 질문의 '매출대금 회수'는 어드민 스윕(락계좌→모계좌) 개념으로 정책상 과지급 회수와 다르며, 이 AI 로그조회는 구조화 활동로그와도 다른 데이터원이다.
연결데이터 출처·서버 연결
조회 대상 서버
어드민 본체와 다른 별도 서버에 질문을 보냄가맹점·정산 정보를 주는 기존 어드민 데이터가 아니라, 서버 로그 분석 전용 서비스(자연어→로그조회)로 별도 전송그래서 이 화면의 답은 정산 장부값이 아니라 '서버가 남긴 로그'를 AI가 읽어 요약한 것확정
화면은 표시만
응답 본문·조회 쿼리(LogQL)·조회 건수·조회 기간·원본 로그 전부 서버(AI) 산출값화면이 계산·판단하는 값이 하나도 없음. 받아서 그대로 그림따라서 수치의 정확성·수수료·정산 판단은 이 화면 로직으로 검증 불가 = 서버 책임확인필요
로그인 연동
어드민 로그인 토큰을 실어 보냄토큰이 없으면 인증정보 없이도 요청은 시도함(서버가 거부 여부 결정)확정
대화 저장 여부
대화 이력은 화면 메모리에만 존재 → 새로고침하면 사라짐서버에 저장/재조회하는 로직 없음. 감사·재열람 필요 시 정책 보완 대상확정
계산조회 시간범위 계산·전송
기본 조회 프리셋
1시간 · 3시간 · 6시간 · 12시간 · 24시간 · 3일 · 7일 중 택1(기본 1시간)선택 즉시가 아니라 질문 보내는 순간 '지금 시각 − 선택시간 ~ 지금 시각'으로 범위를 만들어 전송확정
직접 지정
시작·종료 일시를 직접 입력 가능종료를 비우면 종료 없이(열린 구간) 전송, 서버가 알아서 처리직접지정 켜는 순간 시작=1시간 전, 종료=현재로 자동 채움확정
요청 범위 vs 표시 범위
응답 헤더에 보이는 '시작 ~ 종료'는 서버가 되돌려준 값이라 내가 요청한 범위와 다를 수 있음서버가 범위를 보정/반올림할 가능성 → 두 값 일치 여부는 확인필요가설
데이터단계별 스트리밍 처리
도착 순서 = 문구
서버가 ①쿼리 ②건수·원본로그 ③분석본문 ④종료/오류를 순서대로 밀어줌쿼리 오기 전 "쿼리 생성 중...", 쿼리 온 뒤 "분석 중..."으로 로딩 문구가 자동 전환헤더·토글도 각 데이터가 도착해야 나타남(건수 없으면 뱃지 없음 등)확정
분석 본문 누적
분석 텍스트는 한 번에 오지 않고 조각으로 계속 이어붙여 실시간 렌더마크다운(제목·표·목록·코드블록)으로 표시확정
건수 뱃지 색 규칙
1건 이상 = 초록, 0건 = 회색0건도 정상 응답(로그가 없었다는 뜻)이라 오류와 구분해 표시확정
정책개념·정책 주의
제안 질문 '매출대금 회수'
기본 제안칩의 "매출대금 회수 실패"는 어드민 매출 회수(락계좌→모계좌 스윕) 로그를 뜻함정책상 과지급 회수와 다른 개념. 답변 요약에서 둘이 섞이지 않게 검수 필요확정
AI 로그조회 ≠ 활동로그
이 화면은 서버 원시 로그를 AI가 훑는 것별도의 활동 로그(가맹점 승인·이체 성공/실패 등 구조화 이벤트 표)와는 데이터원·조회방식이 다름. 같은 사건도 표현·건수가 다를 수 있어 대조 시 주의가설
제안 질문 목록
빈 화면 진입 시 4개 예시 제공: 하루 이슈요약 · 이체 실패 · 매출대금 회수 실패 · 스크래핑 오류클릭하면 그 문구로 바로 질문 전송(현재 선택된 시간범위 적용)확정
