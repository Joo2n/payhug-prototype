종류 카드의 '개정' 버튼으로 진입하는 개정 모달의 '종류 고정' 변형. 대상 약관 종류가 읽기 전용으로 잠기고, 그 종류의 최신 버전에서 제목·본문을 그대로 복사해오며, 버전번호는 최신 버전의 정수부+1로 자동 계산된다. 헤더의 '약관 개정'(종류 선택 모드)과 동작이 갈린다.
연결이 모드로 들어오는 경로와 종류 잠금
진입 버튼
각 약관 종류 카드 우측의 '개정' 버튼으로만 이 모드에 진입.헤더 상단의 '약관 개정' 버튼은 종류를 고를 수 있는 선택 모드로, 이 화면과 다름확정
종류 고정 여부
카드에서 열면 대상 종류가 고정됨(revTypeFixed=true). 어느 종류를 개정하는지 이미 정해진 상태로 시작확정
종류 필드 모습
드롭다운이 아니라 회색 읽기 전용 칸으로 표시.컨텍스트 뱃지 + 종류명만 보이고 변경 불가확정
모달 제목
'약관 개정 (새 버전)' — 신규 등록/수정과 공용 모달을 쓰되 신규 등록 문구로 뜸확정
계산버전번호 자동 계산 규칙
기준
그 종류에 등록된 버전들 중 가장 높은 버전을 찾아 계산의 기준으로 삼음확정
계산식
기존 최신 버전의 정수부 + 1 (소수점 첫자리까지 표기).예: 최신이 2.0 → 3.0, 최신이 2.5여도 → 3.0기존 버전이 하나도 없으면 → 1.0확정
소수 개정 불가
이 자동 계산은 정수 단위로만 올라감. 2.1 같은 소수 개정판은 이 모드에서 만들 수 없음확정
버전 칸 편집
버전 칸은 읽기 전용. 관리자가 손으로 못 고침 (임의 버전은 기존 버전 '수정' 모달에서만 가능)확정
동일 버전 중복 처리
같은 종류에 같은 버전번호가 이미 있을 때 서버가 막는지 여부는 화면에서 판단 불가확인필요
데이터최신 버전 복사와 저장
제목·본문 초깃값
고정된 종류의 최신 버전 제목·본문을 그대로 복사해 채워둠. 관리자는 바뀐 부분만 고치면 됨기존 버전이 없으면 빈 칸확정
시행일 초깃값
모달을 연 오늘 날짜가 기본값. 관리자가 달력에서 변경 가능확정
저장 전 필수값
종류·제목·본문·버전·시행일이 모두 있어야 저장. 하나라도 비면 '필수 항목을 입력해주세요' 경고확정
저장 시 기록되는 작성자
로그인한 관리자 이름이 작성자로 남음(이름 없으면 'admin'으로 기록)확정
게시 상태
개정으로 만든 새 버전은 게시 여부를 담아 보내지 않음 → 생성 직후엔 미게시로 두고, 목록의 게시 토글로 별도 공개하는 흐름으로 보임가설
시행종료일·게시일시 확정
새 버전 등록으로 이전 버전의 시행종료가 자동 닫히는지, 게시일시가 언제 찍히는지는 서버 처리라 화면에서 알 수 없음확인필요
