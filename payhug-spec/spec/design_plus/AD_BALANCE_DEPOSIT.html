모 계좌 잔액 대사에서 "현재 잔액 > 기록상 예상 잔액"인 잔차(양수)가 생겼을 때, 시스템(쿠콘) 밖에서 모 계좌로 들어온 입금(대표 충전 등)을 운영자가 직접 원장에 기록하는 빈 폼 모달. 금액·일시가 필수이고, 잔차만큼을 제안금액으로 넘겨 한 번에 채워 잔차를 0으로 맞추게 돕는다. 여기서의 '외부 입금'은 6대 개념(미지급금·선정산 제외·바로이체·과지급·미회수금·환급)과도, 어드민 '매출 회수'와도 무관한 별도의 수동 잔액 보정 항목이다.
계산제안금액 계산·전달 (이 모달만의 진입 로직)
제안금액이 생기는 조건
잔액 대사에서 잔차(현재 잔액 − 기록상 예상 잔액)가 양수일 때만 제안금액이 채워진다.잔차 0(일치) 또는 음수(현재 잔액이 기록보다 적음)면 모달은 빈 폼으로 열림 (제안 없음)확정
기록상 예상 잔액 산식
최근 이체 직후 잔액(앵커) + 앵커 이후 입금 − 앵커 이후 출금.앵커 = 마지막으로 출금이 성공한 이체 직후 잔액잔차 = 현재 잔액(쿠콘 실시간 조회값) − 위 예상 잔액확정
두 진입 버튼 모두 같은 제안값
대사 카드의 '외부 입금 등록 →'(잔차 양수일 때만 노출)와 원장 헤더의 '외부 입금 등록' 버튼이 같은 모달·같은 제안값을 연다.제안값은 버튼 종류와 무관하게 현재 잔차(양수)에서 계산됨확정
제안금액의 의미
추정 미기록 외부 입금액. "이만큼 시스템 밖 입금이 있었던 것으로 추정된다"는 값.이 금액대로 등록하면 잔차가 0원으로 맞춰진다고 안내확정
설정입력 필드·검증 (모달 폼 자체)
입금 금액 (필수)
제안금액이 있으면 그 값으로 미리 채워짐, 없으면 빈칸.숫자만 인정(입력 중 숫자 외 문자는 계산에서 제거)0 이하이면 "입금 금액을 올바르게 입력해주세요" 경고 후 저장 차단'추정 미기록 입금 N원 채우기' 버튼은 제안금액이 있을 때만 표시확정
입금 일시 (필수)
기본값 현재 시각(분 단위 선택).비우면 서버가 서버 현재 시각으로 기록확정
입금자 / 출처 (선택)
자유 입력. 예시 안내 문구 "대표 충전".미입력 가능확정
메모 (선택)
자유 입력, 미입력 가능확정
정책'외부 입금' 개념·저장 후 처리 (정책)
외부 입금의 정의
시스템(쿠콘) 밖에서 모 계좌로 직접 들어온 입금(대표 충전 등)을 운영자가 원장에 수동 기록하는 항목.6대 개념(미지급금·선정산 제외금액·바로이체·과지급·미회수금·환급) 어디에도 속하지 않음어드민 '매출 회수'(락계좌→모계좌 스윕, 자동 입금)와도 다른, 순수 수동 잔액 보정확정
저장 후 동작
등록 성공 시 모달 닫힘 → 입·출금 원장 재조회 → 실시간 잔액 재조회가 연달아 실행.원장에 '외부 입금' 구분(초록/청록 계열)으로 한 줄 추가되고, 대사 잔차가 그만큼 줄어 0에 근접확정
수정 불가·삭제만 가능
등록된 외부 입금 건은 편집 기능이 없고 원장에서 삭제만 가능(수동 등록분에 한해 삭제 버튼 노출).자동 발생분(지급 출금·매출 회수)은 삭제 불가확정
잔차 음수는 이 모달 대상 아님
현재 잔액이 기록보다 적은 경우는 출금 로그 누락/조회 시점 차이 의심 → '확인 필요'로 안내하며 외부 입금 등록으로 해결하지 않음확정
데이터데이터 출처·서버 확인 필요
현재 잔액 출처
쿠콘 모 계좌 실시간 잔액 조회 응답의 잔액값(성공 응답 기준).제안금액의 한 축인 '현재 잔액'이 이 값에 의존확정
앵커/이후 입출금 합계 산출
최근 이체 직후 잔액, 앵커 이후 입금·출금 합계는 서버가 원장을 집계해 내려주는 값. 화면은 받아서 대사만 표시.집계 기준·시점 규칙은 코드에 없음확인필요
일시 저장 시점·중복 방지
동일 외부 입금을 두 번 등록하는 것에 대한 중복 방지, 미입력 일시의 서버 확정 규칙은 서버 처리라 화면에서 확인 불가확인필요
