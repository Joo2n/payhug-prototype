1:1 문의 목록에서 상단 '대기' 탭을 누른 상태. 탭 클릭 시 서버에 대기 상태만 다시 요청해 목록을 갈아끼운다(서버 재조회). 이 상태 특유의 포인트는 (1) 탭 카운트가 서버가 준 목록만으로 계산돼 대기 필터 중엔 '전체'가 대기 건수와 같아지고 다른 탭은 0으로 보이는 점, (2) 대기 건은 대부분 가맹점이 마지막 발신이라 제목 옆 NEW 배지가 붙는 점, (3) 검색은 서버 재조회 없이 이미 받아온 대기 목록 안에서만 걸린다는 점이다.
설정대기 필터의 조회 동작
대기 탭 = 서버 재조회
상단 탭에서 대기를 고르면 목록을 화면에서 걸러내는 게 아니라 서버에 '대기 상태만' 다시 요청해서 목록 전체를 새로 받아온다.카테고리(일반/결제/정산/기술/계정) 필터도 같은 방식으로 서버 요청에 함께 실려 나간다확정
화면 복귀 시 자동 새로고침
이 탭이 활성화되거나 브라우저 포커스가 돌아올 때마다 현재 필터(대기) 그대로 목록을 다시 불러온다.대기 건이 실시간으로 줄고 느는 성격이라 최신 상태 유지 목적으로 보임가설
검색은 대기 목록 안에서만
검색창(제목·가맹점명·작성자)은 서버 재조회 없이 이미 받아온 대기 목록 안에서만 걸러낸다.즉 대기 필터 중 검색하면 처리중·종료 건은 절대 안 잡힌다확정
데이터대기 상태에서 보이는 표시값
탭 건수 계산의 맹점
각 탭 옆 건수는 지금 화면에 받아온 목록만 세서 매긴다. 대기 필터 상태에선 서버가 대기 건만 주므로 '전체' 탭 숫자가 대기 건수와 똑같아지고 처리중·답변완료·종료 탭은 전부 0으로 표시된다.헤더의 '총 N건'도 대기 건수만 나타냄전체 분포를 보려면 '전체' 탭으로 돌아가야 함확정
NEW 배지
제목 옆 빨간 NEW는 '마지막 메시지를 가맹점이 보냈고 + 종료 상태가 아닐 때' 붙는다. 대기 건은 대개 가맹점이 막 접수해 관리자 답변 전이라 대부분 NEW가 달린다.관리자가 답변을 달면(마지막 발신=관리자) 배지가 사라짐확정
'대기'의 실제 의미
신규 접수돼 아직 관리자 답변/처리 착수가 안 된 문의로 추정. 상태값 자체는 서버가 관리하며 화면에서 자동 부여 규칙은 확인 안 됨확인필요
정책대기 건 처리 흐름
상태 직접 변경
문의를 열면 우측 패널 상단 드롭다운으로 대기 → 처리중 / 답변완료 / 종료를 관리자가 직접 바꾼다. 답변 등록과 상태 변경은 별개 동작이라, 답변을 달아도 상태가 자동으로 '답변완료'로 바뀌지 않는다.상태를 바꾸면 서버 반영 후 목록도 다시 불러옴 → 대기 필터 중이면 방금 바꾼 건이 목록에서 빠짐확정
답변 입력 가능 여부
종료가 아닌 한 답변 입력창이 열려 있어, 대기 상태에서도 바로 답변을 보낼 수 있다.답변 전송 시 상태는 대기 그대로 유지됨(위 규칙과 연결)확정
가맹점 상세로 이동
패널에서 가맹점명을 누르면 해당 가맹점 상세 화면을 탭으로 연다.탭 모드일 때만 동작확정
