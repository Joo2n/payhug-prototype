정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
모 계좌(입금이체 PG) 잔액을 쿠콘 실시간 조회로 띄우고, 같은 계좌의 입·출금 원장을 시간순으로 보여주는 페이허그 내부 전용(운영/관리자) 화면. 핵심 로직 두 가지. (1) 잔액 히어로는 쿠콘 6140 잔액조회 응답을 그대로 표시하되 '조회 시각'은 서버 스크래핑/잔액 기준 시각이 아니라 화면이 응답을 받은 브라우저 로컬 시각이다. (2) '잔액 대사' 카드는 서버 계산이 아니라 프론트 휴리스틱(가설)으로, 서버가 내려주는 '대사 기준값'(앵커 잔액·이후 입금·이후 출금)을 받아 현재 잔액과 뺄셈해 잔차를 만들고, 잔차 0이면 '일치', 양수면 '차이 발생(미기록 외부 입금 추정)', 음수면 '확인 필요'로 해석한다. 원장의 '매출 회수'(락계좌→모계좌 스윕 입금)는 정책의 과지급 '회수'와 다른 개념이며, '외부 입금'은 6대 개념 어디에도 속하지 않는 시스템 밖 충전을 잔차 0으로 맞추기 위한 수동 기록이다. 초안 대비 3건 수정: (a) 삭제 성공 시에는 원장만 재조회하고 잔액은 갱신하지 않음(등록만 둘 다 갱신), (b) 앵커는 '기간 내 최근 출금 성공 건'이 아니라 서버가 내려주는 '전역 대사 기준값', (c) '이체 직후 잔액이 6120 출금 성공 건에만 채워진다'는 서버 계약(코드 주석)이라 확인필요로 강등.
설정접근·조회 기본 설정
접근 권한
페이허그·관리자 계정만 열람.그 외 계정은 화면 대신 '이 페이지는 관리자만 접근할 수 있습니다' 안내문만 노출가맹점에는 절대 노출되지 않는 내부 전용 화면확정
원장 기본 조회 기간
진입 시 최근 7일(오늘−7일 ~ 오늘)로 자동 설정.시작일은 종료일을 넘길 수 없고, 종료일은 오늘을 넘길 수 없게 입력 제한확정
자동 로드 vs 수동 조회
최초 진입 시 잔액과 원장을 각각 1회 자동 조회.이후 기간을 바꾸면 자동 갱신되지 않고 반드시 '조회' 버튼을 눌러야 원장이 반영됨확정
잔액 자동 재조회
다른 탭에 갔다가 이 탭으로 돌아오면 잔액만 자동으로 새로 조회(원장은 갱신 안 함).상단 '새로고침' 버튼으로도 잔액만 재조회확정
연결데이터 출처·연결
현재 잔액(히어로)
쿠콘 6140 잔액조회 결과를 불러와 그대로 표시(화면 라벨은 '실시간').'입금이체 PG' 계좌 = 정책상 모 계좌확정
입·출금 원장 + 대사 기준값
선택 기간을 넘겨 원장 목록과 대사 기준값(앵커 등)을 한 번에 받아옴.기간 요약(지급 출금·매출 회수 입금·외부 입금 합계·총 건수)도 이 응답에 포함확정
외부 입금 등록·삭제 후 갱신
수동 외부 입금은 별도 등록/삭제 연결로 처리.등록 성공 시: 원장과 잔액을 모두 다시 불러옴삭제 성공 시: 원장만 다시 불러오고 잔액은 갱신하지 않음(초안의 '등록·삭제 모두 잔액 재조회'는 오류 — 삭제는 원장만)확정
쿠콘 잔액 갱신 주기
화면은 '실시간'이라 표기하지만, 실제 쿠콘 스크래핑/잔액 기준 시각은 서버 몫이라 화면 코드로는 알 수 없음.갱신 주기·지연 여부는 서버 확인 필요확인필요
데이터잔액 히어로·원장 표시 데이터
잔액 히어로 구성값
현재 잔액 + 출금 가능 / 출금 불가 두 보조값.하단에 응답 상태·거래일련번호·조회 시각 병기확정
응답 상태 판정
쿠콘 응답코드가 성공 코드(0000)면 '성공'으로 표기.그 외에는 응답 메시지와 코드를 함께 노출해 실패 원인 확인확정
원장 '구분' 4종
선정산 지급·수동 지급(출금) / 매출 회수·외부 입금(입금).입금 건은 좌측 초록 띠, 출금 건은 회색 띠로 방향 구분'상대/메모' 칸에 상대방·메모 표시확정
원장 '상태' 5종
성공 / 확인완료 / 실패 / 요청중 / 타임아웃.실패 건은 거래번호 자리에 실패 메모(사유)를 빨간색으로 대신 표시확정
'이체 직후 잔액' 칸
원장 각 행에 '이체 직후 잔액' 칸이 있어 값이 있으면 표시, 없으면 '—'. 입금 건(매출 회수·외부 입금)은 대체로 공란.다만 '쿠콘 6120 출금 성공 건에만 값이 채워진다'는 건 서버가 채워 내려주는 계약(코드 주석 기준)이라 서버 확인 필요확인필요
외부 입금 등록 입력 항목
모달에서 입금 금액(필수)·입금 일시(필수)·입금자/출처·메모 입력.입금 일시 기본값은 브라우저 현재 시각, 미입력 시 서버 현재 시각 사용(서버 처리 부분은 확인 필요)확정
계산잔액 대사 계산(프론트 휴리스틱)
대사 수식
현재 잔액 = 최근 이체 직후 잔액(앵커) + 이후 입금 − 이후 출금 + 잔차.이 뺄셈(대사)은 서버가 아니라 화면에서 직접 계산앵커·이후 입금/출금 합계 자체는 서버가 '대사 기준값'으로 내려준 값을 그대로 사용가설
잔차 부호별 해석
잔차 0 = 대사 일치 / 양수 = 차이 발생(미기록 외부 입금 추정) / 음수 = 확인 필요.카드는 앵커가 있고(현재 잔액·앵커 모두 존재) 잔차가 계산될 때만 노출가설
미기록 입금 추정액
잔차가 양수면 그 금액을 '미기록 외부 입금(추정)'으로 제시하고, 외부 입금 등록 시 금액을 자동 채워줌.'등록하면 잔차가 0으로 맞춰진다'는 안내 문구가설
'조회 시각'의 의미
히어로의 조회 시각은 화면이 응답을 받은 시점(브라우저 로컬 시각).쿠콘 스크래핑 시각·잔액 기준 시각과 다를 수 있어 혼동 주의확정
앵커·이후 입출금 산출 주체
앵커(최근 이체 직후 잔액)·기준 시각·거래번호와 '이후 입금/출금' 합계는 서버가 '전역 대사 기준값'으로 산출해 내려줌.앵커가 조회 기간과 무관한 전역 최신값인지(초안의 '기간 내 최근 출금 성공 건'은 근거 없음), 어떤 거래를 앵커 이후로 보는지, 실패·대기 건 포함 여부는 서버 확인 필요확인필요
정책개념 구분·운영 정책
'매출 회수' ≠ 과지급 '회수'
원장의 매출 회수는 락계좌→모계좌 스윕 입금(모 계좌로 돈이 들어오는 거래).정책상 과지급금 '회수'와는 전혀 다른 개념 — 같은 단어로 합치면 안 됨(코드는 '매출 회수' 라벨·입금 방향만 확인, 스윕 성격은 정책 근거)확정
'외부 입금'의 성격
