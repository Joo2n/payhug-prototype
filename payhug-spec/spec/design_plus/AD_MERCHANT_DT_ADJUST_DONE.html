차액 정산 이력의 [완료] 필터 활성 variant. 표 구조·계산은 베이스(AD_MERCHANT_DT_ADJUST)와 동일하고, 이 화면만의 특수점은 (1) [완료] 탭이 상태값 '완료(APPLIED)'를 서버 조회 조건으로 넘겨 완료 건만 받아오려는 의도, (2) 상단 4개 요약 카드가 서버가 걸러 내려준 완료 건 집합만으로 재계산되는 것, (3) '정산일' 컬럼이 완료 상태에서만 실제 날짜로 채워지는 것이다. 다만 목업 캡처는 서버 필터가 미적용되어 대기 건까지 14건 전부 노출되는 한계가 있다.
연결완료 필터의 조회 조건 전달
[완료] 탭 클릭 시 서버로 넘기는 값
탭이 전체 / 완료 / 대기 3개이고, [완료]를 누르면 화면이 '완료' 상태값을 조회 조건에 실어 목록을 다시 불러온다.[전체]일 때는 조건 없이 전 건, [완료]/[대기]일 때만 해당 상태 조건을 붙임확정
서버 필터 실제 반영 여부
완료 건만 걸러 내려주는 것은 서버 응답에 달려 있음. 화면은 받은 목록을 그대로 뿌리며 자체적으로 대기 건을 숨기지 않는다.목업 캡처는 서버 필터가 미적용되어 대기 행 포함 14건 전체가 그대로 표시됨(전체 탭과 동일 모습)확인필요
탭 전환마다 재조회
탭을 바꿀 때마다 목록을 새로 서버 조회한다. 화면에 이미 받아둔 데이터를 걸러 보여주는 방식이 아니다.확정
계산완료 집합 기준 요약 카드 재계산
상단 카드 4종
전체 건수 / 환급 / 추가 차감 / 순 차액. 이 값들은 별도 요약 API가 아니라 현재 목록에 담긴 건들만으로 즉석 합산된다.따라서 [완료] 필터에서 서버가 완료 건만 내려주면 카드도 완료 건만 반영확정
환급 / 추가 차감 카드의 집계 범위
'환급' 카드는 구분이 카드수수료 환급인 건만, '추가 차감' 카드는 카드수수료 차감인 건만 세고 금액을 더한다.예상매출·배달수수료·미회수 이월·취소 환수 등 다른 구분은 이 두 카드의 건수·금액에서 빠짐(집계 누락 소지)가설
순 차액
환급 합계 − 추가 차감 합계로 계산하고, 양수면 파란색 '+', 음수면 빨간색으로 표기.위와 같은 이유로 카드수수료 외 구분은 순 차액에도 반영 안 됨가설
차액의 원천 산식
차액 = 정산 적용 수수료 − 실제 수수료. 실제 수수료는 매입 확정 후 확인되는 값이라 최종 산술·확정 수수료율은 서버 소관.확인필요
데이터완료 상태에서의 표·날짜 표기
'정산일' 컬럼
완료 처리 시각(적용 완료 일시)을 날짜로 표기. 완료 건은 날짜, 값이 없으면 '-'로 나온다.대기 건은 아직 적용 전이라 '-'가 정상. [완료] 필터에서는 원칙적으로 모든 행에 날짜가 찍혀야 함확정
상태 배지
대기 / 완료 / 취소 3종. 완료는 초록 배지로 표시.[완료] 필터가 제대로 걸리면 표에는 초록 '완료' 배지만 남아야 함확정
구분 배지 종류
카드수수료 환급/차감, 예상매출 환급/차감, 배달수수료 환급/차감, 미회수 이월, 취소 환수까지 표기하고 환급은 '+', 차감·이월·환수는 '-' 부호.'미회수 이월'은 정책상 미회수금을, '취소 환수'는 취소로 인한 환수를 가리키는 별도 구분(과지급 회수와 혼동 금지)가설
