가맹점 관리 목록의 '심사대기' 필터 상태. 계약상태가 심사대기(PENDING)인 가맹점만 클라이언트에서 걸러 보여주는 화면으로, 서류가 다 들어왔는지(계약 진행 6단계)를 한눈에 보고 상세로 넘어가 승인/반려를 판단하는 트리아지용 뷰다. 심사대기 특유의 정렬·집계·액션 라벨과, 상세 화면에서의 승인 게이트(투자자 매칭 선행)를 다룬다.
계산심사대기 필터·정렬·집계
필터 방식
서버가 아니라 화면에서 걸러낸다. 전체 가맹점을 한 번 다 불러온 뒤, 계약상태가 '심사대기'인 행만 남겨 보여주는 클라이언트 필터다.검색어(가맹점명·사업자번호·대표자명·사용자명)와 함께 걸린다확정
탭 카운트 숫자
'심사대기' 탭 옆 숫자는 전체 목록 중 심사대기 건수를 세어 표기. 검색 결과가 아니라 원본 전체 기준이라, 검색 중에도 숫자는 안 변한다.확정
정렬 순서
필터와 무관하게 승인+정산활성 → 승인 → 그 외 순으로 고정 정렬. 심사대기는 '그 외'라 항상 맨 뒤 그룹으로 밀린다.심사대기만 봐도 이 정렬이 그대로 적용됨확정
행 액션 라벨
행 hover 시 우측 화살표 문구가 상태별로 갈린다. 심사대기 = '심사', 승인 = '관리', 미등록(사업자ID 없음) = '상세'.확정
데이터계약 진행 현황(서류 6단계) 집계
진행률의 정체
'계약 진행' 칸의 막대·분수(예 4/6)는 서류 제출 완료 단계 수 ÷ 전체 단계 수. 심사대기 가맹점이 서류를 어디까지 냈는지 보는 지표다.확정
6개 단계 구성
사업자 · 신분증 · 락계좌 · 정산계좌 · 플랫폼(외부 계정) · 계약동의. 행 위에 커서를 올리면 각 단계의 완료 여부가 체크로 뜬다.이관(부채) 가맹점은 별도 단계 세트를 씀확정
완료했는데도 심사대기
6단계 전부 완료여도 계약상태는 심사대기로 남을 수 있다. 상세 화면 배지가 이 경우 '심사 대기 중'(서류는 끝, 승인 판단만 남음)으로 표기된다.단계 완료 = 자동 승인 아님확정
각 단계 완료 판정 기준
무엇을 근거로 '락계좌 완료' 등을 판정하는지(어떤 서류·연동 상태를 봐서)는 서버가 계산해 내려주는 값이라 화면 코드에선 알 수 없다.확인필요
정책승인 게이트(심사대기 → 승인)
승인 처리 위치
심사대기 목록에선 승인 못 함. '심사'로 가맹점 상세에 들어가 거기서 승인/반려한다. 이 목록은 진입점 역할.가설
투자자 매칭 선행 조건
투자자가 매칭돼 있지 않으면 승인 버튼이 막힌다. '승인 전 투자자를 먼저 매칭 → 투자자 매칭 후 매출 건전성 검증 완료돼야 승인 가능'이라는 안내가 뜬다.예외: '투자자 없음'으로 명시 설정한 가맹점은 매칭 없이 승인 가능확정
매출 건전성 검증
안내 문구상 승인 전 '매출 건전성 검증'을 통과해야 한다고 명시. 다만 이 검증이 실제로 어떤 데이터·기준으로 통과/실패를 가르는지는 화면에 없어 서버 정책 확인 필요.확인필요
반려 처리
반려 모달에 사유 입력(필수). 심사대기 상태의 반려는 '정보 수정 후 재심사'로 안내되며, 이미 승인된 가맹점 반려와는 경고 문구가 다르다(승인 반려 시 '서비스 중단' 경고).확정
