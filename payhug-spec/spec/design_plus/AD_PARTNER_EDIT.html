회원 수정 모달의 심화 로직. 화면설계서가 다루지 않은 저장 시 필드 처리 규칙(비밀번호·전화번호·추천코드), 프리필 데이터 출처(목록 행 재사용·비밀번호 미프리필), 유형 옵션이 '생성 가능 유형'으로 제한되어 수정 시 발생하는 부작용, 상태 변경의 이중 경로에 집중.
계산저장 시 필드 처리 규칙
비밀번호 전송 방식
입력값이 있을 때만 저장 데이터에 비밀번호 항목을 실어 보냄.빈 값이면 항목 자체를 아예 빼고 전송 → 서버에서 기존 값 그대로 유지'빈 문자열로 덮어써서 초기화'되는 사고를 구조적으로 차단확정
전화번호(아이디) 정규화
저장 직전 하이픈(-) 모두 제거 후 숫자만 전송.화면엔 010-0000-0034로 보여도 저장은 01000000034 형태아이디로도 쓰이므로 저장 형태가 로그인 판정 기준이 됨(가설)가설
추천 코드 처리
입력값을 대문자로 자동 변환하고, 저장 시 공백 제거 후 값이 있을 때만 전송.기존 코드를 지우고 저장해도 '빈 값'은 전송되지 않아 코드 삭제(비우기)가 불가(확인필요)확인필요
이름·전화번호 필수 검증
이름 또는 전화번호가 비면 등록과 동일 문구로 차단.수정에서는 비밀번호는 필수 검증에서 제외(등록만 필수)확정
데이터프리필 데이터 출처와 함정
프리필 원천
수정 모달의 초기값은 목록 화면이 이미 들고 있는 그 행의 값을 그대로 채움.수정 진입 시 별도 상세 재조회 없음 → 목록이 최신이 아니면 옛 값으로 열릴 수 있음(가설)가설
비밀번호는 프리필 안 함
비밀번호 칸은 항상 빈 칸으로 열림(기존 값을 불러와 채우지 않음).실제 저장된 비밀번호는 서버 전용이라 화면에서 확인 불가(확인필요)확인필요
유형 선택지 제한의 부작용
수정 모달의 유형 드롭다운도 '내가 만들 수 있는 유형' 목록으로만 채워짐.대상 회원의 현재 유형이 그 목록에 없으면 선택지에 안 뜸 → 무심코 저장 시 다른 유형으로 바뀔 위험(확인필요)확인필요
상위 회원 옵션 구성
상위 후보 = 활성 회원 중 자기 자신 제외.실제 상위가 조회 범위(자기+하위) 밖이면 목록에 없으므로 '(현재 상위)'로 맨 위에 강제 추가해 '없음'으로 잘못 저장되는 것을 방지확정
정책상태 변경 이중 경로 · 권한
상태 변경 두 갈래
① 수정 모달 상태 드롭다운(활성/비활성) — 다른 수정 항목과 함께 저장② 목록 행의 비활성화 버튼 — 상태만 단독으로 비활성 처리(별도 경로).두 경로가 같은 '비활성' 결과를 만들지만 진입점·저장 범위가 다름확정
비활성의 의미
비활성 회원은 로그인 불가(비활성화 확인 문구에 명시).삭제와 달리 데이터는 남김확정
법인·사업자 토글 잠금
법인 여부·사업자 여부 토글은 관리자 권한(관리자/페이허그)에서만 조작 가능, 그 외엔 잠김.사업자 여부는 화면상 부가세 적용 기준으로 안내되나 실제 정산 반영 로직은 서버 전용(확인필요)확인필요
