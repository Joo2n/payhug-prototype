정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
어드민이 특정 가맹점의 카드·배달앱 매출 원자료를 기간을 지정해 소급(백필) 재수집하는 모달. 비동기 배치로 돌며 헤더 버튼이 '수집 중'으로 잠기고, 완료 시 소스별 건수와 누락 구간을 알려 관리자가 그 기간만 다시 수집하도록 유도한다.
설정수집 대상·기본 기간
접근 권한
내부 관리자에게만, 그리고 사업자번호가 있는 가맹점에만 버튼 노출.총판·영업 등 파트너 계정에는 버튼 자체가 보이지 않음확정
기본 기간
모달을 열면 시작일 = 오늘 기준 3개월 전, 종료일 = 오늘로 자동 세팅.관리자가 두 날짜를 자유롭게 바꿔 실행확정
실행·시작 안내
모달 하단 [수집 시작](앰버) 클릭 시 즉시 배치 요청.시작되면 "매출 데이터 수집 시작 (시작일 ~ 종료일)" 안내 표시확정
상시 토글과의 경계
이 모달(과거 기간 소급 재수집)은 가맹점 상세의 상시 '데이터 수집 ON/OFF' 토글과 다른 기능.토글은 앞으로의 자동 수집을 켜고 끔, 이 모달은 지정 기간을 되짚어 수집가설
연결수집 소스·건수 집계
대상 소스
카드 매출 + 배달 플랫폼 매출을 한 번에 수집확정
배달 3사 구분
누락 구간 표기에서 배민·요기요·쿠팡이츠(및 '전체')로 나뉘어 표시 → 3사를 개별 추적확정
건수 두 묶음
진행·완료 표시에서 카드 건수와 배달앱 건수를 각각 세어 보여줌확정
배달앱 건수 집계 범위
실시간 진행 표시는 '배달앱' 한 덩어리 건수인데 누락 표기는 3사로 분리됨.배달앱 건수가 3사 합산인지 특정 앱만인지 코드상 불명확인필요
데이터진행 표시·배치 처리
비동기 배치
시작하면 수집 작업 식별값을 브라우저에 저장 → 다른 화면으로 이동하거나 여러 탭을 열어도 진행 상태가 이어짐확정
진행 중 버튼 잠금
수집 중에는 헤더 버튼이 "수집 중..."으로 바뀌고 비활성확정
상태 폴링
15초 간격으로 서버에 진행 상태를 재조회.여러 탭이 동시에 열려도 10초 내 중복 조회는 건너뜀확정
진행 토스트
진행 중이고 누적 건수가 있으면 "수집 중... 카드 N건, 배달앱 M건" 표시확정
종료 상태값
완료·실패·'알 수 없음'이 오면 폴링 종료·작업 식별값 삭제.각 상태값(특히 '알 수 없음')의 서버 판정 규칙은 미확인확인필요
정책부분 실패·누락 구간 재수집
완료 알림
"매출 데이터 수집 완료 — 카드 N건, 배달앱 M건" 뒤에 카드오류·배달앱 스킵·실패 건수를 덧붙여 표시확정
누락 구간 재수집 유도
누락 구간이 있으면 소스별로 "누락 구간: [카드] 2026.04.01 ~ ... / 해당 기간을 지정하여 재수집해 주세요" 안내.자동 재수집이 아니라 관리자가 그 기간을 다시 넣어 재실행하는 방식확정
실패 판정 기준
실패 건수 > 0, 또는 카드오류 > 0, 또는 누락 구간 존재 중 하나라도 있으면 완료 알림을 오류(빨강)로 띄우고 자동으로 닫지 않음확정
배달앱 스킵 예외
'배달앱 스킵' 건수는 표기만 하고 실패 판정에는 넣지 않음 — 스킵은 정상 처리로 간주확정
중복 실행 차단
이미 진행 중이면 새 요청을 거부하고 "이미 매출 데이터 수집이 진행 중입니다." 안내확정
