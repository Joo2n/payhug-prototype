특정 가맹점의 정산 상세를 VOC(가맹점 문의) 대응용 엑셀로 뽑는 내부 전용 도구. '조회'로 데이터 유무를 먼저 확인한 뒤에만 엑셀을 받을 수 있는 2단계 구조이며, 엑셀 본문·산술은 전부 서버가 만들어 완성 파일로 내려준다. 단, '내역 없음' 안내와 통신 실패 오류가 화면상 같은 붉은 박스로 표시돼 구분되지 않는다.
설정대상·권한 조건
탭 노출 권한
VOC 대응 탭은 페이허그 내부 관리자에게만 보인다. 파트너·영업조직 계정에는 탭 자체가 나타나지 않고, 주소로 직접 접근해도 화면이 열리지 않음.확정
권한 기준의 성격
이 탭이 걸린 '내부 관리자' 조건은 미정산 누락 조회 등 실제 지급 권한이 필요한 다른 내부 전용 기능과 동일한 기준이다.다만 VOC 도구 자체가 지급을 실행하는 건 아니므로, '지급 권한자용'이라는 성격 규정은 근거 확인 필요가설
가맹점 목록 후보
드롭다운에는 계약이 '승인' 상태이고 사업자번호가 등록된 가맹점만 나온다.계약 진행중·반려·사업자번호 미입력 가맹점은 애초에 선택지에 없음목록에는 '가맹점명 (사업자번호)'로 보이지만, 실제 조회 기준값은 사업자번호 (동명 가맹점 혼선을 막으려는 의도로 보임)확정
기간 기본값·독립 필터
이 탭은 화면 상단 공통 기간 필터를 숨기고 자체 기간 필터를 쓴다.기본 기간은 이달 1일 ~ 오늘시작일이 종료일보다 뒤인지 등 기간 유효성 검사는 화면에 없음 (확인 필요)확정
연결조회·다운로드 2단계 흐름
가맹점 선택은 조회의 전제
가맹점을 고르지 않으면 [조회] 버튼이 눌리지 않고, 강제로 누르더라도 "가맹점을 선택해주세요" 안내가 뜬다. 기간만으로는 조회할 수 없음.확정
먼저 '조회'로 유무 확인
엑셀을 바로 못 받는다. [조회]를 눌러 해당 가맹점·기간에 정산 내역이 있는지 먼저 확인해야 하고, 내역이 있을 때만 파란 결과 박스와 [엑셀 다운로드] 버튼이 나타난다.데이터가 없으면 파란 결과 박스도 다운로드 버튼도 뜨지 않고, 대신 붉은 안내 문구만 표시됨확정
조회 = 서버에 유무 질의
[조회]는 서버에 '이 가맹점·이 기간에 정산 데이터가 있나'를 물어보고, 있으면 요약값(배치 수·거래 수·실지급 합계·가맹점명)을 받아 파란 박스에 보여준다.데이터 없음으로 응답하면 "○○의 해당 기간에 정산 내역이 없습니다" 안내확정
조건 바꾸면 결과 초기화
가맹점·시작일·종료일 중 하나라도 바꾸면 이전 조회 결과와 안내·완료 문구가 즉시 사라진다. 낡은 결과로 엉뚱한 엑셀을 받는 것을 막는 장치.확정
다운로드는 별도 서버 요청
[엑셀 다운로드]는 조회와는 별개로 서버에 파일 생성을 다시 요청한다. 파일명도 서버가 정해 내려준 값을 그대로 쓴다(내려오지 않으면 'VOC_사업자번호_기간' 형식으로 자동 지정).확정
다운로드 완료 안내
엑셀이 정상적으로 내려오면 결과 박스 안에 "다운로드가 완료되었습니다" 초록 안내가 뜬다. 실패하면 붉은 오류 문구로 바뀜.확정
데이터데이터 출처·표시값
결과 박스 3개 숫자
조회 성공 시 파란 박스에 보여주는 값은 배치 N건 · 거래 N건 · 실지급 합계 N원이며, 가맹점명·사업자번호가 함께 표기된다.배치 = 정산이 한 회차로 묶인 단위 수거래 = 그 기간 거래 건수실지급 합계 = 실제 지급 금액으로 표기된 값 (예상값·예정값 아님)거래 수·실지급 합계는 서버가 안 내려주면 빈칸으로 표시됨확정
'실지급 합계'의 성격
이 숫자는 예상 지급액이 아니라 이미 지급이 끝난 확정 결과의 합으로 보인다. VOC(가맹점 문의) 대응이 목적이므로, 실제 통장에 나간 금액 기준으로 설명하려는 의도.가설
엑셀 본문의 원천
화면(프론트)은 엑셀 내용을 전혀 만들지 않는다. 거래 목록·수수료·배분·지급액 등 엑셀 안의 모든 행과 숫자는 서버가 생성해 완성된 파일로 내려준다.참고: 같은 화면의 '차액 정산' 탭은 화면이 직접 엑셀을 조립하지만, VOC 엑셀은 서버 완성본이라는 점이 다름확정
계산계산·엑셀 구성
수수료 3종→지급액 산술
선정산 수수료(가맹점 마진·시스템 수수료 등) 적용, 원장 반영, 파트너 배분, 최종 지급액 산출이 엑셀 안에 어떤 항목·순서로 담기는지는 서버에만 있어 이 화면 코드로는 확인 불가.확정 수수료율(C1)·지급 캘린더(C2)와 직결되므로 서버 산출식 확인 필요확인필요
6대 개념 포함 여부
엑셀에 미지급금·선정산 제외금액·바로이체·과지급·미회수금·환급이 각각 별도 항목으로 분리돼 들어가는지, 아니면 합산돼 나오는지 화면 코드로는 알 수 없다. VOC 대응 품질을 위해 서버 엑셀 서식 확인 필요.확인필요
실지급 합계 집계 방식
결과 박스의 '실지급 합계'가 취소·과지급 회수·차감을 반영한 순액인지, 지급 총액인지 서버 계산이라 미확정. 가맹점에 설명하는 숫자이므로 정의 확정 필요.확인필요
정책정책·주의
어드민 '매출 회수'와 무관
이 도구는 조회·엑셀 추출 전용이다. 락계좌→모계좌 스윕(어드민의 '매출 회수')이나 과지급 '회수'(정책)를 실행하지 않으며, 지급 상태를 바꾸는 어떤 동작도 하지 않는다. (화면이 부르는 건 읽기·다운로드 요청뿐)확정
'내역 없음'과 '통신 실패'가 같은 붉은 박스
현재 화면은 '정산 내역 없음' 안내와 서버 통신 실패 오류를 똑같은 붉은 박스에 표시해 시각적으로 구분되지 않는다.'내역 없음'은 정상 응답, '통신 실패'는 오류로 성격이 다른데도 같은 모양이라 응대자가 혼동할 소지두 상태를 다른 색·문구로 구분하는 표시 정책 필요확인필요
가맹점 목록 로딩 실패가 조용히 묻힘
가맹점 목록을 불러오지 못해도 오류 안내 없이 빈 드롭다운만 남는다.사용자는 '해당 가맹점이 없다'고 오해할 수 있어, 로딩 실패를 알리는 처리 필요확인필요
엑셀 최신성
엑셀이 만들어지는 시점(스크래핑·동기화·배치 반영 이후 어느 시점의 스냅샷인지)은 서버 배치 스케줄에 달려 있어 화면 코드로는 확인 불가. 문의 응대 시 '언제 기준 값'인지 표기 정책 필요.확인필요
