정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
거래를 여러 건 입력해 하나의 배치처럼 실행하는 상태. 단건 대비 특수한 것은 '배치 단위 합산' 로직이다. 시스템 이용료는 건별로 계산하지만 참여자 단위로 다시 합산해 별도 카드로 보여주고, 이체 수수료는 건수와 무관하게 배치당 1회만 부과한다. 수수료 유형별 '부과 총액'도 다건을 가로질러 집계하며, 스킵된 건은 이 합산에서 빠진다. 카드·배달 정책을 각각 지정해 유형별로 다른 정책을 태워볼 수 있고, 결과는 저장하지 않는다.
계산다건이라서 생기는 배치 단위 합산
시스템 이용료 건별 합산
건마다 따로 계산된 시스템 이용료를 참여자(이름+역할) 단위로 다시 합쳐 별도 '건별 합산 N건' 카드로 보여줌같은 참여자면 매출·원가·수익·VAT·배분액을 모두 더함N = 시스템 이용료가 잡힌 건수(스킵·미해당 건 제외)확정
이체 수수료는 배치당 1회
건수가 몇 건이든 이체 수수료는 배치 전체에 딱 1번만 부과 (건별 원장이 아니라 배치 단위 별도 카드)카드 문구도 '배치당 1회'로 고정확정
채권매입 수수료 합산
요약의 채권매입 부과액 = 각 건 수수료의 단순 합, 단 스킵된 건은 0으로 제외확정
부과 총액의 정의
수수료 유형별 '부과' 금액은 제외(기록용) 아닌 행 중 배분액이 양수인 것만 더한 값 = 실제 부담자에게 물린 금액음수·기록용 행은 부과 총액에 안 들어감확정
연결정책 지정과 서버 실행
유형별 정책 분리 적용
카드 정책·배달 정책을 각각 골라 실행 → 각 거래 행의 유형에 맞는 정책이 적용됨한 배치 안에서 카드·배달 혼합 입력 가능, 유형별로 서로 다른 정책을 태워볼 수 있음확정
실행 최소 조건
카드·배달 정책 중 최소 1개를 골라야 실행 버튼 활성화둘 다 '선택 안 함'이면 실행 불가확정
서버로 보내는 값
각 행의 유형·금액 목록 + 선택한 카드/배달 정책 ID를 실행 시 함께 전송 → 서버가 원장·배분을 계산해 돌려줌확정
정책 목록 출처
화면 진입 시 어드민 정산 정책 목록을 불러와 드롭다운 구성 (규칙유형·정책명·ID 표기)확정
결과 미저장
실행해도 서버에 저장하지 않는 미리보기 전용 — 확정·지급과 무관확정
정책건별 스킵과 배분 유형
건별 스킵 처리
특정 건이 정책 미해당 등으로 계산 제외되면 그 건 머리에 빨강 '스킵: 사유'만 뜨고 수수료·정책명·원장은 숨김스킵 건은 채권매입 합산·건수에서 빠짐확정
직접배분 vs 기록용
배분 요약에서 참여자를 두 유형으로 구분직접배분: 실제로 배분액이 나가는 대상기록용: 장부 기록만, 배분 총액에 안 잡힘(회색 기울임)확정
참여자 속성 뱃지
참여자에 법인·사업자(VAT) 뱃지 — 세금계산서/부가세 처리 대상 여부를 시각 구분가설
수수료율·배분 산식
화면에 뜨는 수수료·배분액은 서버 계산 결과일 뿐이고, 실제 수수료율(C1)·산정 근거는 이 화면에서 알 수 없음확인필요
