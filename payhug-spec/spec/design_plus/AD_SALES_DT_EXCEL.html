가맹점 상세의 '엑셀 일괄 등록' 모달은 업로드→미리보기→결과 3단계 마법사다. 이 모달에만 있는 특수 로직은 세 가지다. (1) 파일 확장자를 프런트에서 먼저 거르고, 서버가 카드(여신금융협회) 승인/매입 양식과 배달 단건등록 양식을 자동으로 구분해 '타입'을 판정한다. (2) 행마다 신규/중복/에러 3상태로 판정해 집계하고, 중복 행은 저장 시 기존 데이터를 덮어쓴다. (3) 파싱과 저장이 별도 단계로 분리돼, 미리보기는 저장 없이 확인만 하고 실제 반영은 별도 저장 요청에서 일어난다. 최종 저장 시 부과되는 수수료·정산 계산과 중복 판정 키, 에러 행 제외 여부는 서버 전용이라 확인필요.
설정파일·양식 인식 규칙
허용 파일 형식
.xls / .xlsx 만 허용그 외 확장자는 업로드 시도 즉시 '.xls 또는 .xlsx 파일만 업로드할 수 있습니다' 안내로 막음드래그앤드롭·파일선택 두 경로 모두 동일하게 검사확정
인식 대상 양식
세 종류 양식을 자동 인식카드 승인내역(여신금융협회)카드 매입내역배달 단건등록 양식안내문구: '카드 승인내역/매입내역, 배달 단건등록 양식 자동 인식'확정
타입 판정 주체
업로드 파일을 서버가 읽어 카드 승인 / 카드 매입 / 배달 중 하나로 스스로 판정해 돌려줌운영자가 타입을 고르지 않음미리보기 상단에 판정된 타입이 표시됨가설
양식 구분 기준(컬럼 매핑 규칙)
어떤 컬럼·헤더로 세 양식을 구분하고 각 칸을 주문번호·거래일자·금액·카드사에 대응시키는지는 서버 파싱 로직 소관확인필요
계산행 판정·집계·중복 처리
행별 3상태 판정
업로드된 각 행을 신규 / 중복 / 에러로 분류신규: 처음 들어오는 건중복: 이미 존재하는 건에러: 파싱 불가·형식 오류 행(미리보기에서 빨간 배경 강조)확정
상단 집계 카드
미리보기 상단에 타입 · 신규 건수 · 중복 건수 · 에러 건수 4칸으로 요약확정
중복 행 처리 방침
중복 건은 기존 데이터를 덮어씀(업데이트)중복이 1건이라도 있으면 '중복 건은 기존 데이터를 업데이트합니다' 경고 노출즉 중복이라고 버리지 않고 최신 업로드값으로 갱신확정
저장 버튼 활성 조건·라벨
저장 버튼 라벨 = (신규+중복) 건수 + '건 저장'신규·중복이 모두 0(에러만 있음)이면 저장 버튼 비활성에러 행은 저장 대상 집계에서 제외됨확정
에러 행 최종 처리·중복 판정 키
저장 시 에러 행을 실제로 어떻게 처리하는지, 중복 여부를 무엇(주문번호+거래일자 등)으로 판정하는지, 저장된 매출에 부과되는 수수료·선정산 계산은 모두 서버 전용확인필요
연결2단계 저장 흐름·데이터 출처 표시
미리보기는 저장 아님
업로드=파싱만, 저장은 별도 단계1단계 업로드 요청은 파일을 해석해 신규/중복/에러 결과만 돌려줌(실제 반영 없음)운영자가 미리보기를 확인하고 저장을 눌러야 2단계 저장 요청이 나감저장 전 '다시 선택'으로 파일 교체 가능확정
저장 결과 화면
3단계 결과에서 성공 · 중복 · 실패 건수 를 서버 확정값으로 다시 표시미리보기의 예상 집계와 별개로, 실제 반영 결과를 재확인확정
저장 시 넘기는 정보
저장 요청에 사업자번호 · 판정된 타입 · 미리보기의 전체 행을 함께 전달특정 가맹점(사업자번호) 매출로 귀속확정
업로드 매출 출처 표식
이 모달로 저장된 건은 매출 목록에서 '엑셀' 배지(보라색)로 구분 표시단건 수동등록은 '수동' 배지와 구별됨나중에 원천이 엑셀 업로드임을 목록에서 식별 가능확정
업로드 이력 조회
사업자번호별 업로드 이력을 불러오는 연결이 별도로 존재(현재 이 모달 화면에는 미노출)가설
