회원 목록 행의 [비활성화]를 누르면 뜨는 확인 모달. 활성 회원에만 노출되며, 실행하면 해당 회원의 상태가 활성→비활성으로 바뀌고 로그인이 차단된다. 같은 화면의 [삭제]와는 다른 처리(경고 vs 위험, 되돌림 가능 vs 불가)이며, 비활성 회원을 다시 활성으로 되돌리는 경로는 이 모달이 아니라 [수정] 모달의 상태 드롭다운이다.
정책비활성화 vs 삭제 — 같은 화면 두 액션의 구분
이 모달의 처리 효과
상태만 활성→비활성으로 전환, 회원 데이터는 그대로 보존.보조문구: "비활성화하면 해당 사용자는 로그인할 수 없게 됩니다" → 효과는 로그인 차단으로 한정확정
삭제와 다른 점
바로 옆 [삭제]는 완전 삭제·되돌릴 수 없음이고 "정산 상품에 배정된 경우 삭제 불가" 전제 경고가 붙는다.비활성화에는 이런 배정 여부 전제 경고가 없다 (되돌릴 수 있는 조치라 경고 강도가 낮음)확인 버튼 스타일도 비활성화=주황(경고), 삭제=빨강(위험)으로 다름확정
재활성화(비활성→활성) 경로
이 모달에는 되돌리기 액션이 없다. 비활성 회원을 다시 활성화하려면 [수정] 모달의 상태 드롭다운(활성/비활성)을 써야 함.즉 비활성화 진입점은 2개(이 전용 버튼 + 수정 모달), 활성화 진입점은 수정 모달 1개뿐확정
설정[비활성화] 버튼 노출·권한 조건
버튼이 보이는 조건
행 회원이 활성 상태일 때만 [비활성화] 버튼 노출. 이미 비활성인 회원 행에는 버튼 자체가 안 보임 (모달도 활성 회원에만 등장)확정
권한 차이 (삭제와 비교)
[삭제]와 [프로필]은 관리자·페이허그 권한자에게만 노출.반면 [비활성화]는 권한 조건 없이 활성 회원 행이면 노출 → 하위 운영자도 비활성화는 가능확정
확인 문구에 회원명 삽입
제목 "회원 비활성화", 본문 "{회원명}을(를) 비활성화하시겠습니까?"로 대상 회원 이름이 그대로 들어감. 성공 토스트도 "{회원명}이(가) 비활성화되었습니다"확정
연결실행 시 처리 연결
전용 처리 경로
[비활성화] 확정 시 비활성화 전용 처리를 호출(회원 수정 저장과 다른 별도 경로).수정 모달에서 상태를 비활성으로 바꾸는 건 일반 수정 저장 경로를 탐 → 같은 결과(비활성)라도 내부 처리 창구가 둘로 나뉨확정
실패 시
처리 실패하면 오류 토스트만 뜨고 목록은 갱신 안 함. 성공하면 목록을 다시 불러와 상태 배지가 즉시 비활성으로 바뀜확정
서버측 차단 조건 여부
화면에는 비활성화를 막는 사전 조건이 없음. 진행 중 정산·미회수금이 있는 회원의 비활성화를 서버가 별도로 막는지·차단 시 어떤 메시지인지는 화면 코드로 확인 불가확인필요
