정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
"컨텍스트 관리" 카드를 펼친 상태의 목록 테이블. 스크린샷 워크스루엔 표 항목·버튼만 있으나, 실제로는 (1)"약관 종류 수"가 서버 집계가 아니라 화면에서 컨텍스트 코드로 실시간 매칭해 세는 값이고, (2)컨텍스트는 코드가 아니라 코드값을 연결키로 삼아 종류·버전과 묶이며, (3)추가/수정 모달에 코드 정규화·수정 불가·삭제 없음 같은 특수 제약이 걸려 있다. 최종 저장·중복검증은 서버 소관이라 확인 필요.
데이터데이터 출처와 '약관 종류 수' 집계
테이블에 뿌리는 3종 데이터
화면 진입 시 컨텍스트 목록·약관 종류 목록·약관 버전 목록을 한꺼번에(동시) 불러옴.컨텍스트 테이블 자체는 컨텍스트 목록만 쓰지만, '약관 종류 수' 칸 때문에 종류 목록도 필요확정
'약관 종류 수' 값의 정체
서버가 내려준 숫자가 아니라 화면에서 즉석 집계한 값.불러온 전체 종류 목록 중 '해당 컨텍스트 코드'와 같은 종류만 세어 표시종류를 추가/삭제하면 목록 새로고침 후 자동으로 숫자가 바뀜(실시간 반영)확정
카드 헤더의 (N개)
'컨텍스트 관리 (N개)'의 N은 불러온 컨텍스트 행 개수를 그대로 센 값확정
탭 재활성화 시 재조회
다른 탭 갔다가 이 어드민 탭으로 돌아오면 목록 3종을 다시 불러옴 — 여러 운영자가 동시에 만질 때 최신 상태 반영 목적확정
표시 안 되는 숨은 조건
목록 데이터에 '활성 여부' 값이 함께 오지만, 이 펼침 테이블은 활성/비활성 구분 없이 받은 행을 전부 표시 — 비활성 컨텍스트를 거르는 로직은 화면에 없음가설
연결컨텍스트를 묶는 연결키
연결 기준은 '코드'
컨텍스트–약관 종류–버전을 묶을 때 내부 일련번호가 아니라 컨텍스트 코드 문자열(예: signup, contract)로 매칭.그래서 코드가 사실상 컨텍스트의 고유 식별값 역할확정
행 [수정] 연결
각 행 [수정] → 컨텍스트 수정 모달(AD_TERMS_CTX_EDIT).수정 모달에서 코드 칸은 잠김(변경 불가), 이름·정렬 순서만 고칠 수 있음코드가 연결키라서 바꾸면 하위 종류/버전 매칭이 깨지기 때문으로 보임확정
삭제 버튼 없음
컨텍스트 행에는 삭제 기능이 아예 없음 — 수정만 가능(워크스루에도 명시). 잘못 만든 컨텍스트를 지우는 경로가 화면상 부재확정
종류가 0개인 컨텍스트
아래 '메인 목록'에서는 종류가 하나도 없는 컨텍스트는 화면에서 숨겨짐. 하지만 이 펼침 테이블에는 그대로 노출되어, '표엔 보이는데 본문 목록엔 안 보이는' 상태가 생길 수 있음확정
설정추가/수정 시 입력 규칙
코드 자동 소문자화
[+ 컨텍스트 추가] 모달에서 코드를 입력하면 자동으로 소문자로 변환됨(signup, contract 형태 강제). 대문자로 쳐도 소문자로 저장확정
필수 입력·순서 기본값
이름은 필수(빈칸이면 경고), 추가 시 코드도 필수.정렬 순서는 숫자만 입력 가능, 안 넣으면 0으로 저장확정
코드칩 색상 규칙
코드 종류별 색상 칩: signup=하늘색, contract=보라색, 그 외=회색.새 코드를 만들면 미리 지정된 두 색 외에는 전부 회색 처리(색은 코드값에 고정 매핑)확정
코드 중복·형식 검증
같은 코드 중복 입력이나 형식 위반을 화면에서는 막지 않음 — 저장 시 서버가 거르는지 여부는 화면 코드만으론 알 수 없음확인필요
