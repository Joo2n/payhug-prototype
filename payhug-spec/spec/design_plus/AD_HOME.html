6하단
3열 카드		 매출 유형 구성부제 "카드 vs 배달앱 매출 비율"카드 매출(남색) · 배달앱 매출(주황) 각 금액과 비율(%) 막대맨 아래 총 매출 합계수수료 산정 현황부제 "예상 vs 실제 수수료 확정 비율"실제 수수료 확정 N건(초록) · 예상 수수료 (매입대기) N건(황색) · 각 비율(%)아래 막대 + "총 N건 · 확정률 %"예상 = 아직 카드 매입 전이라 확정되지 않은 건 (매입 확정 시 실제로 이동)가맹점별 선정산 TOP 5부제 "선정산 지급액 기준 상위 가맹점"선정산 지급액 상위 5개 가맹점 · 순위 1~5순위 뱃지색 : 1위=초록 · 2위=회색 · 3위=주황 · 그 외 옅은 회색가맹점명 길면 …로 줄여서 표시데이터 없으면 "데이터 없음"
정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
관리자 대시보드는 로그인 직후 진입하는 읽기 전용 요약 화면이다. 화면 뒤에는 (1) 서로 다른 세 출처(가맹점 목록 조회·선정산 요약 조회·서버 점검 통신), (2) 화면단에서 직접 돌리는 파생 계산(차액 순액·확정률·매출비율·가맹점 TOP5 집계·차트 정렬), (3) 로그인 허용 유형 7종과 내부관리자/참여자 대시보드·메뉴 분기, (4) 인증 우회 진입과 150분 세션, (5) 대시보드 위에 상주하는 매출 재수집 진행 알림이 얽혀 있다. 표시되는 숫자 대부분은 서버가 계산해 내려주는 값을 그대로 노출하는 것이며, 최종 정산 산술·수수료율(C1)·예상 지급 차액 정의(C4)는 서버·정책 확인 필요다. '가맹점 수'가 상단 카드(등록 기준)와 선정산 헤더(선정산 참여 기준) 두 곳에서 서로 다른 기준으로 나오는 점, 화면이 쓰는 '환급·차감'이 정책 6대 개념과 매핑되는지 미확정인 점을 주의.
연결데이터 출처 — 카드마다 다른 곳에서 온다
상단 가맹점 수 카드
가맹점 목록 조회 응답의 총 건수를 그대로 표시불러오기 전에는 "-", 통신 오류 시 0으로 표시(조회는 됐으나 실패 응답이면 "-" 유지)아래 문구는 "등록된 활성 가맹점"이라 쓰지만, 실제로 활성 상태만 세는지(상태값 필터)는 화면코드에 없어 서버 확인 필요확정
선정산 현황(KPI·차트·하단 3열)
선정산 요약 조회 한 번의 응답으로 상단 6개 KPI·추이 차트·하단 3열이 전부 채워짐조회 범위는 오늘 기준 7일 전 ~ 어제(오늘 제외)응답이 기간 합계(요약)와 일자별 목록 두 덩어리로 나뉘어 옴이 화면이 '최근 7일'이라 부르는 구간이 오늘을 뺀 7일치라는 점 유의확정
선정산 헤더의 별도 가맹점 수·거래 건수
선정산 현황 제목 우측에 거래 건수와 가맹점 개수가 따로 표기됨이 가맹점 개수는 상단 카드(등록 가맹점)와 다른 기준(해당 7일간 선정산에 잡힌 가맹점)같은 '가맹점 수' 라벨이라도 두 값의 의미가 다름확정
시스템 상태 카드
정산(배치) 서버와 지능(분석) 서버 두 곳에 각각 점검 신호를 보내 응답 여부만 확인서로 다른 별개 서버각 5초 안에 응답 없으면 "응답 없음"이 점검은 내부관리자에게만 실행, 참여자에겐 아예 호출하지 않음확정
자동 다시 불러오기
화면(탭)이 활성일 때 진입 시 1회 조회, 수동 새로고침 버튼 없음다른 탭 갔다가 창 포커스가 돌아오면 가맹점 수·선정산 요약을 다시 조회단, 포커스 복귀 재조회에는 시스템 상태 점검은 포함되지 않음(진입 시에만 점검)확정
데이터 없음/로딩 상태
선정산 요약이 로딩 중이면 골격(스켈레톤) 표시요약이 비었거나 일자별 목록이 0건이면 "최근 7일간 선정산 데이터가 없습니다" 안내와 함께 "매출 데이터 수집 후 정산을 실행하면 통계가 표시됩니다" 문구 노출확정
계산화면에서 직접 돌리는 계산 — 서버가 안 주고 화면이 만든 값
가맹점별 선정산 TOP 5
서버가 순위를 주는 게 아니라 화면단에서 집계7일치 일자별 목록을 사업자번호로 묶어 가맹점별 매출(카드+배달)·선정산 지급액을 누적 합산선정산 지급액이 큰 순으로 정렬해 상위 5개만 노출, 막대 길이는 1위 대비 비율확정
차액 반영 순액
표시값 = 반영된 환급액 − 반영된 차감액(순액)대기 알림 띠의 금액도 대기 환급 − 대기 차감으로 같은 방식반영 순액은 양수면 강조색, 음수면 빨강, 0이면 회색단, 대기 금액 색은 0을 강조색(양수와 동일) 처리해 반영 카드와 기준이 다름확정
차액의 환급/차감 = 6대 개념 어디?
화면이 쓰는 '환급·차감'이 정책 6대 개념의 환급 / 과지급 회수와 같은 것인지 매핑 미확정임의로 동일시하지 말 것확인필요
수수료 확정률·예상비율
확정률 = 실제 확정 건수 ÷ (예상 + 실제 건수)예상비율 = 100 − 확정률두 건수가 0이면 0%로 표시화면 라벨상 예상 수수료는 "매입대기", 실제 수수료는 "확정"으로 예상값/확정값을 구분해 표기확정
매출 유형 비율
카드% = 카드매출 ÷ (카드+배달매출), 배달%도 동일총매출은 카드+배달 단순 합합이 0이면 각 0%확정
6개 KPI 구성
상단 KPI는 총 매출액·총 수수료·순 지급액·선정산 수수료·차액 반영·선정산 지급액 6개순 지급액 라벨 "매출 − 수수료", 선정산 수수료 라벨 "매입 + 시스템 + 이체", 선정산 지급액 라벨 "순지급액 − 수수료 + 차액"라벨은 산식 설명일 뿐, 실제 값은 서버 응답을 그대로 표시확정
차트·정렬
추이 차트는 일자별 오래된→최신 순으로 정렬해 그림(매출·수수료·선정산 지급액 3계열)확정
최종 정산 산술 자체
순지급액·선정산 지급액·수수료(매입/시스템/이체) 금액은 서버에서 계산돼 내려오는 값을 그대로 노출화면코드엔 이 금액을 만드는 산술이 없음수수료율(C1)·예상 지급 차액 정의(C4)는 여기서 확인 불가, 서버·정책 확인 필요확인필요
정책권한 분기 — 누가 로그인되고, 무엇이 갈리나
로그인 허용 유형
총 7종만 로그인 통과: 내부관리자 2종(관리자·페이허그)과 참여자 5종(파트너·영업조직·영업사원·제휴·투자자)그 외 유형은 인증이 성공해도 "접근 권한이 없는 계정입니다"로 차단(접속 토큰 저장 안 함)확정
관리자 vs 참여자 대시보드 차이
내부관리자: 가맹점 카드 "총 가맹점" + 시스템 상태 카드까지 2칸참여자: "소속 가맹점" 카드 한 칸만(시스템 상태 카드 숨김, 서버 점검도 실행 안 함)확정
좌측 메뉴도 권한별로 다름
내부관리자: 전체 메뉴(가맹점 관리·매출 조회·1:1 문의·정산 현황·정산 상품관리·정산 시뮬레이션·모 계좌 잔액 조회·회원 관리·약관 관리·스크래핑 장애 이력·활동 로그·AI 모니터링)참여자: 축소 메뉴(가맹점 관리·매출 조회·정산 현황·회원 관리)확정
라벨상 '활성 가맹점' 판정
상단 카드 문구는 활성이라 하지만 실제 집계 기준(상태값 필터)이 화면코드에 없음 — 서버 확인 필요확인필요
설정로그인·세션 설정
로그인 입력 항목
아이디 칸에 휴대전화번호 또는 사업자번호, 비밀번호 입력둘 다 채워야 버튼 활성, Enter로도 로그인서버에는 아이디(식별자)+비밀번호로 전송확정
세션 유지 시간
로그인 성공 시 접속 토큰을 150분 유효로 저장만료 후 재진입하면 로그인 화면에 "세션이 만료되어 다시 로그인해 주세요" 안내 표시확정
인증 우회 진입
인증 우회 설정이 켜진 환경에서는 로그인 없이 더미 관리자(테스트 관리자)로 자동 진입다른 화면의 관리자 게이팅을 통과시키려 더미 계정을 실제 저장운영 배포에는 해당 없음, 검토·캡처 편의용확정
재로그인 동선
로그인하면 원래 가려던 화면으로 되돌려 보냄(기본은 홈)로그인 페이지는 히스토리에서 빼서 뒤로가기로 다시 돌아오지 않음이미 로그인된 상태로 로그인 페이지에 오면 곧장 되돌려 보냄확정
데이터대시보드 위에 상주하는 매출 재수집(백필) 알림
전역 진행 알림
가맹점 매출 재수집이 돌고 있으면 대시보드 위에 진행 알림 띠가 상주"수집 중... 카드 N건, 배달앱 N건"처럼 실시간 건수 표시약 15초 간격으로 상태를 다시 확인하며, 여러 탭이 열려도 중복 알림을 막음확정
매출 소스 구성
수집 소스가 카드 + 배달앱 3종으로 구분됨: 배민·요기요·쿠팡이츠완료 문구에 소스별 건수·카드 오류·배달앱 스킵·실패 건수가 쪼개져 나옴확정
누락 구간 재수집 안내
일부 기간이 빠지면 완료 알림에 누락 구간(소스·기간)을 찍어주고 "해당 기간을 지정하여 재수집" 유도즉, 수집이 통째로 성공/실패가 아니라 구간·소스 단위로 부분 실패할 수 있음확정
이 알림 vs 화면 통계
이 알림은 대시보드 숫자를 갱신하지 않고 배경 수집 작업의 진행/결과만 알림(완료 후에도 KPI 자동 갱신 없음)데이터 없음 화면 문구("매출 데이터 수집 후 정산을 실행하면 통계가 표시됩니다")가 수집≠정산임을 뒷받침다만 수집→정산→KPI 반영의 실제 배치 순서·시점은 서버 확인 필요확정
