'카드 수수료 차액 정산 현황' 카드 안에서 [상세 통계 보기]를 누르면 인라인으로 펼쳐지는 3줄 통계(총 환급 / 총 추가 차감 / 순 차액) variant. 펼침은 순수 화면 토글이라 추가 조회가 없고, 3개 값은 base 카드가 처음 부를 때 이미 다 받아온다. 이 화면만의 특수점은 (1) 총 환급은 무조건 +초록·총 추가 차감은 무조건 -빨강으로 부호를 강제 표기하는 규칙, (2) 순 차액만 실제 부호를 따르는 점, (3) 차액 정의 자체가 수수료율 근거 미확정(C1)이라는 점이다.
설정펼침 토글 동작
펼침 방식
[상세 통계 보기] ↔ [간단히 보기] 토글같은 카드 안에서 3줄 통계 블록이 인라인으로 열리고 닫힘별도 페이지·모달 이동 없음, 화면 안 표시/숨김만 전환확정
추가 조회 여부
펼칠 때 서버를 다시 부르지 않음총 환급·총 추가 차감·순 차액 3개 값은 base 카드가 처음 열릴 때 요약 조회 1회로 이미 다 받아둔 값토글은 순수 화면 표시 전환이라 로딩·지연 없음확정
카드 자체 노출 조건
전체 누적 건수가 0이면 카드 통째로 안 보임차액 정산 이력이 하나도 없는 가맹점은 이 카드도, 상세 통계 펼침도 아예 존재하지 않음즉 펼침 variant는 '차액 이력이 1건 이상 있는 가맹점'에서만 나타남확정
계산상세 통계 3줄 표기 규칙
총 환급 표기
항상 '+' 초록색으로 강제 표기가맹점에게 돌려준(유리한) 차액의 합계값 앞에 무조건 + 를 붙이고 초록으로 렌더확정
총 추가 차감 표기
항상 '-' 빨강색으로 강제 표기가맹점에서 추가로 떼어간 차액의 합계값 앞에 무조건 - 를 붙이고 빨강으로 렌더확정
총 추가 차감 부호 중복 우려
서버가 추가 차감 합계를 어떤 부호로 주는지 확인 필요화면은 값 앞에 - 를 직접 붙임 → 서버가 절대값(양수)로 주면 정상, 이미 음수로 주면 '--' 중복 표기 위험서버 전용 값이라 실제 부호 규약 확인 필요확인필요
순 차액
= 전체 누적 정산 금액을 그대로 표시 (환급 − 추가차감의 순액)상세 통계 안에서 다시 계산하지 않고, 카드 상단 '전체 누적'과 같은 값을 재사용이 줄만 실제 부호를 따름: 양수면 +초록, 음수면 빨강, 0이면 부호 없이 '0원'확정
차액 계산 정의
차액 = 정산 적용 수수료 − 실제 확정 수수료승인 시 예상 수수료로 먼저 선정산 → 매입 확정 후 실제 수수료와의 차이를 다음 선정산에서 환급 또는 추가 차감적용 수수료율 근거는 미확정(C1). 최종 산술은 서버에서 계산확인필요
데이터데이터 출처
상세 통계 전용 값
총 환급·총 추가 차감은 차액 정산 현황 요약 데이터에만 있는 별도 항목base 카드의 대기/이번 달/전체 누적 3블록과 같은 한 번의 요약 조회로 함께 내려옴순 차액은 그 안의 '전체 누적 금액'을 재활용확정
건별 근거는 별도 화면
이 펼침에는 건별 명세가 없음어떤 주문·카드사에서 얼마의 차액이 났는지 건별 이력은 [차액 이력 보기](AD_MERCHANT_DT_ADJUST)에서 확인펼침은 합계 3줄 요약까지만 담당확정
