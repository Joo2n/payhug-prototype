약관 버전 수정 모달은 기존 버전의 값을 채워 여는 수정 전용 화면이다. 생성 모달과 달리 '약관 종류' 선택 영역이 아예 사라지고(종류 변경 불가), 버전 번호는 읽기전용으로 고정된다. 실제로 고칠 수 있는 값은 제목·시행일·본문 3개뿐이다. 핵심 미확정: 이 화면은 게시(노출) 중이거나 시행일이 이미 지난 버전에 대해서도 아무 경고·차단 없이 그대로 열리고 저장된다 — 게시·시행 중 버전 사후수정 허용 여부가 정책으로 확정돼야 한다.
설정수정 모달에서만의 입력 규칙
생성 모달과의 결정적 차이
'약관 종류' 선택 영역이 통째로 사라진다생성 시엔 종류 드롭다운(또는 고정표시)이 뜨지만, 수정 모달에는 아예 렌더링되지 않음즉 이미 만든 버전의 소속 약관 종류는 수정으로 절대 바꿀 수 없다확정
버전 번호
읽기전용(회색 고정) — 기존 값 그대로 표시, 손댈 수 없음수정 저장 시 서버로 기존 버전값을 다시 실어 보내지만 화면상 변경 불가개정(버전 올리기)은 '개정' 버튼의 새 버전 생성으로만, 수정으로는 안 됨확정
실제 수정 가능 항목
제목 · 시행일 · 본문 3개뿐 (모두 필수)하나라도 비면 '필수 항목을 입력해주세요' 안내 후 저장 차단확정
종료일(시행 종료) 입력란
화면에는 종료일 입력 필드가 없다다만 저장 통신 규격상 종료일 항목은 열려 있어, 화면 개편 시 노출 가능현재는 종료일을 이 모달에서 지정/해제할 방법이 없음확정
정책게시·시행 중 버전 수정 (핵심 미확정)
게시 중 버전도 수정 허용됨
게시(가맹점 노출) 상태와 무관하게 수정 버튼이 항상 노출되고, 모달도 제약 없이 열린다게시 여부에 따른 경고 문구·확인 절차·필드 잠금이 전혀 없음삭제만 '미게시일 때'로 제한될 뿐, 수정은 게시본에도 열림확정
시행일 지난 버전 수정
시행일이 오늘보다 과거인 버전도 그대로 수정·저장 가능이미 효력 발생/동의를 받은 문안을 사후에 바꾸는 상황을 막는 장치 없음확정
정책 확정 필요
게시·시행 중 버전의 본문 사후수정을 허용할지 결정 필요원칙적으로 효력 발생본은 수정 금지 + 신규 개정으로 유도가 안전오탈자 등 경미 수정만 예외 허용할지, 수정 시 재동의 트리거가 필요한지 함께 정의확인필요
동의 이력과의 관계
삭제 안내에는 '동의 이력 있으면 삭제 거부' 문구가 있으나, 수정에는 동의 이력 관련 경고가 없다동의를 받은 버전의 본문 변경이 기존 동의의 법적 유효성에 미치는 영향 검토 필요확인필요
연결저장 처리와 진입 경로
저장 통신
수정 저장은 해당 버전 1건을 지정해 갱신하는 별도 처리로 나감(생성과 다른 경로)제목·본문·버전·시행일을 실어 보냄성공 시 '수정되었습니다' 안내 후 목록 재조회확정
미리보기에서 바로 진입
미리보기 모달 하단 '수정하기' 버튼 → 미리보기 닫고 곧바로 이 수정 모달을 연다목록의 '수정' 버튼과 동일한 진입점확정
게시 상태 전환은 별도
게시 on/off는 이 수정 모달이 아니라 목록의 게시 토글에서만 처리수정 저장이 게시 상태를 바꾸지 않음(기존 게시/미게시 유지)확정
