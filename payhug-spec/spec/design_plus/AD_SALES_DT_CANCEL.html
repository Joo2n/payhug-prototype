정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
거래상태 토글을 '취소'로 놓으면 서버에 취소필터(CANCELLED)로 재조회하는 변형 화면. 취소 판정은 '카드 승인취소' 또는 '배달앱 매입취소' 두 경우로만 성립하며(백엔드 표준과 동일), 취소 건은 순지급액을 금액이 아닌 회색 '-'로 표기해 정산 대상에서 배제됨을 시각적으로 드러낸다. 표·요약 구조 자체는 베이스 화면(AD_SALES_DT)과 동일하고, 취소에 특수한 것은 조회 파라미터·취소 판정 기준·순지급액 마스킹·엑셀 출력 처리 4가지다.
연결취소 필터 조회 방식
필터 선택지
거래상태 토글은 전체 / 정상 / 취소 3택.이 화면은 '취소' 선택 상태의 변형이다.확정
동작 방식
'취소' 클릭 시 화면에서 걸러내는 게 아니라 서버에 취소조건으로 재조회한다.조회 파라미터의 거래상태 값을 '취소'(CANCELLED)로 실어 매출원장 조회를 다시 호출즉 표에 나오는 건 서버가 취소로 판정해 돌려준 건들이다확정
요약·표 구조
표 컬럼과 상단 요약 구성은 베이스 화면과 완전히 동일.취소 조건에 맞는 건만 채워질 뿐 별도 취소 전용 컬럼/요약은 없다.확정
초기화 시 거동
필터 초기화를 누르면 거래상태가 '전체'로 되돌아간다(취소 유지 안 됨). 기간도 이번 달 1일~오늘로 리셋.확정
정책취소 판정 기준 (이 화면의 핵심)
취소 = 두 경우뿐
한 건이 '취소'로 잡히는 조건은 딱 둘.카드: 승인취소배달앱: 매입취소두 상태 중 하나면 취소 건으로 본다(코드 판정과 화면 상단 안내가 일치).확정
화면상 라벨 표기
거래상태 배지는 '승인취소'와 '매입취소' 모두 빨간 '취소'로 통일해 보여준다.다만 매입상태 컬럼에서는 '승인취소'를 그대로 '승인취소'로 노출 — 거래상태(취소)와 구분해 운영자가 취소 원인을 알게 한다.확정
'취소'와 '취소 환수'는 다름
여기서 말하는 취소는 거래 자체의 취소 상태다.차액정산 유형에 있는 '취소 환수'(취소로 인한 사후 회수 항목)와는 별개 개념 — 혼동 금지.확정
계산취소 건 금액 처리
순지급액 마스킹
취소 건은 순지급액 칸에 금액 대신 회색 '-'를 찍는다.취소는 지급 대상이 아님을 한눈에 드러내는 의도참고로 '현장수령(오프라인)' 건은 '-'가 아니라 '현장수령'으로 따로 표기(취소와 구분됨)확정
엑셀 다운로드도 동일
엑셀 출력 시에도 취소 건의 순지급액 열은 숫자가 아니라 '-'로 기록된다. 화면과 파일이 같은 규칙.확정
취소 건의 정산 반영
취소로 인한 실제 금액 되돌림(과지급 회수·환급·환수 등)이 이 화면에서 계산되진 않는다.화면은 취소 '상태 표시'와 순지급액 배제까지만 담당취소에 따른 최종 정산 조정 산술은 서버(정산 로직) 소관확인필요
