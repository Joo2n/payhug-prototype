차액 정산 탭에서 매출 유형 '카드'를 선택했을 때만 하위 카드사 칩(2뎁스)이 노출되는 상태. 카드사·매출 유형 선택은 클라이언트가 걸러내는 것이 아니라 서버 재집계 파라미터로 넘어가며, 그래서 상단 KPI 카드와 일별 추이 차트까지 선택한 카드사 기준으로 다시 그려진다. 이 화면만의 특수 규칙은 (1) 카드사 칩 노출/숨김 조건, (2) 선택값을 서버 파라미터로 바꾸는 변환 규칙, (3) 카드사 옵션 목록의 출처와 유지 방식, (4) 매출 유형별 원장 연결 여부 안내 문구다.
설정카드사 칩이 뜨는 조건과 사라질 때 동작
칩 노출 3중 조건
카드사 2뎁스 칩은 세 가지가 동시에 참일 때만 뜬다.차액 정산 탭에 있고매출 유형에서 '카드'가 선택돼 있고서버가 내려준 카드사 옵션이 1개 이상 존재확정
카드 해제 시 자동 초기화
매출 유형에서 '카드'를 빼면, 그 아래에서 고르고 있던 카드사 선택이 자동으로 '전체'로 되돌아간다.이유: 숨겨진 채로 특정 카드사 조건이 남아 빈 결과가 나오는 것을 막기 위함확정
기본 선택값
카드사 칩의 최초 상태는 '전체'. 매출 유형도 최초 '전체'.조회 조건 초기화를 누르면 둘 다 다시 '전체'로 리셋확정
복수 선택 규칙
카드사 칩은 여러 개 동시 선택 가능.'전체'를 누르면 개별 선택이 모두 풀림개별 카드사를 처음 누르면 '전체'가 풀리고 그 카드사만 선택마지막 하나까지 해제하면 자동으로 '전체'로 복귀확정
연결선택값 → 서버 재집계 (클라이언트 필터 아님)
선택 즉시 서버 재조회
카드사나 매출 유형 칩을 바꾸면 조회 버튼을 누르지 않아도 곧바로 서버를 다시 부른다.첫 진입 시 1회는 이 자동 재조회를 건너뜀(중복 호출 방지)확정
KPI·차트까지 필터 반영
카드사 필터는 서버가 집계 단계에서 적용한다. 그래서 상단 KPI 카드 4개(전체 차액·유형별 금액)와 일별 추이 차트도 선택한 카드사 기준으로 다시 계산돼 내려온다. 화면에서 표만 걸러내는 방식이 아니다.확정
카드사 값 전송 조건
카드사 조건은 '카드'가 선택돼 있고 + 카드사가 '전체'가 아닐 때만 서버로 넘어간다.카드 미선택이거나 카드사 '전체'면 카드사 조건은 빈 값(=제한 없음)으로 전송확정
'전체' = 조건 없음
매출 유형/카드사 모두 '전체'는 서버에 빈 값으로 전송돼 '조건 없음(전 범위)'을 의미한다. 특정 값만 선택했을 때 그 목록이 서버로 전달됨.확정
에이전시·가맹점명은 여기서 안 걸림
같은 화면의 에이전시·가맹점명 검색은 서버가 아니라 화면에서 걸러낸다. 카드사/매출 유형(서버 집계)과 성격이 다르므로, 에이전시·가맹점명은 KPI 숫자를 바꾸지 않고 표 행만 줄인다.확정
데이터카드사 옵션 목록의 출처와 유지
옵션 목록 출처
칩에 뜨는 카드사 항목들은 화면이 만든 고정 목록이 아니라, 서버가 차액 정산 대시보드 응답에 함께 실어 내려주는 '조회 가능한 카드사' 목록이다.즉 해당 기간에 실제 차액 정산 건이 있는 카드사만 칩으로 노출확정
필터 적용 후에도 옵션 유지
특정 카드사를 골라 재집계돼도 칩 목록 자체는 줄지 않고 그대로 유지된다.서버가 '필터 적용 전 전체 기준' 목록을 내려주기 때문(선택을 바꿔가며 비교 가능)가설
매출 유형 고정 목록
매출 유형 상위 칩은 고정: 전체 / 카드 / 배달의민족 / 요기요 / 쿠팡이츠. 이 중 '카드'에만 하위 카드사 뎁스가 붙는다(배달 3사는 하위 뎁스 없음).확정
정책매출 유형 선택 시 원장 연결 안내
특정 유형 선택 = 원장 연결 건만
매출 유형 라벨 옆 물음표 안내: 카드·배달의민족·요기요·쿠팡이츠 등 특정 유형을 고르면 '원장과 연결된 건'만 표시된다.원장 미연결 건(예: 예상매출 대사)은 이 필터에서 빠짐확정
예상매출 대사는 '전체'에서만
원장에 아직 붙지 않은 예상매출 대사 성격의 건은 매출 유형 '전체'에서만 확인 가능하다는 점을 안내 문구로 명시. 카드사까지 좁히면 해당 건은 집계에서 제외될 수 있음.확정
'없음' 표시 분기
재집계 결과 건수가 0이면 표 대신 '해당 기간에 차액 정산 내역이 없습니다' 안내가 뜬다.카드사를 너무 좁게 걸어 결과가 빈 경우도 이 화면으로 떨어짐확정
서버 최종 집계식
카드사별 차액 금액·건수·대기 건수의 최종 산출은 서버 집계 결과를 그대로 표시. 화면은 부호 표기(환급 +, 차감/환수 −)만 담당.실제 계산 로직·수수료율 기준은 서버 전용이라 화면 코드로 확인 불가확인필요
