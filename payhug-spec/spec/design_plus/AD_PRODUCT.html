정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
정산 상품(정산 정책)을 만들고 관리하는 어드민 화면이다. 상품 1개 = "누가 참여하고(투자자·페이허그·파트너/영업), 각자 어떤 수수료를 몇 %(또는 몇 원) 떼가고, 그 수수료를 누가 내고 누가 받으며, 부가세는 별도인지 포함인지"를 한 묶음으로 정의한 규칙집이다. 이 상품을 가맹점에 배정하면 그 규칙대로 정산 수수료·배분·지급액이 계산되므로, 이 화면의 값은 이후 모든 정산 계산의 뿌리가 된다. 단 이 화면은 규칙을 저장할 뿐, 실제 금액 계산·배분·지급은 다른(정산 계산) 단계에서 이 값을 입력으로 받아 수행한다.
설정상품 유형과 참여자 구성
상품 유형 2종
상품은 일반 또는 다우 둘 중 하나로 만든다.일반: 파트너 채널용. 참여자가 투자자·페이허그·상위파트너·하위파트너·영업조직 5역할다우: 영업 채널용. 참여자가 투자자·페이허그·상위영업·하위영업 4역할, 파트너 개념이 없음투자자와 페이허그 2역할은 두 유형 공통이다.확정
유형은 생성할 때만 선택, 수정 불가
일반/다우는 상품 생성 시점에만 고를 수 있다. 이미 만든 상품을 수정할 때는 유형 칸이 '(변경 불가)'로 잠긴다.유형이 바뀌면 참여자 구성과 요율 표 자체가 통째로 달라지기 때문이다. 유형을 바꾸려면 새 상품을 만들어야 한다.확정
참여자는 후보 목록에서 지정
각 역할 칸은 '미지정'이 기본이고, 드롭다운에서 등록된 대상을 골라 채운다. 비워둔 채로 저장할 수 있어 모든 역할을 반드시 채울 필요는 없다(상품명만 필수).일반의 상위파트너/하위파트너는 같은 파트너 후보 목록을 공유한다.다우의 상위영업/하위영업 후보에는 영업 대상과 제휴사가 함께 나온다.확정
참여자마다 법인/개인·사업자 꼬리표
고른 참여자 옆에 '법인 또는 개인', 그리고 사업자면 '사업자' 태그가 붙는다. 다만 이 화면에서는 표시만 한다. 이 성격이 실제 세금계산서/면세계산서 발행이나 부가세 처리로 어떻게 이어지는지는 이 화면이 아니라 정산 계산·계산서 발행 단계에서 결정된다.확정
계산요율 3종과 값의 단위·저장 방식
수수료는 3종류로 나뉨
요율 표는 채권매입 수수료·시스템 이용료·이체 수수료 세 종류로 구성된다. 이 3종이 곧 선정산 수수료의 뼈대이고, 가맹점 지급액은 매출에서 이 수수료들을 뗀 뒤 각 참여자에게 배분되는 구조다. 실제 뗀 금액·배분 계산은 이 화면 밖(정산 계산 단계)에서 이 값을 입력으로 받아 이뤄진다.확정
%와 원, 단위가 다름
채권매입과 시스템이용료는 %로 입력(예: 1% → '1'), 이체 수수료만 원(₩) 정액으로 입력한다. 화면에도 '이체수수료는 원 단위, 나머지는 % 단위' 안내가 붙어 있다.%는 소수 둘째 자리 단위, 원은 1원 단위로 입력받으며 음수는 넣을 수 없다.확정
빈칸은 0으로 저장됨 (주의)
요율 칸을 비워두고 저장하면 그 수수료는 0%(또는 0원)로 저장된다. '설정 안 함'과 '실제 0'이 구분되지 않는다. 특정 참여자 수수료를 진짜 0으로 둘 의도가 아니라면 빈칸으로 남기지 않도록 주의해야 한다.확정
소수 셋째 자리는 반올림되어 사라짐
입력한 %는 내부적으로 정수 단위로 반올림되어 저장된다. 그래서 예컨대 0.604%를 입력해도 0.60%로 저장되어 소수 셋째 자리가 잘린다. 수수료율 후보로 거론되는 0.604% 같은 값을 이 화면으로는 정밀하게 입력할 수 없다는 뜻 — 확정 수수료율 미확정 쟁점(레지스터 C1)과 함께 반드시 확인 필요.확인필요
유형에 따라 요율 행이 자동 생성
유형을 고르면 요율 표의 행이 미리 깔린다.일반: 채권매입 5행(투자자·페이허그·상위파트너·하위파트너·영업조직) + 시스템이용료 3행(페이허그·상위·하위) + 이체수수료 1행(페이허그) = 9행다우: 채권매입 4행(투자자·페이허그·상위영업·하위영업) + 이체수수료 1행(페이허그) = 5행. 다우에는 시스템이용료 행 자체가 없다.이체수수료 행은 두 유형 모두 페이허그 1행뿐이며, 상위·하위가 이체료를 받는지는 아래 '수취 옵션'으로 따로 정한다.확정
참여자 미지정과 요율 행 연동은 두 역할만
투자자를 미지정하면 투자자 채권매입 행이, 영업조직을 미지정하면 영업조직 채권매입 행이 표에서 숨겨지고 저장에서도 빠진다. 단 이 연동은 투자자·영업조직 두 역할에만 걸려 있다. 상위·하위파트너(또는 영업)는 참여자를 비워둬도 해당 요율 행이 표에 그대로 남아 입력·저장되므로, 참여자 없이 파트너 수수료만 저장되는 상태가 생길 수 있다 — 의도된 동작인지 확인 필요.확인필요
목록에서 요율 미리보기
상품 목록의 각 상품을 펼치면 채권매입/시스템이용료/이체수수료 3그룹으로 묶여 각 역할의 값이 표시된다(채권매입은 값 큰 순 정렬). 이 미리보기 표시 자체는 확정 동작이나, 실제 배분·최종 지급액 산술은 이 화면이 아니라 정산 계산 단계에서 이 값들을 입력값으로 돌린다(그 계산부는 이 화면에서 확인 불가).가설
정책수수료 납부 옵션 (누가 부담하나)
기본은 가맹점 부담
납부 옵션을 모두 끄면 가맹점이 그 수수료를 부담한다(화면에도 빨간 글씨로 명시). 특정 파트너/영업을 켜면 그쪽이 대신 낸다는 뜻이다.확정
납부자는 한 명만 (상호배타)
시스템이용료 납부, 이체료 납부는 각각 상위/하위 중 한쪽만 지정된다. 상위를 켜면 하위가 자동으로 꺼진다(같은 '납부자' 자리를 두고 다투는 구조). 즉 한 수수료의 대납자는 최대 1명. 단 이체료 납부자와 시스템료 납부자는 서로 별개라 각각 다른 사람이 될 수 있다.확정
유형별 납부 토글이 다름
일반: 상위/하위 파트너의 '이체료 납부', 상위/하위 파트너의 '시스템료 납부' 4종다우: 상위/하위 영업의 '이체료 납부' 2종(시스템료 납부 없음 — 다우엔 시스템이용료 자체가 없어서). 이체료 납부 자체는 두 유형 공통으로 존재한다.확정
정책수수료 수취 옵션 (누가 받나)
기본은 페이허그만 수취
수취 옵션을 모두 끄면 페이허그만 그 수수료를 가져간다(화면 명시). 특정 파트너/영업을 켜면 그쪽도 자기 몫을 받는다.확정
수취는 여러 명 동시 가능 (독립 스위치)
납부와 달리 수취 스위치는 서로 독립이라 상위·하위를 동시에 켤 수 있다. 즉 한 수수료를 여러 참여자가 나눠 받는 설정이 가능하다.일반: 상/하위 파트너 이체료 수취, 상/하위 파트너 시스템료 수취 4종다우: 상/하위 영업 이체료 수취 2종확정
수정 시 저장값 없으면 켜진 채로 뜸 (주의)
기존 상품을 수정할 때, 저장된 수취 설정이 비어 있으면 대부분의 수취 토글이 기본 켜짐 상태로 표시된다(단 '하위영업 이체료 수취'만 기본 꺼짐). 반대로 납부 옵션은 비어 있으면 '가맹점 부담'으로 뜬다 — 즉 빈 값의 기본 처리가 수취/납부에서 서로 다르다. 화면에 보이는 값이 원래 저장값인지 편집 기본값인지 혼동 소지 — 표기 정책 확인 필요.확인필요
정책부가세(VAT) 별도/포함 처리
요율 행마다 별도/포함 선택
각 요율 행에 VAT 별도 / 포함을 고르는 칸이 있고 기본값은 '별도'다. 이 화면은 별도/포함 값을 저장할 뿐이고, '별도면 부가세가 얹히고 포함이면 안에 들어있다'는 실제 계산·계산서 반영은 정산 계산 단계에서 이 값을 사용해 처리한다.확정
페이허그 대상 행은 VAT 선택 없음
수취 대상이 페이허그인 요율 행은 VAT 칸이 '—'로 비활성 처리된다. 즉 페이허그 몫에는 별도/포함 개념을 적용하지 않는다.확정
정책비활성화·삭제·수정 규칙
비활성화 = 이력 유지, 신규 배정만 차단
비활성화하면 이미 이 상품이 배정된 가맹점 이력은 그대로 유지되고, 앞으로 신규 배정만 막힌다(확인창에도 명시). 운영 중 상품을 조용히 물릴 때 쓰는 방식이다.확정
비활성 상품이 목록에서 구분되는지 불명확
상품 목록은 활성/비활성 상품을 함께 불러오며, 비활성 상품임을 나타내는 별도 상태 표시가 목록에 보이지 않는다. 비활성화한 상품이 활성 상품과 똑같이 나열돼 운영자가 상태를 한눈에 구분하기 어려울 수 있다 — 목록 표시 정책 확인 필요.확인필요
삭제 = 되돌릴 수 없음, 배정 있으면 불가
완전 삭제는 되돌릴 수 없다. 게다가 이 상품에 배정된 가맹점이 하나라도 있으면 삭제가 거부된다(확인창에 명시). 실질적으로 아무도 안 쓰는 상품만 삭제 가능.확정
생성/수정 두 경로가 같은 폼을 씀
'+ 상품 생성'과 각 행의 '수정'은 같은 입력창을 연다. 차이는 유형 잠금(수정 시 변경 불가)과 저장 버튼 문구뿐. 상품명은 두 경우 모두 필수이며, 비어 있으면 저장 전에 막힌다(상품명 외 값은 별도 검증 없이 그대로 저장 시도).확정
데이터데이터 출처와 연결
참여자 후보는 유형별로 불러옴
상품 생성/수정 창을 열 때 투자자·페이허그·파트너·영업·영업조직·제휴사 후보 목록을 각각 불러와 드롭다운에 채운다. 여기 없는 대상은 먼저 다른 화면에서 등록돼 있어야 고를 수 있다.확정
목록은 화면 진입·복귀 때 자동 갱신
이 화면 탭으로 들어오거나 다른 창 갔다 돌아올 때마다 상품 목록을 다시 불러온다. '새로고침' 버튼으로도 즉시 갱신 가능.확정
이 화면은 예상/확정/실제 같은 시각·상태 값이 없음
이 화면은 순수하게 정산 규칙(상품)만 정의하므로, 스크래핑 시각·지급 시각·기준일 같은 시점 개념이나 예상값/확정값/실제 지급값 구분이 등장하지 않는다. 그 구분은 이 규칙을 입력으로 쓰는 정산 계산·지급 단계에서 발생한다.확정
'매출 회수/과지급 회수'와 무관
이 화면은 규칙만 정의한다. 어드민의 '매출 회수'(락계좌→모계좌 스윕)나 정책상 '회수'(과지급 되돌림), 그리고 미지급금·바로이체·환급 같은 정산 실행 개념과는 별개다. 이 상품 값은 그 계산들의 입력 조건일 뿐 실행 주체가 아니다.확정
배정·적용 시점은 이 화면 밖
만든 상품이 어느 가맹점에 언제부터 적용되는지(배정·유효 시작일)는 이 화면이 아니라 별도의 배정 화면에서 다뤄진다. 여기서는 상품 자체만 만든다.가설
