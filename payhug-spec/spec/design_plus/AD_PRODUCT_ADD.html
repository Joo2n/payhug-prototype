정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
정산 상품 생성 모달의 '일반(GENERAL)' 빈 폼 상태 심화. 유형을 일반으로 두면 참여자·요율·수수료 옵션 구성이 다우와 다르게 세팅되며, 화면에 보이는 라벨 뒤에는 (1) 유형별 기본 요율 9행 자동 세팅, (2) 요율 입력값의 저장단위 변환, (3) 수수료 '납부자'·'수취' 옵션의 기본값·상호배타 규칙, (4) 참여자 드롭다운의 서버 조회가 숨어 있다. 스크린샷만으로는 안 보이는 조건 분기·기본값·계산 규칙에 집중.
설정유형=일반 선택 시 폼 구성 분기
유형 토글의 성격
생성 화면에서만 일반/다우 전환 가능.수정 화면에서는 유형이 고정 표시되고 '(변경 불가)'.즉 상품의 유형은 생성 시점에만 정해지고 이후 못 바꿈확정
일반 선택 시 참여자 항목
투자자·페이허그 공통 + 상위파트너·하위파트너·영업조직 노출.다우로 바꾸면 대신 상위영업·하위영업만 노출되고 위 3개는 사라짐확정
일반 기본 요율 9행
빈 폼이지만 요율표에 행이 미리 깔림:채권매입 5행(투자자/페이허그/상위파트너/하위파트너/영업조직)시스템이용료 3행(페이허그/상위파트너/하위파트너)이체수수료 1행(페이허그)값은 전부 빈칸, VAT 기본 '별도'확정
투자자·영업조직 요율행 조건부 숨김
참여자에서 투자자를 안 고르면 채권매입-투자자 행이, 영업조직을 안 고르면 채권매입-영업조직 행이 요율표에서 사라짐.저장 시에도 숨겨진 행은 서버로 안 보냄(제외)확정
계산요율 입력·저장 규칙
입력 단위
이체수수료 행만 원 단위(정수, 증감 1), 나머지(채권매입·시스템이용료)는 % 단위(소수 둘째자리, 증감 0.01).안내문 '1% → 1 입력'확정
저장 시 내부 변환
화면 %값은 저장할 때 ×100 하여 미세단위(bps)로 변환(예: 1% → 100). 이체수수료는 입력 원값을 그대로 반올림해 저장.빈칸/숫자아님은 0으로 저장확정
실제 정산에 적용되는 확정 요율
이 화면은 요율을 '입력·등록'만 한다. 실제 정산에 곱해지는 확정 수수료율 자체는 서버 산정이라 여기서 검증 불가 — C1(1%/0.604%/… 병존) 미해결.확인필요
VAT 별도/포함 선택
각 요율행마다 VAT 별도/포함 선택 가능하나 페이허그 행은 VAT 선택칸이 '—'로 비활성(선택 불가).왜 페이허그만 제외인지 정책 근거 확인 필요확인필요
정책수수료 납부·수취 옵션 규칙(일반)
납부 옵션 기본값
하위/상위파트너의 이체료·시스템료 납부 토글 4개 모두 기본 OFF.경고문: '모두 OFF일 경우 가맹점이 납부'확정
납부자는 한 명만
이체료 납부는 상위/하위 중 하나만 켜지는 구조(같은 항목에서 다른 쪽을 켜면 앞선 선택이 덮어써짐). 시스템료도 동일.즉 이체료 납부자·시스템료 납부자 각각 '없음(가맹점)/상위/하위' 셋 중 하나가설
수취 옵션 기본값(신규)
하위/상위파트너 이체료·시스템료 수취 토글 4개 모두 기본 OFF.경고문: '모두 OFF일 경우 페이허그만 수취'참고: 수정 화면에서 값이 없을 땐 오히려 ON으로 채워지는 곳이 있어 신규/수정 기본값이 어긋남(확인필요)확정
저장 페이로드 분기
일반이면 상위/하위파트너·영업조직 id와 파트너 수취 4토글, 시스템료 납부자를 보냄. 이체료 납부자는 유형 무관 항상 전송.다우 전용(영업 id·영업 수취 토글)은 일반에선 미전송확정
연결참여자 드롭다운 데이터 출처
참여자 후보 조회
모달 열 때 투자자·페이허그·파트너·영업·영업조직·제휴사 유형별 사용자 목록을 서버에서 각각 조회해 드롭다운 채움.일반의 상위·하위파트너는 같은 '파트너' 목록을 공유확정
후보에 붙는 꼬리표
각 후보는 이름 뒤 법인/개인, 사업자 여부 태그로 표시.정산·계산서 발행 시 과세 구분에 쓰이는 값으로 보임(확인필요)가설
필수값·저장 경로
생성 시 상품명만 필수(빈값이면 '상품명을 입력해주세요'). 나머지 참여자·요율은 미지정 허용.저장하면 상품 신규 등록 처리 후 목록 갱신확정
