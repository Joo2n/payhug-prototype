1:1 문의 목록의 '답변완료' 필터 상태. 목록 로직 자체는 전체 화면과 동일하나, 답변완료 상태에서만 드러나는 특수점은 3가지다. (1) 답변완료는 서버가 답변 등록 시 자동으로 부여하는 것으로 보이며(확인필요), 상단 드롭다운으로 관리자가 수동 재지정도 가능. (2) 답변완료 건이라도 가맹점이 다시 답을 달면 목록에 NEW 배지가 그대로 붙는다(재문의 신호). (3) 답변완료 상태에서도 답변 입력창은 계속 열려 있어 추가 답변이 가능하고, 오직 '종료' 상태만 입력이 잠긴다. 상단 상태별 건수는 현재 필터로 걸러진 목록에서만 집계돼, 답변완료 필터를 켜면 다른 상태 탭 숫자가 0으로 보이는 왜곡이 있다.
정책답변완료 상태의 의미와 전환
답변완료 부여 시점
관리자가 답변을 전송하면 해당 문의가 답변완료로 넘어가는 것으로 보인다.화면 코드는 답변 전송 후 상태를 직접 바꾸지 않고 상세를 다시 불러오기만 함 → 상태 전환은 서버가 처리확인필요
관리자 수동 재지정
상세 패널 상단 드롭다운으로 대기·처리중·답변완료·종료를 언제든 수동 변경 가능.답변완료로 자동 넘어간 건도 관리자가 처리중/종료 등으로 되돌릴 수 있음확정
답변완료 → 종료 구분
답변완료는 '답을 달아둔' 상태일 뿐 종료가 아니다.종료는 별도 상태로, 종료가 되어야만 대화가 잠김(아래 참조)확정
상태값 라벨·색
답변완료 배지는 초록색으로 표기(다른 상태와 색 구분).대기=주황, 처리중=파랑, 종료=회색확정
데이터답변완료 목록에서의 표시 특수성
답변완료인데 뜨는 NEW 배지
답변완료 건이라도 마지막 발신자가 가맹점이면 제목 옆에 빨간 NEW가 붙는다.즉 '관리자가 답했는데 가맹점이 또 되물은' 재문의 신호종료 상태에서는 NEW가 절대 안 붙음확정
상태별 건수 집계 방식
상단 탭의 건수는 현재 화면에 불러온 목록만 세어 표시.답변완료 필터를 켜면 서버가 답변완료만 내려주므로, 대기·처리중·종료 탭 숫자가 모두 0으로 보이는 왜곡 발생확정
카테고리·검색은 그대로
카테고리(일반/결제/정산/기술/계정) 토글, 제목·가맹점명·작성자 검색은 답변완료 상태에서도 동일하게 병행 적용.카테고리는 서버 필터, 검색어는 화면 안 필터확정
최근 활동 시각
목록 우측 시각은 마지막 메시지 시각 기준 상대표기('n시간 전').마지막 메시지 시각이 없으면 최초 접수 시각으로 대체확정
연결답변완료 상태에서의 조작 동작
추가 답변 가능 여부
답변완료 상태에서도 답변 입력창이 계속 열려 있어 추가 답변 전송 가능.입력이 잠기는 건 오직 '종료' 상태뿐 → 이때만 '종료된 문의입니다' 안내로 대체확정
답변 전송 후 흐름
답변 전송 시 로그인한 관리자 계정을 함께 실어 등록 → 상세 대화 새로고침 → 목록 새로고침 순으로 갱신.관리자 로그인 정보가 없으면 전송 자체가 중단됨확정
가맹점 상세로 이동
패널 상단 가맹점명 클릭 시 가맹점 상세 화면을 새 탭으로 연다(탭 모드일 때).확정
