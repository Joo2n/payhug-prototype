회원 완전 삭제 확인 모달은 공용 확인 다이얼로그(위험/빨강 스타일)를 그대로 재사용하며, 화면 자체에는 별도 안전장치(이름 재입력 등)가 없다. 특수 포인트는 세 가지다. (1) [삭제] 버튼과 이 모달은 관리자·페이허그 등급에만 노출된다(비활성화는 모든 운영자). (2) "정산 상품 배정 시 삭제 불가"는 화면이 검사하지 않고 서버가 막으며, 화면은 실패 메시지를 그대로 토스트로 흘려보낼 뿐이다(서버 강제 여부·조건 확인필요). (3) 삭제는 되돌릴 수 없는 완전 삭제(서버 삭제 호출)로, 로그인만 막는 비활성화와 다른 별개 동작이다.
정책삭제 확인 모달 동작
모달 정체
공용 확인 다이얼로그를 그대로 재사용삭제 전용 화면이 아니라 제목·본문·버튼만 바꿔 띄우는 공통 모달위험(danger) 스타일 = 빨강 아이콘 + 빨강 [삭제] 버튼확정
본문 문구
제목 "회원 삭제"본문 "{회원명}"을(를) 완전히 삭제하시겠습니까?보조1 "이 작업은 되돌릴 수 없습니다."보조2 "정산 상품에 배정된 경우 삭제할 수 없습니다."세 줄 모두 고정 안내문이며 회원별로 달라지지 않음확정
안전장치 없음
이름 재입력·체크박스 같은 추가 확인 없음[취소] / [삭제] 두 버튼뿐[삭제]를 누르면 모달이 즉시 닫히고 삭제 요청이 뒤에서 진행 → 성공·실패 결과는 모달이 사라진 뒤 토스트로만 표시확정
성공 처리

정책삭제 차단 규칙 (정산 상품 배정)
차단 주체
"정산 상품 배정 시 삭제 불가"는 화면이 검사하지 않는다화면은 배정 여부를 모른 채 무조건 삭제 요청을 보냄실제 막는 곳은 서버 (거절 시 화면은 에러 메시지를 토스트로 그대로 노출)확정
차단 조건·강제 여부
정산 상품 배정 상태의 정확한 정의와 서버가 실제로 이 규칙을 강제하는지는 코드에서 확인 불가화면 문구상 존재만 확인, 서버 규칙 개발 확인 필요확인필요
실패 시 표시
서버가 거절하면 서버가 내려준 실패 사유 문구를 그대로 빨강 토스트로 표시화면이 만든 문구가 아니므로 실제 사용자에게 보이는 실패 메시지는 서버 응답에 좌우됨가설
연결노출 권한·비활성화와의 구분
삭제 버튼 노출
[삭제] 버튼과 이 모달은 관리자·페이허그 등급 로그인 시에만 표시그 외 운영자 화면엔 삭제 진입로 자체가 없음확정
비활성화와 별개
같은 행의 [비활성화]는 성격이 다른 동작비활성화 = 로그인만 막는 되돌릴 수 있는 처리(활성 회원 행에 노출, 등급 제한 없음)삭제 = 되돌릴 수 없는 완전 삭제(관리자 전용)두 버튼은 서로 다른 서버 요청·다른 확인 문구를 사용확정
6대 개념과 무관
여기서의 '삭제·차단'은 회원 계정 삭제일 뿐, 정책의 회수/과지급이나 어드민의 매출 회수(락→모계좌 스윕)와 무관확정
