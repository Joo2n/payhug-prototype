정산 상품 목록의 [비활성화] 버튼이 띄우는 확인창(경고 스타일)에 특수한 내용만 정리. 이 화면 고유 요소는 (1) 상품명이 삽입된 2줄 경고 문구와 그 안에 담긴 '이력 유지·신규 배정 차단' 정책 주장, (2) 완전삭제와 구분되는 별도 처리 경로·성공/실패 분기, (3) 코드상 비활성 여부를 목록에서 시각 구분하지 않는 한계. 실제 서버가 정말 이력만 남기고 신규 배정을 막는지는 안내 문구 기준일 뿐 서버 동작 확인이 필요하다.
설정비활성화 확인창의 고유 설정
확인창 형태
경고(노랑) 스타일 확인 다이얼로그제목 "상품 비활성화", 실행 버튼 "비활성화"(노랑), 취소 버튼 병기같은 화면의 완전삭제 확인창은 빨강(위험) 스타일로, 색·문구·되돌림 안내가 다름확정
상품명 자동 삽입 문구
안내 문구는 2줄로 상품명이 끼워짐1줄: "○○ 상품을 비활성화하시겠습니까?"2줄: "배정된 가맹점 이력은 유지되며, 신규 배정만 불가능해집니다."이 2줄째가 이 화면의 핵심 정책 주장확정
연결처리 경로와 결과 분기
비활성화 처리
확인 시 해당 상품 1건에 대해 비활성화 전용 처리를 호출(상품 삭제와는 다른 경로)완전삭제와 달리 데이터를 지우는 게 아니라 '비활성 상태로 전환' 성격가설
성공/실패 안내
성공 → 토스트 "○○ 상품이 비활성화되었습니다." 노출 후 목록 자동 새로고침실패 → 서버가 준 사유 우선, 없으면 "비활성화에 실패했습니다."통신 자체 오류 → "비활성화 중 오류가 발생했습니다."확정
완전삭제와의 차이
완전삭제는 배정된 가맹점이 있으면 막힘(되돌릴 수 없음 경고)비활성화는 배정 이력이 있어도 진행되며 이력을 남기는 것이 전제즉 '삭제 불가한 상품을 정리하는 대안'으로 비활성화가 설계됨가설
정책정책 주장과 확인 필요 사항
이력 유지·신규 배정 차단
"배정 가맹점 이력 유지 + 신규 배정만 불가"는 안내 문구가 선언한 규칙일 뿐실제로 서버가 기존 배정·정산 이력을 보존하는지, 신규 배정만 실제로 막는지는 개발 확인 필요확인필요
비활성 상태 표시 부재
상품 데이터에 활성 여부 값은 있으나 목록 화면이 이를 표기하지 않음비활성화 후에도 목록에서 활성 상품과 시각적으로 구분되지 않아, 운영자가 상태를 알기 어려움 — 개선/확인 필요확인필요
재활성화 경로
확인창·목록 어디에도 비활성 상품을 되살리는 동작이 보이지 않음비활성화가 사실상 일방향인지, 별도 경로로 복구 가능한지 확인 필요확인필요
