화면 성격  약관을 컨텍스트 > 종류 > 버전 3계층 트리로 관리하는 화면 (검색창 없음) 데이터  실데이터는 서버 조회값 — 캡처는 예시 시드 (회원가입 3종 · 전자계약 3종 · 마케팅 수신 1종) 로드  진입 시 컨텍스트·종류·버전 3종을 동시에 불러옴 (다른 탭 갔다 돌아와도 다시 불러옴)

관리		 접힌 카드 "컨텍스트 관리 (N개)" — N = 전체 컨텍스트 수누르면 아래로 펼쳐지며 컨텍스트 목록 테이블 노출[AD_TERMS_CTX]기본은 접힘 상태
3컨텍스트
필터		 [전체] + 컨텍스트별 칩 (기본 전체)각 칩 옆 숫자 = 그 컨텍스트에 속한 약관 종류 수칩 목록은 서버에서 동적으로 불러옴 (고정 아님)누르는 즉시 목록이 걸러짐 (서버에 다시 묻지 않음)칩은 숫자가 0이어도 항상 노출 — 목록에서는 종류 0개인 컨텍스트 그룹만 빠짐(칩은 남음)
4약관 목록
(트리)		 3계층 구성① 컨텍스트 그룹 헤더 : 컨텍스트 뱃지 + "N개 종류"② 종류 카드 : 종류명 + 코드칩 + 필수/선택 뱃지 + [종류 수정][개정]③ 버전 테이블 : 각 종류 아래 버전 행들종류 카드 헤더종류명이 길면 …로 줄여서 표시[종류 수정] → 종류 수정 모달[AD_TERMS_TYPE_EDIT][개정] → 새 버전 등록 모달[AD_TERMS_REVISE_FIXED] (그 종류로 고정)4-1 컨텍스트 · 필수 뱃지 색컨텍스트 : 회원가입 = 하늘 · 전자계약 = 보라그 외 컨텍스트(마케팅 수신 등)는 색 미정의 → 회색 기본값종류 : 필수 = 주황 · 선택 = 회색상황별 문구불러오는 중 → "로딩 중..."약관 0건 → "등록된 약관이 없습니다."종류에 버전 없음 → "등록된 버전이 없습니다."로드 실패 → "데이터 로드에 실패했습니다." (토스트)
5버전 행
· 관리		 표 항목버전 · 제목 · 시행일 · 게시 · 관리제목이 길면 …로 줄여서 표시행 클릭 이동 없음 — 버튼으로만 동작 (행에 마우스 올리면 배경만 옅게 변함)버전 행 정렬 순서는 서버가 준 순서 그대로 — 정렬 기준 개발 확인 필요 (캡처는 1.0→2.0 오름차순)5-1 게시 토글켜짐 = 초록 · 꺼짐 = 회색누르면 즉시 게시/미게시 전환, "게시됨"/"미게시됨" 토스트5-2 관리 버튼[미리보기] · [수정] 는 항상 노출[삭제] 는 미게시 버전에만 노출 (게시 중이면 숨김)[미리보기]→[AD_TERMS_PREVIEW] · [수정]→[AD_TERMS_VER_EDIT] · [삭제]→[AD_TERMS_VER_DEL]
정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
약관 관리는 '어디서 동의받나(컨텍스트) > 무슨 약관인가(종류) > 몇 번째 판인가(버전)' 3계층을 한 화면에서 다루는 어드민이다. 진입 시 컨텍스트·종류·버전 세 목록을 각각 통째로 받아 화면에서 트리로 묶고, 필터도 화면 안에서 처리한다. 세 조회는 한 묶음으로 기다려 하나라도 예외로 실패하면 셋 다 반영하지 않는다. 개정 버전 번호는 화면이 자동으로 매기고 직전 버전의 제목·본문을 미리 채워 준다. 코드값은 한 번 정하면 못 바꾸고, 게시 중 버전은 삭제 버튼이 아예 숨는다. 선정산 정산 6대 개념과는 무관한 순수 문서관리 화면이다. 서버가 실제로 매기는 정렬·중복검증·삭제거부 판단은 확인 필요.
연결데이터 출처 · 조회 구조
무엇을 어디서 받나
세 개의 창구를 따로 두드림 — 컨텍스트 목록 · 종류 목록 · 버전 목록한 번에 합쳐 주는 창구는 없고, 각각 전체 목록을 통째로 받아 옴확정
언제 다시 부르나
화면 진입 시 세 개를 동시에 조회다른 탭 갔다 돌아오면 자동으로 다시 조회저장·수정·삭제·게시전환 성공 후에도 매번 전체 재조회확정
한 창구라도 실패하면
세 조회를 한 묶음으로 함께 기다림 — 하나라도 예외로 실패하면 셋 다 화면 반영 없이 "데이터 로드에 실패했습니다." 안내응답이 실패로 돌아온 창구는 조용히 건너뛰고 이전 상태 유지(별도 오류 안내 없음)확정
계산3계층 묶기 · 필터 (화면 내부 계산)
트리 묶음은 누가
서버가 트리로 주는 게 아니라 화면이 조립종류는 컨텍스트 코드로, 버전은 종류 식별값으로 각각 이어 붙임확정
컨텍스트 필터
칩을 누르면 서버에 다시 묻지 않고 이미 받은 목록에서 즉시 걸러 냄그래서 반응이 즉각적확정
빈 그룹 처리
(필터 반영 후) 종류가 0개인 컨텍스트 그룹은 목록에서 통째로 빠짐단, 상단 필터 칩은 0개여도 항상 남음 (칩과 목록의 노출 기준이 다름)확정
버전 행 정렬
화면은 서버가 준 순서 그대로 뿌림 — 자체 정렬 안 함실제 정렬 기준(시행일/버전/등록순)은 서버 몫 → 확인 필요확인필요
계산개정(새 버전) 번호 · 초기값 자동 처리
버전 번호 자동 매김
그 종류의 가장 높은 버전 값의 정수부 +1 로 매김 (예: 1.0·2.3 있으면 → 3.0)버전이 하나도 없으면 1.0입력칸은 읽기 전용, 사람이 못 고침확정
버전 비교 방식 주의
버전을 숫자값(소수)으로 비교 — 판(semver)이 아님예: '2.10'은 2.1로 읽혀 '2.3'보다 낮게 취급됨 → 소수 두 자리 이상 운용 시 '최신 버전' 오판 소지 → 확인 필요확인필요
직전 내용 자동 채움
개정 시 직전(최고) 버전의 제목·본문을 그대로 미리 채워 줌수정 편집 후 저장하는 방식 유도확정
시행일 기본값
오늘 날짜로 자동 세팅 (수정 가능)확정
'약관 개정'(상단) vs '개정'(카드)
카드의 [개정] = 그 종류로 고정, 번호도 미리 계산됨상단 [약관 개정] = 종류를 먼저 고르는 모드, 고른 뒤에야 번호 자동 계산종류가 하나도 없으면 상단 개정 자체를 못 엶확정
저장 필수값
제목·본문·버전·시행일이 모두 있어야 저장 (하나라도 비면 "필수 항목을 입력해주세요.")상단 개정 모드는 약관 종류 미선택 시 저장 차단확정
등록자 기록
새 버전 저장 시 로그인한 어드민 이름을 등록자로 함께 보냄 (이름 없으면 기본값 대체)확정
정책코드값 · 수정 범위 제약
컨텍스트 코드
새로 만들 때만 입력, 수정 화면에선 잠김(못 바꿈)입력 시 자동 소문자화 (예: signup, contract)확정
종류 코드
새로 만들 때만 입력, 자동 대문자화 (예: SERVICE, PRIVACY)수정 시엔 코드를 아예 안 보내므로 사실상 잠김확정
종류 수정으로 바꿀 수 있는 것
종류명 · 필수/선택 · 정렬순서만소속 컨텍스트 이동은 불가 (수정 시 컨텍스트 안 보냄)확정
컨텍스트 수정으로 바꿀 수 있는 것
이름 · 정렬순서만 (코드 잠김)활성 여부는 수정 저장에 실제로 담기지 않음확정
코드 중복 검증
화면단엔 중복 검사 없음 → 서버가 거를 것으로 추정 → 확인 필요확인필요
정책게시 · 삭제 정책
게시 토글
누르면 확인 없이 즉시 게시/미게시 전환되돌아온 상태값에 따라 "게시됨"/"미게시됨" 안내확정
삭제 노출 조건
삭제 버튼은 미게시 버전에만 뜸 — 게시 중이면 버튼 자체가 사라짐실수로 라이브 약관을 지우는 것 방지확정
삭제 확정 시
확인 팝업 거쳐 삭제 (되돌릴 수 없음 경고)안내문상 "사용자 동의 이력이 있으면 삭제가 거부됨"실제 거부 판정은 서버 몫 → 확인 필요확인필요
종류/컨텍스트 삭제
종류·컨텍스트에는 삭제 기능이 없음 (수정만 가능)비활성 상태값이 데이터엔 있으나 화면에서 끄고 켜는 조작은 없음확정
설정표시 규칙 · 미사용 항목
컨텍스트 뱃지 색
회원가입(signup)=하늘 · 전자계약(contract)=보라만 고정 지정그 외(마케팅 수신 등)는 색 정의가 없어 회색 기본값 — 컨텍스트를 늘려도 색은 자동 안 붙음확정
종료일
데이터엔 시행 종료일 칸이 있고 수정 전송에도 자리가 있으나 화면에서 입력하는 곳이 없음개정하면 이전 버전 종료일을 자동 닫는지는 화면상 불명 → 확인 필요확인필요
검색
검색창 없음 — 필터 칩으로만 좁힘확정
미리보기 본문
저장된 본문을 입력한 줄바꿈 그대로 보여 줌 (별도 서식 변환 없음)미리보기에서 바로 [수정하기]로 편집 모달 전환 가능확정

6대 개념 무관
이 화면은 순수 문서(약관) 관리미지급금·선정산 제외금액·바로이체·과지급·미회수금·환급 어느 것도 다루지 않음어드민 '매출 회수'(락계좌→모계좌)와도 무관확정
