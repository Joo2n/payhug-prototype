정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
차액 정산 탭의 '미회수 이월' 서브탭 심화 로직. 화면 워크스루(음수 빨강·유형열 숨김·0건 문구·상한 미확정)와 중복을 피하고, 이 서브탭에만 특수한 3가지에 집중했다. (1) '미회수 이월' 숫자가 두 곳(차액 대시보드 서브탭/KPI vs 정산상세 탭의 배치별 이월액)에서 서로 다른 출처로 나오며 코드상 연결되지 않음, (2) 이 카테고리는 다른 차액 유형과 달리 부호가 항상 차감(-)으로 고정되고 엑셀에서도 음수로 강제됨, (3) 실질은 과지급 회수 실패분을 다음 정산으로 넘긴 '미회수금'이나 화면 라벨은 '차액'이며 상한·기간·차감 우선순위 정책은 프론트에 없다(서버/정책).
데이터이 숫자가 나오는 두 갈래 출처
서브탭·KPI 카드
차액 정산 대시보드 조회 결과를 카테고리 '미회수 이월'로만 걸러 만든 목록·집계서브탭 옆 건수, KPI 카드의 금액·건수·대기건수 모두 이 한 번의 조회에서 나옴기간(조회일 범위)에 걸린 이월 건들의 합계확정
정산상세 탭의 배치별 이월액
같은 '미회수 이월'이지만 다른 화면(정산상세)에서 배치 1건을 열 때 따로 내려오는 값그 배치가 다음 정산으로 넘긴 미회수 차액을 배치 단위로 보여줌서브탭 목록과 코드상 서로 연결·대사되지 않음(같은 개념, 다른 진입점)확정
거래일의 의미
표·정렬 기준이 '거래일'인데, 이월 건의 거래일이 원거래일인지 이월이 발생한 날인지 화면 코드로는 구분 불가확인필요
계산이 카테고리만의 표시·부호 규칙
부호 고정 = 항상 차감(-)
다른 차액 유형은 환급(+)/차감(-)이 섞이지만, '미회수 이월'은 환급 유형 목록에 포함되지 않아 화면에서 항상 빨강 '-'로만 표기됨즉 이월은 정의상 가맹점에서 더 받아내야 할(차감) 방향으로만 계산확정
엑셀도 음수로 강제
다운로드 시 이월 금액은 부호를 뒤집어 마이너스 값으로 기록됨(환급 건만 양수)확정
대기/완료 2상태
이월 건도 반영완료(초록, 반영일 표시)와 대기중(노랑)을 가짐KPI의 '대기 N건'이 아직 다음 정산에 반영 안 된 이월 잔량확정
필터가 KPI까지 흔듦
카드사·매출유형 필터는 서버 재집계라 이월 KPI 금액 자체가 바뀜(에이전시·가맹점명 검색은 목록만 거르는 화면 필터)매출유형을 특정 값으로 좁히면 원장 미연결 이월 건이 빠질 수 있음(화면 툴팁 경고)확정
정책개념 정체와 미확정 정책
실질은 '미회수금'
라벨은 '차액'이지만 내용은 당일 회수로 다 못 걷은 과지급분을 다음 정산으로 넘긴 금액 = 6대 개념 중 미회수금락계좌→모계좌 스윕(어드민 '매출 회수')과 무관, 과지급 회수의 이월분가설
상한·기간·우선순위 없음
이월 상한 금액·최대 이월 기간/회차·다음 정산에서 차감할 때의 우선순위를 정하는 로직이 프론트에 전혀 없음 — 전부 서버/정책 소관화면 안내문은 '잔액 0까지 매일 반복'만 언급확인필요
실제 이월·차감 산술
이월액을 얼마로 확정하고 다음 정산에서 어떻게 깎는지의 최종 계산은 서버 전용(확정 수수료율·지급 캘린더와 함께 미확인)확인필요
