헤더 [약관 개정] 버튼으로 연 새 버전 등록 모달의 '종류 직접 선택' 모드. 카드별 [개정] 버튼과 달리 종류가 고정돼 있지 않아, 종류를 고르는 순간 버전·제목·본문이 그 종류의 최신 버전 기준으로 자동 계산·복사되는 것이 이 화면의 핵심이다. 버전 자동 계산은 정수 단위만 올리는 규칙이라 소수점(1.1 등) 부여가 UI로는 불가능한 한계가 있고, 종류 드롭다운은 페이지 상단 컨텍스트 필터와 무관하게 전체 종류를 보여준다. 게시·시행일 확정 로직은 서버 소관이라 확인이 필요하다.
설정이 진입경로만의 특수 동작
두 가지 개정 진입의 차이
헤더 [약관 개정](이 화면) = 종류 미지정으로 열림 → 종류 선택칸이 수정 가능한 드롭다운으로 노출, 버전·제목·본문 모두 빈칸으로 시작.반면 각 종류 카드의 [개정] 버튼 = 종류가 이미 고정(회색 배지)되어 열리고, 열리는 순간 자동 채움이 끝나 있음.확정
진입 차단 조건
등록된 약관 종류가 0개면 모달이 아예 열리지 않고 "약관 종류를 먼저 등록해주세요." 토스트로 막힘.컨텍스트가 아니라 '종류' 유무가 기준.확정
종류 드롭다운 목록 범위
드롭다운은 상단 컨텍스트 필터와 무관하게 모든 종류를 나열함(필터는 뒤 목록에만 적용).표기: "[컨텍스트명] 종류명", 기본값 "약관 종류를 선택해주세요".확정
계산종류 선택 시 자동 채움 계산
버전 자동 계산 규칙
선택한 종류의 기존 버전 중 최신값을 찾아 그 정수부에 +1 한 값을 넣음(예: 최신 1.0 → 2.0, 최신 2.0 → 3.0). 기존 버전이 없으면 1.0.정수 단위로만 올라감 — 최신이 1.5여도 결과는 2.0. 즉 1.1·1.2 같은 소수 마이너 버전은 이 UI로 만들 수 없음(버전칸은 읽기전용).확정
제목·본문 복사
제목·본문은 그 종류의 최신 버전 내용을 그대로 복사해 채움(직전 약관을 밑그림 삼아 고쳐 쓰는 방식). 기존 버전이 없으면 둘 다 빈칸.확정
시행일은 복사 안 함
제목·본문과 달리 시행일은 항상 '오늘'로 초기화되고 이전 버전 값을 따라오지 않음.다른 종류로 다시 고르면 시행일도 오늘로 리셋됨.확정
'최신 버전' 판정 방식
버전 문자열을 숫자로 바꿔 가장 큰 값을 최신으로 봄. 숫자로 못 바꾸는 버전명이 섞이면 0으로 취급돼 계산이 틀어질 여지가 있음.가설
데이터저장·데이터 처리
저장 검증 순서
① 종류 미선택 → "약관 종류를 선택해주세요."② 제목·본문·버전·시행일 중 하나라도 비면 → "필수 항목을 입력해주세요."통과 시 등록, "등록되었습니다." 후 목록 새로고침.확정
등록자 기록
저장 시 현재 로그인한 어드민 이름을 작성자로 함께 남김(이름 없으면 기본값 처리). 이후 수정에서는 작성자를 바꾸지 않음.확정
게시 상태는 별도
새 버전은 저장돼도 바로 게시되지 않음 — 목록의 게시 토글을 켜야 실제 노출. 시행일 입력과 게시 여부는 별개 값.가설
중복 버전 방어
같은 버전명이 이미 있는 경우를 막는 검사는 화면단에 없음 → 서버 거부에 의존.확인필요
데이터 출처·갱신
컨텍스트·종류·버전 3개 목록을 함께 불러와 구성하며, 브라우저 탭을 다시 활성화할 때마다 자동 재조회함(다른 창에서의 변경 반영).확정
시행일·게시 확정 산출
종료 시행일·게시 시각 등 서버가 확정하는 값은 등록 직후 비어 있음. 시행일 도래 시 자동 게시 여부 등 확정 로직은 서버 소관이라 확인 필요.확인필요
