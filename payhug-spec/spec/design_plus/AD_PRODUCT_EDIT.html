정산 상품관리 목록에서 "수정"을 눌러 여는 상품 수정 모달(일반 상품). 생성 모달과 같은 폼을 재사용하되, 기존 상품값을 프리필하고 유형(일반/다우)은 회색 배지로 잠금해 변경 불가. 저장은 신규 생성이 아니라 해당 상품ID로 덮어쓰는 수정 방식이며, 요율은 내부 저장 단위와 화면 표시 단위 사이를 왕복 변환한다. 이 페이지는 정산 수수료 정책(요율·수취/납부 주체)을 설정하는 화면으로 6대 정산 개념(미지급금·과지급·환급 등)과는 무관하다.
설정수정 모드에서만 달라지는 동작
유형(일반/다우) 잠금
수정 진입 시 유형은 선택 버튼이 아니라 회색 배지로 표시되고 옆에 "(변경 불가)" 문구가 붙는다.한 번 만든 상품의 계산 골격(일반 vs 다우)은 바꿀 수 없다는 정책확정
화면 문구 전환
제목 "정산 상품 수정", 하단 버튼 "상품 수정"/저장 중 "수정 중..."으로 바뀐다 (생성 모드는 "생성").확정
저장 = 덮어쓰기
저장 시 신규 추가가 아니라 해당 상품ID 앞으로 전체 내용을 덮어쓰는 방식으로 전송된다.즉 이 화면은 부분 수정이 아니라 폼 전체를 다시 보내는 통짜 갱신확정
상품명은 여전히 필수
상품명이 비어 있으면 "상품명을 입력해주세요" 경고 후 저장 중단. 수정이어도 동일하게 검증.확정
데이터일반 상품(A값) 프리필 규칙
요율값 역변환 표시
저장된 내부 수치를 화면 단위로 되돌려 채운다.채권매입/시스템이용료: 내부값 ÷ 100 → % 표시이체수수료: 내부값 그대로 → 원 표시확정
요율 행은 템플릿 기준으로 재구성
일반 상품 고정 요율표(채권매입 5역할·시스템이용료 3역할·이체수수료 1역할) 틀에 기존 값을 얹는다. 저장값 없는 칸은 빈칸.상품에 값이 없던 항목도 입력칸으로 노출확정
수취 옵션 기본값 채움 규칙
저장된 수취 옵션값이 없을 때의 기본이 항목마다 다르다.파트너 이체료/시스템료 수취 4종·상위영업 수취: 값 없으면 ON으로 채움하위영업 이체료 수취만 값 없으면 OFF옛 상품(옵션 미저장분) 편집 시 화면 기본 상태가 이 규칙에 좌우됨가설
참여자 프리필
투자자·페이허그·상위파트너·하위파트너·영업조직을 기존 지정값으로 채운다. 미지정이면 "— 미지정 —".확정
계산저장 시 값 처리·행 노출 조건
표시 단위 → 저장 단위 변환
저장 시 다시 변환한다.이체수수료: 입력 원값을 정수 반올림나머지: 입력 %값 × 100 후 반올림빈칸/숫자아님은 0으로 저장확정
요율 입력 스텝
이체수수료 칸은 1원 단위(정수), 채권매입·시스템이용료 칸은 0.01% 단위 입력.확정
미지정 참여자의 요율 행 숨김·제외
투자자를 지정 안 하면 투자자 채권매입 행이, 영업조직을 지정 안 하면 영업조직 채권매입 행이 화면에서도 숨고 저장에서도 빠진다.참여자 없는 역할에 요율이 남는 것 방지확정
VAT 별도/포함
각 요율 행마다 VAT 별도·포함을 고를 수 있으나, 페이허그 역할 행은 VAT 선택칸이 없음(— 표시).확정
최종 정산 산술 반영
여기서 정한 요율·수취/납부 설정이 실제 정산액에 어떻게 곱해져 적용되는지는 서버 계산 영역. 확정 수수료율(C1)과도 연결되므로 이 화면만으로 단정 불가.확인필요
정책수수료 납부·수취 주체 설정(일반 상품)
납부 주체 = 3중 택일 토글
이체료 납부·시스템료 납부를 각각 상위파트너/하위파트너 중 한 쪽으로 켠다(같은 항목은 한 쪽만).둘 다 OFF면 가맹점이 납부(화면에 빨간 경고문 명시)확정
수취 주체 = 개별 ON/OFF
상·하위파트너 이체료/시스템료 수취 4종을 독립 토글.모두 OFF면 페이허그만 수취(빨간 경고문 명시)확정
일반 vs 다우 구성 차이
이 화면은 일반 상품이라 파트너 기준으로 참여자·납부/수취 항목이 뜬다. (다우 상품이면 상·하위영업 기준으로 항목 구성이 달라짐)확정
여기 '수취/납부'는 정책 6개념과 무관
이 설정은 수수료를 누가 부담·수취하는지 배분 규칙일 뿐, 어드민 '매출 회수'(락→모계좌 스윕)나 정책 '회수'(과지급 회수)와 전혀 다른 개념.확정
