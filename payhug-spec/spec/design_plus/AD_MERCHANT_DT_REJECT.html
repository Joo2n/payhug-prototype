가맹점 계약을 반려 처리하는 어드민 모달. 이 화면 특수 로직은 (1) 반려 버튼 노출 조건(관리자+사업자번호 존재+아직 반려 아님), (2) 반려 시점 계약상태(심사대기/승인완료)에 따라 안내 문구·헤더 톤이 갈리는 분기, (3) 반려 사유 필수 입력 게이트, (4) "반려=상태만 변경, 데이터 보존" 정책과 삭제는 계약 초기화(하드리셋)로 분리한다는 원칙이다. 서버 최종 처리 결과 메시지는 서버가 내려주므로 확인필요.
설정반려 버튼·모달 진입 조건
반려 버튼 노출 조건
세 조건 모두 충족 시에만 '가맹점 반려' 버튼 노출관리자 권한 계정사업자등록번호가 등록된 가맹점현재 계약상태가 반려가 아님 (이미 반려면 버튼 숨김)확정
재반려 차단
이미 반려된 가맹점은 버튼 자체가 사라져 중복 반려 불가확정
처리 중 잠금
다른 처리(승인 등)가 진행 중이면 반려 버튼 비활성화확정
정책반려 시점 상태별 분기
심사대기 상태에서 반려
헤더가 red 톤으로 강조 + amber 안내박스"반려 시 상태만 변경되며 기존 서류 및 데이터는 보존됩니다. 데이터 삭제는 계약 초기화에서 진행하세요."확정
승인완료 상태에서 반려
헤더는 일반 톤 + amber 안내박스"승인된 가맹점을 반려하면 서비스가 중단됩니다. 기존 매출/정산/계좌 데이터는 보존됩니다."확정
경고 강도 차이 의도
심사대기(아직 서비스 전) vs 승인완료(운영 중 서비스 중단)의 파급이 다르므로 문구를 분리승인완료 반려 = 운영 중단이라 더 무거운 조치가설
정책사유 입력·확정 처리
반려 사유 필수
사유가 공백뿐이면 '반려 확정' 버튼 비활성사유 없는 반려는 UI에서 원천 차단확정
반려 사유 저장·노출
입력한 사유는 그대로 저장되어, 반려 후 상세화면 '반려 사유' 영역에 표시됨확정
확정 처리 결과 메시지
'반려 확정' 누르면 서버가 처리하고 성공/실패 메시지를 내려줌실제 상태 전환·후속 처리는 서버 소관(확인필요)확인필요
데이터 보존 원칙
반려는 계약상태만 변경, 서류·매출·정산·계좌 데이터는 삭제하지 않음완전 삭제가 필요하면 별도 계약 초기화(하드리셋)로 처리확정
데이터반려 후 화면
반려 완료 표시
반려되면 상세화면에 red 박스로 "반려 처리된 가맹점" + "정보 수정 후 재심사가 필요합니다" 안내확정
재심사 경로
반려 후 정보 수정 → 재심사 흐름 전제. 재심사 시 상태 복귀 규칙은 이 화면에 없음(확인필요)확인필요
