카드수수료 차액 정산 이력 전용 라우트. 화면 특유 포인트는 (1) 상호명·이력이 서로 다른 두 출처에서 각각 조회되고 상태 필터가 서버 재조회 파라미터라는 점, (2) 상단 4개 통계 카드가 목록 중 '카드수수료 환급/차감' 두 유형만 클라이언트 합산해 나머지 6개 유형(예상매출·배달·취소환수·미회수이월)을 순차액에서 누락시키는 집계 한계, (3) '구분' 8종 라벨이 6대 개념과 어떻게 맞물리는지의 정책 매핑이다. 최종 수수료율·차액 산정은 서버 산출로 확인필요(C1).
연결데이터 출처와 연결
두 갈래 조회
상호명과 이력 목록을 서로 다른 곳에서 각각 불러온다.상호명: 가맹점 기본정보 조회이력: 이 가맹점의 차액정산 목록 조회둘은 독립이라 하나가 실패해도 다른 하나는 뜬다확정
상호명 실패 대체
상호명 조회가 실패하거나 값이 비면 부제를 "가맹점"으로 대체 표기(빈칸 방지)확정
상세페이지와의 관계
이 화면은 별도 전용 라우트. 가맹점 상세 안에는 같은 데이터의 요약 블록이 따로 박혀 있고, 그 요약은 승인 완료 + 사업자번호 보유 + 편집권한/파트너일 때만 노출된다(전용 라우트 자체의 접근 조건은 코드에 없음 → 확인필요)가설
행마다 숨은 연결키
각 이력 행은 화면에 안 보이지만 원장 · 원선정산 지급건 · 차액반영 선정산 지급건 식별값을 물고 있다. "차액을 어느 선정산에 태웠는가"를 역추적할 근거로, 상세 드릴다운을 붙일 여지확정
계산통계 카드 집계 규칙(이 화면 특유의 함정)
4개 카드 산출
전체 건수 · 환급 N건/+원(초록) · 추가 차감 N건/-원(빨강) · 순차액(부호). 모두 서버 합계가 아니라 현재 화면에 로드된 목록만 그 자리에서 더한 값확정
집계 대상이 2종뿐
환급/차감/순차액 카드는 구분값이 '카드수수료 환급'·'카드수수료 차감'인 행만 센다.예상매출 환급/차감, 배달수수료 환급/차감, 취소 환수, 미회수 이월은 순차액에 미반영→ 표에 취소환수 -45,200·미회수이월 -18,900이 보여도 순차액엔 안 빠짐(수치 착시 위험)확정
필터에 따라 합계가 흔들림
'대기'만 필터하면 통계도 대기 건만 합산됨. 카드 숫자는 전체 누계가 아니라 현재 뷰의 부분합이라는 점을 라벨로 명시할 필요가설
차액은 서버가 준 값 그대로
표의 '차액'은 화면에서 (정산적용−실제)로 계산하지 않고 서버가 내려준 차액값을 부호만 붙여 표시. 정산적용/실제 수수료도 서버값 표기 → 실제 산식·확정 수수료율은 확인필요(C1)확인필요
정책'구분' 8종과 6대 개념 매핑
라벨 8종
카드수수료 환급/차감 · 예상매출 환급/차감 · 배달수수료 환급/차감 · 미회수 이월 · 취소 환수. 환급계열=초록/+, 차감계열=빨강/−, 미회수이월=주황/−, 취소환수=빨강/−확정
6개념 대응(잠정)
예상매출 환급/차감 → 예상 지급 차액(C4) 성격, 정의 미확정취소 환수 → 취소로 인한 과지급 회수 계열(어드민 '매출 회수' 스윕과는 무관)미회수 이월 → 미회수금의 다음 회차 이월임의 확정 금지, 매핑 검증 필요확인필요
하단 3단계 안내
1)선정산=적용수수료로 지급 → 2)매입확정=실제 수수료로 차액 계산 → 3)다음 선정산에서 환급/추가차감. "환급·추가차감을 다음 회차 선정산에 태운다"는 정책 서술이 화면에 노출됨. 수수료율 근거 미확정(C1)확인필요
설정필터·상태 표기 규칙
필터 탭 3개뿐
전체 / 완료 / 대기 (기본=전체). '취소' 전용 탭은 없음 → 취소된 행은 전체에서만 볼 수 있음확정
상태 뱃지 3종
대기(노랑) · 완료(초록) · 취소(회색)확정
정산일 표기
완료(정산 반영)된 건만 정산일 표시, 값 없으면 "-". 즉 대기/취소 행은 정산일 항상 "-"확정
빈/로딩 상태
이력 0건 → "차액 정산 이력이 없습니다.", 조회 중 → "로딩 중..."확정
