5-2 상태 뱃지 색
감지 (미해소)=빨강 · 예상 정산 중=주황 · 해소 (대사 대기)=파랑 · 대사 완료=진초록
시각 컬럼발생·예상 정산·해소·대사 완료 4개 : "YYYY. MM. DD. 오전/오후 HH:MM" 표기

행에 마우스 올리면 배경 옅게 강조 / 단 행 클릭 이동 없음(조회 전용, 조치 버튼 없음)
상황별 문구로딩 → 스피너만 표시(문구 없음)
0건 → "조회된 장애 이력이 없습니다." (검색어 유무 분기 없이 단일 문구, 조회 실패 시에도 동일)
정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
4개 매출원(카드·배달의민족·요기요·쿠팡이츠)의 수집 장애를 감지→예상 정산 중→해소→대사 완료 4단계로 추적하는 조회 전용 화면. 스크래핑이 막힌 동안은 실매출 대신 예상값으로 먼저 정산하고 실매출이 들어오면 맞대보는(대사) 구조라, 예상값 정의(C4)와 직접 맞물린다. 다만 이 이력표 자체에는 금액이 없고 대상일·플랫폼·사업자번호·유형·상태·4개 시각만 담긴다.
계산장애 이력 4단계 흐름
4단계 상태 흐름
한 건의 장애는 감지(미해소) → 예상 정산 중 → 해소(대사 대기) → 대사 완료 순으로 진행.단계마다 시각이 따로 찍힘: 발생 · 예상 정산 · 해소 · 대사 완료 4개 시점확정
이력표에 담기는 항목 — 금액 없음
한 줄에 담기는 건 대상일 · 플랫폼 · 사업자번호 · 장애 유형 · 상태 · 4개 시각(발생·예상 정산·해소·대사 완료)뿐.금액 칸이 아예 없음. 따라서 '예상 정산 중'이라고 해서 이 표에 예상 금액이 보이는 게 아니라, 상태와 시각만 표시됨확정
'예상 정산 중'의 진짜 의미
스크래핑이 안 돼 실제 매출을 못 받은 동안, 시스템이 실매출 대신 예상값으로 먼저 지급 정산을 돌려 놓은 상태로 해석됨.다만 이 화면 코드에는 그 예상 금액도, '예상 지급 차액'의 정의(C4)도 없음. 실제로 얼마를 어떤 근거로 먼저 지급했는지는 정책·서버 영역이라 확인 필요확인필요
'해소'와 '대사 완료'에서 말하는 대사
스크래핑이 정상 복구돼 실제 매출이 들어오면 해소, 그 실제값과 앞서 예상으로 정산했던 값을 맞대보는 것이 대사로 보임.이건 데이터 맞대기이지 과지급 회수도 아니고, 락계좌→모계좌 '매출 회수' 스윕과도 다름. 다만 코드는 상태 이름만 있을 뿐 무엇을 어떻게 맞추는지 로직은 없어 가설가설
장애 유형 4종
API 오류 · 타임아웃 · 데이터 없음 · 주말 데이터 없음.'주말 데이터 없음'은 실제 오류가 아니라 원래 안 들어오는 날일 수 있어 별도 유형으로 떼어 둠확정
데이터조회 방식·요약 카드
필터 두 종류가 서로 다르게 동작 (핵심)
기간·상태를 바꾸면 서버에 다시 물어 목록·건수를 새로 받아옴. 반면 플랫폼 필터는 서버에 안 물어보고 이미 받아 둔 목록을 화면에서만 걸러냄.그래서 플랫폼을 바꿔도 요약 카드 숫자는 그대로. 상단 '조회 N건'만 화면 필터 결과 수로 바뀜확정
기본 조회 기간은 최근 30일
화면을 열면 오늘로부터 30일 전 ~ 오늘이 자동으로 잡혀 조회됨.초기화 누르면 이 30일 기본값과 필터 없음 상태로 되돌아감확정
요약 카드 숫자의 모수 차이
'전체(기간 내)'는 조회 기간 안의 건수. '감지(미해소, 전체)'·'예상 정산 중(전체)' 두 숫자는 라벨이 '전체'라 기간과 무관한 누적일 수 있음.세 숫자 모두 서버가 내려준 값이고, 플랫폼 필터로는 줄지 않음. 정확히 어떤 모수인지는 코드만으로 단정 불가확인필요
계산플랫폼 카드 현재 상태
플랫폼 카드 3색 상태
정상 · 장애 발생 중 · 장기 장애 3단계.'장기 장애'는 장애가 오래 지속된 경우로, 더 진한 빨강으로 강조확정
카드 안내 문구가 3갈래로 갈림 (누락 보완)
① 장애 중: 미해소 N건 · N일째 지속 · 최근 대상일 표시.② 수집은 정상인데 과거 미해소가 남음: '최근 수집 정상' + '과거 미해소 잔여 N건'만 흐리게 표시(별도 상태).③ 완전 정상: '미해소 장애 없음'.즉 '정상'이라도 예전 미해소가 남아 있으면 그 잔여 건수를 따로 알려줌확정
'N일째 지속'·미해소 건수는 서버 판정
며칠째 지속인지, 미해소가 몇 건인지, 최근 대상일이 언제인지, 정상/장애/장기 장애 구분 모두 서버가 계산해 내려준 값을 그대로 표시.며칠부터 '장기 장애'로 넘기는지 기준선은 이 화면에 없음확인필요
정책플랫폼 검증 상태 5종 (락계좌 연결 검증)
검증 상태 5종은 이 이력표와 다른 체계
정상 · 이상 · 장애 · 스킵 · 검증 제외 — 이 5종은 플랫폼 정산 대금이 락계좌로 제대로 들어오게 연결됐는지 확인하는 '검증'에서 쓰는 값.본 화면 이력표의 상태(감지·예상 정산 중·해소·대사 완료)와는 다른 벌이므로 섞지 말 것확정
검증이 확인하는 것
각 플랫폼(여신협회·배민·요기요·쿠팡) 정산금이 락계좌로 향하도록 결제계좌가 설정됐는지를 점검.이상·장애가 잡히면 안내: "플랫폼에서 결제계좌를 락계좌로 변경 후 다시 검증해 주세요"확정
장애 시 '이전 검증 시각 기준' (핵심)
플랫폼 스크래핑이 장애면, 개별 항목에 장애 표시가 없더라도 그 플랫폼 전체에 "스크래핑 장애 (이전 검증 시각 기준)"으로 표시됨.즉 지금 새로 검증하지 못하고, 마지막으로 검증에 성공했던 시각의 상태를 그대로 근거로 삼는다는 뜻확정
검증 시각 표기 방식
서버가 주는 검증 시각은 '연월일 시:분'을 붙인 압축형이라, 화면에서 '2026.07.21 14:30' 형태로 풀어 보여줌.검증 시각 값이 없으면 아예 표기하지 않음확정
연결쿠콘 연동·모계좌 대사
쿠콘으로 모계좌 잔액·원장을 받아옴
가맹점 지급에 쓰는 모계좌의 잔액과 입출금 내역을 쿠콘 연동으로 가져옴.용도: 가맹점에 돈 보내기 전 '지금 얼마까지 보낼 수 있나'를 확인확정
잔액은 총잔액·출금가능·출금불가로 나뉨
쿠콘이 주는 잔액은 총잔액 · 출금 가능액 · 출금 불가액 세 갈래.실제로 가맹점 지급에 쓸 수 있는 '가용'은 이 중 출금 가능액을 봐야 함(총잔액과 다를 수 있음)확정
모계좌 원장 4종 구분 — '매출 회수' 주의
모계좌 입출금은 지급(가맹점 송금) · 관리자 수동 · 매출 회수 · 수동 입금으로 나뉨.여기 '매출 회수'는 락계좌에 모인 돈을 모계좌로 쓸어담는 스윕(모계좌로 들어오는 입금). 정책상 '과지급 회수'와는 전혀 다른 개념이니 혼동 금지확정
모계좌 수동 입금은 등록·삭제 가능 (쓰기)
