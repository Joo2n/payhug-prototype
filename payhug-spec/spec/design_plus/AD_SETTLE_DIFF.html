정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
선정산을 지급할 때 '예상 수수료'로 먼저 지급한 금액과, 매입 확정 뒤 드러난 '실제 수수료'의 차이를 모아 다음 선정산에서 환급하거나 추가로 차감하도록 관리하는 어드민 화면이다. 카드 수수료 차액, 배달 수수료 차액, 취소 환수, 예상매출 대사, 미회수 이월 5개 구분을 한 화면에서 집계하고 '대기중/반영완료' 상태로 추적한다.
연결화면 위치·다른 화면과의 연결
화면 위치
'정산 현황' 화면 안의 탭 하나인 '차액 정산'이다. 탭 줄에서 '선정산 결과' 다음에 오며, 페이허그 내부 직원에게는 그 사이에 '정산 상세'가 껴 있어 세 번째로, 외부 사용자에게는 두 번째로 보인다.같은 화면에 선정산 결과 / 정산 상세 / 이체 내역 / 계산서 발행 / VOC 대응 탭이 함께 있고, 이 탭들과 날짜 조회 필터를 공유한다.확정
접근 권한
차액 정산 탭 자체는 모든 사용자에게 노출된다.정산 상세·계산서 발행·VOC 탭은 페이허그 내부 직원에게만 보인다(차액 정산·이체 내역은 그 제한이 없음).확정
가맹점 화면 쪽 짝
가맹점 상세 화면에는 '카드 수수료 차액 정산 현황' 요약 카드가 따로 있다. 그 카드에서 '매출 내역 보기'(매출 조회 화면)와 '차액 이력 보기'(가맹점별 차액 이력 화면)로 이동한다.'매출 내역 보기'는 사업자번호가 있을 때만 뜬다.즉 어드민 대시보드는 '전체 집계', 가맹점 요약 카드는 '한 가맹점 관점'으로 나뉜다.확정
조회 시작 방식
기간(기본값 이번 달 1일 ~ 오늘)을 정하고 조회해야 표가 뜬다. 탭에 처음 들어오면 자동으로 한 번 조회한다. 조회 전에는 '기간을 선택하고 조회 버튼을 눌러주세요' 안내가 뜬다.확정
데이터차액을 나누는 5개 구분·8개 유형
5개 구분
① 카드 수수료 차액 ② 배달 수수료 차액 ③ 취소 환수 ④ 예상매출 대사 ⑤ 미회수 이월. 맨 위 KPI 카드도 '전체 차액' 하나 뒤에 이 구분별 카드를 이어 붙여 보여주고, 하단 표도 이 5개(+전체) 서브탭으로 걸러 본다.확정
8개 세부 유형
각 건은 8개 유형 중 하나로 배지가 붙는다.카드수수료 환급 / 차감배달수수료 환급 / 차감취소 환수예상매출 환급 / 차감미회수 이월확정
구분·유형 색·배지
구분마다 색이 정해져 있다(카드=파랑, 배달=주황, 취소환수=빨강, 예상매출=보라, 미회수이월=호박색).표의 유형 배지는 구분 색과 꼭 같지는 않다(예: '예상매출 차감' 배지는 호박색, '카드수수료 차감' 배지는 빨강). 라벨은 '카드수수료 환급'처럼 유형 이름 그대로 단다.확정
계산차액이 생기고 부호가 갈리는 로직
차액 발생 3단계
가맹점 요약 카드 하단에 정책이 그대로 적혀 있다.승인 단계: 예상 수수료로 선정산 지급매입 확정: 실제 수수료 확인 후 차액 계산다음 선정산: 차액을 환급하거나 추가 차감즉 이 화면은 '예상값으로 먼저 준 뒤 실제값으로 정산하는' 구조의 뒤처리 장부다.확정
부호(+/−) 규칙
환급 3종(카드환급·배달환급·예상매출환급)만 +로, 가맹점에게 돌려주는 돈이다. 나머지(카드차감·배달차감·취소 환수·예상매출차감·미회수 이월)는 모두 −, 가맹점에서 더 떼거나 회수하는 돈이다. 화면·엑셀 모두 이 규칙으로 부호를 붙인다.확정
예상수수료·실제수수료·차액 3열
표에는 건마다 예상수수료 / 실제수수료 / 차액을 나란히 보여준다. 차액 금액은 절대값으로 들고 있다가 화면에서 부호를 붙여 표시한다.표의 두 금액 열 제목은 유형과 상관없이 항상 '예상수수료·실제수수료'로 고정돼 있다.확정
전체 차액 KPI 계산
맨 위 '전체 차액' 카드는 서버가 계산해 내려준 순액이다. 0 이상이면 파랑, 마이너스면 빨강으로 뜨고(플러스일 때만 앞에 + 표기), 옆에 '총 N건 (대기 N건)'을 단다.'환급에서 차감을 뺀 값'으로 보이나, 정확한 산식은 화면 코드만으로 단정할 수 없다.가설
차액이 두 수수료의 차이인지
'카드/배달 수수료 차액' 유형은 예상수수료−실제수수료로 볼 수 있으나, 취소 환수·미회수 이월·예상매출 대사는 두 금액 열과 별개의 금액일 수 있어 차액=예상−실제라고 단정할 수 없다. 실제 수수료율(C1)·예상 지급 차액 정의(C4)가 미확정이라 이 화면 숫자만으로 계산식을 확정할 수 없다.확인필요
계산대기 · 예정 · 누적 · 이월
건별 상태 2가지
각 차액 건은 '반영완료'(다음 선정산에 이미 환급/차감 반영, 반영일을 날짜로 함께 표기) 또는 '대기중'(아직 미반영) 둘 중 하나다.확정
'대기 N건'의 뜻
KPI에 붙는 '대기 N건'은 아직 환급/차감이 실제로 이뤄지지 않은 예정분 건수로 읽힌다.'전체 차액' 카드는 대기 건수를 항상 표기하고, 구분별 카드는 대기 건이 있을 때만 덧붙인다.'언제 반영되느냐'는 다음 선정산 시점(지급 캘린더 C2)에 걸려 있다.가설
미회수 이월(⑤)의 의미
추가 차감·취소 환수 금액을 다음 지급액에서 다 빼지 못하면, 못 뺀 만큼을 다음 정산으로 넘긴다. 이게 '미회수 이월'이며 6대 개념 중 미회수금에 해당한다. 정산 상세 탭에서도 배치별로 '다음 정산으로 이월된 미회수 차액'으로 잡힌다.가설
가맹점 요약의 누적 지표
가맹점 요약 카드에는 차액 정산 대기(건수+예정 금액), 이번 달 누적, 전체 누적 세 덩어리가 있다.대기 블록은 대기 건이 있을 때만 뜬다.'총 환급 / 총 추가 차감 / 순 차액' 상세는 '상세 통계 보기'를 눌러야 펼쳐진다.금액이 +면 '환급(가맹점에 유리)' 파랑, −면 '추가 차감' 빨강.차액 이력이 하나도 없으면 카드 자체가 안 뜬다.확정
설정필터와 집계 방식(서버 집계 vs 화면 필터)
매출 유형 필터
전체 / 카드 / 배달의민족 / 요기요 / 쿠팡이츠를 복수 선택한다(매출 조회 화면과 같은 버튼 방식).확정
필터의 숨은 정책(중요)
특정 매출 유형을 고르면 원장과 연결된 건만 보인다. '예상매출 대사'는 원장에 연결되기 전 건이라 '전체'에서만 보이고, 특정 유형을 고르면 사라진다. 화면 안내 툴팁에 이 내용이 그대로 적혀 있어, 기획·CS 응대 시 '유형 선택했더니 예상매출 건이 안 보인다'는 오해를 막아야 한다.확정
카드사 2뎁스 필터
매출 유형에서 '카드'를 골랐을 때만 그 아래 카드사 칩 필터가 뜬다(복수 선택). 선택지 목록은 필터를 걸기 전 전체 기준으로 서버가 내려준 값이라, 하나를 골라도 다른 카드사 선택지가 사라지지 않는다.확정
서버 집계 vs 화면 필터
매출 유형·카드사를 바꾸면 서버가 다시 집계해서 KPI 숫자까지 그 기준으로 바뀐다. 반면 에이전시·가맹점명 검색은 화면에서만 걸러 표와 서브탭 건수만 줄고 KPI 총액은 변하지 않는다. 두 종류 필터의 성격이 달라, 상단 숫자와 아래 표 합계가 안 맞아 보일 수 있음을 안내해야 한다.확정
데이터데이터는 어디서·언제·무엇을 가져오나
대시보드 데이터 출처
차액 대시보드는 서버가 기간·매출유형·카드사 기준으로 미리 집계해 한 번에 내려주는 자료다. KPI, 일별 추이, 상세 건 목록, 카드사 선택지가 한 묶음으로 온다.확정
예상매출 대사의 뿌리(예상값)
선정산 예측 자료를 보면, 주말이거나 스크래핑 장애일 때 실제 매출이 아직 없어 평균 매출로 '예상' 지급한다. 이렇게 예상으로 나간 건이 나중에 실제 확정되면 그 차이가 '예상매출 대사'(환급/차감)로 이 화면에 잡히는 것으로 보인다. 평균매출 사용 여부·사유(주말/장애)·'마지막 실제 데이터 일자'가 예측 자료에 함께 있다.가설
일별 추이 차트
환급·차감·취소환수 3계열 막대로 날짜별 추이를 보여준다. 일별 데이터가 2일치 이상 있을 때만 나타난다(기간이 길어도 데이터가 하루치뿐이면 안 뜬다).확정
엑셀 다운로드 항목
거래일·가맹점명·사업자번호·에이전시·승인번호·카드사·구분·유형·예상수수료·실제수수료·차액·상태(반영완료/대기중)로 내려받는다. 차액은 환급이면 +, 아니면 − 부호로 저장된다.확정
스크래핑 시각·확정 수수료율·지급일
실제 수수료를 언제 확정하는지(스크래핑/매입 확정 스케줄), 어떤 수수료율로 확정하는지, 차액을 어느 지급일에 반영하는지는 서버 전용이라 이 화면 자료만으로 확정할 수 없다(C1·C2·C4).확인필요
정책6대 개념 분리·정책 주의
'취소 환수' ≠ 어드민 '매출 회수'
여기서 '취소 환수'는 지급이 끝난 뒤 거래가 취소돼 이미 준 돈을 되받는, 과지급 성격의 회수로 읽힌다. 어드민의 '매출 회수'(락계좌→모계좌 스윕)와는 전혀 다른 개념이므로 라벨·설명에서 섞지 말 것.가설
환급/차감/환수/이월 구분 유지
화면상 5개 구분·8개 유형은 6대 개념(미지급금·선정산 제외금액·바로이체·과지급·미회수금·환급)과 얽힌다. 특히 환급=돌려줌, 추가차감/취소환수=더 뗌·과지급 회수, 미회수 이월=미회수금으로, 하나로 합치지 말고 분리 서술해야 한다.확정
지급 전/후에 따라 처리 다름
같은 마이너스 차액이라도 지급 전이면 그날 지급액에서 바로 차감, 지급 후면 회수/이월 검토 대상이다. 이 화면의 '차감'과 '취소 환수·미회수 이월'이 그 갈림을 반영한다고 볼 수 있으나, 실제 판정 시점은 서버 로직이라 확인 필요.확인필요
