1:1 문의 목록에서 카테고리 필터를 '결제'로 선택한 상태. 베이스 목록(AD_INQUIRY)과 화면 구조·답변/상태변경 동작은 동일하고, 이 변형에서만 특수한 것은 '결제' 칩 선택에 따른 서버 재조회·단일 선택 토글·상태탭 건수 재집계 방식이다. 결제 카테고리라 해서 정산/6대 개념 관련 자동 분기는 없으며, 카테고리 값 자체는 어드민에서 바꿀 수 없다.
설정'결제' 카테고리 필터 동작
필터 대상
카테고리 칩 5종(일반·결제·정산·기술·계정) 중 '결제' 선택 상태이 값은 가맹점이 문의 접수 시 지정한 분류이며, 어드민 화면에서는 변경 수단이 없음(어드민은 상태만 변경)확정
단일 선택·토글
한 번에 한 카테고리만 활성다른 칩 누르면 그 카테고리로 교체같은 '결제' 칩을 다시 누르면 해제되어 '전체'로 복원확정
활성 표시
'결제' 칩은 연한 파랑(primary) 배경으로 강조, 나머지 4개는 옅은 회색다른 카테고리와 색이 다름(정산=초록, 기술=보라, 계정=주황)확정
연결조회·재집계 방식
서버 재조회
'결제' 선택 시 목록을 서버에서 결제 문의만 다시 받아옴상태 탭(대기/처리중/…)과 조합되어 함께 서버 조건으로 전달확정
상태 탭 건수
화면 상단 상태별 건수(대기 N·처리중 N 등)는 현재 받아온 결제 목록만 기준으로 다시 셈'결제' 필터를 켜면 상태별 숫자도 결제 문의 기준으로 바뀜확정
검색창은 별개
제목·가맹점명·작성자 검색은 이미 받아온 결제 목록 안에서만 걸러냄(브라우저 내 필터)검색어로는 서버 재조회 안 함확정
목업 캡처 주의
현재 설계 캡처는 칩 강조만 바뀌고 목록 12건이 그대로라 실제 서버 필터 결과가 아님(작성자 메모의 red 경고)확인필요
정책결제 문의 처리 특성
카테고리별 자동 분기 없음
'결제' 카테고리라고 해서 담당자 자동 배정·전용 답변 템플릿·정산 연동 같은 특수 처리는 코드상 없음답변 등록·상태 변경 흐름은 모든 카테고리와 동일가설
6대 개념과의 관계
'결제' 문의는 카드결제/승인 등 결제 자체 이슈 분류로, 선정산 6대 개념(미지급금·과지급·미회수금 등)과 직접 연결되지 않음정산 관련은 별도 '정산' 카테고리로 분리가설
