AI 모니터링 어시스턴트는 어드민의 나머지 화면(활동로그·가맹점·정산)이 쓰는 서버와 다른, 별도의 로그분석 서버에 붙어 자연어 질문을 서버 운영로그 조회식으로 바꿔 실행하고, 그 결과를 여러 단계로 나눠 실시간으로 흘려받아 그대로 표시하는 읽기전용 화면이다. 화면은 건수·본문·원본로그·조회식·실제 조회범위를 스스로 계산하지 않고 서버가 산출·반환한 값을 표시만 한다. 화면설계서에 이미 있는 UI 워크스루(헤더·프리셋 칩·추천 칩·입력창)는 제외하고, 그 아래 숨은 연결/데이터출처/응답단계/기간전송규칙/추천칩이 가리키는 6대 개념을 정리했다.
연결어느 서버에 붙나 (활동 로그와 별개)
붙는 서버
활동로그·가맹점·정산 화면이 쓰는 서버 주소와 다른, 별도의 로그분석 서버 주소로 요청한다.같은 '활동 로그' 화면과는 데이터 출처가 완전히 다른 별개 시스템 (활동로그는 어드민 공용 서버, 이 화면만 별도 서버)확정
인증
로그인 때 받아 저장해 둔 어드민 접속 토큰을 질문과 함께 실어 보낸다.토큰이 없어도 요청 자체는 나가며(인증 정보만 빠짐), 서버가 거부하면 화면에 "요청 실패(상태코드)" 오류를 그대로 노출확정
주고받는 방식
질문 1건 + 조회기간을 한 번 보내고, 서버가 답을 여러 단계로 쪼개 실시간으로 흘려보내는 방식(서버→화면 단방향 스트리밍)확정
데이터무엇을 읽고 무엇을 표시하나 (데이터 출처)
조회 대상
'활동 로그' 테이블이 아니라 서버 운영 로그 저장소다(헤더 문구 "자연어로 서버 로그를 조회").내가 쓴 자연어 질문을 서버가 로그 조회식으로 바꿔 실행한 결과를 본다확정
표시 원칙
답변 본문·건수·원본 로그·조회식 전부 서버가 산출한 값을 그대로 표시한다. 화면은 숫자를 세거나 가공하지 않는다.그 산출·집계의 정확성은 화면 코드로 검증 불가, 서버 몫확인필요
조회범위 배지
답변 상단의 '기간 ~ 기간' 배지는 내가 고른 프리셋이 아니라, 서버가 응답에 되돌려 보낸 시작·종료 값을 그대로 표시한다(건수 배지도 서버가 보낸 값).화면이 이 값을 프리셋 대신 쓴다는 점은 확정이나, 그 값이 '실제 조회된 범위'와 일치하는지는 서버 몫확정
휘발성
대화 내역은 어디에도 저장되지 않고 화면 메모리에만 있다. 새로고침·화면 이탈 시 질문·답변·원본로그가 전부 사라짐확정
연결답이 도착하는 단계 (실시간 스트리밍)
단계 A · 조회식
서버가 만든 로그 조회식과 그 설명을 먼저 내려준다 → 답변 상단 'LogQL' 토글에서 열람확정
단계 B · 건수/원본
조회 건수 + 서버가 판단한 시작·종료 시각 + 원본 로그 묶음을 내려준다 → '원본 로그' 토글에서 열람.건수 0건이면 회색 배지, 1건 이상이면 컬러 배지확정
단계 C · 분석 본문
분석 텍스트를 조각조각 이어붙여 점진적으로 채운다(표·코드블록·인용 등 서식 지원)확정
완료/로딩 문구
완료 신호가 오면 스트리밍 표시를 끈다. 진행 중 문구는 조회식 도착 전 "쿼리 생성 중...", 도착 후 본문 채우는 중 "분석 중..."으로 단계에 따라 바뀜확정
오류 처리
'요청 실패(상태코드)'·'스트림을 읽을 수 없음'·'요청 중 오류' 등 상황별로 다른 문구 표시. 도중 오류가 나면 그 자리에서 스트리밍을 멈추고 붉은 에러박스로 전환확정
계산고른 기간을 어떻게 서버로 보내나
프리셋 계산
고른 프리셋(예: 1시간)을 질문 보내는 그 순간의 현재시각 기준 (현재-N ~ 현재)로 잡아 국제표준시로 변환해 함께 전송확정
직접 지정
입력한 시작·종료 일시를 국제표준시로 변환해 전송.종료를 비우면 종료값을 아예 보내지 않음(열린 구간). 시작만 있어도 전송됨확정
실제 매칭 로그
이 기간으로 실제 어떤 로그가 잡히는지는 서버가 판단하는 몫(화면은 서버가 되돌린 범위·건수만 표시)확인필요
정책추천 칩이 가리키는 개념 (6대 개념 분리)
추천 칩 구성
첫 질문 전 빈 화면에 고정 문구 4개가 노출된다: '오늘 하루 비즈니스 이슈 요약' / '이체 실패 건' / '매출대금 회수 실패 내역' / '최근 스크래핑 오류'. 칩을 누르면 그 문구가 질문으로 그대로 전송됨확정
"이체 실패" 칩
가맹점에게 선정산금 지급 이체가 실패한 건(활동로그의 '가맹점 이체 실패')을 가리키는 것으로 읽힘가설
"매출대금 회수 실패" 칩
어드민의 '매출대금 회수'(락계좌→모계좌 스윕) 실패를 가리킴.정책의 '회수'(과지급 회수)와는 다른 개념가설
"스크래핑 오류" 칩
가맹점 매출 스크래핑 실패를 가리키는 것으로 읽힘(활동로그에는 대응 이벤트 라벨이 없음)가설
실제 조회 대상
칩 4개 문구는 고정이지만, 실제로 어떤 로그를 볼지는 서버가 해석·결정한다. 화면 문구만으로 조회 대상을 확정할 수 없음확인필요
