1펼침
헤더		 펼치면 카드 아래 회색 패널로 참여자 · 옵션 · 요율 3개 영역이 순서대로 표시펼침 화살표(∨)가 위로 뒤집힘
2참여자 소제목 "참여자" — 역할별 참여자 칩 나열일반 유형 역할 : 투자자 · 페이허그 · 상위파트너 · 하위파트너 · 영업조직칩 = 역할 라벨 + 이름 + (회원유형이 역할과 다르면 유형 알약)법인/개인 뱃지 : 법인 = 보라 · 개인 = 회색사업자 뱃지(초록)는 사업자일 때만 붙음지정 안 된 역할은 회색 칩 "미지정"으로 자리만 표시일반이라도 상위영업·하위영업 슬롯은 미지정 회색 칩으로 함께 노출
3옵션 소제목 "옵션" — 수수료 납부/수취 설정 칩이체수수료(원) : 금액을 노란 칩으로 표시 (예 300)수취 옵션 : ON = 초록 · OFF = 빨강납부 칩(시스템이용료 납부·이체수수료 납부) : 납부자 있으면 파랑, 없으면 회색 "가맹점 부담"
4요율 소제목 "요율" — 수수료 유형별 그룹 표그룹(유형)채권매입(남색) · 시스템이용료(초록) · 이체수수료(노랑)그룹 헤더에 건수(n건) 표시 · 해당 유형 요율이 없으면 그룹 자체가 숨겨짐행 표기역할 + 값 (채권매입·시스템이용료 = %, 이체수수료 = 원)채권매입 그룹만 요율 높은 순 정렬 · 나머지 그룹은 서버 순서 유지표시 요율(0.6% / 0.2% / 300원 등)은 서버값 그대로 — 정책 수수료율은 미확정(C1), 개발 확인 필요
정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
일반(파트너) 정산 상품 카드를 펼친 상태의 심화 로직. 펼침은 목록 응답을 그대로 재사용하는 순수 화면 토글이라 별도 상세 조회가 없고, 요율 표시값은 저장값을 100으로 나눠 %로 환산한 결과이며(이체수수료만 원 단위 그대로), 옵션 칩의 납부자 라벨은 상품 유형(일반/다우)에 따라 파트너/영업으로 갈린다. 실제 수수료율 수치 자체는 C1 미확정이라 화면은 서버값을 그대로 보여줄 뿐이다.
데이터펼침 패널 데이터 출처
펼침 시 추가 조회
없음. 카드를 펼쳐도 서버에 다시 묻지 않는다.목록을 불러올 때 받은 상품 응답 안에 이미 참여자·옵션·요율이 다 들어있고, 펼침 패널은 그 데이터를 그대로 펼쳐 보여줄 뿐확정
펼침 동작 성격
순수 화면 상태 토글(서버 반영 아님).한 번에 한 카드만 열림 — 다른 카드를 펼치면 앞의 것은 닫힘확정
세 영역 공통 출처
참여자·옵션·요율 세 영역 모두 같은 상품 응답에서 나온다새로고침 버튼을 눌러 목록을 다시 받아야 값이 갱신됨확정
계산요율 표시값 환산
채권매입·시스템이용료
저장값을 100으로 나눠 %로 표시.예: 저장 60 → 화면 0.6% / 저장 20 → 0.2%워크스루에 적힌 '서버값 그대로'는 부정확 — 실제로는 100으로 나눈 값확정
이체수수료
저장값을 그대로 원(₩) 단위로 표시(나누지 않음).예: 저장 300 → 300원확정
실제 요율 수치
화면은 서버가 준 숫자를 환산만 해서 보여줄 뿐, 어떤 요율이 맞는지는 화면이 정하지 않음.정책상 확정 수수료율(1%/0.604%/0.25% 등 병존, C1)은 미확정 → 개발/서버 확인 필요확인필요
정책옵션 칩 구성·납부자 라벨
일반 상품의 옵션 구성
이 펼침에 뜨는 옵션 칩은 일반 유형 기준으로이체수수료(원) 금액 칩수취 토글 4종: 하위파트너·상위파트너 이체료 수취 / 하위파트너·상위파트너 시스템료 수취납부 칩 2종: 시스템이용료 납부 · 이체수수료 납부(다우 유형의 상위/하위영업 옵션은 나오지 않음)확정
납부자 라벨 유형 분기
납부 칩의 납부자 표기는 상품 유형에 따라 다른 말로 번역된다.일반 상품: 상위 납부=상위파트너 납부, 하위 납부=하위파트너 납부(다우였다면 같은 값이 상위영업/하위영업 납부로 표기)납부자 지정이 없으면 회색 가맹점 부담확정
6개념 구분
여기 '이체수수료'는 이체 실행에 드는 수수료(비용) 항목이다.가맹점이 즉시 받는 바로이체나 과지급 회수와는 무관 — 혼동 금지확정
옵션 칩 렌더 방식
패널은 서버가 준 옵션 키를 준 순서대로 칩으로 나열한다.값 형태로 표기가 갈림: 숫자=노란 금액 칩 / 참거짓=초록 ON·빨강 OFF / 납부자=파랑 또는 회색가설
