정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
직접 지정 토글을 켠 상태의 특수 로직은 화면 워크스루(토글·기본값·검증없음)에 이미 정리돼 있어, 여기서는 그 뒤편의 값 변환·전송·서버 처리 규칙만 보강한다. 화면에서 고른 시작/종료 일시는 사용자 PC의 로컬 시각으로 읽혀 세계표준시(UTC)로 바꿔 로그 조회 요청에 실린다. 종료를 비우면 종료 자체가 요청에서 빠져(서버가 열린 구간으로 해석), 시작을 비우면 직접 지정을 켰더라도 무시되고 마지막에 눌러둔 프리셋 기간으로 조회된다. 화면 어디에도 조회 기간 상한이 없어 임의로 긴 구간도 그대로 서버에 전달된다. 이 화면은 로그 모니터링용 조회 범위 지정일 뿐이며 6대 정산 개념(미지급금·선정산 제외금액·바로이체·과지급·미회수금·환급) 및 매출 회수 스윕과는 무관하다.
계산입력한 일시가 서버로 넘어가는 방식
시각 해석 기준(타임존)
화면의 시작·종료 일시 입력은 보는 사람 PC의 로컬 시각으로 읽힌 뒤, 전송 직전 세계표준시(UTC)로 환산되어 요청에 실림한국에서 "오후 8시"로 넣으면 서버에는 "오전 11시(UTC)"로 전달됨해외/타임존 다른 PC에서 접속하면 같은 입력이라도 실제 조회 구간이 달라짐(개발 확인 필요)확정
전달되는 값
질문 문구 + 시작시각 + 종료시각을 로그 조회 요청에 함께 실어 보냄조회 결과(조회 건수·실제 적용된 시작~종료·원본 로그·생성된 조회식)는 서버가 되돌려 화면 상단 메타줄에 표시확정
조회 기간 상한
화면에는 최대 기간 제한이 없음 — 몇 달·몇 년짜리 구간도 그대로 요청됨실제로 얼마나 스캔·응답하는지는 서버가 결정(과도한 구간 컷/타임아웃 여부)확인필요
정책빈칸·비정상 입력의 실제 처리
종료를 비웠을 때
종료 일시 자체가 요청에서 아예 빠짐(빈 종료가 아니라 종료 키 미포함)"지금까지"로 볼지, 시작만으로 어디까지 볼지는 서버 해석에 위임(개발 확인 필요)확인필요
시작을 비웠을 때
직접 지정을 켰어도 시작이 비면 이 구간이 통째로 무시되고 프리셋 방식으로 되돌아가 조회됨이때 적용되는 건 "1시간 고정"이 아니라 가장 마지막에 눌러둔 프리셋(직접 지정 켜기 전 상태). 아무것도 안 골랐으면 1시간화면상 프리셋 버튼은 숨어 있어 사용자는 어떤 기간으로 조회됐는지 알기 어려움가설
시작>종료 등 뒤집힌 구간
화면에서 막지 않고 그대로 전송 — 결과 0건 또는 오류 여부는 서버 몫잘못된 구간에 대한 경고/토스트 문구 없음확정
