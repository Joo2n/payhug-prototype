결과		 [취소] · [삭제](빨강)성공 → 토스트 "○○ 상품이 삭제되었습니다." + 목록 새로고침실패(배정 존재 등) → 서버 메시지 또는 "삭제에 실패했습니다." / "삭제 중 오류가 발생했습니다."
정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
정산 상품 목록에서 [삭제]를 누르면 뜨는 '완전 삭제' 확인창. 같은 목록의 [비활성화]와는 별개 동작으로, 삭제는 되돌릴 수 없고 배정 가맹점이 있으면 서버가 막는다. 화면단에는 배정 여부를 사전 판별하는 로직이 없어 성공/실패는 전적으로 서버 응답에 달려 있으며, 실패 사유는 서버 메시지를 그대로 노출한다.
정책삭제 vs 비활성화 — 두 갈래 처리
[삭제]와 [비활성화]는 다른 동작
같은 목록 행에 [비활성화](주황)와 [삭제](빨강)가 나란히 있고, 각각 별도의 확인창을 띄운다.비활성화: 되돌릴 수 있는 '끄기', 삭제: 되돌릴 수 없는 '완전 제거'확정
비활성화의 의미
확인창 문구가 "배정된 가맹점 이력은 유지되며, 신규 배정만 불가능해집니다".기존에 이 상품을 쓰던 가맹점은 그대로 두고, 앞으로 새로 붙이지만 못하게 하는 것확정
완전 삭제의 의미
확인창 문구가 "이 작업은 되돌릴 수 없습니다" + "배정된 가맹점이 있으면 삭제할 수 없습니다".즉 배정 이력이 하나도 없는 상품만 지울 수 있다는 전제확정
확인 버튼 색·라벨 차이
비활성화 창은 경고(주황) 스타일 + [비활성화] 버튼, 삭제 창은 위험(빨강) 스타일 + [삭제] 버튼으로 시각적 위험도를 구분확정
삭제 후 복구 수단
화면상 복구/휴지통 기능 없음. 문구도 '되돌릴 수 없음'을 명시.서버에 소프트 삭제(표시만 숨김) 여부가 있는지는 화면에서 알 수 없음확인필요
연결배정 가맹점 검증 — 서버 전담
삭제 가능 여부 판별 위치
화면에는 배정 가맹점 수를 미리 세거나 [삭제] 버튼을 잠그는 로직이 전혀 없다. 어떤 상품이든 버튼이 항상 눌리고 확인창이 뜬다.'배정 있으면 불가'는 순수하게 서버가 판단확정
삭제 요청 방식
확인창에서 [삭제]를 누르면 해당 상품 ID로 삭제 요청을 보내고 응답을 기다린다(선차감/미리보기 없음)확정
실제 강제 여부
설계 노트에 '실제 강제 여부 개발 확인 필요'로 표기됨. 서버가 정말 배정 존재 시 거부하는지, 어떤 조건(활성 배정만? 과거 이력 포함?)으로 막는지는 서버 규칙확인필요
배정 이력의 범위
'배정 가맹점'이 현재 유효 배정만인지, 만료·해지된 과거 배정까지 포함인지 화면 문구만으로는 불명확확인필요
데이터성공·실패 결과 처리
성공 시
토스트 "○○ 상품이 삭제되었습니다." 노출 후 목록을 다시 불러와 해당 행이 사라짐확정
실패 시(배정 존재 등)
서버가 내려준 안내 메시지를 그대로 붉은 토스트로 노출. 서버 메시지가 없으면 기본 문구 "삭제에 실패했습니다."확정
통신 자체 오류 시
요청이 끊기거나 예외가 나면 "삭제 중 오류가 발생했습니다." 별도 문구 노출확정
실패 사유 안내의 구체성
'배정 N개 때문에 삭제 불가' 같은 구체 사유는 서버 메시지에 담겨야만 사용자에게 보임. 화면은 사유를 자체 생성하지 않음가설
