수동 매출 등록 모달의 '카드 매입' 탭. 카드 승인 건이 실제로 매입 확정된 사실(확정 수수료 포함)을 운영자가 손으로 넣는 화면이다. 승인 탭과 달리 '실제 수수료 합계' 입력이 필수이며, 이 값이 나중에 원장의 정산적용수수료와 대조돼 '차액'을 만든다. 매입일자·지급예정일은 선택 입력이고, 저장 시 매입(PURCHASE) 유형으로 서버에 전송된다.
설정카드 매입 탭에서만 나타나는 입력
실제 수수료 합계 (필수)
이 탭에만 있는 필수 항목. 카드사가 실제로 떼어간 확정 수수료 금액을 운영자가 직접 입력.승인 탭에는 없음비워두면 "수수료를 입력해주세요" 경고로 저장 차단확정
매입일자 (선택)
카드사가 매입 처리한 날짜. 비워도 저장됨(선택 입력).원장 목록에서 카드 건은 이 매입일자를 '매입일' 컬럼에 노출확정
지급예정일 (선택)
매입 대금이 들어올 예정일. 비워도 저장됨(선택 입력).확정
라벨이 바뀌는 공통 항목
같은 입력칸이지만 탭에 따라 이름이 달라짐.승인번호 → 카드 매입에서도 '승인번호'금액칸은 승인 탭 '매출금액' → 매입 탭에선 '매입금액'으로 표기확정
카드사·결제수단
카드사 10종 목록(신한·KB국민·삼성·현대·롯데·하나·BC·농협NH·우리·씨티) 선택, 결제수단은 신용/체크. 승인 탭과 동일하게 공통 노출.확정
가맹점번호(merNo)
화면에 별도 입력칸은 없이 payload에 선택값으로만 실려 감(값 있으면 전송, 없으면 생략). UI 노출 여부 확인필요.확인필요
연결저장 동작·전송 규칙
저장 유형 = 매입
저장 시 '카드 / 매입' 유형으로 표시해 서버에 전송. 승인 탭(승인 유형)과 구분되는 별개 데이터.확정
검증 순서
① 승인번호·거래일자·금액(공통 필수) 누락 시 "필수 항목을 모두 입력해주세요"② 통과 후 실제 수수료 누락 시 "수수료를 입력해주세요"두 관문을 모두 넘어야 전송확정
전송 목적지
단건 등록 전용 저장 경로로 1건 전송. 성공 응답이면 모달 닫고 목록 새로고침, 실패면 서버 메시지 그대로 노출.확정
저장 후 원장 반영
등록된 매입 건은 원장에서 매입상태 '매입완료'로 잡히고, 정산적용수수료·실제수수료·차액 컬럼이 채워짐.가설
계산실제 수수료 → 차액 연결
이 입력값의 쓰임
여기 넣는 실제 수수료가 원장에서 이미 잡혀 있던 정산적용수수료(예상/정산 기준 수수료)와 대조되는 기준값이 됨. 카드 매입 탭 입력의 최종 목적.확정
차액의 방향
정산적용수수료에서 실제 수수료를 뺀 값이 '차액'.원장은 매입완료 건에 대해서만 차액을 계산·표시차액이 0이 아니면 '대기', 0이면 '차액없음'으로 상태 표기확정
차액 산출의 실제 계산
예상값·실지급값 대조와 최종 차액 확정은 서버 몫. 이 모달은 실제 수수료를 넘길 뿐, 확정 수수료율(C1)·예상 차액 정의(C4)에 걸린 부분은 서버 확인필요.확인필요
6대 개념 경계
여기서 생기는 '차액'은 카드 수수료 정산차액 개념. 과지급·미회수금 회수(정책)나 매출 회수(락→모계좌 스윕)와 혼동 금지.확정
