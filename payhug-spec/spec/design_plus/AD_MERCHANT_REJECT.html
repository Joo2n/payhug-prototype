가맹점 관리 목록에서 계약상태 '반려'만 걸러본 상태. 필터는 이미 받아온 목록을 화면단에서만 걸러내고 서버에 다시 묻지 않는다. 반려 자체는 이 목록 화면이 아니라 가맹점 상세에서 사유를 적어 처리하며, 반려된 가맹점은 상세에서 '계약 프로세스 초기화'(전체 데이터 영구 삭제 후 재계약)만 가능하다. 반려는 데이터를 지우지 않고 상태만 바꾸는 '보존형' 처리라는 점이 핵심이다.
연결반려 필터 동작
필터 적용 방식
이미 받아온 전체 목록을 화면 안에서만 걸러냄반려 탭을 눌러도 서버에 다시 조회하지 않는다검색어(가맹점명·사업자번호·대표자명·사용자명)와 반려 상태를 동시에 만족하는 행만 남김확정
탭 옆 건수
받아온 전체 목록 중 계약상태가 반려인 가맹점 수를 그 자리에서 센 값목록을 새로 열거나 다른 탭을 다녀오면 다시 계산됨확정
정렬
반려 가맹점은 계약 승인 + 정산 활성, 계약 승인 그룹 다음의 최하위 그룹으로 밀려 내려감(그 외로 취급)확정
행 클릭
반려 상태여도 상세 진입 가능마우스 올림 시 액션 라벨은 '관리'(심사대기만 '심사', 미등록만 '상세')확정
정책반려 처리 규칙 (상세 화면에서 수행)
처리 위치
이 목록 화면에는 반려 버튼이 없음. 반려는 가맹점 상세에서만 수행이미 반려된 가맹점 상세에서는 반려 버튼이 숨겨짐(중복 반려 불가)확정
반려 사유 입력
필수. 사유가 비어 있으면 '반려 확정' 버튼이 눌리지 않음입력한 사유는 상세 상단 '반려 사유'로 그대로 노출됨확정
반려 = 데이터 보존
반려는 상태만 변경, 서류·매출·정산·계좌 데이터는 모두 보존삭제가 필요하면 별도의 '계약 초기화'를 쓰라고 안내확정
승인건 반려 시 경고
승인 상태를 반려로 되돌리면 서비스가 중단된다는 경고 문구가 뜸심사대기건 반려 시에는 '데이터 보존' 안내 문구가 뜸(같은 모달, 다른 문구)확정
반려 후 안내
상세 상단에 '반려 처리된 가맹점 · 정보 수정 후 재심사 필요' 배너 노출확정
데이터반려 상태의 표시·후속 조치
계약 진행 막대
반려돼도 진행 막대(예: 3/6)는 반려 시점 그대로 유지막대는 주황(미완료 색), 정산은 비활성(회색)으로 표시확정
계약 프로세스 초기화
반려 가맹점 상세에서만 제공되는 후속 조치사업자정보·계약서(서명)·약관동의·계좌·신분증·첨부파일(원본 저장분 포함)을 영구 삭제삭제 후 가맹점이 처음부터 재계약하도록 되돌림확정
초기화 후 이동
초기화 성공 시 현재 상세 탭을 닫고 가맹점 관리 목록으로 되돌아감확정
반려 사유 노출 대상
운영자가 입력한 사유가 가맹점에게도 노출되는지(내부용/가맹점용 구분) 코드만으로는 불명확인필요
