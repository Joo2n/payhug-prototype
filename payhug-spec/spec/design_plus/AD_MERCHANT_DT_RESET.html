정책 · 계산 로직 · 데이터 출처 코드 기반 심화 · 확정 / 가설 / 확인필요 표기
가맹점 로그인 비밀번호를 관리자가 직접 새 값으로 덮어쓰는 모달. 특수점은 (1) 유일한 활성화 조건이 '4자 이상'뿐이고 형식·복잡도·확인재입력·최대길이 규칙이 전혀 없다는 것, (2) 대상 식별은 화면의 상호명이지만 실제 초기화 요청은 가맹점 ID 기준으로 나간다는 것, (3) 문자·이메일 자동 발송이 없어 새 비밀번호 전달을 관리자 구두 안내에 맡긴다는 것. 같은 화면의 계약 초기화·하드리셋과는 별개 동작이다.
설정입력 규칙 (이 모달 특수)
버튼 활성 조건
새 비밀번호가 4자 이상일 때만 [비밀번호 초기화] 버튼 활성화.4자 미만이면 회색 비활성 (오타·빈칸 방지 정도의 최소 가드)확정
없는 규칙
이 모달에는 형식 검사·복잡도(영문/숫자/특수문자)·최대 길이·확인용 재입력 칸이 전혀 없다.관리자가 넣은 값이 그대로 새 비밀번호가 됨확정
입력창
단일 텍스트 입력칸 1개, 안내문구 "새 비밀번호를 입력하세요".처리 중에는 버튼이 "처리 중..."으로 바뀌며 중복 클릭 차단확정
실제 유효성·저장
입력값의 최종 형식 검증·중복 여부·암호화 저장은 서버가 담당.화면 규칙(4자)과 서버 규칙이 같은지는 화면만으로 알 수 없음확인필요
연결대상과 처리 경로
대상 식별
모달 문구는 화면에 잡힌 상호명으로 "{상호명} 가맹점의 비밀번호를 초기화합니다" 표시.눈으로 보는 건 상호명이지만…확정
실제 초기화 기준
요청은 가맹점 단위 식별값(가맹점 ID) 기준으로 전송된다.같은 화면의 '하드리셋'이 사용자 계정 기준인 것과 대비됨 (초기화 범위가 다름)확정
성공/실패 처리
성공 시 "비밀번호가 초기화되었습니다" 알림 후 모달 닫힘·입력값 비움.실패 시 서버 메시지 또는 "비밀번호 초기화에 실패했습니다", 통신 오류는 별도 문구확정
권한
관리자·파트너 공통으로 노출되는 것으로 보임(버튼이 상세 상단에 상시 노출).파트너에게도 동일 권한을 줄지는 운영 정책 확인 필요확인필요
정책운영 안내 정책
전달 방식
새 비밀번호를 가맹점주에게 자동 발송(문자·이메일)하지 않는다.안내문 "가맹점주에게 새 비밀번호를 안내해 주세요"로 관리자 구두 전달에 의존확정
변경 유도
안내문에 "로그인 후 직접 변경하도록 권장합니다" 명시.임시 비밀번호 성격이지 강제 변경 로직은 화면에 없음가설
다른 초기화와 구분
이 모달은 로그인 비밀번호만 바꾼다.같은 상세의 '계약 초기화', '하드리셋'과는 완전히 별개 동작 — 데이터 삭제 아님확정
