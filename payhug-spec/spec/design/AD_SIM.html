key note
화면 성격  정책·거래를 가상 입력해 원장·배분 결과를 미리 계산하는 내부 시뮬레이터 — 실제 정산 아님, 저장하지 않음 데이터  정책 목록만 서버 조회(정산 상품관리와 동일 목록), 계산·배분은 실행 시 서버가 수행 (목업 아님·실계산). 캡처는 실행 전 초기 상태 — 결과 영역 비어 있음 진입하면 정책 목록을 자동으로 불러옴 (진입 1회, 탭·포커스 복귀 재조회 없음)
No이름설명
1헤더 제목 "정산 시뮬레이션" + 안내문안내문 : "거래 건을 입력하면 DB 저장 없이 원장과 배분 결과를 미리 확인할 수 있습니다."계산·배분은 서버가 수행하고 결과를 DB에 저장하지 않음 (검토용 미리보기)
2정책
선택		 카드 정책 · 배달 정책 두 개 드롭다운기본값 default : 둘 다 "선택 안 함"옵션은 등록된 정책을 [규칙유형] 정책명 (ID: N) 형식으로 나열 (원문 그대로)등록 정책이 0개면 드롭다운에 "선택 안 함"만 남음진입 시 정책 목록 자동 로드불러오기 실패 → No.4 아래 공통 오류 박스(빨강)에 "정책 목록을 불러올 수 없습니다" — 드롭다운 옆이 아니라 실행 버튼 아래 박스에 표시카드·배달 정책 둘 다 미선택이면 No.4 [시뮬레이션 실행] 버튼 비활성 (최소 1개 선택 필요)
3거래
입력		 소제목 "거래 입력" 우측에 [+ 거래 추가] 버튼거래 행 구성순번 · 유형(카드 / 배달 2종만) · 금액 · "원" · [삭제]기본값 default : 1행 (카드 · 20,000원)[+ 거래 추가] 누르면 카드 · 20,000원 행이 아래에 추가됨순번은 위에서부터 다시 매겨짐[삭제]는 2건 이상일 때만 각 행에 노출 (마지막 1건은 삭제 불가) → 다건 상태 [AD_SIM_MULTI]금액 입력입력창 안내문 : "금액" · 숫자 입력창 (기본 20,000이라 안내문은 값 비웠을 때만 보임)최소·최대·음수·필수 검증이 코드에 없음 — 입력값 유효성 개발 확인 필요하단 합계"총 N건, 합계 X원" — 입력 즉시 반영 · 천단위 [,] 콤마 표기
4실행
버튼		 전체폭 [시뮬레이션 실행] 버튼계산 중엔 라벨이 "계산 중..." 으로 바뀌고 비활성카드·배달 정책 둘 다 미선택이거나 계산 중이면 회색 비활성 (캡처가 이 상태)실패 시 버튼 아래 공통 오류 박스(빨강) 노출 — 정책 로드 실패도 여기에 표시서버 메시지 우선, 없으면 "시뮬레이션 실패" / 통신 오류 시 "네트워크 오류"
5실행
결과		 실행 전엔 비어 있음 → 실행하면 버튼 아래에 결과가 펼쳐짐 (캡처엔 미표시)정산 요약 카드 4개총 거래금액 · 거래 건수 · 총 수수료 (가맹점 부담) · 가맹점 지급액(남보라 강조)총 수수료 카드 하단 부과 내역 : "부과: 채권매입 … · 시스템 … · 이체 …"이어지는 결과 카드 순서① 건별 원장 카드 — 카드 안에 MARGIN(채권매입)·SYSTEM_FEE(시스템) 원장 표② SYSTEM_FEE 건별 합산 카드 (합산 대상 있을 때만)③ TRANSFER_FEE 배치당 1회 카드④ 이해관계자 배분 요약 표 (항목·뱃지 상세는 [AD_SIM_MULTI])수수료·배분액은 서버가 선택 정책으로 계산하고 화면은 표시만 함 — 수수료율 산정 근거 미확정(TBD)
