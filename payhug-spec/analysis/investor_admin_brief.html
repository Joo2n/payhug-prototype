00 / Summary

한눈에 보기

결론부터: 투자자 어드민은 화면·와이어프레임 차원에서 완전 신규 작업이다. 다만 로그인·권한 인프라는 이미 기존 어드민이 투자자(INVESTOR)를 참여자로 절반쯤 받아들이고 있어서, 별도 포털이 아니라 기존 어드민 안의 신규 role-view로 붙이는 쪽이 유리해 보인다. 단 하나, 투자자에게 실제로 얼마를 어떻게 배분하는지(보상 산식) 자체가 문서마다 다르게 나온다 — 이게 정해지지 않으면 "계산식 노출" 화면은 뭘 보여줄지부터 못 정한다.

발견 1

스토리보드 17장 = 16개 화면/기능, GNB 7메뉴(투자자산·투자수익·쿠콘 관리현금·가맹점·정산채권양수·계약기록·비밀번호변경) 고정 구조. 산식 자체보다 산식이 반영된 결과표+엑셀/증명서 다운로드가 핵심 요구.

발견 2

플로우차트는 사용자 우려대로 실제 문제가 있다 — 분기 6곳 전부 "성공 시"만 있고 "실패 시" 경로가 하나도 없으며, 슬라이드 간 연결이 화살표가 아니라 텍스트 참조뿐이다.

발견 3

기존 코드에 재사용 가능한 부품이 이미 많다 — 엑셀 다운로드 공용 유틸, 참여자별 배분 원장 테이블, 계산식 문구 상수, 가로수식 컴포넌트까지.

발견 4

투자자 보상 산식이 정책서 안에서도 두 갈래다 — 매출 대비 0.11% 배분과, 원금 대비 연 12% 대출이자. 어느 쪽을 화면에 보여줄지는 서비스 정책 결정이 먼저 필요하다.

로그인 화면(슬라이드2)과 투자수익 화면(슬라이드7)에는 실제 목업 대신 기존 화면 스크린샷이 붙어 있다. 로그인은 기존 가맹점 앱 로그인 플로우 3장, 투자수익은 실제 PayHug Admin admin.payhug.co.kr/profit/list "수익 > 전체 수익" 화면 캡처다. 즉 작성자가 이미 "기존 화면을 베이스로 만든다"는 의도를 스토리보드 안에 스스로 남겨둔 셈 — 이번 재설계 방향과 정확히 일치한다.

원본에서 그대로 넘어온 사소한 결함 4가지

재설계 시 그대로 베끼지 않도록 표시해 둔다.

1

기준일 불일치 — 메인 화면의 "가맹점별 투자자산" 표는 기준일 2025.9.14, 같은 표의 다운로드 화면(슬라이드5)에서는 2025.9.15로 하루 어긋난다.

2

PPT 편집기 스크린샷 오삽입 — 슬라이드14에 실제 UI가 아니라 PowerPoint 편집 화면 자체가 캡처되어 끼어 있다.

3

비밀번호 확인란 라벨 미분리 — 슬라이드17에서 새 비밀번호 입력·재입력 필드 라벨이 둘 다 "새로 등록할 비밀번호"로 동일하다.

4

장식 이미지 반복 삽입 — 여러 슬라이드 좌상단에 가맹점 앱 로그인 스크린샷 1장이 내용과 무관하게 반복 붙어 있다(작업 중 잔존물로 추정).

02 / 플로우차트_투자자 UI_V1.3.pptx · 13슬라이드

플로우가 정말 맞는지

결론부터: "맞는지 확신이 없다"는 감이 맞았다. 이 파일은 화살표로 이어진 플로우차트라기보다, 번호가 매겨진 처리단계를 세로로 나열한 스펙 목록에 스윔레인 흔적만 남은 형태다. Keynote로 이미지 렌더링을 시도했으나 타임아웃되어, 대신 도형·커넥터 XML을 전부 파싱해 실제 연결 관계를 그래프로 재구성했다 — 즉 아래 내용은 추측이 아니라 도형 데이터 그대로다.

13슬라이드는 하나로 이어진 플로우가 아니라 허브(로그인 성공 후 투자자산 메인)에서 8개 메뉴로 갈라지는 구조다. 이 연결선 대부분은 PPT 안에 실제로 그려진 화살표가 아니라, 본문 문구("861화면에서 11번 버튼 선택")로만 확인된다.

⚠ 분기 6곳, "실패 시" 경로가 전부 없다

로그인 일치 확인(×2), 증명서 서명검증 성공 여부, 정산채권 양수 서명 검증 여부, 비밀번호 변경 일치 확인(×2) — 6개 분기 다이아몬드 전부 "Yes"만 있고 "No"/실패 경로가 파일 전체에 단 하나도 없다. 같은 틀을 복사하면서 매번 실패 분기 연결을 빠뜨린 것으로 보인다. 재설계 시 이 6곳의 실패 처리(에러 메시지·재시도·잠금 등)는 새로 정의해야 한다.

그 밖에 눈에 띄는 결함

·

슬라이드8 제목 오타 — 내용은 투자수익(③) 엑셀 다운로드인데 제목엔 "②투자수익"으로 표기됨.

·

슬라이드7 단계번호 중복 — 937·944·946·947·948번이 각 슬라이드 안에서 서로 다른 계산에 중복 사용되어, 계산 순서를 코드로 옮길 때 특히 주의가 필요.

·

정산채권 양수(슬라이드11) 흐름 단절 — "가맹점명 리스트 출력" 다음 화살표가 정식 다음 단계가 아니라 번호 없는 메모("사전 구두합의와 상이한 점 검토")로 향해 있음. 이 메모가 실제 처리단계인지 주석인지 불명확.

기존 어드민에 무엇이 이미 있는가

레포 /Users/semi/cursor/payhug-admin-web(HEAD f79997b, 8/25) 기준. 흥미롭게도 투자자(INVESTOR)는 이미 이 어드민에 로그인할 수 있는 계정 유형이다 — 다만 지금은 파트너·총판과 뭉뚱그려진 축소 메뉴 4개짜리 뷰만 보인다.

확정 로그인·권한 판정(lib/permissions.ts)이 이미 INVESTOR를 isPartnerUser로 받아들이고 있어, 새 포털을 만들면 인증 체계를 중복 구축하게 된다. 반면 세분화된 role enum 분기는 없어서(전부 불리언 2종) 투자자 전용 메뉴를 새로 넣으려면 최소 isInvestorUser() 헬퍼 하나는 신설해야 한다. 권한 가드가 메뉴·탭·필드 3층위로 이미 존재하는 컨벤션이라, 이 틀에 맞추는 편이 자연스럽다.

단, 프론트가 방어선이 될 수 없다

서버사이드 middleware.ts가 없고 라우트 보호가 전부 클라이언트 useEffect 기반이다. 원가·타 파트너 마진처럼 투자자에게 절대 보이면 안 되는 값이 있다면, 그 마스킹은 화면 조건부 렌더가 아니라 백엔드 API 응답 자체에서 제외되어야 한다.

04 / payhug-spec 정책서 대조

산식을 보여주기 전에 걸리는 것들

"계산식 노출"이 이번 기획의 핵심 요구인데, 정작 03_SETTLEMENT_LOGIC.md(정책서 본체)에는 "투자자"라는 단어가 한 번도 나오지 않는다. 투자자 배분 구조는 전부 아카이브·Figma 역분석 쪽에서만 나온다.

최우선 · 확인 필요

투자자에게 얼마를 어떻게 주는지가, 산식이 두 개다

독립된 출처에서 서로 다른 두 가지 투자자 보상 모델이 나온다. 동시 적용인지 택일인지는 어디에도 명시돼 있지 않다.

모델 A · 매출 배분형
투자자 몫 = 채권매입수수료 × 0.11%

3개 독립 출처(총판등록수수료 시트·VAT계산방식 시트·Figma 요율표)에서 반복 확인. VAT 면제. 가설 — "확정"은 아니고 "가장 자주 등장하는 값".

vs
모델 B · 대출 이자형
투자자 차입 = 대출차입금 × 연12% × 사용일수/365

Figma "자금조달(대출) 이자 정산"(1442:8879)에 별도 산식·전용 어드민 기능(정산 버튼·인터넷뱅킹 자동발송)까지 설계되어 있음. 확인필요

계산식 노출 화면을 설계하려면 이 중 무엇을(혹은 둘 다를 어떻게 함께) 보여줄지부터 정해야 한다. 이건 서비스 정책 결정이라 이 리서치 단계에서 임의로 택하지 않았다.

그 밖의 확인 필요 항목

?

C1 수수료율 자체가 미확정 — 최소 5개 버전이 병존한다. 0.11%는 그 중 한 세트 안의 값일 뿐이라, 상위 총요율이 안 정해진 채로는 "0.11%가 전체의 몇 %인지"조차 흔들린다.

"투자자 없음" 케이스 — 모든 가맹점에 투자자가 매칭돼 있다고 가정하면 안 된다. 명시적으로 투자자 없이 승인되는 경로가 정책상 허용된다.

✓

용어 이중화 — 같은 실체가 어드민에서는 "투자자", 계약서에서는 "유동화기관"으로 불린다. 화면 문구 통일이 필요.

✓

알려진 투자자 실례 = ㈜스페이스서비스 1개 법인. 이 상호는 "고객센터 노출 금지" 내부 전용 명단에 등재돼 있다 — 화면 문구 설계 시 참고.

✓

정산 주기 — 투자자 수익금은 월 1회 정산. 총판(20일)과 같은 날짜인지는 확인 필요.

쿠콘은 "투자자"와 다른 개념

쿠콘은 이체(펌뱅킹·오픈뱅킹) 실행 벤더 — 락계좌↔모계좌 자금 이동을 처리하는 제3자 기술 파트너다. "투자자"(자금 공급자)와 문서상 교차되는 지점은 없었다. 스토리보드의 We-bank 링크는 이 쿠콘 관리자 콘솔로 그대로 이동시키면 된다는 뜻으로 읽힌다.

"투자자 어드민"이라는 이름 자체는 씨앗이 있었다

2025.10 최초 기획 흐름도(Figma 774:812)에 이미 "실사용자: 관리자 어드민, 투자자 어드민"이라는 행위자 표기가 있다. 다만 와이어프레임·설계 실체는 전무 — 이번이 사실상 첫 착수다.
