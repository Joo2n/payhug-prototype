## 3. 확정 — 3단계 수수료 구조와 부과 단위 (1442:8836)

원문 파이프라인:

```
[infotech API] ──(주기적 수집)──▶ unified_purchase_ledger
        │  bizNo → user_businesses.businessNumber → users.id (merchantId)
        │  salesSource → txType 매핑 (CARD=CARD, BM/YO/CPE=DELIVERY)
        │  netPayoutAmt = 승인금액 − 원천수수료 = 정산 대상 금액
        ▼
   transactions (purchase_ledger_id로 원본 연결)
        │
   [1단계 MARGIN]      [2단계 SYSTEM_FEE]
    건별 정산 원장       건별 정산 원장
        │                   │
        └──── 하루치 거래 마감 ────┘
                 │
        [3단계 TRANSFER_FEE]  → settlement_batches
         배치당 1회 정산 원장
                 │
        settlement_payouts (배분 집계) "누구에게 얼마를 이체할지"
                 │
        [실제 이체 실행] status: PENDING → TRANSFERRED
```

테이블 역할 정의 (원문 표):

| 테이블 | 역할 | 상태의 의미 |
|---|---|---|
| unified_purchase_ledger | 매출 원장 — 외부(카드사/배달앱)에서 가져온 원천 거래 데이터 | 이 건이 정산 처리 흐름에 진입했는지 여부 |
| transactions | 정산 계산의 기준 거래 단위 | — |
| settlement_ledgers | 참여자별 원장 (MARGIN, SYSTEM_FEE, TRANSFER_FEE) | — |
| settlement_batches | 배치 마감 단위 | — |
| settlement_payouts | 최종 배분 집계 → 실제 이체 대상 | PENDING → TRANSFERRED (이게 진짜 "지급") |

**확정 (출처: Figma 24:2079 > 계산식 모음 > 계산식 (1442:8836))**
- 수수료는 `MARGIN` / `SYSTEM_FEE` / `TRANSFER_FEE` 3종으로 코드 레벨에서 분리된다.
- `MARGIN`·`SYSTEM_FEE`는 **건별(건별 정산 원장)** 생성.
- `TRANSFER_FEE`는 **하루치 거래 마감 이후 배치당 1회** 생성.
- 실제 "지급"의 정의는 `settlement_payouts.status = TRANSFERRED`. 그 이전(PENDING)은 지급이 아니다 → 02의 `예상값/확정값/실제 지급값` 3분 구조와 매핑 가능.

**가설**: `MARGIN` = 페이허그 수수료(채권매입수수료), `SYSTEM_FEE` = 시스템이용료, `TRANSFER_FEE` = 전산 수수료(이체수수료). 명시적 매핑 표는 Figma에 없음 → `확인 필요`.

## 4. 확정 — 정산 대상 금액 정의 (1442:8837)

salesSource → txType 매핑:

| unified_purchase_ledger.salesSource | transactions.txType | 상품 유형 |
|---|---|---|
| CARD | CARD | 카드 정산 |
| BM (배민) | DELIVERY | 배달 정산 |
| YO (요기요) | DELIVERY | 배달 정산 |
| CPE (쿠팡이츠) | DELIVERY | 배달 정산 |

정산 대상 금액 (원문 그대로):

```
unified_purchase_ledger.totalSalesAmt    = 승인금액 (매출액)
unified_purchase_ledger.cardFeeAmt       = 원천사 수수료 (카드사/배달 플랫폼)
unified_purchase_ledger.deliveryFeeAmt   = 배달료
unified_purchase_ledger.netPayoutAmt     = 지급예정액 = 승인금액 − 수수료 − 배달료

transactions.txAmount = netPayoutAmt  (이 금액에 대해 채권매입수수료 부과)
```

**확정**: 채권매입수수료(MARGIN)의 **부과 기준금액은 `netPayoutAmt`(지급예정액)** 이지 승인금액이 아니다. 출처: Figma 24:2079 > 계산식 모음 > 계산식 (1442:8837).

**충돌**: 낱개 텍스트 `3336:111`은 "투자자 투자자 수익 0.11% **(매출액)**"이라 적어 기준금액을 매출액으로 표기. 또한 1-2 프레임 제목은 "가맹점 **원본 결제 대금** 20,000원 기준"이라 표현. 세 표현(지급예정액 / 매출액 / 원본 결제 대금)이 상충 → `확인 필요`.

- **충돌**: 2026-05-05 요율설정표(2222:1097)는 시스템이용료를 **페이허그 0.10% 단독**으로 두고 상위/하위 파트너는 "없음"으로 설정 → 가맹점 부담이 0.3%가 아니라 0.1%가 된다. 두 문서가 3배 차이. `확인 필요`.
