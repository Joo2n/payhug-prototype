## 7. 정책과 충돌하는 부분

1. **회수·추가지급의 단일 순액 합산 (핵심)**: `페이허그 -104,743원` = 예상 지급 차액 순액을 당일 지급액에서 즉시 차감하는 구조(488,086 = 253,935 + 338,894 − 104,743 − 0). 03 §6은 "추가 지급 필요 → 차기 지급 또는 바로이체", "초과 지급 → 회수건 생성"으로 **방향별 분리**를 요구하고, 02 §4는 과지급(발생액)과 미회수금(잔액)의 구분을 요구한다. 현 설계는 +차액(추가 지급)과 −차액(회수)을 하나의 순액으로 상계해 버려 **미지급금·과지급·미회수금·환급이 '예상 지급 차액' 하나에 흡수**된다. 6개 개념 분리 원칙과 충돌(확정).
2. **예상값 표시 부재**: 카드 `차감액`의 카드 수수료는 keynote상 "예상 카드 수수료"(확정)인데 화면 라벨에는 `예상` 표기가 없다. 02 §1의 예상 지급액/확정 지급액 구분이 UI에 없음 — 4번 질문("왜 달라졌나") 민원의 원인이 되는 구조.
3. **지급 상태·지급 시점 부재**: 03 §5(익일 11:30 지급)와 02 §5 지급 상태 11종이 화면 어디에도 상태값으로 존재하지 않음. `내역 반영 시간 11:30`은 데이터 갱신 시각이지 지급 완료 확인이 아님(가설: 입금 내역 존재 = 지급 완료로 갈음하는 설계).
4. **광고비 환급(+) 미분기**: 배민 상세의 `광고비`는 차감 단방향. 04 §1의 "우리가게클릭 특별프로모션 환급으로 순액이 +가 될 수 있음 → 부호별 분기" 요구가 반영 안 됨(확정). 수정안(3357:900)도 환급금을 −로 표기해 오히려 02 §3과 상충.
5. **음수 지급액 처리 미정의**: 만나서 결제 건 `미리 받는 돈 -898원`(건별 음수)은 표시되지만, 일 합산이 음수가 되는 경우(04 §2 가게배달 정산금 음수: 지급 전 차감/지급 후 회수건)의 화면 상태·문구가 없음.
6. **선정산 제외액의 지급 경로 서술**: "정산금은 기존 금액 그대로 이체돼요" + 입금자명 `페이허그` 14:30 입금(확정 표기). 제외 건이 언제·누구 명의로·어떤 주기로 입금되는지는 02/03에 정의가 없어 화면이 정책을 앞서감 — 확인 필요(특히 04 §6 바로이체와의 관계).
7. **더미 데이터 요일 오류(경미)**: 0원 상태 상세가 `26년 6월 13일 (목)` — 2026-06-13은 토요일. 메인 0원 변형은 연도 없이 `6월 13일 · 오늘`로 날짜 포맷도 keynote 규격(YY년 M월 DD일 (요일))과 불일치(확정).
8. **미매입 내역과 선정산 제외액의 관계 모호**: 두 화면 모두 합계 83,641원으로 동일 데이터의 다른 절단면으로 보이나(가설), 미매입 내역에는 `매입 완료` 건(13,796원)이 합계에 포함된 채 남아 있음. 매입 완료되면 언제 지급되는지(제외액 해소 흐름)가 화면 간에 연결되지 않음 — 확인 필요.

## 9. 수정 제안

1. **메인에 상태·시점 정보 추가**: `지급 상태`(지급 예정→지급 완료), `다음 지급 예정일(시각 포함, 오전 11:30)`, `최종 업데이트 일시`를 메인 카드에 노출. "오늘 얼마·언제·확정 여부"가 메인에서 끝나야 05 §1 원칙 충족.
2. **'예상 지급 차액'을 방향별로 분리**: 가맹점 라벨을 `더 받을 금액(추가 지급 예정)` / `다음 지급에서 조정될 금액(이전 지급 조정금액)` 두 항목으로 분리 표기하고, 합산 순액은 보조 정보로. 내부적으로도 과지급(발생)과 미회수금(잔액)을 화면 데이터 소스에서 구분 유지.
3. **용어 정비(05 §5 표 준수 + 확장)**: `선정산 제외액` → `이번 선정산 미반영 금액`, `전산 수수료` → `이체수수료`, `미매입` → `정산 확인 중`(또는 `매입 대기` 순화어). 아울러 `미리 받는 돈`(시제 통일), `페이허그 수수료`, `예상 지급 차액`의 확정 대체어를 05 §5 표에 정식 등재.
4. **예상/확정 구분 표기**: 지급 전 데이터에는 `예상` 프리픽스(예: `예상 카드 수수료`), 지급 완료 후에는 확정 표기. 미리 받는 돈 금액에도 산정 중/확정 뱃지를 부여해 02 §1의 예상 지급액/확정 지급액 구분을 UI로 구현.
5. **환급 항목 양방향 설계 확정 후 반영**: 광고비 행을 `광고비(차감)`과 `프로모션 환급(+)`으로 분리(04 §1 개발 필요사항). 수정안(3357:900)의 `환급금` 부호·위치(매출 하위 vs 차감 하위 vs 가산 섹션)를 02 §3 원칙(+, 추가 지급)에 맞게 확정.
6. **05 §6 상태 문구 세트 이식**: 메인/상세 공통 상태 배너 컴포넌트로 8종 문구(매출 수집 중, 일부 수집, 매입 지연, 지급 예정, 지급 완료, 추가 지급 예정, 이전 지급 조정, 선정산 미반영)를 정의. 현 `어제 매출액 집계중`을 이 세트로 편입.
7. **선정산 미반영 금액의 접근성 개선**: 미반영 금액이 있는 날은 메인·미리 받는 돈 상세에 요약 행(`이번 선정산 미반영 N원 - 확인하기`)을 추가. 계좌 입금 내역 라벨 경유 단일 진입은 발견성이 낮음. 미매입 내역 화면과 선정산 제외액 내역 화면의 관계(동일 데이터 여부)를 정리해 하나의 여정으로 통합.
8. **음수·실패 케이스 화면 추가**: 일 지급액 음수(지급 없음+차기 조정 안내), 지급 실패/재지급, 플랫폼 환급 미지급(수동이체 완료 안내) 상태 화면을 예외 플로우로 추가.
