## 0. 한 줄 결론

**담당 프레임 `2222:1108`은 사실상 빈 껍데기다.** 제목은 "중단 **및 해지**"인데 그려진 것은 중단 1개 노드뿐이고, **해지에 관한 플로우·절차·기한·잔여대금·재이용·통지가 단 하나도 그려져 있지 않다.**
반면 같은 캔버스에 **래스터 이미지로 첨부된 계약서(760:11, 760:45, 760:51)에는 중단 사유 11개와 해지 조항이 전문(全文)으로 존재한다.** 즉 정책의 실체는 계약서에만 있고 시스템 기획에는 반영되지 않은 상태다.

그리고 **현재 고객센터 본문은 계약서 제11조 제1항(가맹점의 임의 철회 금지)을 누락한 채 "신청하면 3영업일 내 해지"로만 안내하고 있어, 계약과 안내가 어긋난다.** 이것이 이번 검토의 최우선 수정 대상이다.

### 여기서 읽어낼 수 있는 것 (확정)
1. `확정` 선정산 중단은 **관리자 어드민이 토글로 수동 활성화**하는 방식이다. 자동 중단 트리거는 이 프레임에 없다.
2. `확정` 중단의 기술적 정의는 **"가맹점 락계좌 잔액 → 쿠콘 계좌로 출금 이체하는 거래의 중단"**이다. 즉 중단 = **집금(스윕) 중단**이지, 가맹점 지급 중단이라고 적혀 있지 않다.
3. `확인 필요` 위 메모는 도착지를 **`쿠콘 계좌`**라고 적었다. 전체_flow(503:2)와 어드민에서 쓰는 **`모계좌`(K뱅크 가상계좌)**와 같은 계좌인지 다른 계좌인지 이 프레임만으로는 판정 불가. → CLAUDE.md 원칙 6(어드민 '매출 회수' = 락계좌→모계좌 스윕)과의 용어 정합 확인 필요.
4. `확인 필요` **중단 시 가맹점에게 이미 지급된 선정산 대금(미회수 잔액)을 어떻게 처리하는지 이 프레임에 전혀 없다.** 집금만 멈추면 미회수 잔액이 회수되지 않고 고착되는데, 그 처리 경로가 설계되지 않았다.

### 여기에 **없는** 것 (설계 공백)
- 해지 플로우 (제목에 있으나 노드 0개)
- 중단 → 재개 경로
- 중단·해지 시 가맹점 통지(알림톡·앱 노출) 노드
- 중단 상태값(DB 필드) 정의 — 회원DB_가맹점(503:158)의 `영업상태(영업중/영업중단/폐업)`는 **가맹점 영업 상태**이지 선정산 중단 상태가 아니다. 선정산 중단 토글에 대응하는 상태 필드가 DB 설계에 없다. `확인 필요`
- 중단 사유 코드 / 사유별 분기

## 4. 중단 vs 해지 — 개념 구분 (본 검토의 핵심 산출)

| 구분 | 중단(중지) | 해지 |
|---|---|---|
| 근거 | 계약 제7조 / 운영메모 1071:597 / Figma 토글 2222:1114 | 계약 제11조, 제3조 / 양수도 제5조3 |
| 발동 주체 | **서비스제공사(관리자 어드민 토글)** | 가맹점 요청 또는 만료 자동연장 거절 |
| 사전 통보 | **불요** ("통보 없이") | 전자적메시지로 요청 |
| 계약 존속 | **존속** (일시 정지) | **종료** |
| 시스템 동작 | 락계좌 잔액 → 쿠콘 계좌 출금이체 거래 중단 (2222:1116) | **Figma에 설계 없음** |
| 원상복구 | 사유 해소 후 **가맹점이 재개 요청** | 재이용 조건 미정의 |
| 기한 | 없음 | 접수일로부터 3영업일 이내 처리 완료 |

`확정` **중단과 해지는 명백히 다른 절차다.** 그런데 Figma 프레임 제목이 둘을 하나로 묶어 놓고 중단만 그려 놓은 탓에, 설계상 해지가 중단의 일종처럼 취급될 위험이 있다.

## 7. 고객센터 반영 사항

대상 파일: `/Users/semi/cursor/payhug-support/content/settlement.html`, `faq.html`, `contract.html`

### 7-1. 🔴 최우선 — 해지 신청 자격을 잘못 안내 중
**현재 (contract.html 48행, settlement.html 205행)**
> "해지는 이메일·문자 등 전자적메시지로 신청하시면 접수일로부터 3영업일 이내에 처리돼요. 위약금은 없어요."

**문제**: 계약 제11조 **1항**이 통째로 빠졌다. 원문은 `"가맹점"은 계약기간 중 "서비스제공사"의 사전동의 없이 "페이허그서비스" 이용을 임의로 철회할 수 없다`이다. 지금 안내는 **가맹점이 언제든 자유롭게 해지할 수 있는 것처럼 읽힌다.** 실제로 신청했다가 거절당하면 분쟁 소지가 크다.

**수정 방향**: 3영업일 처리 문구 앞에 ①계약기간 중에는 원칙적으로 사전동의가 필요하다는 점, ②예외(서비스제공사의 계약 위반 / 이용 개시 전 / 서비스가 제대로 이루어지지 않을 때)는 철회 가능하다는 점, ③이용 개시 시점 = **전용계좌 등록 완료 시점**(제11조2)임을 명시.

### 7-2. 🔴 "위약금은 없어요" — 근거 없는 단정
contract.html 48행 / settlement.html 206행이 위약금 부재를 **단정**하고 있으나, Figma 첨부 계약서 어디에도 위약금 관련 조항이 확인되지 않았다. **조항이 없다는 사실**과 **위약금이 없다는 보증**은 다르다. 특히 §7-3의 잔액 변제 의무가 있으므로 "부담할 금액이 없다"는 표현은 오해를 부른다. → 근거 조항 확인 전까지 `확정 예정` 처리하거나, "별도의 위약금 조항은 없으나 잔여 선정산 대금은 변제해야 한다"로 정정.

### 7-3. 🟠 해지 시 잔여 대금 — 가맹점의 **변제 의무**를 안내하지 않음
settlement.html 205행은 "해지는 선정산 대금 회수가 완료되어야 가능해요"라고 **수동적**으로 서술한다. 그러나 양수도 제5조3의 실체는 **가맹점이 정산금채권 총 잔액을 변제해야 해지 요청권이 생긴다**는 능동적 의무다. → "잔여 선정산 대금(정산금채권 총 잔액)을 모두 변제하시면 해지를 요청하실 수 있어요"로 정정. 단 C-S1/C-S2 판본 확정 후 확정 문구 결정.

### 7-4. 🟠 중지 사유 — 11개 중 6개만, 그것도 부정확
settlement.html sec-1-3의 6개 항목은 계약 제7조 11개 중 5개(3·5·6·8·10호)만 반영. **누락**: 천재지변·국가비상사태(1호), 정전·설비장애·이용량 폭증(2호), 고의 정보 유포(4호), 대표자 명의 매출 등 비정상 거래 소명 불응(7호), 통지 규정 위반(9호), **아이디·비밀번호 분실·도용 통지 접수(11호)**.

### 7-5. 🟠 "통보 없이 중지" 사실 미고지

현재 settlement.html 33행·faq.html 147행은 "문의해 주세요"로만 안내. 계약 제7조 전문은 **가맹점이 사유를 해소한 뒤 서비스 재개를 요청**하는 구조다. 즉 **사유 해소가 선행 조건이고, 재개는 자동이 아니다**. → "중지 사유를 해소하신 뒤 재개를 요청해 주세요"로 절차를 명확히.

### 7-7. 🟡 재이용 조건 — `확정 예정` 유지가 맞음
