### F-T1. 미정산금 이중 정의 (Figma 내부 충돌) — 확정

| 출처 | 기준점 |
|---|---|
| 257:2417 | 예정된 **채권매입대금**보다 부족하게 입금 |
| 760:100 | **실제로 입금되어져야 할 금액**보다 적게 입금 |

기준점이 다르면 금액이 다르다. 채권매입대금은 선정산 지급액(수수료·선정산율 반영 후), 실제 입금되어야 할 금액은 정산주체가 지급할 총 정산금이다. 정상 케이스에서도 후자 > 전자이므로 **760:100 정의를 쓰면 상시 미정산금이 발생**한다. 단일화 필요.

### F-T2. 미수금액(257:2307) vs 미수금(760:103) — 확정

- `미수금액`: 발생 사유만 나열, **지급 전/후 구분 없음**
- `미수금`: "페이허그가 **선정산은 하였으나** … 당장 받지 못하게 될 금원" → 명시적으로 **지급 후**

CLAUDE.md 원칙 4(지급 전 음수=당일 차감 / 지급 후 음수=회수 검토)에 비추면 **`미수금`만이 미회수금 개념**이고 `미수금액`은 지급 전·후를 뭉갠 상위 개념이다. 두 용어를 같은 문서에 병존시키면 운영이 회수 판단을 못 한다.

### F-T3. 지정계좌 정의가 전용계좌 기능을 서술 — 확정

Figma `지정계좌` = "가맹점이 **정산주체로부터 정산금을 지급받는** 계좌"
고객센터 `전용계좌` = "카드사·배달앱이 지급하는 정산금을 받는" 계좌

**같은 기능을 서로 다른 이름으로 정의**하고 있다. 실제 운영 모델에서는 온보딩으로 지정계좌 슬롯을 전용계좌로 바꾸므로, 변경 완료 후 "정산주체로부터 정산금을 받는 계좌"는 곧 전용계좌다. Figma의 지정계좌 정의는 **변경 전 상태(가맹점 자기 계좌)와 변경 후 상태(전용계좌)를 구분하지 못한다.**

Figma 257:2296 + 257:2310 + 257:2325가 그리는 구조:

```
가맹점(양도인) → 채권매입업체(양수인) → 페이허그(재양수자) → 유동화기관(재양수)
```

고객센터 contract.html: "사장님이 … 받으실 정산금에 대한 권리(정산금 채권)를 **페이허그가 완전히 사 오는 방식**(양수도)이에요."

페이허그는 1차 양수인이 아니라 **재양수자**다. "페이허그가 사 온다"는 설명은 단계를 생략한 것으로, 채권의 실제 보유자가 누구인지(그리고 최종적으로 유동화기관으로 넘어간다는 사실)를 가린다. 대출이 아님을 설명하려는 의도는 타당하나, 사실관계 자체가 다르다.

### F-T5. 총판·유동화기관 정체 미확정 (Figma가 스스로 물음표) — 확인 필요

제목이 **원문 그대로** `총판 (채권매입업체? 파트너? 양수인?)`, `유동화기관(투자자?)`. 작성자 본인이 미결로 남긴 항목이다. 임의 확정 금지.

파장이 크다: 총판 = 채권매입업체라면 **총판이 곧 1차 양수인(가맹점 채권의 법적 상대방)**이다. 고객센터 signup.html은 "총판이나 제휴 플랫폼에는 심사 권한도, 서비스 개시 권한도 없어요"라고만 안내 — 심사 권한 얘기는 맞을 수 있으나, 총판이 계약상 채권 양수인일 가능성은 전혀 노출되지 않는다.

### F-T6. 유동화기관 채권양도 조항 미고지 — 확인 필요

Figma 257:2325: "최초 계약시에 페이허그 서비스 이용 계약서 상에 **유동화 기관으로의 채권 양도 문구가 계약서상 나와 있으며**". 고객센터 7개 아티클 어디에도 `유동화` 문자열이 없다. 계약서에 있는 양도 조항이 고객 안내에서 누락된 상태.

### F-T7. 정산주체 카드사 목록에 우리카드 없음 — 확인 필요

Figma 257:2313 열거: 현대카드, 롯데카드, 신한카드, NH농협카드, 비씨카드, 삼성카드, KB국민카드, 하나카드 (8개) + 배민, 요기요, 쿠팡이츠, PG사 등.

**우리카드 누락.** 단순 누락인지 실제 미지원인지 확인 필요. 고객센터는 "카드사"로만 뭉뚱그려 안내하므로, 미지원 카드사가 있다면 현재 안내는 과대 포괄이다.

### F-T8. 미정산금이 고객센터에서 미정의 상태로 사용 — 확정

고객센터 5개 아티클(contract, documents, faq, sales, settlement)이 계좌 변경 경고문에서 `미정산금`을 쓴다 — "위반으로 미정산금이나 손해가 발생하면 손해배상 책임". 그런데 **어느 아티클도 미정산금을 정의하지 않는다.** F-T1대로 Figma 정의 자체가 둘로 갈린 용어를, 손해배상 책임이 걸린 문장에서 미정의로 쓰고 있다.
