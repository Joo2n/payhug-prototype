# /qa-report — 적용 결과 검수 리포트 게시

최근(또는 인자로 지정한) 라운드의 적용·QA 결과를 사용자가 훑어볼 수 있는 리포트 페이지로 만든다. **Figma 쓰기 0건** — 조회·스크린샷만.

## 1. 대상 수집

- 라운드 디렉토리 특정(인자 없으면 `payhug-spec/_pipeline/enhance_*/round*` 중 최신). `apply_report_*.md`·`qa_*.md`·`build_report_*.md`를 읽어 대상 노드ID·판정 데이터를 확보.
- QA 보고서가 없으면 먼저 Agent(doc-qa)를 실행해 만든 뒤 진행.

## 2. 스크린샷 수집·리사이즈

- 대상 장·시트를 get_screenshot으로 수집 → scratchpad `shots/`에 PNG 저장. 기존 QA 스크린샷이 있으면 재사용.
- 전/후 비교가 가능하면(구판 노드 잔존·이전 라운드 스크린샷) 전·후 쌍으로 정리.
- `sips --resampleWidth`로 리사이즈: 판정표용 900px, 확대 크롭 1400px. 총량은 Artifact 16MB 한도 안쪽으로.

## 3. 리포트 HTML 작성

- **artifact-design 스킬을 먼저 로드**한 뒤 작성(디자인 투자 수준 판단). 파일은 scratchpad에.
- 구성: ① 요약(대상 범위·적용/건너뜀/실패·PASS/FAIL 집계) ② 판정표(항목|기준|판정|비고 — qa 보고서 전재) ③ 전/후 스크린샷 갤러리(base64 data URI 임베드 — 외부 URL 불가) ④ 관찰·차기 후보 목록 ⑤ 산출물 파일 경로 표.
- 이미지는 가로 스크롤 컨테이너(`overflow-x:auto`)에, 페이지 가로 넘침 금지. 라이트/다크 토큰 규약 준수.

## 4. Artifact 게시

- Artifact 도구로 게시: `<title>` 간결·고정, description 1문장, favicon 이모지 1개 고정(재게시에도 동일 유지).
- 같은 리포트의 갱신은 같은 파일 경로로 재게시(새 URL 만들지 않기). 다른 세션에서 만든 리포트를 갱신하려면 url 파라미터로 대상 지정.

## 5. 기록

- 리포트 HTML 사본과 게시 URL을 라운드 디렉토리에 기록(`qa_report_publish.md`).

## 최종 보고 (5줄 이내)

게시 URL · 대상 장/시트 수 · PASS/FAIL 집계 · 스크린샷 수 · 기록 파일 경로.
