# /screen-add — 신규 화면 캡처 → 신규 시트 제작

인자(화면 라우트·계정 유형·데이터 상태·모달 여부)를 받아 캡처부터 시트 완성·QA까지 진행한다. **시트 쓰기는 직렬.**

## 0. 준비

- 라운드 디렉토리 확보. page_id 부여: 기존 명명 규칙(AD_*/MC_*/ST_* + 화면 위계 접미) 확인 — `payhug-spec/_pipeline/screen_manifest.json` 대조로 중복 방지.

## 1. 캡처 — Agent(screen-capturer)

- 지시에 포함할 것: 화면 경로·상태(인자 그대로), run-* 사본 파이프라인(목데이터+`?__devuser=` 시드+`/__preview/*` 하네스, MOCK_API=1), **헤드리스 크롬(`--headless=new` + `#figmacapture=` 해시, 창 금지)**, capture.js 태그, generate_figma_design 폴링, 추출본 clone+폰트 리매핑+rescale(1250/w).
- 산출: 추출 페이지의 화면 노드ID.

## 2. 신규 시트 제작 (직렬 — Agent(sheet-applier)에 위임하거나 오케스트레이터가 use_figma 직접)

1. **템플릿 2103:2 clone** → 대상 섹션 그리드의 빈 슬롯에 배치(신규 시트 섹션 관례: 2759:2883 계열, 기존 시트 피치 준수).
2. **텍스트 슬롯 기입 — 템플릿 136슬롯 인덱스 맵** (clone 직후 findAll 텍스트 덤프로 실물 대조 후 사용):
   - 1=Page(page_title) / 3=Page ID / 7=Date(26.MM.DD) / 11=Flow / 24=메모(Note)
   - 키노트 8쌍: 이름=29+3k, 설명=30+3k (k=0..7 → 29/30, 32/33, 35/36, 38/39, 41/42, 44/45, 47/48, 50/51)
   - 54=키노트 요약
   - 심화 상태 pill 13개: 63 / 68 / 73 / 82 / 85 / 92 / 101 / 106 / 115 / 120 / 125 / 130 / 135 — pill 텍스트+색은 상태 4종 스타일(확정=녹 0.039,0.561,0.357 / 확인필요=회 0.420,0.447,0.502 / 가설=앰버 0.706,0.325,0.035 / 신규=남 0.294,0.278,0.839, 텍스트 백색)
   - 심화 제목·설명·근거 슬롯은 pill 인접 인덱스 — 덤프에서 그룹 헤더([데이터 출처]/[계산·판단 로직]/[설정·연결]/[정책·주의])와 행 구조를 확인해 기입
   - 원고가 없으면 먼저 Agent(sheet-writer)로 keynote 8쌍+심화 13행(3/3/2/5) 원고를 만든 뒤 기입
3. **화면부 삽입**: 1단계 추출 노드를 시트 화면 크롭 컨테이너에 clone 삽입 — 컨테이너 높이는 형제 시트와 동일한 고정(FIXED) 유지, hug 오확대 금지.
4. **마커 배치**: 템플릿 **인덱스 15~22 = 숫자 마커(숫자 텍스트의 부모 원형)** 8개를 키노트 1~8 대응 위치(화면부 해당 영역 위)로 이동, **최상위 재부착**(가림 금지). 캡처에 없는 영역의 마커는 해당 키노트 행 옆 여백에.
5. Apple SD 폴백 발생 시 재구성 레시피(스타일 복사→Noto Sans KR 신규→같은 인덱스). 폭 초과는 textAutoResize=HEIGHT+폭 고정 캡. 키노트 표 재적층 후 시트 높이 hug 갱신.

## 3. QA — Agent(doc-qa)

- 원고 대 실물 일치·이력체 0·순한글·pill·마커 8개 노출·화면 크롭 높이·시트 총높이. FAIL 시 2단계 재작업 1회.

## 4. 기록

- `roundN/`에 캡처 로그·시트 제작 로그(신규 노드ID·page_id) 보존, `figma_map_deep.json`·`screen_manifest.json`에 신규 화면 등재, PROGRESS.md 세션 블록. 커밋은 기획 레포만.
