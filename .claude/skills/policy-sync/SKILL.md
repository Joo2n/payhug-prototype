# /policy-sync — 자료 → 정책서 반영 파이프라인

인자로 받은 자료를 정책서(IFX A4 문서군)와 payhug-spec 문서에 같은 양식으로 반영한다. 오케스트레이터(현 세션)는 아래 단계를 순서대로 실행한다. **병렬은 분석·원고 단계까지만, Figma 쓰기(조판)는 반드시 직렬 단일 에이전트.**

## 0. 준비

- 라운드 디렉토리 결정: `payhug-spec/_pipeline/enhance_YYYYMM/roundN/` (YYYYMM=당월, N=기존 최대+1). 없으면 생성.
- 자료 경로 확인(파일 존재·형식). 데스크톱 아카이브 소속 자료면 읽기만 한다는 점을 에이전트 지시에 명기.

## 1. 자료 분석 — Agent(policy-analyst)

- 자료가 여러 개면 자료별로 **병렬** 실행 가능.
- 지시에 포함할 것: 자료 경로, 라운드 디렉토리, "결정/방향/액션/미결 + 영향 매핑표 + 용어 대조표" 산출.
- 산출: `roundN/analysis_*.md`.

## 2. 영향 매핑 확정 (오케스트레이터)

- 분석 파일을 읽고 반영 대상을 확정: 정책서 9문서 중 영향 장·절 / `payhug-spec/01~07_*.md` 중 영향 파일.
- **미확정 3대(C1·C2·C4)를 건드리는 항목은 자동 반영하지 않는다** — 결정 주체·시점이 자료에 명시된 "결정"만 반영, 나머지는 07 미결로.
- 반영 항목 0건이면 여기서 종료(분석 파일만 보존, 보고).

## 3. 원고 증분 — Agent(policy-writer)

- 영향 문서 단위로 **병렬** 실행 가능(같은 문서를 두 에이전트가 다루지 않게 분배).
- 지시에 포함할 것: 분석 파일 경로, 대상 문서·장·절, 기준 원고(`round2/dsl_A/B/C.md` 또는 최신 라운드 원고), "증분 패치 형식(교체 전/후 DSL)" 요구, EQ/EX 검산표 요구.
- 산출: `roundN/dsl_patch_*.md` (전면 재작성이 필요한 문서만 `dsl_*.md`).

## 4. 조판 — Agent(policy-typesetter) ※ 직렬

- **한 번에 1개 에이전트만.** 원고 패치 전체를 하나의 typesetter에 순서대로 맡긴다.
- 지시에 포함할 것: 패치 파일 경로 목록, 대상 섹션 = IFX `IFX4GRC60ibOVCWNrd6VQt` 3783:906 한정, 2-pass reflow·DSL 누출 0건 자가 스캔, 신판 생성→QA 후 구판 제거 순서, 마커·꺾쇠 재연결.
- 산출: `roundN/build_report_*.md`.

## 5. QA — Agent(doc-qa)

- 지시에 포함할 것: 원고 패치·조판 로그 경로, 대상 장 노드ID, 검수 항목(원고 일치·이력체 0·DSL 누출 0·산식 검산·레이아웃·C1/C2/C4 고정 문구).
- FAIL 발생 시: 보고서의 원인 노드·기대값으로 4단계 typesetter에 재작업 1회 → 재QA. 2회 연속 FAIL이면 중단하고 사용자에게 보고.

## 6. 문서 동기화·보존·커밋

1. 반영 내용에 따라 `payhug-spec/01~07_*.md` 갱신 — 특히 미확정 신설·해소 시 **07_OPEN_QUESTIONS 동기화 필수**, 새 확정 사실은 출처(문서명·조항·노드ID) 병기.
2. `payhug-spec.zip` 재생성(관례 스크립트 또는 zip 명령).
3. `payhug-spec/PROGRESS.md`에 세션 블록 추가(무엇을 반영했고 산출물이 어디 있는지).
4. 커밋은 **기획 레포(`~/cursor/payhug`)만** — 자료 원본 레포·프론트 레포 커밋 금지. 커밋 전 `git status`로 의도치 않은 파일 확인.

## 최종 보고 (5줄 이내)

반영 항목 수(결정/미결 분리) · 수정 문서·장 수 · QA 판정 · 산출물 라운드 경로 · 커밋 해시.

## 공통 규율 (PayHug 문서 작업 6원칙 — 위반 금지)

1. **현재 상태만 서술** — 시트·정책서 본문에 변경이력체("삭제/이동/구 X/개편/신설/현행화/이번/종전/스왑") 금지. diff·신구대조 문서를 원고로 쓰지 말고 재서술. 적용 전 이력체 스캔 필수.
2. **순한글** — 본문·설명란에 영문 개발 식별자(함수·변수·상수·라우트) 금지. 영문은 코드 근거 열·SRC(근거) 줄에만 허용.
3. **미확정 단정 금지** — C1(수수료율)·C2(지급 캘린더)·C4(예상 지급 차액)는 값 채택 금지, 고정 문구로만 인용. 6대 개념(미지급금·선정산 제외금액·바로이체·과지급·미회수금·환급) 혼용 금지. '회수' 3갈래(매출 회수=락계좌→모계좌 스윕 / 과지급 회수 / 플랫폼 조정 회수) 혼용 금지.
4. **Figma 쓰기는 단일 세션 직렬** — 쓰기 병렬 금지(검증·스크린샷은 병렬 가능). 쓰기 허용 범위 = 서준 파일 `Tcf69tIciGxmlqCIuRb0iI`(화면설계서 303:173 계열) / IFX `IFX4GRC60ibOVCWNrd6VQt`의 [정책] 정산 페이지 3783:890(섹션 3783:906) 한정. 그 밖 파일·페이지 쓰기 금지. 화면 캡처는 헤드리스 크롬(`--headless=new`)만 — 브라우저 창 금지.
5. **원본 보호** — `/Users/semi/Desktop/01_PayHug/81_아카이브/` 수정·이동 금지(읽기만). 페이허그 프론트 원본 레포는 클론 읽기 전용 — 커밋·푸시 절대 금지. 커밋은 기획 레포(`~/cursor/payhug`)만.
6. **산출물은 파일로 보존** — 원고·로그·보고서는 `payhug-spec/_pipeline/enhance_YYYYMM/roundN/`에 저장. 각 에이전트 최종 응답은 5줄 이내 요약.
