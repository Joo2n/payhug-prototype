# /sheet-update — 코드 변경 → 화면설계서 현행화 파이프라인

프론트 코드의 최신 변경을 화면설계서(서준 파일 `Tcf69tIciGxmlqCIuRb0iI`)에 반영한다. **병렬은 감사·원고까지, Figma 쓰기(적용)는 직렬 단일 에이전트.**

## 0. 준비

- 라운드 디렉토리: `payhug-spec/_pipeline/enhance_YYYYMM/roundN/` (다음 N, 없으면 생성).
- 기준 커밋 확인: 직전 현행화 기록(`payhug-spec/PROGRESS.md` 세션 블록·직전 라운드 로그)에서 admin/merchant 각각의 마지막 반영 HEAD를 찾는다. (참고: 2026-08-12 기준 admin `9e2741b`, merchant `e083af8`.)

## 1. 최신 코드 확보 (읽기 전용 클론)

- `gh repo clone`으로 페이허그 어드민·가맹점 레포 develop 최신본을 scratchpad에 받는다(관례 디렉토리명 `fresh-admin`/`fresh-merchant`).
- **원본 레포에는 커밋·푸시 절대 금지 — 클론은 읽기만.** 실행이 필요하면 screen-capturer가 별도 사본(run-*)을 뜬다.
- 새 HEAD 해시·일자를 기록.

## 2. diff → 영향 시트 특정 (오케스트레이터)

- `git diff --stat <기준커밋>..HEAD`로 변경 파일 목록 → 화면 매핑: `payhug-spec/_pipeline/screen_manifest.json`(208화면 메타)·`figma_map_deep.json`(page_id→노드) 참조.
- 분류: (a) 기존 시트 영향 — 변경 파일이 걸린 화면 / (b) **신규 화면** — 새 라우트·새 모달 / (c) 삭제·이동 화면 — 사용자 결정 필요 항목으로 분리(임의 삭제 금지).
- 변경 0건이면 종료(기준 커밋만 기록·보고).

## 3. 감사 — Agent(sheet-auditor)

- 영향 시트를 시트 묶음으로 나눠 **병렬** 실행 가능.
- 지시에 포함할 것: 대상 시트 노드ID 목록, diff 요지(어떤 코드가 바뀌었는지), 4판정(OK설명체/변경이력체/빈약/영문노출) + 코드 변경으로 서술이 낡은 슬롯 특정.
- 산출: `roundN/audit_*.md`.

## 4. 원고 — Agent(sheet-writer)

- 화면 묶음으로 **병렬** 실행 가능.
- 지시에 포함할 것: 클론 경로·HEAD 해시, 감사 파일 경로, admin_content.md 스키마(키노트 8쌍 + 심화 13행 3/3/2/5), "현재 상태 서술만·diff 재서술" 요구.
- 산출: `roundN/*_content.md`.

## 5. 적용 — Agent(sheet-applier) ※ 직렬

- **한 번에 1개 에이전트만.** 원고·감사 목록 전체를 하나의 applier에 맡긴다.
- 지시에 포함할 것: 원고 경로, 노드 재특정 규약(ID 무효 시 텍스트 매치), pill 재도색·Apple SD 재구성 레시피·폭 캡·격자 복구·마커 재부착, 적용 전 이력체 스캔.
- 산출: `roundN/apply_report_*.md`.

## 6. 신규 화면 (있을 때만)

- 신규 화면은 `/screen-add` 절차를 따른다: Agent(screen-capturer)로 캡처·추출 → 템플릿 2103:2 clone 시트 제작(인덱스 맵은 screen-add 스킬 참조) → 마커 배치. 시트 쓰기는 5단계 applier와 순서를 겹치지 않게 직렬 배치.

## 7. QA — Agent(doc-qa)

- 지시: 원고·적용 로그 경로, 대상 시트 노드ID, 검수 항목(원고 일치·이력체 0·순한글·pill·마커·화면 크롭·시트 높이).
- FAIL 시 applier 재작업 1회 → 재QA. 2회 연속 FAIL이면 중단·보고.

## 8. 기록·커밋

- `payhug-spec/PROGRESS.md`에 세션 블록(새 기준 커밋 해시 명기 — 다음 /sheet-update의 기준점).
- 커밋은 기획 레포(`~/cursor/payhug`)만.

## 공통 규율 (PayHug 문서 작업 6원칙 — 위반 금지)

1. **현재 상태만 서술** — 시트·정책서 본문에 변경이력체("삭제/이동/구 X/개편/신설/현행화/이번/종전/스왑") 금지. diff·신구대조 문서를 원고로 쓰지 말고 재서술. 적용 전 이력체 스캔 필수.
2. **순한글** — 본문·설명란에 영문 개발 식별자(함수·변수·상수·라우트) 금지. 영문은 코드 근거 열·SRC(근거) 줄에만 허용.
3. **미확정 단정 금지** — C1(수수료율)·C2(지급 캘린더)·C4(예상 지급 차액)는 값 채택 금지, 고정 문구로만 인용. 6대 개념(미지급금·선정산 제외금액·바로이체·과지급·미회수금·환급) 혼용 금지. '회수' 3갈래(매출 회수=락계좌→모계좌 스윕 / 과지급 회수 / 플랫폼 조정 회수) 혼용 금지.
4. **Figma 쓰기는 단일 세션 직렬** — 쓰기 병렬 금지(검증·스크린샷은 병렬 가능). 쓰기 허용 범위 = 서준 파일 `Tcf69tIciGxmlqCIuRb0iI`(화면설계서 303:173 계열) / IFX `IFX4GRC60ibOVCWNrd6VQt`의 [정책] 정산 페이지 3783:890(섹션 3783:906) 한정. 그 밖 파일·페이지 쓰기 금지. 화면 캡처는 헤드리스 크롬(`--headless=new`)만 — 브라우저 창 금지.
5. **원본 보호** — `/Users/semi/Desktop/01_PayHug/81_아카이브/` 수정·이동 금지(읽기만). 페이허그 프론트 원본 레포는 클론 읽기 전용 — 커밋·푸시 절대 금지. 커밋은 기획 레포(`~/cursor/payhug`)만.
6. **산출물은 파일로 보존** — 원고·로그·보고서는 `payhug-spec/_pipeline/enhance_YYYYMM/roundN/`에 저장. 각 에이전트 최종 응답은 5줄 이내 요약.
